목차

TL;DR

  • 문제: 오픈소스 LLM 생태계는 test-time scaling(추론·RL) 축에서는 빠르게 발전했지만, pre-training scaling 축에서는 1T급 파라미터 근방에 정체되어 있다. 비슷한 규모의 사전학습 기반 위에 점점 정교한 RL을 얹는 방식은 결국 수렴하고, 최강 프로프라이어터리 모델과의 격차는 벌어진다.
  • 해결: 두 축을 동시에 프론티어까지 밀어붙인다. ##2.8T 총 파라미터 / 104B 활성 파라미터의 네이티브 멀티모달 MoE (Mixture-of-Experts)를 1M 토큰 컨텍스트로 학습##하고, 그 위에 long-horizon 에이전틱 RL을 여러 reasoning effort 레벨에서 수행한 뒤 하나의 모델로 증류(MOPD)한다.
  • 왜 작동하는가: 정보 흐름(information flow)을 세 방향으로 동시에 확장했기 때문이다. 시퀀스 방향은 KDA(선형 어텐션)+주기적 Gated MLA 하이브리드, 깊이 방향은 Attention Residuals(층 간 선택적 어텐션), 너비 방향은 896개 라우팅 전문가의 Stable LatentMoE. 여기에 안정화 장치(SiTU-GLU, RMSNorm, Quantile Balancing, Per-Head Muon)를 붙여 극단적 sparsity와 3T급 규모에서 학습이 발산하지 않게 했다. 결과적으로 Kimi K2 대비 ##scaling efficiency 약 2.5배##.
  • 비유: 기존 Transformer의 residual stream은 "층마다 메모를 한 장씩 덧붙여 쌓아 올린 노트"다. 뒤로 갈수록 앞의 메모는 묻힌다. AttnRes는 이 노트를 "목차가 달린 파일 캐비닛"으로 바꿔, 각 층이 필요한 앞 층의 메모만 골라 꺼내 보게 한다. 마찬가지로 KDA는 모든 대화를 녹취하는 대신 "고정 크기 요약 수첩"을 계속 갱신하고, 4개 층마다 한 번씩만 전체 녹취(MLA)를 참조한다.

핵심 기여 (Key Contributions)

  1. 오픈 프론티어 사전학습: 2.8T 총 파라미터 / 104B 활성 파라미터의 네이티브 멀티모달 MoE를 1M 토큰 컨텍스트로 학습. KDA, AttnRes, Stable LatentMoE와 개선된 데이터·학습 레시피가 합쳐져 Kimi K2 대비 전체 scaling efficiency를 약 2.5× 개선.
  2. Multi-effort test-time scaling을 위한 강화학습: general / general agent / coding agent 3개 도메인 × {low, high, max} 3개 reasoning effort = 9개 전문가 모델을 RL로 학습한 뒤, Multi-Teacher On-Policy Distillation(MOPD)으로 단일 모델에 통합.
  3. 다조(多兆) 파라미터·백만 토큰 인프라: KDA 알고리즘–시스템 co-design(FlashKDA 커널, KDA Context Parallelism, state-aware prefix cache), 완전 균형 EP 학습(MoonEP), resumable microVM 샌드박스를 갖춘 co-located RL 시스템, 프로덕션 서빙 최적화.
  4. 오픈 프론티어 모델 공개: Kimi K3 전체 가중치를 공개하여 연구·배포·후속 혁신에 개방. ##세계 최초의 오픈 3T급 모델##.

배경 (Background)

두 개의 스케일링 축

LLM 개발 초기의 스케일링은 배포 이전 연산(pre-deployment compute)에 대한 투자였다. 더 큰 모델을 더 많은 데이터로 학습시키는 것이다. 추론(reasoning) 모델의 등장은 test-time computation이라는 두 번째 축을 열었다. OpenAI o-series는 RL과 test-time reasoning을 스케일링했고, Anthropic의 extended-thinking 모델은 적응적 thinking budget을 할당하며 추론과 도구 사용을 교차시켰다. DeepSeek-R1과 Kimi K1.5는 대규모 RL이 강한 사전학습 모델로부터 정교한 추론 행동을 이끌어낼 수 있음을 보였고, Kimi K2.5 Agent Swarm은 이를 순차 추론에서 병렬 에이전트 조율로까지 확장했다.

문제는 비대칭이다. 오픈소스 생태계는 두 번째 축에서는 빠르게 따라잡았지만 첫 번째 축에서는 1T급 근방에 머물렀다. 비슷한 규모의 기반 위에서 RL 기법만 정교해지면 오픈 진영 내부의 성능은 서로 수렴하고, 최강 프로프라이어터리 시스템과의 격차만 벌어진다. Kimi K3는 두 축을 함께 민다.

Kimi Linear와 delta rule — KDA의 직계 조상

KDA를 이해하려면 먼저 linear attention과 delta rule을 알아야 한다. 소프트맥스 어텐션은 모든 과거 토큰의 key–value를 캐시에 보관하므로 KV 캐시가 시퀀스 길이에 비례해 자란다. Linear attention은 대신 고정 크기 상태 행렬 $S \in \mathbb{R}^{d_k \times d_v}$ 하나로 과거를 요약하고, 토큰마다 $S_t = S_{t-1} + k_t v_t^\top$처럼 갱신한다(단순 누적형). 읽기는 $o_t = S_t^\top q_t$이다.

단순 누적은 상태가 포화되는 문제가 있다. delta rule은 여기에 "덮어쓰기"를 도입한다: 새 $(k_t, v_t)$를 쓸 때 기존 상태에서 $k_t$ 방향 성분을 먼저 지우고 쓴다. 즉 $S_t = (I - \beta_t k_t k_t^\top) S_{t-1} + \beta_t k_t v_t^\top$. 직관적으로, 같은 키에 대한 옛 값을 새 값으로 교체하는 연상 기억(associative memory) 갱신이다.

Kimi Delta Attention (KDA)는 여기에 channel-wise forget gate를 더한다. 채널마다 독립적인 감쇠율 $\alpha_t \in (0,1)^{d_k}$로 과거 상태를 차등 망각시켜, 어떤 채널은 오래 기억하고 어떤 채널은 빨리 잊게 한다. Kimi K3는 이 KDA를 시퀀스 축의 주력 믹서로 삼고, 4개 층마다 1개씩 전역 어텐션(Gated MLA)을 끼워 넣어 "무제한 전역 상호작용"을 보존한다.

MLA와 MoE — 이전 세대에서 물려받은 것

MLA (Multi-head Latent Attention)는 DeepSeek-V2에서 도입된 기법으로, 각 토큰의 key–value 표현을 저차원 latent 벡터 $c_t = W_c x_t$로 압축해 캐시하고, 어텐션 계산 시 학습된 up-projection으로 head별 key/value를 복원한다. KV 캐시 용량을 크게 줄이면서 전역 토큰 간 어텐션을 유지한다. Kimi K2/K2.5가 채택했고 K3도 주기적 전역 어텐션 층에서 유지한다.

DeepSeekMoE 계열의 shared/routed expert 구조: 모든 토큰이 통과하는 shared expert와 라우터가 선택하는 routed expert를 분리한다. Kimi K3의 Stable LatentMoE는 여기에 LatentMoE를 결합한다 — routed expert만 좁은 latent 공간(폭 $\ell$)에서 동작시켜, 전문가 수를 늘려도 통신량과 가중치 트래픽이 폭증하지 않게 한다.

1.1 Hybrid Attention

Kimi K3는 층 단위 하이브리드를 쓴다. 각 블록은 3개의 KDA 층 + 1개의 Gated MLA 층 (3:1 비율)로 구성되고 이 패턴이 백본 전체에 반복된다. 백본 끝에 Gated MLA 층 하나를 추가로 두어 최종 층이 항상 전역 어텐션을 수행하게 한다.

1.1.1 Kimi Delta Attention (KDA)

토큰 위치 $t$, 모델 hidden 차원 $d$의 은닉 상태 $x_t \in \mathbb{R}^d$를 생각하자. 단일 헤드 기준으로 query·key $q_t, k_t \in \mathbb{R}^{d_k}$, value $v_t \in \mathbb{R}^{d_v}$, 재귀 상태 $S_t \in \mathbb{R}^{d_k \times d_v}$이다. KDA는 delta-rule 갱신 이전에 channel-wise 감쇠를 적용한다:

$$S_t = \left(I - \beta_t k_t k_t^\top\right) \mathrm{Diag}(\alpha_t) S_{t-1} + \beta_t k_t v_t^\top, \qquad \tilde{o}_t = S_t^\top q_t \tag{1}$$

여기서 $\alpha_t \in (0,1)^{d_k}$는 채널별 1-step 유지 계수(retention factor), $\beta_t \in (0,1)$은 delta-rule의 쓰기 강도(write strength)를 조절한다.

직관적으로 말하면: $\mathrm{Diag}(\alpha_t)$는 "채널마다 다른 속도로 과거를 흐리게 만드는 필터", $(I - \beta_t k_t k_t^\top)$는 "지금 쓰려는 키 방향의 옛 기억을 지우는 지우개", 마지막 항은 "새 기억을 그 자리에 써넣는 펜"이다. 세 동작이 매 토큰마다 순서대로 일어난다.

헤드별 양들은 Kimi Linear를 따라 다음과 같이 파라미터화된다:

$$\begin{aligned} q_t^h, k_t^h &= \mathrm{L2Norm}\!\left(\mathrm{Swish}\!\left(\mathrm{ShortConv}\!\left(W^h_{q/k} x_t\right)\right)\right) \in \mathbb{R}^{d_k},\\ v_t^h &= \mathrm{Swish}\!\left(\mathrm{ShortConv}\!\left(W^h_v x_t\right)\right) \in \mathbb{R}^{d_v},\\ \beta_t^h &= \mathrm{Sigmoid}\!\left(W^h_\beta x_t\right) \in (0,1),\\ z_t^h &= W_\alpha^{\uparrow} W_\alpha^{\downarrow} x_t + b^h_\alpha \in \mathbb{R}^{d_k}. \end{aligned} \tag{2}$$

query/key/value 투영에 ShortConv → Swish를 적용하고, query와 key는 추가로 L2 정규화한다. 저랭크 투영 $W_\alpha^{\uparrow} W_\alpha^{\downarrow}$와 헤드별 bias $b^h_\alpha$가 각 key 채널에 대한 세밀한 decay logit $z^h_t$를 만든다.

Chunkwise parallel form. KDA는 청크 간에는 재귀적, 청크 내에서는 병렬이다. 청크 크기 $C$에 대해 채널별 누적 감쇠를 정의한다:

$$\gamma_{[t]}^{i \to j} := \prod_{r=i}^{j} \alpha^r_{[t]}, \qquad \gamma^r_{[t]} := \gamma^{1\to r}_{[t]} \tag{3}$$

$\Gamma_{[t]} \in \mathbb{R}^{C \times d_k}$는 $\gamma^1_{[t]}, \dots, \gamma^C_{[t]}$를 행 방향으로 쌓은 것이다. UT transform이 $U_{[t]}, W_{[t]}$를 만들고 pseudo-value $\tilde{V}_{[t]} := U_{[t]} - W_{[t]} S_{[t]}$를 정의하면, 청크 $t$의 모든 출력이 병렬로 계산된다:

$$\begin{aligned} A_{[t]} &= \mathrm{Tril}\!\left[\left(Q_{[t]} \odot \Gamma^{1\to C}_{[t]}\right)\left(K_{[t]} / \Gamma^{1 \to C}_{[t]}\right)^\top\right],\\ O_{[t]} &= \underbrace{\left(\Gamma^{1\to C}_{[t]} \odot Q_{[t]}\right) S_{[t]}}_{\text{inter-chunk}} + \underbrace{A_{[t]} \tilde{V}_{[t]}}_{\text{intra-chunk}}. \end{aligned} \tag{4}$$

$\mathrm{Tril}(M)$은 상삼각(엄격) 성분을 0으로 만들고 대각 포함 하삼각을 남긴다. 대각을 남기는 이유는 각 출력이 현재 토큰 갱신 이후의 상태를 읽기 때문이다. 첫 항은 앞선 청크들로부터 오는 정보, 둘째 항은 현재 청크 내 상호작용을 담당한다.

Lower-bounded decay — K3가 Kimi Linear에서 바꾼 첫 번째 지점

왜 문제인가: Eq. 4는 청크 내 key를 역수 누적감쇠 $1/\Gamma^{1\to C}_{[t]}$로 재스케일한다. $\Gamma^{1 \to C}_{[t]}$는 $(0,1)$ 구간 값들의 곱이므로 이 역수는 무한히 커질 수 있고 유한 정밀도에서 오버플로한다. Kimi Linear는 로그 공간에서 상대 감쇠를 계산하고 청크를 16-토큰 2차 타일로 쪼개 이를 통제했다. 비대각 타일은 Tensor Core의 dense matmul로 처리할 수 있지만, 대각 타일은 여전히 명시적 position-pair 계산이 필요했고 이것이 intra-chunk의 주 병목이었다.

K3의 해법: decay logit $z^h_t$에서 per-step log-decay $g^h_t$로 가는 매핑을 바꾼다. Kimi Linear는 GDN/Mamba-2를 따라 negative-Softplus 매핑 $g^h_t = -e^{A_h}\mathrm{Softplus}(z^h_t) \in (-\infty, 0)^{d_k}$를 썼다. K3는 대신 scaled sigmoid로 아래를 막는다:

$$g^h_t = g_{\min}\,\mathrm{Sigmoid}\!\left(e^{A_h} z^h_t\right) \in (g_{\min}, 0)^{d_k}, \qquad \alpha^h_t = \exp(g^h_t) \in (e^{g_{\min}}, 1)^{d_k} \tag{5}$$

$A_h$는 학습 가능한 헤드별 log-scale로 $A_h = 0$으로 초기화하고, $g_{\min} = -5$로 고정한다. 이때 모든 유지 계수가 $\alpha^h_{t,j} > e^{-5} \approx 6.7 \times 10^{-3}$을 만족하며, 16-토큰 타일에 걸친 누적 log-decay는 $(-80, 0)$ 안에 놓인다. 따라서 역수 재스케일 계수는 $e^{80}$보다 작아 ##BF16 동적 범위 안에 안전하게 들어간다##.

직관적으로 말하면: "얼마나 빨리 잊을 수 있는가"에 하한선을 긋는 것이다. 아무리 잊고 싶어도 한 스텝에 $e^{-5}$ 이하로는 못 줄인다. 이 작은 제약 하나로 대각 타일도 dense Tensor Core matmul을 쓸 수 있게 되어 position-pair 경로 자체가 사라진다 — 수치 안정성 트릭이 곧바로 커널 단순화로 이어진 사례.

Full-rank gate — 두 번째 변경점

KDA의 출력 게이트를 Kimi Linear의 저랭크 파라미터화에서 입력 의존 full-rank 투영으로 바꿨다. 재귀 출력에 head-wise RMSNorm을 적용한 뒤 데이터 의존 출력 게이팅을 수행한다:

$$y_t = W_o\left[\mathrm{Sigmoid}(W_g x_t) \odot \mathrm{RMSNorm}(\tilde{o}_t)\right] \tag{6}$$

1.1.2 Gated MLA

K3는 MLA를 주기적 전역 어텐션 층에 유지하되 두 가지를 바꿨다.

(a) NoPE (No Position Encoding). Kimi K2/K2.5와 달리, Kimi Linear의 하이브리드 설계를 따라 모든 MLA 층에 위치 인코딩을 적용하지 않는다. 중간의 KDA 층들이 위치 민감·최신성 인식 시퀀스 믹싱을 제공하고, MLA 층은 제약 없는 전역 콘텐츠 상호작용만 담당한다. 이 분리 덕분에 컨텍스트 길이를 늘릴 때 RoPE frequency base 재조정이나 YaRN 같은 위치 인코딩 파라미터 수정이 전혀 필요 없다.

(b) 입력 의존 channel-wise full-rank 출력 게이트. 게이팅되지 않은 MLA 출력 $\tilde{o}_t$에 대해

$$y_t = W_o\left[\mathrm{Sigmoid}(W_g x_t) \odot \tilde{o}_t\right] \tag{7}$$

$W_g$는 full rank로, KDA의 새 파라미터화와 일치시킨 것이다. 각 토큰이 전역 어텐션에서 읽어올 채널을 스스로 조절할 수 있게 한다.

추가로, flash attention에서 발생하는 편향된 반올림 오차를 보정하기 위해 학습 중 어텐션 출력을 FP32로 유지한다. 이는 출력 타일의 on-chip 사용량을 2배로 늘리므로, 학습 커널을 재설계해 출력 타일을 query 타일 대신 KV staging 버퍼와 겹치게 배치했다 — shared memory를 확보해 더 깊은 KV 파이프라인과 높은 학습 처리량을 얻었다.

1.2 Attention Residuals (AttnRes)

왜 필요한가: 표준 residual connection은 깊이 방향으로 모든 이전 정보를 단일 상태 $h_l$에 압축한다. 이는 시간 방향에서 RNN이 겪던 병목과 정확히 같은 구조다. Transformer가 시퀀스 모델링에서 재귀를 어텐션으로 대체해 각 위치가 데이터 의존 가중치로 이전 모든 위치에 선택 접근하게 만들었듯, AttnRes는 같은 방법론을 깊이 축에 적용한다.

Full Attention Residuals

각 층 $l$에 대해 층별 학습 가능 pseudo-query $q_l = w_l \in \mathbb{R}^d$와 key/value를 정의한다:

$$k_i = v_i = \begin{cases} h_1 & i = 0\\ f_i(h_i) & 1 \le i \le l-1 \end{cases} \tag{8}$$

$f_i(h_i)$는 층 $i$의 출력이고 $h_1$은 토큰 임베딩이다. 어텐션 가중치는 softmax 커널 $\phi(q,k) = \exp\!\left(q^\top \mathrm{RMSNorm}(k)\right)$를 따르며, RMSNorm은 출력 크기가 큰 층이 가중치를 독식하는 것을 막는다:

$$\alpha_{i \to l} = \frac{\phi(q_l, k_i)}{\sum_{j=0}^{l-1}\phi(q_l, k_j)}, \qquad h_l = \sum_{i=0}^{l-1}\alpha_{i\to l}\cdot v_i \tag{9}$$

네트워크 깊이가 크지 않으므로($L < 100$) $O(L^2 d)$ 연산은 감당 가능하다. 실질적 부담은 모든 층 출력을 살려 두는 $O(Ld)$ 메모리(및 파이프라인 병렬 시 스테이지 간 통신)다.

Block Attention Residuals — 실제로 쓰는 형태

$L$개 층을 $N$개 블록($S = L/N$층씩)으로 분할한다. 블록 $n$(층 인덱스 집합 $B_n$) 내부에서는 층 출력을 합으로 축약해 단일 표현 $b_n = \sum_{j \in B_n} f_j(h_j)$를 만든다. $b^i_n$은 블록의 처음 $i$개 층에 대한 부분합이며, $b_0 = h_1$로 두어 토큰 임베딩이 항상 소스에 포함되게 한다. 블록 간에는 $N$개 블록 수준 표현에 대해서만 full attention을 적용한다. 블록 $n$의 $i$번째 층에 대한 value 행렬은:

$$V = \begin{cases} \left[b_0, b_1, \dots, b_{n-1}\right]^\top & i = 1 \ \text{(블록 } n \text{의 첫 층)}\\ \left[b_0, b_1, \dots, b_{n-1}, b^{i-1}_n\right]^\top & i \ge 2 \ \text{(이후 층)} \end{cases} \tag{10}$$

최종 출력 층은 $N$개 블록 표현 전체를 집계한다. Block AttnRes 하에서 메모리·통신 오버헤드는 $O(Ld)$에서 $O(Nd)$로 줄어든다. 또한 이 블록 구조는 추론 시 상태 크기를 유한하게 묶어, 병렬 inter-block 결과를 순차 intra-block 부분합과 online softmax로 병합할 수 있게 하여 추론 비용을 크게 낮춘다.

경험적으로 $N \approx 8$이 모델 규모 전반에서 이득 대부분을 회수한다. Kimi K3는 층을 12층 크기의 8개 블록으로 분할하며, 마지막은 부분 블록이고 임베딩 층까지 세면 총 9개 블록이 된다.

1.3 Stable LatentMoE

왜 필요한가: 전문가 풀과 활성 전문가 수를 모두 늘리면 전문가 특화의 공간이 넓어진다. 그러나 기존 MoE에서는 선택된 각 전문가가 전체 $d$차원 토큰 표현을 받으므로, 통신량과 전문가 가중치 트래픽이 라우팅 다중도(multiplicity)에 비례해 증가한다.

LatentMoE는 모델 전체 너비와 routed expert 너비를 분리해 이 확장을 감당 가능하게 만든다. shared expert는 공통 변환을 위해 full-width 경로를 유지하고, 특화된 routed expert는 폭 $\ell$의 좁은 latent 공간에서 동작한다. 덕분에 K3는 ##채널 믹싱을 896개 라우팅 전문가·토큰당 16개 활성(sparsity 56)까지 확장##할 수 있었다.

하지만 이 극단적 sparsity는 vanilla 설계의 두 가지 실패 모드를 증폭시킨다:

  1. 활성값 폭발: routed 경로가 $W_\downarrow$ → 게이팅된 multi-branch 전문가 FFN → $W_\uparrow$로 이어져 거의 4개의 연속 행렬곱 사슬이 된다. 이 ill-conditioned 구조가 2.8조 파라미터 규모와 결합하면 routed branch의 내부 활성값이 폭발한다.
  2. 로드 밸런싱 붕괴: 약 $10^3$개 전문가의 부하를 맞추는 것은 기존 auxiliary-loss-free bias 갱신이 잘 작동하는 영역을 벗어난다.

Stable LatentMoE는 세 구성 요소로 대응한다: (i) up-projection 앞의 RMSNorm, (ii) SiTU-GLU (활성값 폭발 억제), (iii) Quantile Balancing (로드 밸런싱).

$x \in \mathbb{R}^d$에 대해 shared expert는 $x$를 직접 처리하고, routed 경로는 $z = W_\downarrow x \in \mathbb{R}^\ell$로 투영해 선택된 전문가들에 디스패치한 뒤 가중 집계를 $W_\uparrow$로 $\mathbb{R}^d$에 되돌린다:

$$\begin{aligned} u &= \sum_{i \in T_k(x)} p_i E^{\text{routed}}_i (W_\downarrow x),\\ y &= \sum_{j=1}^{N_s} E^{\text{shared}}_j(x) + W_\uparrow\,\mathrm{RMSNorm}(u). \end{aligned} \tag{11}$$

$u \in \mathbb{R}^\ell$는 집계된 routed 표현, $E^{\text{shared}}_j : \mathbb{R}^d \to \mathbb{R}^d$와 $E^{\text{routed}}_i : \mathbb{R}^\ell \to \mathbb{R}^\ell$는 각각 shared/routed 전문가 FFN, $p_i$는 Quantile Balancing 규칙으로 정의되는 라우터 가중치다. K3는 모든 층에서 full-width shared expert 수를 $N_s = 2$로 고정한다.

1.3.1 Normalized LatentMoE

원래 LatentMoE는 집계된 routed 표현 $u$에 $W_\uparrow$를 직접 적용했는데, $u$의 스케일은 선택된 전문가와 라우팅 가중치에 따라 크게 변한다. K3는 Eq. 11처럼 전문가 집계와 up-projection 사이에 RMSNorm을 삽입한다. 이 정규화는 routed branch가 full-width shared branch와 결합되기 전에 스케일 변동에 대한 민감도를 낮춘다. 학습 안정화를 넘어 validation loss와 다운스트림 벤치마크를 일관되게 개선한다.

1.3.2 SiTU-GLU (Sigmoid Tanh Unit GLU)

왜 필요한가: SwiGLU는 $\mathrm{Swish}(W_g x) \odot W_u x$로, 두 곱셈 인자가 모두 무계(unbounded)다. 두 좌표가 동시에 커지면 활성값 이상치가 생기고 저정밀도 연산에서 오버플로 위험이 커진다. 반대로 원래 GLU의 sigmoid 게이트는 게이트 성장을 막지만 Swish의 "양수 영역에서 거의 선형" 특성을 잃는다. 필요한 것은 큰 값의 성장은 억제하되 SwiGLU 특유의 국소·양수측 응답은 보존하는 활성 함수다.

SiTU-GLU는 smooth cap $\mathrm{softcap}(x, \beta) = \beta \tanh(x/\beta)$를 Swish 게이트의 선형 인자와 up branch에 독립적으로 적용한다:

$$\mathrm{SiTU\text{-}GLU}(x) = \left[\beta_1 \tanh\!\left(\frac{W_g x}{\beta_1}\right) \odot \mathrm{Sigmoid}(W_g x)\right] \odot \left[\beta_2 \tanh\!\left(\frac{W_u x}{\beta_2}\right)\right] \tag{12}$$

Kimi K3는 게이트 branch에 $\beta_1 = 4$, up branch에 $\beta_2 = 25$를 쓴다.

직관적으로 말하면: scaled tanh는 원점 근처에서 거의 항등함수($\beta\tanh(z/\beta) = z + O(z^3/\beta^2)$, Eq. 18)라서 SwiGLU와 1차까지 동일하게 행동하지만, 값이 커지면 $\beta$에서 부드럽게 멈춘다. "평소엔 SwiGLU처럼, 폭주할 때만 브레이크." 그리고 hard clamping과 달리 포화 경계 밖에서도 gradient가 0이 되지 않아 학습이 더 잘 된다.

부록 B는 국소 전개, 극한($\beta_1, \beta_2 \to \infty$이면 SwiGLU로 수렴), 형식적 출력 경계를 제시한다: $|\tanh(z)| < 1$이고 $0 < \mathrm{Sigmoid}(z) < 1$이므로 모든 출력 좌표가

$$\|\mathrm{SiTU\text{-}GLU}(x)\|_\infty \le \beta_1\beta_2 = 100 \tag{19}$$

을 만족한다.

1.3.3 Quantile Balancing (QB)

왜 필요한가: K3는 auxiliary-loss 기반 라우팅 대신 auxiliary-loss-free 라우팅을 쓴다. 로드 밸런싱은 Top-k 선택에 쓰이는 라우터 점수에 전문가별 bias $b_j$를 더해 구현한다. 토큰 $x_i$에 대해 라우터는 $s_i = \mathrm{Sigmoid}(W_r x_i)$를 계산하고,

$$T_i = \mathrm{argtopk}\left(s_i + b\right), \qquad p_{i,j} = \frac{s_{i,j}}{\sum_{r \in T_i} s_{i,r}}, \quad j \in T_i \tag{13}$$

$b$가 $p_{i,j}$에서 빠져 있으므로, bias는 디스패치만 조절할 뿐 혼합 가중치나 라우터의 gradient 기반 최적화를 바꾸지 않는다.

기존 방법은 고정 스텝 규칙 $b^{(t+1)}_j = b^{(t)}_j + \gamma\,\mathrm{sign}(\bar\ell - \ell_j)$로 $b$를 갱신하는데, $\gamma$가 느린 적응과 부하 진동 사이의 트레이드오프를 만든다. LatentMoE가 층당 라우팅 전문가 풀을 896개로 늘리면 균형 유지가 훨씬 어려워진다. 불균형 라우팅은 expert-parallel 학습을 느리게 하고 일부 전문가를 제대로 학습되지 않은 채로 남긴다.

QB의 아이디어: 각 전문가 bias를 목표 부하에 대응하는 라우터 점수 quantile에서 직접 읽어온다. $m$개 토큰이 $n$개 전문가로 Top-k 라우팅되는 배치에서 목표 부하는 $q := mk/n$이다. QB는 단 한 번의 forward pass로 다음 bias를 유도한다.

라우팅에서 Top-k 대신 biased score $s_i + b^{(t)}$에 대해 Top-(k+1)을 취한다. 앞의 $k$개는 실제로 선택된 경로이고, $(k{+}1)$번째 항목이 바로 어떤 전문가가 토큰 $i$의 Top-k에 진입하려면 넘어야 하는 컷오프 $\alpha^{(t)}_i$다. Top-(k+1)에서 컷오프를 취하면 별도의 토큰 측 quantile 계산이 필요 없다.

컷오프를 고정한 채, 후보 bias $\hat b^{(t+1)}_j$ 하에서 전문가 $j$로 라우팅되는 토큰 수는 $\sum_{i=1}^m \mathbb{1}\!\left[s_{i,j} + \hat b^{(t+1)}_j > \alpha^{(t)}_i\right]$이고, 이는 임계값 $-\hat b^{(t+1)}_j$에 대해 단조 감소한다. 동점이 없다고 가정하면, 이 개수를 $q$로 만드는 것은 $-\hat b^{(t+1)}_j$를 margin $s_{i,j} - \alpha^{(t)}_i$의 $(q{+}1)$번째로 큰 값에 두는 것과 같다. $q/m = k/n$이므로 이는 토큰 전체에 걸친 margin의 $(1 - k/n)$-quantile이고, QB 갱신은:

$$\begin{aligned} \hat b^{(t+1)}_j &\leftarrow -\,\mathrm{quantile}_{1-k/n}\left(s_{:,j} - \alpha^{(t)}\right),\\ b^{(t+1)} &\leftarrow \hat b^{(t+1)} - \mathrm{mean}\!\left(\hat b^{(t+1)}\right)\mathbb{1}. \end{aligned} \tag{14}$$

둘째 줄은 Top-k 선택을 바꾸지 않는 공통 오프셋을 제거한다. 인과성을 위해 갱신은 다음 스텝에만 적용된다 — 배치가 자기 자신에서 유도된 bias로 라우팅되는 일은 결코 없다. 최종 bias는 추론 시 고정(freeze)된다.

직관적으로 말하면: 기존 방법이 "부하가 많으면 조금 낮추고, 적으면 조금 올리는" 비례 제어라면, QB는 "각 전문가가 정확히 $q$개 토큰을 받으려면 문턱이 어디여야 하는가"를 분포에서 직접 읽어내는 일발 조준이다. 스텝 크기 $\gamma$라는 하이퍼파라미터 자체가 사라진다.

Histogram estimation. 실제 규모에서 Eq. 14의 quantile은 글로벌 배치 전체에 걸치는데, margin 개수가 수백만이고 랭크와 누적 스텝에 흩어져 있어 정확한 quantile을 위해 모두 모으는 것은 불가능하다. 대신 각 전문가의 margin 히스토그램에서 quantile을 읽는다: 랭크별 bin 카운트를 all-reduce 한 번으로 합치고 pooled count에서 quantile을 복원한다. 카운트는 가법적이므로, 토큰이 어떻게 샤딩되든 히스토그램은 pooled global batch를 표현한다. 통신 비용은 전문가당 수백 개 bin 수준에 불과하다. 1.4 Native Vision

Kimi K3는 네이티브 멀티모달이다. 텍스트·이미지·비디오가 하나의 컨텍스트 안에서 단일 공유 백본으로 처리되며, 사후 모달리티 정렬(post-hoc modality-alignment) 단계가 없다. 이는 long-horizon vision-in-the-loop 행동의 아키텍처적 기반이다: 렌더링된 결과물과 그것을 만든 코드가 같은 토큰 스트림에 살기 때문에, 모델은 코드를 쓰고 → 결과 스크린샷/비디오 프레임을 검사하고 → 시각적 산출물(UI, 그래픽, 비디오)을 반복 개선하는 루프를 모델 간 hand-off 없이 돌 수 있다.

MoonViT-V2 — SigLIP 초기화를 버리다

Kimi K2.5와의 핵심 차이: K3의 비전 인코더 MoonViT-V2는 ##next-token prediction으로 완전히 처음부터(from scratch) 학습##된다. 기존 관행(K2.5 포함)은 SigLIP 같은 대조학습(contrastive) 사전학습 모델로 비전 인코더를 초기화하는 것이었다. 사전학습된 시각 지식이 유리한 출발점을 준다는 전제였다.

K3가 이 관행을 버린 주된 이유는 학습 안정성이다. 사전학습된 인코더를 LLM에 붙이면 공동 최적화가 불안정해진다 — SigLIP으로 초기화한 MoonViT-3D는 지속적으로 더 높은 gradient norm과 잦은 spike를 보이는 반면, MoonViT-V2는 학습 내내 안정적이다(Fig. 6).

(b) 14k~16k 구간 확대(y축 0~0.15): 확대해서 보아도 MoonViT-V2의 gradient norm이 일관되게 낮고 spike가 적다. 이 그림이 "학습 안정성 때문에 SigLIP 초기화를 버렸다"는 저자들의 주된 근거다.

또한 next-token prediction으로 학습하면 인코더 표현이 대조 손실(전역 의미론을 선호하고 세밀한 텍스트·구조 단서를 경시)이 아니라 언어 모델링 목적함수에 의해 직접 형성된다.

주목할 결과: MoonViT-V2는 비전 평가 전반에서 SigLIP 초기화 베이스라인과 동등한 성능을 낸다. 즉 대규모 멀티모달 언어 모델에서 대조 사전학습은 초기화로서 불필요하다. 이는 "SigLIP/CLIP 초기화는 필수"라는 업계 통념에 대한 직접적 반례다.

아키텍처: MoonViT-V2는 27층, 약 0.4B(401M) 파라미터의 vision transformer로, RMSNorm을 채택하고 linear·attention 투영의 모든 bias 항을 제거해 from-scratch 최적화를 더 안정화했다. 이미지와 비디오는 MoonViT-3D처럼 완전히 공유된 파라미터로 처리된다: 어텐션은 프레임 내 공간(intra-frame spatial) 패스와 프레임 간 시간(inter-frame temporal) 패스로 분해되고, temporal pooling이 시간 축으로 토큰을 추가 압축한다. 투영 전에 2×2 다운샘플링 pixel-shuffle이 시각 토큰 수를 1/4로 줄여, 최대 3584×3584 픽셀 입력을 1M 토큰 컨텍스트 안에서 감당할 수 있게 한다. patch size 14, 어텐션 헤드 12.

1.5 Per-Head Muon

K2를 이어 K3도 행렬 파라미터의 옵티마이저로 Muon을 쓰되, 어텐션 투영에 대해서는 per-head 변형으로 정제했다. 전체 $Q, K, V$ 투영 행렬에 Newton–Schulz orthogonalization을 적용하는 대신, momentum 행렬을 head 차원으로 분할해 각 head의 블록을 개별적으로 orthogonalize한다.

직관적으로 말하면: 전체 행렬 orthogonalization은 모든 head를 하나의 결합된 블록으로 취급하므로, gradient/momentum 스케일이 큰 head가 공유 업데이트 방향을 지배하고 작은 head는 충분히 정규화되지 않은 업데이트를 받는다. Head별로 나누면 업데이트 스케일이 head 전체에서 균등해진다. 실무적으로 head 간 학습 동역학이 균형을 이루고 대규모에서 학습 안정성이 개선된다. 부수 효과로 tall per-head 블록에 대한 Newton–Schulz 반복이 전체 행렬보다 싸서 옵티마이저 오버헤드도 약간 줄어든다.

2. 사전학습 (Pre-Training)

2.1 사전학습 데이터

Kimi K3는 4개 주요 텍스트 도메인(Web Text, Code, Mathematics, Knowledge)과 대규모 비전 코퍼스로 구성된 큐레이션 코퍼스에서 학습된다. 비전 데이터는 캡션, interleaved image–text 문서, OCR, perception, 비디오, visual coding 데이터를 아우른다. 데이터 파이프라인은 Kimi K2에서 개발하고 K2.5에서 정제한 것을 기반으로 한다.

텍스트 데이터: 각 도메인은 규칙 기반 휴리스틱 + 분류기 기반 품질 스코어링 + 중복 제거의 조합으로 필터링되며, 도메인별 샘플링 비율은 소형 모델에서의 ablation으로 결정한다. Kimi K2의 rephrasing 레시피를 따라 knowledge·mathematics 코퍼스를 스타일·관점이 다양한 프롬프팅, chunk-wise autoregressive 생성, 원문 대비 fidelity 검증을 거쳐 재작성한다.

비전 데이터: K2.5의 분류 체계를 따르되, 오픈소스 컬렉션과 자체 필터링·합성·중복제거 파이프라인을 결합한다. 학습 중 좌표 supervision은 절대 좌표와 정규화([0,1]) 좌표 두 형식 모두로 제공되어, 정밀하면서도 해상도에 강건한 localization을 가능하게 한다. 고전적 text-captioned 이미지에 더해 programmatic multimodal 데이터를 대폭 확대했다 — SVG, 3D 에셋, Webpage, Game, CAD 스키매틱 등 도메인 특화 포맷에서 코드 스니펫과 그 렌더링 결과를 짝지은 데이터다. (이것이 §6 케이스 스터디의 웹개발·3D/WebGL 강세와 직결된다.)

2.2 Scaling Law

아키텍처·데이터·학습 개선은 최적 학습 레짐 자체를 바꾸므로, 저자들은 배치 크기, learning rate, tokens-per-parameter 비율(TPP), 모델 shape를 재조정하기 위한 전용 scaling-law 연구를 수행했다. Held-out OOD validation 데이터에서 평가한 scaling law 곡선(Fig. 7)은 이 개선들이 합쳐져 Kimi K2 대비 전체 scaling efficiency를 약 2.5× 개선함을 보인다.

Cosine decay vs. WSD — 공정 비교의 방법론적 교훈

Scaling-law 연구는 일관되게 cosine decay가 Warmup Stable Decay(WSD)보다 낫다고 나왔고, 이에 따라 cosine decay를 기본 LR 스케줄로 채택했다. 흥미로운 것은 왜 선행 연구와 결론이 다른가에 대한 설명이다.

방법론적 주장: 선행 연구는 WSD가 cosine decay와 대등하거나 더 낫다고 보고했지만, 저자들은 두 스케줄의 최적 하이퍼파라미터가 현저히 다르다는 것을 관찰했다. 같은 모델 크기와 학습 토큰 예산에서도 최적 peak LR과 배치 크기가 크게 다르다. 따라서 공유된 하이퍼파라미터 세트로 두 스케줄을 비교하면, 단지 그 하이퍼파라미터가 한쪽에 더 잘 맞았다는 이유로 불공정하게 유리해질 수 있다. 각 스케줄에 대해 독립적인 scaling-law 탐색을 수행한 뒤, 각자의 최적 설정에서 비교하면 cosine decay가 일관되게 더 낮은 최종 loss를 달성한다.

2.3 학습 레시피

Kimi K3는 네이티브 멀티모달 학습 전략을 채택한다. 사전학습된 언어 모델에 비전 인코더를 사후 정렬 단계로 접붙이는 대신, 언어와 비전을 학습 시작부터 공동 최적화한다. 시각 토큰과 텍스트 토큰은 단일 next-token prediction 목적함수 안에서 interleave 되어, 공유 백본이 처음부터 통합 멀티모달 표현을 학습한다.

  • 옵티마이저: Per-Head Muon (§1.5) + Kimi K2에서 도입한 weight-clipping 메커니즘
  • MoE 로드 밸런싱: Quantile Balancing (§1.3.3)
  • LR 스케줄: cosine, 1% linear warmup
  • Weight decay: 0.1 (전 구간 고정)
  • 컨텍스트: 8k로 시작 → 후속 단계에서 64k로 확장

2.4 Long-Context Extension

Positional encoding: K3는 명시적 위치 임베딩을 쓰지 않고(NoPE), KDA의 재귀 게이팅·감쇠 메커니즘을 통해 위치 정보를 암묵적으로 인코딩한다. 결과적으로 RoPE rescaling이나 interpolation 같은 위치 인코딩 수정 없이 1M 토큰 컨텍스트로 곧바로 외삽(extrapolate)된다.

Long-context 데이터: 자연 출처의 긴 문서와 비디오에는 근사 중복, 바이너리 blob, 잘린 파일, 짧은 비디오 클립, 유효하지 않은 기계 생성 로그 같은 저품질 콘텐츠가 상당량 섞여 있다. 전용 클리닝 파이프라인은 (i) exact + fuzzy 중복 제거, (ii) 비디오의 경우 프레임에 대한 perceptual hashing 보완, (iii) 휴리스틱·분류기 기반 품질 필터링, (iv) 구조적 검증을 조합한다. 진짜로 길고 일관된 문서·비디오는 짧은 텍스트에 비해 희소하므로, cooldown 중 long-context 분포가 짧은 시퀀스에 압도되지 않도록 업샘플링한다.

핵심 통찰: 길이 자체가 long-range 능력을 주지는 않는다(Length alone does not confer long-range capability). 그래서 저자들은 멀티모달 문서와 하위 과제를 신중하게 순열·연결해 long-context 데이터를 합성한다 — 내장된 과제가 1M 토큰 전체에 흩어진 정보에 주의를 기울여야만 풀리도록 만든다. 이것이 어텐션을 의도한 스케일에서 훈련시키고, 국소 패턴으로 퇴화하는 것을 막는다.

점진적 컨텍스트 확장: 4단계 커리큘럼을 따른다.

1M 토큰 학습을 가능하게 하는 KDA 층의 시퀀스 차원 분할은 §4.1.2 (KDA Context Parallelism)에서 다룬다.

3. 후속학습 (Post-Training)

후속학습 파이프라인은 3단계다.

[Stage 1] SFT XTML 기반 chat template으로 직렬화된 대규모 agentic trajectory + MXFP4 QAT 시작 ↓ [Stage 2] RL — 3 도메인 × 3 reasoning effort = 9개 전문가 general / general agent / coding agent × {low, high, max} ↓ [Stage 3] MOPD (Multi-Teacher On-Policy Distillation) 9개 교사 → 단일 통합 학생 모델 Kimi K3

3.1 Supervised Fine-Tuning

SFT 단계는 후속 RL을 위한 고품질 cold-start policy를 확립한다. 이전 Kimi 모델들의 SFT 파이프라인 위에서 K3용 SFT 데이터셋을 확장해 복잡한 agentic 과제의 커버리지를 대폭 넓혔다. 구체적으로는 이전 Kimi 시리즈의 도메인 특화 모델들로 데이터 trajectory를 합성한 뒤, 다단계 검증과 human-in-the-loop 어노테이션을 거친다.

복잡한 agentic trajectory를 일관되게 표현하기 위해 모든 데이터를 XTML 기반 chat template(eXtensible Token Markup Language, 부록 F)으로 직렬화한다. 또한 SFT 단계부터 quantization-aware training(QAT)을 적용한다 — MXFP4 가중치, MXFP8 활성값 (§3.4).

3.2 Reinforcement Learning

과제별로 특화 RL 모델을 만드는 대신, 넓은 하위 과제 스펙트럼을 포함하는 3개 도메인으로 RL을 스케일링하고 각 도메인마다 모든 reasoning effort 레벨에서 단일 전문가를 학습한다:

  1. general tasks: general experience, vision, reasoning, faithfulness, search 능력, knowledge work
  2. general agents: long-horizon assistant 과제, deep research, 문단 수준 writing
  3. coding agents: software engineering(SWE), coding experience, kernel 과제, 웹 개발
[Figure 8 설명]: RL FLOPs를 스케일링하면 knowledge, reasoning, vision, general agent, coding에 걸쳐 성능이 일관되게 향상된다. 8개 패널(Coding Experience, General Tool Use, Web Development, Agentic Search, Professional Workflows, Office Deliverables, Agentic Chart Understanding, Agentic Visual Puzzles) 각각에서 점수 곡선과 평균 assistant step 수 곡선이 함께 그려지는데, RL FLOPs가 늘면 tool-call step 수가 일관되게 증가하며 이와 동반해 전반적 능력이 향상된다. 즉 RL이 단순히 정답률만 올리는 게 아니라 "모델이 더 많은 단계를 밟으며 일하는 법"을 학습시킨다는 증거다.

알고리즘 — Partial Rollout

왜 필요한가: long-horizon 과제에서 심화되는 long-tail latency(꼬리 지연)를 완화하기 위해서다. 동기식 RL 프레임워크의 partial rollout 방식을 확장했다.

각 iteration의 rollout 단계에서 $N$개 프롬프트마다 $K$개 completion을 샘플링해 $N \times K$개 trajectory의 active workload를 유지한다. 모든 rollout이 종료되기를 기다리는 대신, 비율 $\lambda \in (0,1)$의 trajectory가 완료되는 즉시($\lambda NK$개) 생성 단계를 일시정지하여 실행 straggler 없이 policy 최적화를 진행한다. 일시정지된 rollout은 큐에 넣어 다음 iteration 시작 시 우선 재개하며, 이는 샌드박스 인프라(§4.3.2)가 뒷받침한다. 한 프롬프트의 $K$개 응답이 모두 완료되면 즉시 policy 최적화로 디스패치되고, 최적화 자체는 Kimi K2.5의 알고리즘을 따른다.

staleness 문제: partial rollout 하에서 개별 long-horizon trajectory는 자연스럽게 여러 iteration에 걸치므로 데이터 staleness가 학습 안정성을 위협한다. K3의 policy 최적화 알고리즘은 per-token regularization을 통해 이런 극단적 off-policy 레짐을 본질적으로 견딘다. policy 업데이트를 국소 이웃 안으로 제약함으로써 매우 stale한 데이터도 견고하게 처리하고 학습 안정성을 유지한다.

Reasoning Effort RL

토큰 효율을 최대화하면서 reasoning effort를 미세 조정하기 위해 문제별 토큰 예산 제어를 RL 중에 적용한다. 각 문제 $x$에 cold-start 모델로부터 추정한 초기 토큰 예산 $b_0(x)$를 연결하고, 총 토큰 예산 $T(y)$가 스케일된 임계값 $\tau \cdot b_0(x)$를 초과하는 trajectory는 task reward를 $-1$로 덮어쓴다.

  • general 과제: $T(y)$는 thinking 토큰 수를 측정
  • agentic 과제: $T(y)$는 누적 출력 토큰(추론 trace + tool-call 인자 모두 포함)을 계산

학습은 budget multiplier $\tau$에 대한 단계적 커리큘럼을 따른다. 먼저 상대적으로 큰 $\tau$로 max-budget 변형을 학습하되 과도한 overthinking을 억제하기 위해 최대 예산에 상한을 둔다. 그다음 $\tau$를 더 작은 값으로 anneal해 high·low effort 전문가 모델을 얻는다. $\tau$ 조정은 도메인별로 human-in-the-loop 가이드 하에 설정된다. 모든 추론 레벨의 전문가가 만든 trajectory는 SFT와 MOPD를 위해 함께 수집된다.

Agentic Generative Reward Model (GRM)

검증 불가능한 general 과제에는 Agentic GRM을 쓴다. Kimi K2.5처럼 토너먼트 방식의 group reward + 이진 비교를 유지하되, agentic judge는 다음 필수 프로토콜을 따라야 한다:

  1. 결과물·산출물·텍스트 출력을 읽는다
  2. rubric(채점 기준)을 생성한다
  3. 각 후보를 rubric에 대해 채점한다
  4. rubric이 부여한 점수를 scorepad에 기록한다

점점 장황한 출력으로 향하는 reward hacking을 막기 위해, 위의 reasoning-effort 제어와 유사한 예산 기반 verbosity 제어를 적용한다: cold-start 모델로 추정한 초기 verbosity $\ell_0$와 배수 $\sigma$가 주어질 때, 출력 길이가 $\sigma \cdot \ell_0$를 넘는 후보는 이진 비교에서 자동 패배한다.

3.3 Multi-Teacher On-Policy Distillation (MOPD)

서로 다른 reasoning effort에 걸친 도메인 특화 능력들을 하나의 통합 모델로 합치기 위해 MOPD를 쓴다. 학습 중, 주어진 도메인 $d$와 샘플링된 reasoning effort 레벨 $e \in \{low, high, max\}$에 대해, 9개 전문가 중 대응하는 교사 모델 $\pi^{(d,e)}_{\text{teacher}}$가 최적화를 안내한다. 입력 쿼리 $x$와 접두 응답 $y_{\lt t}$가 주어졌을 때, 교사와 학생 $\pi_\theta$ 사이의 토큰별 OPD reward는:

$$r^d_{\text{opd}}(y_t \mid e, x, y_{\lt t}) = \mathrm{clip}\!\left(\mathrm{sg}\!\left[\log \frac{\pi^{(d,e)}_{\text{teacher}}(y_t \mid x, y_{\lt t})}{\pi_\theta(y_t \mid e, x, y_{\lt t})}\right],\, -R_{\max},\, R_{\max}\right) \tag{15}$$

$\mathrm{sg}(\cdot)$는 stop-gradient 연산자, $R_{\max} > 0$은 극단적 advantage 신호를 제약해 RL 학습을 안정화하는 클리핑 임계값이다.

직관적으로 말하면: "학생이 방금 뱉은 이 토큰을, 담당 교사라면 얼마나 더(또는 덜) 좋아했을까?"를 로그 비율로 재고, 그 값을 토큰 단위 보상으로 준다. 학생이 스스로 생성한 궤적(on-policy) 위에서 채점하므로 분포 불일치가 없고, 이 dense reward 신호가 기존 RL 프레임워크에 그대로 녹아들어 long-horizon 과제용 partial rollout 학습 같은 인프라 최적화를 자연스럽게 활용할 수 있다.

Negative result: 더 세밀한 top-k distillation 목적함수도 실험했으나, 수렴 속도와 최종 성능 어느 쪽에서도 명확한 이점을 관찰하지 못했다.

3.4 배포 인식 후속학습 (Deployment-Aware Post-Training)

MXFP4 Quantization-Aware Post-Training

배포 시 메모리 사용량과 서빙 비용을 줄이기 위해, 모델 파라미터 메모리를 지배하는 MoE 전문가 가중치를 MXFP4로 양자화하고 활성값은 MXFP8로 계산한다. 나머지 비-전문가 구성요소(어텐션 투영, latent MoE 투영, shared expert, MoE 라우터)는 더 높은 정밀도로 유지한다.

QAT는 SFT와 RL을 모두 포함한 후속학습 전 구간에 걸쳐 수행되어, 모델이 양자화로 인한 정밀도 손실에 적응하게 한다. RL 중에는 rollout과 training이 동일한 양자화 스킴을 공유하여 train–inference mismatch를 제거한다.

Draft Model Fine-Tuning (투기적 디코딩)

Kimi K3는 백본 블록 구조를 모사하는 multi-token-prediction(MTP) 층과 함께 사전학습된다. EAGLE-3의 draft 모델이 단일 디코더 층으로 구성되고 그 구조가 MTP 층과 일치하므로, 사전학습된 MTP 층을 EAGLE-3 스타일 draft 모델로 fine-tune한다. target 모델은 freeze하고 draft 층과 feature-fusion 투영만 업데이트한다. EAGLE-3의 training-time test 프로토콜을 따라 draft를 학습 중 7 스텝 unroll하며, 첫 스텝 이후로는 최신 위치의 target측 feature를 쓸 수 없으므로 draft가 자기 자신의 이전 출력을 소비한다(추론 시 재귀적 drafting 절차를 모사).

draft 입력은 target 모델의 low-/mid-/high-level feature를 융합한다 — 각각 1번째, 4번째, 마지막 AttnRes 블록의 출력이다. 이들을 concat한 뒤 bias 없는 행렬 $W_{E3}$로 hidden size에 투영하는데, $W_{E3}$를 $[\,0\ \ 0\ \ I\,]$로 초기화하여 초기 시점의 융합 표현이 high-level feature $h_h$와 일치하도록 한다($h_h$는 MTP 층이 사전학습된 입력). fine-tuning이 진행되며 점진적으로 low-/mid-level feature를 통합하게 된다.

손실 함수: 투기적 디코딩의 speedup은 lossless speculative sampling 하에서 토큰별 수용률(acceptance rate) $\sum_{x \in V}\min(p(x), q(x))$에 의해 결정된다($p$: target, $q$: draft의 다음 토큰 분포). 관례적인 KL-divergence 대리 손실을 최소화하는 것이 용량 제한된 draft 모델에서 이 수용률 최대화를 보장하지 않으므로, 수용률 자체의 음의 로그인 likelihood 기반 LK loss를 직접 최적화한다:

$$\mathcal{L}_{\text{LK}} = -\log \sum_{x \in V}\min\left(p(x), q(x)\right) \tag{16}$$

$p$와 $q$는 temperature 1에서 평가하고, 보조 ground-truth cross-entropy 항은 쓰지 않는다. Draft fine-tuning도 후속학습 QAT 설정을 따른다(MoE 전문가 가중치 MXFP4, 입력 활성값 MXFP8, 비-전문가 모듈은 고정밀도).

3.5 RL 과제 합성과 Agentic 환경

RL 프레임워크의 효과는 풍부하고 다양하며 견고하게 검증 가능한 환경에 크게 의존한다. 저자들은 일련의 특화된 white-box 환경과 과제 합성 패러다임을 설계했다.

3.5.1 Unified White-Box RL Environment

왜 필요한가: 하나의 고정된 agent harness로 학습하면 모델이 특정 도구 스키마, 시스템 프롬프트, 컨텍스트 관리 메커니즘, 상호작용 프로토콜에 과적합될 수 있다.

해법: agent harness를 설정 가능하고 조합 가능한 모듈의 집합으로 표현하는 unified white-box RL 환경. 모듈에는 도구 인터페이스, 시스템 프롬프트, 컨텍스트 관리 전략, skill, memory, subagent 등이 포함된다. 이 모듈들을 설정으로 조합해 Kimi Code, Claude Code, Codex, OpenClaw, Hermes 같은 주류 harness는 물론 완전히 새로운 harness도 인스턴스화할 수 있다. RL 학습 중 과제 그룹마다 서로 다른 harness 설정을 동적으로 구성해, K3를 어느 한 harness의 관습이 아니라 다양한 모듈 조합에 노출시킨다.

3.5.2 Knowledge-Graph-Guided Task Synthesis

동기: 후속학습 과제의 품질과 다양성은 대체로 그 원천 자료(source material)에 의해 결정된다. 세밀한 개념으로 안내되는 검색은 전문적이고 과소대표된 지식을 끌어내고, 다양한 개념에 걸친 샘플링은 도메인 커버리지를 넓힌다. 이 두 가지(granularity와 coverage)를 대규모로 제어하기 위해, 에이전트가 웹 규모 탐색으로 계속 확장하는 자기진화형(self-evolving) 계층 지식 그래프를 구축한다.

Agentic 지식 그래프 구축: 지식 그래프는 재귀적·에이전트 주도 확장을 통해 유향 비순환 그래프(DAG)로 구성된다.

1. 미리 정의된 coarse-grained seed 노드 집합에서 시작 2. 각 노드에 에이전트 인스턴스 할당 → 다중 웹 검색으로 해당 개념 조사 3. 새 노드 추가 전, 기존 그래프를 탐색해 동등/관련 개념 식별 → 가능하면 기존 노드 재사용, 중복 최소화 4. 간선은 항상 coarse → fine 방향 (어느 쪽을 먼저 발견했든 무관) 5. 새로 추가된 노드는 다시 에이전트에 할당되어 추가 탐색 6. 담당 에이전트가 "현재 개념이 충분히 atomic하다"고 판단하면 분기 확장 종료

자료 검색과 과제 합성: 도메인·과제 유형에 걸친 목표 분포를 맞추기 위해, 시스템은 다양한 granularity 수준의 노드를 개별적으로 또는 관련된 조합으로 샘플링한다. 샘플된 노드에서 유도된 키워드가 지식 그래프 내 조상 노드의 맥락 정보와 결합되어 웹 쿼리를 구성한다. 검색된 실세계 자료를 조립해 합성 에이전트가 다양한 유형의 학습 과제를 생성한다.

[Figure 9 설명]: 계층적 지식 그래프는 CS/AI, Biomedicine, Coding, Humanities, Math, Chemistry, Physics 같은 넓은 도메인에서 시작해 여러 층을 거쳐 세밀한 개념(예: RoPE, GPU kernel)까지 내려간다. 관련 노드들을 샘플링해 keyword set을 만들고, 이것이 공개 자료(학술 논문, 블로그 포스트, 코드 저장소) 검색을 안내한다. 각 합성 인스턴스마다 과제 유형(Coding / Knowledge / Vision 등)을 하나 선택해 검색된 자료로 대응하는 과제를 합성한다.

3.5.3 Agentic 환경의 검증 가능 문제

대표적 예시:

  • 다단계 복잡 정보 검색: 모델이 리서치를 계획하고, 웹에서 단계적으로 증거를 수집하며, 검증 가능한 답을 산출
  • 전문가의 실제 일상 업무: 투자은행, 데이터 분석, 법률 실무 등에서 복잡한 요청을 분해하고, 샌드박스 내 도메인 도구를 조작하며, 수십~수백 스텝에 걸쳐 deliverable을 완성
  • 다단계 검증 가능 시각 추론: STEM 문제, 시각 퍼즐, 차트 이해

각 시각 추론 trajectory는 격리된 샌드박스의 Python 인터프리터를 갖춘 에이전트 환경에서 생성된다. 모델은 반복적으로 코드를 작성·실행해 입력 이미지를 crop, zoom, 변환하거나 정밀 계산을 수행하거나 중간 결과를 검증하고, 실행 출력(생성된 이미지 포함)을 여러 상호작용 스텝에 걸쳐 새로운 관측으로 받는다. 모델이 더 많은 이미지 연산을 수행하고 더 많은 관측을 수집하는 법을 배울수록 복잡한 시각 추론 과제 성능이 꾸준히 향상된다.

3.5.4 Kernel Optimization Tasks

GPU 커널 최적화 능력을 강화하기 위해, 단일 연산자 커널부터 fused mega-kernel까지 아우르는 대규모 커널 과제 스위트를 구축했다(Flash Linear Attention 등 고품질 GitHub 저장소에서 조달). 다양한 GPU 프로그래밍 접근법(CUDA, Triton, CuTe DSL, Gluon, ThunderKittens, TileLang)과 널리 쓰이는 GPU 아키텍처·수치 형식(BF16, FP8, FP4)을 커버한다.

Reward 설계는 정확성과 성능 모두를 평가한다:

  • 각 커널은 PyTorch 참조 구현을 제공하며, 사전 정의된 수치 오차 임계값을 넘는 해답은 reward 0
  • 성능은 전문가 구현 대비 채점: 전문가 수준에 도달하면 reward 0.5, 하드웨어 roofline에 접근할수록 1에 가까워짐

reward가 진짜 최적화를 반영하도록, hacking-detection 시스템을 개발해 CUDA graph replay, 입력 캐싱, 정밀도 축소 같은 reward-hacking 전략에 페널티를 부과하며, K3 개발 중 새로운 hacking 전략이 관찰될 때마다 계속 확장했다.

3.5.5 Personal Assistant Tasks

long-horizon 개인 비서 과제를 위해 널리 쓰이는 애플리케이션(Gmail, Notion, Slack, Canvas)의 현실적인 mock 구현을 개발했다. 실제 대응물의 핵심 의미론을 보존하면서도, 외부 API나 rate limit 없이 재현 가능한 대규모 상호작용을 가능하게 한다.

이 mock 앱들 위에 인사(HR), 법률 서비스, 금융 같은 실세계 전문 워크플로우에서 영감을 얻은 복잡한 과제를 설계했다. 각 과제에서 에이전트는 여러 시뮬레이션 일(day)에 걸친 지속적·진화하는 환경에서 동작하며, 애플리케이션 전반에 분산된 수십 개의 상호의존적 이벤트를 만난다. 단일 rollout이 수천 번의 tool call과 수백만 컨텍스트 토큰을 포함할 수 있다. 각 이벤트는 자체 평가 기준을 가지며 결정론적 규칙 또는 LLM 기반 평가자로 평가된다. 초기 workspace는 에이전트들이 자율적으로 웹에서 참고 자료를 검색해 일관되고 과제 관련성 있는 환경으로 변환하여 구성한다. RL 프레임워크도 이런 living environment(복잡한 이벤트 스트림과 그로 인한 world-state 전이 모델링)를 지원하도록 확장했다.

3.5.6 Autonomous Execution Tasks (AET)

verify-in-the-loop 최적화를 통해 long-horizon 에이전트 지능을 학습시키는 환경 패러다임. 각 과제는 초기 상태, 제약된 목표, 도구 기반 행동 공간, 실행 예산, 독립적 verifier를 명시한다.

에이전트는 목적·맥락·제약·검증 인터페이스만 볼 수 있고 참조 trajectory나 사전 정의된 절차는 볼 수 없으며, 과제 분해·도구 선택·계획·오류 복구·종료 판단을 스스로 수행해야 한다. Reward는 에이전트의 자기보고 완료가 아니라 verifier가 평가한 최종 환경 상태에 근거한다. verifier 유형은 black-box 시스템 복제, 정량적 factor discovery, 세무 감사 등 다양한 환경을 지원한다.

Reward hacking 완화: (i) 에이전트를 verifier로부터 격리, (ii) 진단 피드백을 주는 공개 verifier와 held-out 시나리오를 평가하는 숨겨진 verifier를 짝지음, (iii) 제한된 제출 예산 하에 페널티 기반 reward 적용.

4.1 KDA 알고리즘–시스템 공동 설계

KDA는 소프트맥스 어텐션의 증가하는 KV 캐시를 고정 크기 재귀 상태 $S \in \mathbb{R}^{d_k \times d_v}$로 대체한다. 이는 직렬 갱신이라는 병렬 실행상의 난점을 대가로, 전송·재사용이 저렴한 고정 크기 상태라는 이점을 얻는 거래다. 아래 설계들은 첫 번째 성질(직렬성)에 대응하고 두 번째 성질(고정 크기)을 두 실행 레벨에서 활용한다 — 장치 내에서는 fused kernel, 장치 간에는 KDA Context Parallelism.

4.1.1 실행 레짐별 KDA 커널

KDA 상태의 직렬 의존성은 GPU가 선호하는 넓고 균일한 병렬성과 상충하며, 실행 레짐마다 다른 병목으로 나타난다. 그래서 레짐별 전용 커널을 설계했다.

(a) 학습·prefill용 chunkwise 커널 — FlashKDA: KDA의 chunkwise 형태는 청크 내에서는 병렬, 청크 간에는 직렬이다(재귀 상태가 청크에서 청크로 전파되어야 하므로). 순진하게 실행하면 두 위상이 번갈아 나타나며 직렬 전파 동안 SM이 놀게 된다. FlashKDA는 CUTLASS 기반 chunkwise 커널로 intra-chunk 연산과 cross-chunk 상태 전파를 오버랩한다. 작업을 token-parallel 단계들과 head-parallel 재귀로 분해해 각각 독립적으로 스케줄·튜닝하며, Triton 참조 구현을 크게 앞선다. 학습과 추론 prefill 모두에 쓰이며 flash-linear-attention의 백엔드로 자동 디스패치된다.

(b) long-context prefill용 intra-device context parallelism: 텐서 병렬(TP)은 head를 장치에 분할하지만 재귀 자체를 짧게 만들지는 못한다. 순수 TP 배포에서 초장문 시퀀스를 prefill 하면 각 랭크가 몇 개 head만 갖게 되어 대부분의 SM이 논다. 핵심 관찰은 각 세그먼트의 상태 전이(state transition)는 들어오는 상태와 무관하게 평가한 뒤 나중에 정확히 합성할 수 있다는 것이다. 자동 SM-level context-parallel(CP) 플래너가 시퀀스를 단일 랭크의 SM들에 분할해 세그먼트 전이를 병렬 평가하고 병합하여 각 세그먼트의 정확한 초기 상태를 복원한다. §4.1.2의 cross-device KCP와 달리 이 병렬성은 완전히 장치 내부이며 cross-device 통신이 전혀 없다.

4.1.2 KDA Context Parallelism (KCP)

왜 어려운가: 컨텍스트 병렬의 통신 오버헤드는 소프트맥스 어텐션과 선형 어텐션에서 근본적으로 다르다. 소프트맥스 어텐션은 시퀀스 길이에 비례해 커지는 KV 블록을 랭크 간에 교환해야 한다. 선형 어텐션은 대신 고정 크기 재귀 상태 $S$로 이전 컨텍스트를 나른다. 기존 context-parallel 방법들은 vanilla linear attention의 가법적 재귀를 활용해, 각 랭크에서 로컬 토큰이 $S=0$에서 생성하는 상태를 계산하고 선행 랭크들의 로컬 상태를 합산해 들어오는 상태를 복원했다.

그런데 KDA에는 이 직접 합산이 통하지 않는다. Eq. 1에서 KDA는 $S_t = M_t S_{t-1} + \beta_t k_t v_t^\top$로 갱신되며 $M_t := \left(I - \beta_t k_t k_t^\top\right)\mathrm{Diag}(\alpha_t)$이다. delta rule이 토큰 의존 행렬 $M_t$를 들어오는 상태에 곱한 뒤 현재 쓰기를 더하므로, 로컬 시퀀스 세그먼트의 효과가 그 세그먼트에 들어오는 상태에 의존한다. $S=0$에서 계산한 상태만으로는 결정할 수 없다.

KCP의 해법: 각 세그먼트의 효과를 두 개의 로컬 계산 가능 양으로 분해한다 — (1) 들어오는 상태에 작용하는 누적 전이(cumulative transition), (2) 0에서 로컬하게 생성된 상태. 랭크 $i$의 세그먼트에서 로컬 토큰 $t$개 이후의 재귀 상태를 $S^t_{[i]}$, 같은 재귀를 $S=0$에서 시작한 상태를 $\tilde S^t_{[i]}$라 하면, $P$개 컨텍스트 병렬 랭크 중 $(i{+}1)$번째로 임의의 상태가 들어올 때 로컬 토큰 $t$개 이후의 상태는:

$$\begin{aligned} M^{t \leftarrow 1}_{[i+1]} &:= \prod_{r \leftarrow 1}^{t} M_r \in \mathbb{R}^{d_k \times d_k},\\ S^t_{[i+1]} &= \tilde S^t_{[i+1]} + M^{t\leftarrow 1}_{[i+1]} S^{T_i}_{[i]}\\ &= \tilde S^t_{[i+1]} + M^{t \leftarrow 1}_{[i+1]} \sum_{j=1}^{i}\left(\prod_{l \leftarrow j+1}^{i} M^{T_l \leftarrow 1}_{[l]}\right)\tilde S^{T_j}_{[j]} \in \mathbb{R}^{d_k \times d_v}. \end{aligned} \tag{17}$$

$M^{t\leftarrow 1}_{[i+1]}$은 처음 $t$개 로컬 토큰의 누적 전이다. 첫 항은 로컬 토큰이 생성한 상태를, 둘째 항은 선행 랭크들의 컨텍스트를 로컬 KDA 갱신을 통해 전파한 것을 담는다. $t = T_{i+1}$에서 $M^{T_{i+1}\leftarrow 1}_{[i+1]}$과 $\tilde S^{T_{i+1}}_{[i+1]}$은 모두 $S^{T_i}_{[i]}$를 알기 전에 로컬 토큰만으로 계산 가능하며, 이 둘이 각 랭크가 교환하는 fragment다.

Eq. 17의 합산은 모든 상태가 순수하게 로컬 계산 fragment로부터 합성됨을 보여준다. 이 랭크 수준 갱신은 결합법칙(associative)을 만족하므로 각 랭크의 들어오는 상태를 prefix scan으로 복원할 수 있다. 각 랭크는 $M^{T_i\leftarrow 1}_{[i]}$와 $\tilde S^{T_i}_{[i]}$를 로컬 계산한 뒤 단 한 번의 all-gather로 두 텐서를 교환한다. all-gather 후 랭크 $i{+}1$은 같은 문서의 선행 fragment들을 순서대로 처리해($S \leftarrow M^{T_j \leftarrow 1}_{[j]} S + \tilde S^{T_j}_{[j]}$) $S^{T_i}_{[i]}$를 재구성한다. 따라서 KCP는 재귀 상태 동기화를 위해 고정 크기 all-gather 한 번만 필요하고 선형 compute scaling을 달성한다.

4.2 3T급 사전학습 인프라

Kimi K3 사전학습은 Pipeline Parallelism(PP) with virtual stages(VP), Expert Parallelism(EP), ZeRO-1 Data Parallelism, Pipeline ZeRO-2 gradient sharding, Context Parallelism(CP)을 결합한다. MoE 층은 EP 랭크에 복제된 shared expert를 쓰고, expert dispatch/combine의 all-to-all 통신은 연산과 오버랩해 지연을 숨긴다.

  2. 활성값·gradient·optimizer state가 메모리 예산 초과
  3. 비전 인코더의 매우 가변적인 연산이 critical path에 노출됨

4.2.1 완전 균형 Expert-Parallel MoE 학습 — MoonEP

문제: 기존 EP 스킴에서는 토큰 부하가 랭크 간에 불균형하다. 연산 불균형은 학습 처리량을 떨어뜨리고, routed-expert 활성값의 동적으로 변하는 shape가 상당한 메모리 단편화를 유발한다.

MoonEP는 dynamic redundant expert로 완전 로드 밸런스를 달성하는 EP 스킴이다. DeepEP 같은 기존 스킴의 전체 연산 흐름을 보존하면서, redundant expert의 온라인 계획(planning)과 마이그레이션을 추가한다. forward pass에서는 현재 마이크로배치·층의 라우터 출력으로부터 redundant expert를 계획하고 routed-expert 연산 전에 prefetch한다. backward pass에서는 그 gradient를 로컬 reduce 버퍼에 스테이징했다가 연산 완료 후 home 랭크의 gradient 버퍼로 reduce한다.

(a) 유한 개수 redundant expert로 완전 균형 — 이론적 보증: MoonEP는 모든 랭크가 정확히 $S \times K$개 토큰을 받아야 한다($S$: 시퀀스 길이, $K$: 토큰당 선택 전문가 수). 그래야 모든 랭크의 연산량이 동일하다. 핵심 질문은 "그런 균형을 보장하려면 redundant expert가 몇 개나 필요한가"다. $E$를 전문가 수, $R$을 EP 크기라 할 때, 저자들은 부록 E에서 ##랭크당 최대 $E/R$개의 redundant expert로 항상 균형 계획이 존재하며 이 경계가 본질적으로 tight함을 증명##한다.

왜 중요한가: 랭크당 $E/R$개의 redundant-expert 슬롯을 예약하면 planning이 항상 실행 가능한 해를 갖는다는 것이 보장되므로 학습이 절대 중단되지 않는다. 반면 ECHO나 UltraEP 같은 선행 연구는 redundant expert 수를 미리 정하거나 랭크당 토큰 상한을 부과한다. 그러면 상한 안에서 실행 가능한 계획이 없을 때마다 학습이 멈춰야 하고, 상한 자체를 수동 튜닝해야 하면서도 잔여 불균형은 남는다.

(b) 온라인 계획: 매 학습 스텝마다 정확한 최적해를 구하는 것은 지나치게 비싸다. 대신 대표 케이스에 대해 integer linear programming(ILP)으로 오프라인 정확해를 구해 참조로 삼고, 이를 바탕으로 near-optimal하면서 오버헤드가 무시할 수준이고 $E/R$ 상한을 항상 지키는 GPU planning 커널을 설계했다.

(c) Zero-copy 통신: 완전 균형은 통신 경로도 단순화한다. planning 커널이 모든 토큰의 목적지를 미리 계산하는 fused permute/unpermute 연산자를 구현해, 토큰이 원격 랭크의 expert-grouped 위치로 직접 전송되고 통신 버퍼의 view가 연산에 그대로 반환되어 중간 복사가 사라진다. 최악의 불균형에서 DeepEP가 같은 copy-free 데이터 경로를 지원하려면 $S \times K \times R$ 크기 통신 버퍼가 필요하지만, MoonEP는 완전 균형 덕분에 고정 $S \times K$ 버퍼만 필요하다.

(d) Sync-free 실행과 static shape: 기존 MoE 구현에서는 전문가별 토큰 수가 스텝·층마다 달라, 호스트가 매 층에서 디바이스와 동기화해 실제 연산 shape를 알아낸 뒤에야 전문가 연산을 실행할 수 있어 층 간에 파이프라인이 멈춘다. 완전 균형 하에서는 모든 랭크가 정확히 $S\times K$개 토큰을 받으므로 모든 층의 연산 shape가 정적으로 알려진다. 층별 MoE 호스트 동기화가 사라지고 host-side kernel-launch 오버헤드도 완화된다.

(e) Expert-GEMM 스케줄링과 오버랩: 랭크 간 총 부하가 완벽히 균형이어도 랭크 내부 전문가별 토큰 수는 여전히 치우쳐 있고, 고정 순서의 workload-oblivious 스케줄은 이 편향을 SM worker 간 makespan 불균형으로 바꾼다. 그래서 routed-expert GEMM을 workload-aware 스케줄러로 실행한다 — 런치 전에 현재 토큰 분포에 맞춰 파라미터를 적응시키고 실행 중에는 고정한다. 경량 휴리스틱이 하드웨어 지표의 분석적 비용 모델로 파라미터를 선택하며, 핵심 계수는 오프라인 autotuning으로 보정한다. shared expert의 GEMM은 별도 스트림에 디스패치해 다른 커널과 오버랩한다.

4.2.2 메모리 효율 학습

  • Unified activation manager: backward를 위해 저장되는 모든 텐서를 플러그 가능한 storage backend에 연결하는 통합 저장 추상화. Recomputation, quantization, offload/remote-offload가 모두 이 추상화 하의 "저장 정책"일 뿐이며 텐서 단위로 자유롭게 조합된다. 정책은 텐서에 대한 경량 어노테이션으로 선언되어 모델 코드와 완전히 분리된다. Recomputation은 함수 단위로 수행되어 cross-layer recomputation을 지원한다. 모든 GPU 메모리는 main compute stream에서 할당되고 단일 메모리 풀에서 관리되어 multi-stream 단편화와 host-bound 오버헤드를 피한다. K3에서는 대부분의 활성값이 block-wise FP8 양자화 + offload/remote-offload를 쓰고, element-wise 연산자는 recomputation으로 설정된다.
  • Memory-efficient MoE: 네이티브 MoE 구현에서 permuted probs의 gradient 계산이 forward 출력 output에 의존한다. SonicMoE에서 영감을 받아 이 gradient를 수학적 변형으로 재작성해 중간 활성값 act_output과 상류 gradient doutput에만 의존하는 형태로 바꿨다 — 가벼운 element-wise 연산 추가를 대가로 output에 대한 backward 의존성을 제거. 또한 group GEMM forward에서 dispatch 연산의 입력만 저장하고, backward에서 dispatch를 recompute해 group GEMM 입력을 복원한다. 이 recomputation이 유발하는 통신은 group-GEMM backward 연산의 일부와 오버랩될 수 있어, 이 부분 활성값 저장을 무시할 만한 비용으로 제거한다.
  • Memory-efficient Attention Residual: Block AttnRes 기반 동반 최적화. 블록 표현은 경계 층에서 한 번만 생성되어 이후 모든 층이 공유하며 GPU에 상주한다. AttnRes 연산 전체를 checkpointing으로 감싸, 각 층에서 backward를 위해 저장되는 활성값이 표준 residual 아키텍처와 동일해진다. 파이프라인 병렬에는 cache-based pipeline communication을 채택해, 새로 생성된 블록만 스테이지 간에 증분 전송하고 마이크로배치가 끝나는 즉시 해제하여 메모리 footprint의 이론적 하한에 도달한다.
  • PP 랭크 간 활성값 균형: interleaved 1F1B 파이프라인에서 파이프라인 warmup 때문에 활성값이 PP 랭크 간에 불균등하게 분포하며, PP 랭크가 커질수록 상주 활성값 수가 줄어든다. OOM을 피하기 위해 Mooncake Transfer Engine으로 활성값을 다른 PP 랭크의 메모리에 remote offload 하여 PP 랭크 간 활성 메모리를 균형화한다.
  • Pipeline ZeRO-2 gradient sharding + offloading: gradient를 DP 랭크에 샤딩하고, 샤딩된 gradient를 CPU 메모리에 저장해 peak GPU 메모리를 줄인다(double grad buffer는 GPU에 유지). DP 랭크 간 reduce가 double grad buffer로 끝나면 CPU 샤드에 누적한다.
  • P2P 기반 Muon orthogonalization: 분산 옵티마이저는 파라미터를 DP 랭크에 균등 샤딩하지만 Muon의 Newton–Schulz orthogonalization은 전체 파라미터 행렬을 요구하므로, 업데이트 전에 완전한 파라미터를 모으는 통신이 필요하다. 순진하게 전체 파라미터 버퍼에 all-gather를 하면 메모리 footprint가 크고 대규모에서 통신이 주 병목이 된다. 대신 각 랭크가 자기가 소유한 파라미터의 샤드만 소유 랭크로부터 P2P로 가져온다 — 전체 파라미터 버퍼를 없애고 메모리·통신량을 모두 줄인다. 통신과 연산은 model-chunk 버퍼 단위로 파이프라인화해 통신 오버헤드를 숨긴다.

4.2.3 멀티모달 인코더 최적화

Dynamic CP in multimodal encoder: long-context 멀티모달 학습에서 큰 이미지와 긴 비디오는 비전 인코더 연산 시간을 크게 늘리고 장치 간 심각한 부하 불균형을 일으킨다. 그래서 이런 큰 샘플에 컨텍스트 병렬을 확장했다 — 단일 큰 이미지를 patch 차원으로 여러 장치에 분할하고 CP 랭크 간 key–value를 gather(gather-KV)해 어텐션을 계산한다. 또한 각 CP 그룹을 여러 sub-CP 그룹으로 나누고 큰 이미지 여러 장을 로드 밸런싱하며 분배해, 통신 비중이 규모에 따라 커지는 것을 막는다.

PP bubble에 인코더 연산 배치: Kimi K2.5에서 도입한 Decoupled Encoder Process(DEP)는 ViT와 텍스트 학습을 별도 스테이지로 나누고 vision forward/backward를 PP 스테이지에 균형 배치했다. K3는 여기서 관찰을 하나 더 얻었다 — interleaved 1F1B 스케줄에서 첫 PP 마이크로배치들의 텍스트 forward는 모두 맨 앞에 스케줄되고, 마지막 PP 마이크로배치들의 텍스트 backward는 맨 끝에서야 끝난다. 따라서 ViT 연산을 더 분해해, 첫 PP 마이크로배치의 ViT forward는 앞에서 동기적으로 실행하고 나머지 forward는 파이프라인 bubble에 스케줄하며 backward도 대칭적으로 처리한다. 결과적으로 ViT 연산 대부분이 파이프라인 bubble 안에 숨겨져 비전 인코더의 실효 오버헤드가 거의 사라진다.

4.3 1M Agentic RL 인프라

Kimi K3처럼 큰 모델의 agentic RL을 제한된 compute 예산 하에 백만 토큰 컨텍스트로 스케일링하면 자원 효율이 일차 목표가 된다. 두 갈래 노력이 필요하다: (1) 효율적 학습·rollout(KV-cache 관리, 요청 스케줄링, 학습 상태 배치), (2) long-horizon 상호작용을 위한 고성능 resumable 샌드박스.

4.3.1 Long-context RL 인프라

K3는 co-located RL 학습을 채택해 각 1M-컨텍스트 RL 실험을 수백 GPU 이내로 유지하고, partial rollout으로 초장문 trajectory의 tail latency를 줄인다. 이 설계는 하드웨어 활용도가 좋지만, 다음 iteration을 위해 유지해야 하는 rollout KV-cache와 학습에 필요한 메모리 사이에 메모리 경합을 만든다. long-context RL에서 이 문제는 더 심각해진다.

External KV cache pool: 1M 컨텍스트 다단계 rollout에서 prefix KV-cache miss는 극도로 비싸다. Partial rollout은 이전 iteration의 미완료 long prefill 요청들이 동시에 도착하므로 각 iteration 시작 시 문제를 악화시킨다. 투기적 디코딩은 상대적으로 고정된 tool-call 간격 안에서 요청 회전율을 더 높여 prefix-block churn을 증가시킨다. 이런 문제들은 preemption을 유발하고 cache hit rate를 낮춘다.

그래서 write-back 설계로 prefix 유지와 GPU 상주를 분리한다: 활성 디코딩 블록은 GPU KV cache에 남고, 재사용 가능한 idle prefix는 GPU에서 축출될 때만 CPU DRAM의 external KV cache pool에 write-back 되며 다음 재사용 전에 prefetch 된다. KDA 상태는 대응하는 MLA KV cache 블록과 함께 offload·prefetch 되어 생애주기가 정렬된다. write-through 전략과 비교해 이 정책은 active decode path를 떠나는 prefix에 대해서만 CPU DRAM과 전송 대역폭을 소모하므로, 여전히 GPU에 상주·활성인 블록의 중복 CPU 복사를 피한다.

external pool에 충분한 DRAM을 공급하기 위해, 학습 iteration이 끝나면 학습 상태(모델 가중치·optimizer state)를 NVMe로 offload한다. rollout iteration이 끝나면 pool을 해제해 학습 워크로드와의 경합을 피한다.

Rollout auto-throttling scheduler: 다단계 rollout에서 컨텍스트는 trajectory가 진행되며 점진적으로 자란다. 전체 trajectory 평균 길이에 기반한 고정 동시성(concurrency)은 추정하기도 어렵고 초반에는 지나치게 보수적이다. 반대로 동시성을 너무 높이면 후반에 KV cache 압박이 생겨 preemption을 유발한다. 그래서 LLM 요청 스케줄링 계층에 auto-throttling 메커니즘을 뒀다 — 활성 요청 수, 대기 요청 수, KV cache 사용률 같은 런타임 신호로 추론 엔진에 보내는 요청 수를 동적으로 제어한다. 초기 rollout은 잘 활용하면서 KV cache 압박이 커지면 동시성을 줄여, 수동 튜닝 없이 under-saturation과 overload를 모두 피한다.

Gradient-buffer reuse for non-policy model forwarding: RL loss 계산은 reference model처럼 forward만 하는 non-policy 모델을 요구하는데, 그 가중치는 GPU에 상주시키기엔 너무 크다. 이 가중치를 CPU 메모리에 두고 필요할 때만 materialize 하되, 파라미터 텐서를 policy 모델의 FP32 gradient-buffer 저장소로 backing한다. 추가 할당이나 단편화 없이 기존 GPU 메모리를 재사용하며, 실제 gradient가 나중에 계산될 때 버퍼가 덮어써지므로 안전하다. ZeRO-2 gradient sharding·offloading 하에서 K3 RL 학습의 각 GPU는 2개 VPP chunk분의 gradient 버퍼만 유지하므로, reference 가중치를 이 슬롯에 chunk 단위로 스트리밍한다 — 한 슬롯은 현재 forward에, 다른 슬롯은 다음 chunk prefetch에 써서 GPU 메모리 증가 없이 복사 오버헤드를 숨긴다.

4.3.2 샌드박스 인프라 — AgentENV

K3 후속학습·평가의 다양한 요구를 지원하기 위해 여러 샌드박스 런타임을 운용한다: 전통적 컨테이너 기반 런타임, GPU 샌드박스 런타임, 그리고 가장 주목할 만한 microVM 기반 AgentENV.

설계 목표내용
고충실도 격리 런타임 에이전트가 유능해지고 과제가 어려워질수록 더 공격적으로 탐색하며 reward hacking을 시도하기도 한다. 초기 컨테이너 기반 실험에서 의도치 않은 에이전트 조작으로 인한 kernel panic과 deadlock을 여러 번 관찰했다. 한편으로는 에이전트 능력을 제약하지 않기 위해 최대한의 탐색을 허용하고 싶고, 복잡한 과제는 실세계에 가까운 환경(디스크 마운트, 컨테이너 실행, 심지어 VM 실행)을 요구한다. Firecracker 기반 격리 microVM으로 컨테이너 런타임이 못 따라오는 수준의 격리와 충실도를 제공한다.
유연한 샌드박스 생애주기 저수준에서 증분 checkpointing/resuming을 지원 — 마지막 checkpoint 이후 dirty된 메모리 페이지만 저장하여 checkpoint 133 ms, resume 49 ms의 지연을 달성. 그 위에 세 가지 고수준 연산:
(a) Pause/Resume — 일시정지된 샌드박스는 메모리·CPU를 전혀 소모하지 않으므로, 에이전트가 모델 추론 결과를 기다리는 동안(샌드박스 생애의 최대 98%) 정지시킬 수 있다.
(b) Fork — 원본을 계속 실행한 채 정확한 상태로부터 새 샌드박스 생성. 부작용 없는 reward judging에 유용.
(c) Snapshot — 일정 간격으로 저장해 오류 복구.
고효율·고밀도 각기 고유한 이미지를 가진 수만 개 샌드박스를 수 초 내에 생성해야 한다. OverlayBD 이미지 포맷 + 커스텀 ublk 드라이버 구현 + storage-layer 공유 + P2P 전송으로 대규모에서 sub-second 실행 지연 달성. copy-on-write 메모리와 page-cache 최적화로 실제 워크로드에서 메모리 overcommit 비율 최대 6.5× 달성.

4.4 추론과 온라인 서빙

K3 서빙은 생산 측면에서 같은 난제를 노출한다: (i) 하이브리드 KDA–MLA 아키텍처가 근본적으로 다른 두 캐시를 백만 토큰 컨텍스트에서 공동 관리해야 하고, (ii) 새 모듈들과 극도로 희소한 전문가가 각각에 맞춘 커널을 요구하며, (iii) 프로덕션 트래픽은 요청당 비용이 3자릿수 차이 나는 요청들을 섞는다.

4.4.1 KDA-Aware Prefix Cache 관리

문제의 구조: KDA 재귀 상태와 MLA KV 캐시는 크기와 생애주기가 근본적으로 다른데, 캐시된 prefix는 둘 다 같은 경계에서 복원될 수 있을 때만 재사용 가능하다.

(a) 통합 캐시 레이아웃: K3의 각 블록은 3개 KDA 층 + 1개 Gated MLA 층이며 캐시가 근본적으로 다르다 — MLA KV 캐시는 시퀀스 길이에 따라 자라며 토큰 단위로 paging 되지만, KDA 재귀 상태는 크기 고정, 요청당 사본 1개다. 각각 별도 매니저를 두면 할당·축출·전송 로직이 중복된다. 그래서 KDA 상태를 MLA KV와 동일한 paged block pool에 packing하고 페이지를 같은 바이트 크기로 통일해, 두 페이지 유형이 할당·참조 카운팅·축출의 단일 구현을 공유하게 했다. 페이지 내부에서는 모든 head의 상태를 head 단위로 연속 저장해, 각 head의 바이트 스트림이 자기완결적이고 cross-node 전송의 최소 단위가 되게 한다. prefill/decode disaggregation 하에서 prefill 노드와 decode 노드의 TP degree가 다르면 전송 경로에서 re-layout을 수행해 GPU 측 reshuffling을 0으로 만든다.

개발 중 얻은 부수 효과: 이 비대칭성이 유용했다 — 타입이 혼동된 접근은 그럴듯한 데이터가 아니라 쓰레기값을 내놓으므로, pooled layout에 대한 오버헤드 0의 sanity check 역할을 했다.

(b) KDA prefix cache 최적화 — 두 granularity의 분리. 블록 해시 기반 prefix caching은 물리 블록 하나 단위로 KV 캐시를 재사용한다. 완전한 블록만 해싱하므로 블록 정렬된 prefix만 재사용 가능하다. K3에서는 이 결합이 깨진다:

  • 블록 해시 매칭은 모든 층이 공유하는 하나의 블록 크기를 요구한다
  • prefix hit은 hit 경계에서의 KDA 상태가 persist 되어 있어야만 재사용 가능하다
  • KDA 층은 토큰별 항목이 아니라 시퀀스당 하나의 큰 재귀 상태를 유지하므로, 상태 스냅샷은 sparse한 경계에서만 감당 가능하다

결과적으로 공유 블록 크기가 1024–6144 토큰으로 강제되고, 해싱이 저장 블록에 묶여 있으므로 해시 granularity도 함께 커진다 — MLA의 토큰별 항목만이라면 훨씬 미세한 블록도 감당할 수 있는데도 말이다. 이 정도로 거친 granularity에서는 캐싱이 거의 무용지물이다: 한 블록보다 짧은 요청은 절대 재사용될 수 없고, chunked prefill은 완전한 블록 경계를 넘기 전까지 캐시 가능한 prefix를 내보내지 못한다.

해법 — 두 granularity를 분리한다: prefix 해싱은 MLA 페이지 안의 미세한 hash block(예: 512 토큰)에서 수행하고, 물리 블록은 거친 할당 단위로 남긴다. KDA는 정렬 방향이 반대다 — 재귀 상태의 checkpoint를 MLA hash endpoint의 (sparse한) 부분집합에만 저장한다(lookup이 참조할 수 있는 유일한 위치들이므로).

prefill 중, 부분적으로 채워진 MLA 페이지는 마지막 완전 hash block의 chained hash로 prefix-cache 인덱스에 등록되며, 각 해시가 선행 hash block 전부를 커버하므로 endpoint 하나를 매칭하면 그 지점까지의 전체 prefix가 인증된다. 등록된 endpoint는 페이지가 채워지며 전진한다. 한편 매 forward pass 후 KDA 커널은 처리된 마지막 hash-aligned 위치에 재귀 상태를 persist한다. checkpoint는 크므로, 요청이 진행되며 대체된 중간 checkpoint는 재활용하고, 대화 턴 경계의 checkpoint는 cross-request 재사용을 위해 보존한다. 캐시된 checkpoint는 read-only 스냅샷이다 — hit 시 다음 forward pass 전에 요청의 private running state로 복사해 복원하고, 새 checkpoint는 fresh slot에 쓴다. 따라서 다른 요청에 보이는 checkpoint가 in-place로 변경되는 일은 없다.

Lookup은 2단계로 진행된다: (1) MLA 단계는 chained hash로 전체 물리 블록을 매칭하고, 첫 번째 누락 블록에서 그 안의 hash endpoint로 fallback 하여 부분적으로 채워진 페이지도 hit 가능하게 한다. (2) KDA 단계는 후보 경계에서 모든 KDA cache group(각각 독립적 재귀 상태 유지)에 checkpoint가 존재할 것을 요구한다. hit은 두 단계를 모두 만족하는 가장 긴 경계이며, 항상 hash block의 배수이되 물리 블록의 배수일 필요는 없다.

(c) 동시 스케줄링 하의 일관성. 나머지 설계 지점들은 각각 부분적으로 채워진 블록을 공유할 때의 구체적 실패 모드에서 도출된 것이다. hit된 블록은 동시에 공유 캐시 엔트리이자 private 요청의 성장점이고, MLA와 KDA cache group이 모든 hit 경계에 대해 합의해야 한다.

  1. Pinning: 모든 cache group이 하나의 공유 free list에서 블록을 가져오므로, 한 그룹을 위해 private 사본을 할당하다가 다른 그룹이 방금 hit한 블록을 축출할 수 있다. 따라서 어떤 할당보다 먼저 모든 hit 블록을 전 그룹에 걸쳐 pin한다.
  2. 같은 스케줄링 스텝 내 블록 배제: private 블록으로의 복사는 forward pass 직전 GPU에서 실행되므로, 현재 스케줄링 스텝 안에서 할당·등록된 블록은 여전히 이전 소유자의 바이트를 reader에게 넘겨줄 수 있다. 그런 블록은 복사가 착지할 때까지 매칭에서 제외한다.
  3. Checkpoint의 원자적 무효화: checkpoint는 모든 KDA 그룹에 존재할 때만 요청을 복원할 수 있으므로, 한 그룹의 checkpoint를 축출하면 형제 checkpoint들을 원자적으로 무효화한다 — checkpoint는 모든 그룹에서 hit 가능하거나, 어디에서도 불가능하거나 둘 중 하나다.

이 메커니즘들 덕분에 등록된 모든 상태가 항상 정확히 그 선언된 토큰 prefix에 대응하며, 하이브리드 KDA–MLA 모델의 prefix caching이 full-attention 모델과 동일한 일반성에 도달한다 — 요청 길이·chunking·스케줄링 interleaving과 무관하게 어떤 공유 prefix든 512-토큰 경계 어디서나 재사용 가능하다.

4.4.2 고성능 커널

KDA 디코딩: prefill과 달리 디코딩의 주 병목은 병렬성 활용에서 매 디코딩 스텝마다 in-place 갱신되는 재귀 상태의 효율적 관리로 이동한다. 이 in-place 갱신이 MTP 기반 투기적 디코딩에서 문제가 된다 — 검증이 draft 토큰 일부를 거부하면 상태가 이미 마지막 수용 토큰 너머로 전진해 있어 되돌릴 수 없다. draft 위치마다 상태 스냅샷을 유지하면 롤백이 가능하지만 상태 트래픽이 몇 배로 늘어나고, 이는 온라인 서빙의 큰 배치 크기에서 비용을 지배한다.

핵심 관찰: 임의의 수용된 draft prefix 이후의 상태는 draft 토큰들의 투영된 입력(projected inputs)에 의해 완전히 결정되며, 이것은 상태 자체보다 훨씬 작다. 따라서 투영된 입력만 캐시하고, 수용된 토큰들의 상태를 on-chip에서 재구축하며, 검증된 토큰과 bonus 토큰의 상태만 write-back한다(동시기 연구 ReplaySSM에서 독립적으로 제안된 설계). 재생(replay)되는 토큰, bonus 토큰, 다음 draft window가 하나의 fused kernel 안에서 단일 재귀 루프를 공유하며, 이 커널은 short convolution, 입력 정규화, 게이팅, KDA 재귀, 출력 정규화를 모두 포괄한다. 검증 지연은 검증 토큰 수에 대해 sub-linear하게 증가하며 state-caching 베이스라인보다 낮게 유지된다. 투영 캐시는 decode 단계를 절대 떠나지 않으므로, prefix caching과 prefill–decode disaggregation은 비-투기적 서빙과 동일한 payload 위에서 동작한다.

Block AttnRes 커널: 2단계 스케줄을 따른다 — 배치된 inter-block pass가 블록당 한 번 캐시된 블록 표현을 읽고, 이후 각 층이 online-softmax 병합으로 intra-block 부분합을 접어 넣는다. prefill과 디코딩 모두에서 메모리 접근이 비용의 상당 부분을 차지하므로 최적화의 초점도 메모리 효율에 있다.

  • Prefill: 모든 TP 랭크에 블록 표현을 materialize 하면 중복 메모리 소비가 크다. 그래서 활성값에 sequence parallelism(SP)을 적용한다 — TP all-reduce를 reduce-scatter와 all-gather로 분해하고, 두 collective 사이에 intra-block 커널을 삽입해 시퀀스 샤딩된 은닉 상태 위에서 동작시킴으로써 각 토큰의 블록 표현이 정확히 한 랭크에만 materialize 되게 한다.
  • Decoding: inter-block 커널을 side stream에서 실행해 main stream의 독립 연산과 오버랩한다. intra-block 커널은 fusion으로 간소화한다 — AttnRes 출력과 부분합 갱신의 병합, 그리고 뒤따르는 RMSNorm을 선행 TP all-reduce에 융합하여 intra-block 위상 전용 커널을 제거한다.

Stable LatentMoE 커널: 총 전문가 수와 토큰당 활성 전문가 수가 모두 늘어 스케줄링·조율 오버헤드가 커지고, 기존 MoE 커널로는 높은 하드웨어 활용도를 유지하기 어렵다.

  • Latent GEMM 오버헤드 완화 (3가지): (1) latent down-projection을 MoE 라우터와 단일 GEMM으로 융합, (2) latent 가중치 행렬을 랭크 간 샤딩하고 multimem store 명령으로 출력 all-gather를 GEMM epilogue에 융합, (3) 그 통신을 shared-expert 연산 같은 다른 연산자와 오버랩. 중복 가중치 트래픽과 중복 연산을 제거하고 통신 지연을 연산 뒤에 숨긴다.
  • Routed expert 디코딩 커널: 작은 배치 크기에서 group GEMM은 가중치 행렬의 memory-bound 스트리밍으로 축퇴한다. 연산 지향 설계와 전처리 오버헤드 때문에 기존 tile-centric 커널은 이 레짐에 부적합하다. 대신 WarpDecode의 token-centric 설계 위에 MoE 디코딩 커널을 세운다 — 각 warp가 하나의 출력 뉴런을 담당하고 관련 가중치를 메모리에서 직접 스트리밍한다. 병렬성을 더 높이기 위해 각 warp를 더 미세한 lane team으로 세분해 각각 겹치지 않는 전문가 부분집합을 처리한 뒤 warp 전체 reduction을 수행한다. 또한 가중치 레이아웃을 오프라인에서 한 번 permute 해 런타임 dequantization 오버헤드를 크게 줄인다.

4.4.3 Fleet-Level 스케줄링

단일 서빙 인스턴스를 넘어서면 과제는 요청당 효율에서 예측 가능성(predictability)으로 이동한다 — prefix-cache miss는 hit보다 몇 자릿수 비싸고, 백만 토큰 요청의 burst 하나가 짧은 요청들을 굶길 수 있다.

Cache-aware affinity scheduling: 1M 컨텍스트에서 전형적인 코딩 입력은 400K 토큰의 prefix를 나르지만 prefill 증분은 4K 토큰에 불과하다. 따라서 prefix-cache hit은 전체 prefix 재계산을 피하게 해주며 miss보다 몇 자릿수 저렴하다. 그래서 각 요청을 그 prefix 캐시를 보유한 클러스터로 라우팅한다(캐시를 다른 클러스터로 옮기려면 intra-cluster fabric보다 훨씬 느린 inter-cluster 링크로 전송해야 하므로).

그런데 이 cache affinity는 각 세션을 단일 클러스터에 묶으므로, 그 클러스터가 죽으면 묶인 모든 세션이 끊긴다. 그래서 consistent hashing으로 각 세션을 두 클러스터에 pin한다 — 트래픽을 서빙하는 primary와 primary 실패 시 인계받는 사전 할당된 secondary. secondary는 그 세션의 prefix 캐시를 전혀 갖고 있지 않으므로 failover 시 재-prefill 해야 한다. 하지만 consistent hashing이 서로 다른 세션들의 secondary 할당을 fleet 전체에 균일하게 분산시키므로, 이 재-prefill 작업이 한 클러스터에 집중되지 않고 여러 클러스터에 나뉜다. 일반적인 경우에는 캐시 locality가 보존되고, 단일 클러스터 실패의 영향은 유한하게 묶인다.

Budget-based admission control: 프로덕션 트래픽은 2K 토큰 미만의 짧은 요청과 최대 1M 토큰의 초장문 요청을 섞으므로, 요청당 비용이 대략 세 자릿수 범위에 걸치고 고정된 요청 수가 부과하는 총 부하가 매우 예측 불가능하다. "평균 요청"에 기반한 capacity planning, queueing model, rate-limiting quota가 모두 이 분산 하에서 무너진다. 전형적 실패 모드는 long-context 요청 burst가 가용 compute를 포화시키고, 이후 도착한 짧은 요청들이 즉시 스케줄되지 못해 전체 트래픽의 TTFT(time to first token)가 나빠지는 것이다. 그래서 요청 클래스별로 별도 자원 예산을 할당해, 폭주하는 long-context 트래픽이 자기 몫 이상을 소비하지 못하고 다른 클래스가 경험하는 시스템 전역 SLO를 저하시키지 못하게 한다.

모든 Kimi K3 평가는 reasoning effort max, temperature = 1.0. GPQA Diamond, HLE-Full, 도구 없는 비전 벤치마크 같은 단일 스텝 과제는 top-p = 0.95, agentic 과제는 top-p = 1.0. 저자들의 일반 권고: 추론·지식 과제는 top-p 0.95, 코딩·agentic 시나리오는 top-p 1.0.

  • Coding: 각 모델은 Kimi Code, Claude Code, Codex 중 하나의 agentic harness로 평가. DeepSWE는 v1.1 태스크 기준이며, 공식 리더보드 참조 시 K3는 mini-SWE-agent harness로 67.3. Terminal-Bench 2.1은 모든 모델에 대해 harness 간 최고 점수를 보고. SWE-Marathon 평가는 공식 v1.1 릴리스 전인 2026-07-09 기준 H20 보정 브랜치 기반(Docker 이미지·performance gate·GPU 태스크 reference oracle을 H20에 맞춰 재보정, 정확성·anti-cheat validator는 불변). SWE-Marathon에서 Claude Fable 5는 태스크의 35%에서 fallback에 걸린다. PostTrainBench는 K3·Fable 5·GPT-5.6 Sol을 공식 Harbor 구현으로 최대 effort, H20 GPU에서 3회 평균(공식 설정은 H100). FrontierSWE dominance score는 2026-07-16 기준 공식 스크립트로 raw score에서 재계산.
  • Agentic: OfficeQA Pro는 전체 PDF 코퍼스를 이미지로 렌더링해 제공하며 기계 판독 가능한 텍스트가 없다. MCP-Atlas는 500-task 공개 부분집합, 100-turn 제한, Gemini 3.1 Pro를 judge로. AutomationBench는 600-task 공개 부분집합. BrowseComp는 300K 토큰에서 트리거되는 context-compaction 전략을 채택했으며, 전체 1M 컨텍스트로 컨텍스트 관리 없이 평가하면 90.4%(compaction 시 91.2%).
  • Vision: 3회 평균(ZeroBench-main은 공식 설정 따라 5회). MMMU-Pro는 공식 프로토콜(원래 입력 순서 보존, 이미지를 텍스트 앞에 배치). WorldVQA는 모델 전반에서 일관된 거부(refusal) 행동이 관찰되어 프롬프트 엔지니어링으로 답변을 강제.
  • Third-party 인용: GDPval-AA v2, AA-Briefcase, $\tau^3$-Banking, Harvey Lab-AA, APEX-Agents, SciCode, AA-LCR, CritPt는 Artificial Analysis(2026-07-23 기준). 5.1.4 결과 해석과 패턴 분석

전체적으로 Kimi K3는 최강 프로프라이어터리 모델(Claude Fable 5, GPT-5.6 Sol)을 근소하게 뒤따르면서, Claude Opus 4.8·GPT-5.5·GLM-5.2는 벤치마크 스위트 전반에서 일관되게 앞선다.

Reasoning & Knowledge: 대학원 수준 추론에서는 GPQA Diamond 93.5%로 프론티어와 경쟁적이다. 그러나 연구 수준(research-level) 과제에서는 격차가 남는다 — HLE-Full에서 도구 없이 43.5%, 도구 사용 56.0%로 Fable 5와 GPT-5.6 Sol 양쪽에 뒤지고, CritPt는 23.4%로 Fable 5·GPT-5.6 Sol·GPT-5.5에 모두 뒤진다. 저자들도 ##research-level reasoning이 핵심 개선 방향으로 남아 있다##고 명시한다.

Coding: 강력한 agentic 코딩 성능. ProgramBench 최고점(77.8%), GPU 커널 지향 스위트인 SWE-Marathon에서 42.0%로 Fable 5보다 7점 앞선다. Terminal-Bench 2.1은 GPT-5.6 Sol에 거의 근접(88.3% vs 88.8%). DeepSWE는 Fable 5·GPT-5.6 Sol에 뒤지지만 Opus 4.8·GPT-5.5보다는 앞선다. long-horizon 벤치마크인 FrontierSWE에서는 81.2%로 2위 — Fable 5(86.6%)에만 뒤지고 나머지 모든 모델을 크게 앞선다.

Agentic: 광범위한 agentic 스위트에서 SOTA를 달성한다 — BrowseComp 91.2%, DeepSearchQA 95.0% F1, ResearchRubrics 76.2%, MCPMark-Verified 94.5%, AutomationBench 30.8%, SpreadsheetBench 2 34.8%, $\tau^3$-Banking 33.4%, Harvey Lab-AA 94.6% criterion pass rate. 주요 예외는 Elo 기반 knowledge-work 스위트로 둘 다 Fable 5가 선두다 — GDPval-AA v2에서 3위(1,686), AA-Briefcase에서 2위(1,548). 그 외에는 대체로 경쟁적이다: CorpFin v2와 OSWorld-Verified에서는 Fable 5에 단 0.2점 차(71.6 vs 71.8, 84.8 vs 85.0). 더 어려운 컴퓨터 사용 벤치마크(OSWorld 2.0, SaaS-Bench)는 여전히 Fable 5나 GPT-5.6 Sol이 선두.

Vision: 강한 멀티모달 이해력을 보이며 Python 도구가 이를 크게 증폭한다 — Math-Vision 94.3% → 도구 사용 시 97.8%, 난이도 높은 ZeroBench-main에서 Fable 5와 23.0%(pass@5)로 동률이지만 Python 도구 사용 시 41.0%로 급등. OmniDocBench 최고점(91.1%), WorldVQA는 51.0%로 Fable 5 다음 2위이며 GPT-5.6 Sol·Opus 4.8을 앞선다.

패턴 분석 — 어디서 강하고 어디서 약한가
  • 강한 곳: (i) 검색·리서치형 agentic 과제(BrowseComp, DeepSearchQA, ResearchRubrics), (ii) 도구 사용을 통한 시각 추론(ZeroBench, Math-Vision의 도구 유무 차이), (iii) GPU 커널·시스템 코딩(SWE-Marathon), (iv) 구조화된 문서·표 처리(OmniDocBench, SpreadsheetBench 2). 모두 §3.5의 RL 환경 설계와 정확히 대응한다 — 그 환경들을 만들었기 때문에 그 능력이 나왔다는 인과가 비교적 뚜렷하다.
  • 약한 곳: (i) 연구 수준 심층 추론(HLE, CritPt), (ii) Elo 기반 인간 선호 knowledge work(GDPval-AA v2, AA-Briefcase, JobBench, OfficeQA Pro), (iii) 어려운 컴퓨터 사용(OSWorld 2.0). 앞의 둘은 검증 가능한 reward를 설계하기 어려운 영역이라는 공통점이 있다 — RL로 밀어붙이기 가장 어려운 지점이다.
  • 도구가 격차를 메운다: ZeroBench 23.0 → 41.0, Math-Vision 94.3 → 97.8, HLE 43.5 → 56.0. K3의 상대적 위치가 도구 사용 조건에서 더 좋아지는 경향이 있는데, 이는 네이티브 멀티모달 + vision-in-the-loop RL 설계의 직접적 결실로 읽힌다.

5.2 내부 평가 (Internal Evaluation)

공개 벤치마크가 충분히 다루지 못하는 능력 영역을 겨냥한 in-house 벤치마크 모음. 자주 갱신·확장되어 모델의 변화하는 실패 모드를 추적하고 데이터·학습 반복을 직접 안내한다. 세 범주로 나뉜다.

5.2.1 벤치마크 정의

코딩 능력·경험

  • Kimi Code Bench 2.0 (KCB 2.0): 광범위한 프로그래밍 언어와 프로덕션 지향 기술 스택에 걸친 현실적 end-to-end 소프트웨어 엔지니어링 과제에서 code agent를 평가
  • Kimi Webdev Bench: 실사용 시나리오에서 뽑은 도전적 웹 개발 프롬프트를 블라인드 전문가 판정으로 비교
  • Coding Experience: 실제 개발 워크플로우에서 coding agent로서 모델과 함께 일하는 실질적 경험을 평가

일반 에이전트 경험

  • 24/7 ClawBench 2.0: 항상 켜져 있는 assistant 작업 시뮬레이션 — 과제가 여러 날에 걸치고, 이벤트가 동시에 도착하며, 중단(interruption)이 일상적
  • MIRA Bench (Multi-Agent Infra for Routing and Assignment): 장기 체인·다중 역할·다중 시스템 기업 협업 과제. 에이전트가 end-to-end 작업을 수행하고 언제 subagent를 조직하거나 위임할지 판단할 수 있는지 평가
  • KAET (Kimi Autonomous Execution Tasks): 실제 사용자 요청과 기업 시스템 운영을 시뮬레이션한 과제의 long-horizon 자율 실행 평가
  • CLIF Bench (Context Learning and Instruction Following): in-context learning을 겨냥 — 제공된 맥락에서 학습하면서 여러 복잡한 skill이 교차하는 지시를 따라야 함
  • Agentic Vision Bench: 과제 실행 중 핵심 시각 정보를 알아채고 올바르게 사용하는지 평가
  • Swarm Bench: 조율된 분해와 병렬 실행이 유리한 복잡 과제에서 agent swarm을 조율하는 능력
  • Online Experience: 실제 온라인 에이전트 사용 분포를 반영 — 사용자가 가장 자주 요청하는 deliverable 파일 유형에서의 성능
  • Deep Research Bench: 도메인 전문가가 큐레이션한 deep-research 스타일 쿼리를 전문가 정렬 rubric으로 채점
  • Finance Bench: 원천 자료에서 검토 가능한 deliverable까지 완전한 워크플로우의 end-to-end 실행이 필요한 현실적 금융 업무
  • KWV Bench (Knowledge Work Vision): 실제 knowledge-work 시나리오에서 증류한 과제에서 추출한 원자적 시각 능력 평가
  • DECK Bench: 실사용 시나리오의 과제 설명으로부터 고품질 프레젠테이션 덱을 만드는 능력
  • Agent Behavior Bench: 에이전트 평가를 결과 정확성에서 과정 품질로 확장 — 도구 사용 행동, 효율, 규율을 과제 완수와 함께 채점

대화 경험

  • Faithfulness: 응답의 사실 환각(hallucination) 비율을 fact checker로 검증. 보고 지표는 1 − hallucination rate이며 높을수록 좋음
  • Chat All-in-One Bench: 제품 사용의 모든 단계에서 대화 경험 측정, 실제 온라인 사용자 니즈를 중심으로 설계된 시나리오

결과 해석

in-house 스위트는 공개 벤치마크보다 K3의 강점과 약점을 더 날카롭게 갈라놓는다.

  • 코딩도 강점: KCB 2.0에서 Claude Fable 5에만 뒤지고, Coding Experience에서는 최고점. 이는 coding agent로서의 실질적 행동(소통 품질, 행동 적절성, 지시 따르기 안정성)이 원(raw) 태스크 점수보다 앞서 있음을 시사한다. Kimi Webdev Bench에서는 전문가 판정으로 Opus 4.8을 +31.0점 차로 앞서며, 특히 3D/WebGL/Shader에서 이득이 가장 크다(+59.1%).
  • 전문 knowledge work도 이전 세대 대비 현저히 개선 — Finance Bench가 GPT-5.6 Sol과 사실상 동률(62.6 vs 62.7).
  • 뒤처지는 곳: Agent Behavior Bench, MIRA Bench, 24/7 ClawBench 2.0, Agentic Vision Bench, KWV Bench. 나머지 채워진 스위트(KAET, CLIF Bench, Online Experience, DECK Bench, Faithfulness, Chat All-in-One Bench)에서는 1위 또는 근소한 2위다.
주목할 만한 패턴: Fable 5와 GPT 계열의 점수에는 fallback·거부(refusal) 각주가 반복적으로 붙는다(80개 중 10~14건 거부). K3 점수에는 이런 각주가 없다. 벤치마크 해석 시 이 비대칭을 감안해야 하며, 동시에 이는 오픈 모델의 거부 정렬(refusal alignment)이 상대적으로 느슨하다는 사실의 반영이기도 하다 — §5.2.3의 사이버 평가와 함께 읽어야 할 지점이다.

5.3 사이버 보안 평가

운영 위험이 증가하는 2단계 위계로 모델의 사이버 보안 능력을 평가한다. 평가 대상에는 널리 배포된 소프트웨어(OS 커널 구성요소, 오픈소스 프로젝트)의 최신 버전과 자체 내부 인프라(프로덕션 서비스·코드베이스)가 포함되며, 모든 태스크는 실세계 배포를 대표하는 표준 구성에서 실행된다. Anthropic과 OpenAI의 프론티어 모델은 사이버 관련 태스크를 거부하므로 비교 평가가 불가능하여 이 스위트에서 제외했다.

Tier 1 — 취약점 발견 + PoC 개발

알려진 취약점의 재현이 아니라 현재 코드베이스에서 진짜 버그를 찾아내고 재현 가능함을 입증하는 능력. 이는 주로 방어적 보안 연구와 연관된 능력이다.

OS 커널, 데이터베이스, AI 서비스, 웹 프레임워크, 블록체인, VPN 소프트웨어에 걸친 수십 개 시스템에서 모델은 수백 개의 후보 취약점을 식별했다. 사람 검토를 거친 발견 중 약 70%가 진짜로 확인되었으며, 여기에는 6개 프로젝트에 걸친 16개의 미공개(previously unknown) 취약점이 포함된다.

Linux 커널의 두 발견이 결과의 깊이를 보여준다:

  1. 원격 트리거 가능한 heap out-of-bounds write. 이 버그는 불완전한 upstream 수정으로 도입되었고 이후 모든 릴리스(최신 upstream 코드 포함)에 영향을 미친다. 보안 전문가가 원격 서비스 거부(DoS) primitive로 확인.
  2. RDMA 서브시스템의 Dirty-COW급 취약점. 이전 upstream 수정이 실수로 권한 검사를 누락해, 읽기 전용 메모리 페이지에 커널 측 쓰기를 허용. 보안 전문가가 결정론적 로컬 권한 상승 primitive로 확인.

Tier 2 — 익스플로잇 개발

취약점을 작동하는 end-to-end 익스플로잇으로 전환하는 능력. 오용(misuse) 위험과 가장 직결되는 tier다. GLM-5.2를 베이스라인으로, 두 트랙에 걸친 36개 태스크의 in-house 스위트로 평가한다.

  • User-space exploitation (16 태스크): PostgreSQL, XWiki 협업 플랫폼, Apache HTTP Server, 여러 CMS 및 기타 애플리케이션에서 실제 CVE를 end-to-end로 익스플로잇. 각 태스크마다 전체 소스 코드와 라이브 인스턴스가 주어지며, 대상은 추가 hardening 없는 표준 구성으로 실행.
  • Linux kernel exploitation (20 태스크): 각 태스크는 과거 커널 CVE로 구축된 재현 가능한 QEMU 환경을 제공하며, 모델은 비특권 사용자에서 root로 권한을 상승시키는 C 익스플로잇을 작성해야 한다. 난이도 등급에 따라 mitigation이 점진적으로 활성화된다.

스위트의 모든 태스크는 인간 보안 전문가가 풀 수 있음이 검증되었다. 전체 스위트 완수에는 약 540 전문가-시간(태스크당 평균 약 15시간)이 필요한 것으로 추정된다.

결과: 모델은 36개 중 14개(38.9%)를 해결했고 GLM-5.2는 36개 중 8개(22.2%)였다. 그러나 성공은 고르지 않게 분포한다 — 14개 중 10개가 user-space 트랙에서 나왔다. 커널 트랙에서는 두 모델 모두 태스크의 4분의 3을 풀지 못한다.

모든 태스크가 전문가에게는 풀리므로, 미해결 태스크가 곧 인간 수준까지의 남은 격차를 직접 측정한다. Trajectory 분석은 이 격차를 4가지 반복 실패 모드로 귀속시킨다:

  1. 이미 획득한 primitive로부터 익스플로잇 체인의 마지막 단계를 완성하는 데 어려움
  2. mitigation 하에서의 전략 선택 미숙 — 예컨대 data-only 공격이 더 간단하고 신뢰성 높은 상황에서도 control-flow hijacking을 고집
  3. 길고 비생산적인 디버깅 루프에 갇힘
  4. 제출 전 최종 산출물에 대한 검증 부족

요약과 제3자 확인: 모델의 사이버 능력은 Tier 1과 Tier 2의 user-space 익스플로잇에서 가장 강하지만 인간 전문가와의 명확한 격차가 남는다. 방어적 성격의 Tier 1에서는 미공개 취약점을 포함한 진짜 취약점을 찾아내고 재현성을 입증한다. Tier 2에서는 user-space 대상에 대해 end-to-end 익스플로잇을 완성한다. 그러나 hardened 대상에 대해서는 전체 익스플로잇 체인 완성이 병목으로 남고, 전문가가 풀 수 있는 많은 태스크가 미해결로 남는다.

독립 평가: 영국 AI Security Institute와 NIST의 CAISI(Center for AI Standards and Innovation)의 공동 평가도 같은 결론에 도달했다. Kimi K3는 익스플로잇 개발에서 GLM-5.2를 앞서지만(ExploitBench 32% vs 24%; 인간 전문가가 약 20시간 걸리는 32-스텝 모의 기업 네트워크에서 17 vs 11 스텝), end-to-end 익스플로잇 완성에서는 프론티어 사이버 능력 모델에 뒤진다 — ##41개 태스크 중 0개에서만 임의 코드 실행(arbitrary code execution) 달성##. 저자들은 자신들의 평가를 능력의 하한(lower bound)으로 간주하며, 현재 모델 버전과 평가 커버리지에 조건부인 결과이므로 주요 모델 업데이트마다 재검토하겠다고 밝힌다.

6. 케이스 스터디 (Case Studies)

GPU 커널 최적화

각 모델이 동일하게 구성된 샌드박스에서 독립적으로 작업하며, 태스크당 최대 24시간 예산으로 프로파일링·재작성·벤치마킹을 수행한다. 평가는 4개 대표 커널 — AttnRes, DeepSeek Sparse Attention(DSA), KDA, MLA(head dimension 512) — 을 NVIDIA Hopper GPU와 대안 벤더 GPGPU에서 다룬다.

  • AttnRes 지연: 283.6 ms → 114.4 ms
  • DSA 런타임 55.1% 단축, KDA 런타임 73.6% 단축
  • MLA에서 peak TFLOPS의 절반 이상 도달

이 태스크들 전반에서 Kimi K3는 Claude Fable 5(fallback 포함)와 대등했고, Claude Opus 4.8·GPT-5.6 Sol·GPT-5.5를 크게 앞섰다. Figure 14는 AttnRes에 대한 최적화 궤적을 비교하는데, active hour에 따른 FLA Triton 베이스라인 대비 speedup(%)이 그려진다 — Kimi K3 +59.7%(최고 64.1%), Claude Fable 5 +57.1%, GPT-5.5 +30.8%, GPT-5.6 Sol +17.3%.

실무적으로 가장 흥미로운 문장: ##"벤치마크를 넘어, 초기 Kimi K3 체크포인트가 이미 개발 후반부 우리 커널 최적화 작업의 대부분을 처리하고 있었다."## 즉 이 능력은 데모가 아니라 저자들 자신의 개발 파이프라인에 실제로 투입된 능력이다.

GPU 컴파일러 개발 — MiniTriton

Kimi K3는 MiniTriton을 개발했다 — 커스텀 tile-level Python 프론트엔드와 layout 시스템, 경량 warp-level MLIR 어노테이션·최적화 계층, PTX(Parallel Thread Execution) 코드 생성 파이프라인을 갖춘 소형 Triton 유사 컴파일러다. 컴파일러 위에 PyTorch 유사 고수준 인터페이스의 dual-mode tensor 라이브러리가 세워졌으며, eager 경로와 forward-only 컴파일 경로가 같은 DSL 컴파일러·런타임을 공유한다. 라이브러리는 reverse-mode autograd, 신경망 모듈, NCCL 기반 분산 학습 primitive, sparse·visualization primitive까지 제공한다.

성능(NVIDIA L20):

  • 코어 벤치마크 스위트의 기하평균에서 PyTorch eager와 torch.compile을 능가
  • from-scratch tensor-core matmul 경로가 가장 큰 shape에서 cuBLAS에 근접, 측정된 machine roof의 약 90% 도달
  • DSL 수준 KDA prefill 커널이 매칭된 Triton 참조를 뚜렷한 차이로 능가
  • GPT 모델을 end-to-end로 학습시키며 loss 곡선이 PyTorch 참조를 밀접하게 추종. 전체 모델 gradient가 torch autograd와 torch 자신의 fp32 반올림 오차($10^{-4}$) 이내로만 차이 (fp64 참조 대비 측정)

칩 설계

초기 개념 증명으로, Kimi K3는 자신과 같은 아키텍처(하이브리드 KDA + NoPE-MLA 어텐션, 블록 크기 2의 Block AttnRes, shared expert 1개의 sigmoid 기반 MoE 라우팅)를 따르는 nano 모델용 추론 칩 프로토타입을 group-wise INT4 가중치 양자화(group size 128) 하에 설계했다.

Kimi Code로 단일 48시간 자율 실행 안에서 오픈소스 EDA 도구와 Nangate45 표준 셀 라이브러리를 사용해 칩을 구축·최적화·검증했다. 결과:

  • 4 mm² 분석적 면적 예산 내에서 100 MHz에서 timing closure
  • RTL 시뮬레이션 decode 처리량 8,700 tokens/s 이상
  • 1.46M 표준 셀, 0.277 MiB SRAM, fused dequantization을 갖춘 INT4 MAC 배열 통합
  • RTL 코드는 GitHub(MoonshotAI/nano-kpu)에 공개

연구를 위한 코딩

계산천체물리학의 I–Love–Q 보편 관계(universal relations)를 재현하기 위해, Kimi K3는 20편 이상의 논문을 검토·교차 검증하고, 전체 수치 파이프라인을 구현했으며, 300개 이상의 상태방정식(equations of state)을 평가하고, 발표된 공식들에서 불일치를 찾아냈으며, 3,000줄 이상의 Python을 작성해 인터랙티브 HTML 대시보드를 산출했다 — 약 2시간 만에. 숙련 연구자라면 통상 1~2주 걸리는 작업이다.

Knowledge work

  • Kimi Work에서 42년간의 AI ASIC 산업을 다루는 인터랙티브 리서치 웹사이트를 제작. 87개 분기 보고서와 99개 원본 PDF(11,000페이지 이상) 코퍼스를 2,800회 이상의 웹 검색과 1,100회 이상의 터미널 쿼리로 활용하며 120라운드 이상의 반복 개선 수행.
  • 두 번째 사례: GWTC-5의 391개 중력파 이벤트를 20개 이상의 동시 subagent로 분석해 7개 과학 시각화, 2개 요약 테이블, 10편 이상 논문의 문헌 종합을 산출.

비디오 편집·모션 디자인

네이티브 멀티모달 아키텍처를 활용해, Kimi K3는 자기 자신의 아키텍처를 설명하는 3Blue1Brown 스타일 모션 그래픽스를 만들고, 56개 소스 클립으로부터 자신의 티저 비디오를 편집했다. 여기에는 클립 선택, motion-matched cut, 프레임 단위 정확한 비트 동기화, 오디오 처리, 여러 차례의 수정이 포함된다. 비교 가능한 고밀도 short video를 만들려면 숙련 편집자에게 보통 1~2일이 걸린다.

7. 결론

Kimi K3는 Kimi Delta Attention과 Attention Residuals 위에 세워진, 네이티브 비전 능력과 1M 토큰 컨텍스트를 갖춘 오픈 2.8조 파라미터 MoE 모델이다. 세계 최초의 오픈 3T급 모델로서 long-horizon 코딩, agentic, 지식, 추론, 비전 과제 전반에서 프론티어 수준 성능을 낸다. 최강 프로프라이어터리 모델과의 격차는 남아 있지만, Kimi K3는 모두의 손이 닿는 곳에 새로운 오픈 프론티어를 확립한다.

부록 F: XTML Chat Template

Kimi K3의 chat template은 세 가지 목표로 재설계되었다:

  1. 확장성(extensibility): 새 능력은 template 개정이 아니라 하위 호환 메시지 포맷으로 도입되어, 단일 template이 모델 세대 전체를 커버
  2. 낮은 alignment tax: 최소한의 지도 데이터로 학습 가능한 포맷 — 가볍게 fine-tune된 사전학습 모델이 곧바로 RL로 진행할 수 있는 파이프라인 지원
  3. 디코딩 친화성: 단순한 encoder, streaming parser, grammar-constrained enforcer를 허용하는 구조

이를 위해 XTML(eXtensible Token Markup Language)을 채택했다 — XML 유사 마크업이되 꺾쇠괄호 문법을 세 개의 예약 special token [open], [sep], [close]로 대체하고, 생성 중단 마커로 [end_of_msg]를 추가한다. 요소 [open]tag attr="value"[sep] ... [close]tag[sep]는 XML 대응물과 동형(isomorphic)이지만 모든 구조적 경계가 명시적 special token이므로 요소 경계에서의 tokenization 모호성이 제거되고 constrained decoding이 단순해진다.

메시지와 zone: 컨텍스트의 최상위 단위는 message이며 출처에 따라 두 범주로 나뉜다.

  • Input message: 요청의 messages 필드를 직렬화 — system, user, assistant, tool 역할
  • Option message: 요청 옵션을 모델이 컨텍스트에서 읽는 지시로 번역하며, 배치 위치가 그 범위(scope)를 반영
    • Global option — 도구 선언(type="tool-declare")과 reasoning-effort 설정은 모든 input message 앞에 온다. 세션 전체를 지배하고 거의 바뀌지 않으므로, 바꾸면 어차피 KV 캐시가 무효화된다.
    • One-shot option — tool_choice, response_format은 input message 뒤에 붙어, 요청별 변경이 히스토리 KV 캐시를 건드리지 않게 한다.
    • Input option message — input message 사이에 끼워져 세션 중간에 global option을 보완·재정의한다. 이 메커니즘이 동적 로딩 도구를 지원한다 — 대화 중 검색·로드된 도구를 추가 tool-declare 메시지로 알리면, 선행 컨텍스트를 재구축하지 않고도 모델의 가용 도구 집합이 확장된다.

Channel: assistant 메시지의 본문은 channel로 조직된다(OpenAI Harmony response format에서 영감). think는 추론 trace, response는 사용자에게 보이는 답변, tools는 도구 호출을 담는다. 두 생성 모드는 별도 template이 아니라 생성 prefix만으로 선택된다 — thinking 모드는 [open]think[sep], instruct 모드는 [open]response[sep]. Kimi K3는 preserved thinking만 지원한다: thinking 모드에서 think channel은 내용이 비어 있어도 히스토리에 항상 유지되어 모델이 턴 간에 일관된 메시지 구조를 관찰하게 한다. instruct 모드에서 히스토리 메시지는 response와 tools channel만 담는다.

Tool calling: tools channel 안에서 각 호출은 tool과 index 속성을 가진다. index는 한 메시지 내 병렬 호출에 번호를 매기고, 각 tool-result 메시지는 같은 tool/index 쌍을 반복하며 호출 순서를 따라, 결과가 호출과 모호함 없이 연결된다. 인자는 타입이 있다 — 문자열 인자는 raw text로 나타나고 다른 JSON 타입 값은 압축 직렬화된다. 따라서 코드 같은 자유 형식 텍스트가 escape된 JSON 문자열이 아니라 1급 시민(first-class citizen)이다. 인자를 타입별 블록으로 분해할 수 없는 입력을 위한 pure-JSON fallback 블록이 있으나, input token에서만 나타나고 모델 출력에는 절대 나타나지 않으며 학습 중 loss가 마스킹된다.

Reasoning effort와 옵션: reasoning effort는 thinking-effort 타입의 global option message로 노출되며, 도구 선언 뒤·input message 앞에 삽입된다. 생성 prefix를 수정하거나 토큰 예산을 노출하는 대신, 요청된 레벨을 자연어로 진술하고 생성 제약 지시로 작동한다. 스키마는 4개 레벨(low, medium, high, max)을 예약하며 Kimi K3는 그 부분집합을 지원한다. 더 넓게 보면 이것이 모든 option message의 공통 구현이다 — tool_choice, response_format, thinking-effort가 각각 전용 special 문법이 아니라 짧은 자연어 지시로 번역되어 컨텍스트에 놓인다.

왜 이 설계가 우아한가: 사전학습 모델이 이미 그런 지시를 잘 따르므로, 새 옵션을 추가하는 데 추가 학습이 거의 또는 전혀 필요 없다 — low-alignment-tax 설계 원칙의 직접적 구현이다.

비판적 분석

강점

  • 단일 원칙에서 아키텍처를 연역했다: "정보 흐름을 시퀀스·깊이·너비 세 방향으로 확장한다"는 원칙이 KDA·AttnRes·LatentMoE라는 세 선택으로 깔끔히 대응된다. 대부분의 기술 보고서가 개선 사항의 나열인 데 반해, K3는 설계 논리가 있다.
  • 안정성 문제를 정면으로 다뤘다: SiTU-GLU, RMSNorm 삽입, lower-bounded decay, Per-Head Muon, from-scratch ViT — 이들은 모두 "3T 규모·sparsity 56에서 학습이 발산한다"는 구체적 실패 모드에 대한 대응이다. 특히 lower-bounded decay가 수치 안정성 트릭이면서 동시에 커널 병목(position-pair 대각 타일)을 제거하는 대목은 algorithm–system co-design의 모범이다.
  • 이론적 보증이 실무 문제를 푼다: MoonEP의 "$E/R$개 redundant expert면 균형 계획이 항상 존재" 증명은 순수 이론이 아니라 "학습이 절대 중단되지 않는다"는 운영 보증으로 환금된다. 상한이 tight하다는 점까지 증명한 것도 좋다.
  • Negative result와 방법론적 반성을 보고한다: (i) top-k distillation이 이점 없었다는 보고, (ii) cosine vs WSD 비교가 하이퍼파라미터 정렬 때문에 불공정할 수 있다는 지적, (iii) 사이버 평가를 스스로 "능력의 하한"으로 규정. 기술 보고서에서 흔치 않은 정직성이다.
  • SigLIP 초기화 불필요라는 반례: "MoonViT-V2가 SigLIP 초기화 베이스라인과 동등하다"는 결과는 멀티모달 커뮤니티의 기본 관행에 대한 직접적 반론이며, 후속 연구에 실질적 영향을 줄 만하다.
  • 비용 효율을 1급 지표로 다룬다: 점수만이 아니라 태스크당 비용, reasoning effort별 곡선까지 제시. BrowseComp $2.03/task 같은 구체적 수치는 실무 채택 판단에 직접 쓰인다.
  • 가중치 전체 공개: 2.8T 모델의 완전 공개는 그 자체로 생태계 기여다.

한계와 의문점

  • Ablation이 거의 없다. 이것이 가장 큰 약점이다. "2.5× scaling efficiency 개선"은 KDA + AttnRes + Stable LatentMoE + 데이터 레시피 + 학습 레시피의 합계로만 보고된다. 각 구성요소가 얼마씩 기여했는지 분해가 없어, 후속 연구자가 무엇을 취사선택해야 할지 알 수 없다. Fig. 6(비전 tower gradient norm)과 "RMSNorm이 validation loss를 일관되게 개선"이라는 정성적 언급 정도가 전부다.
  • 표준편차·seed 반복이 보고되지 않는다. 비전 벤치마크는 3회(ZeroBench 5회) 평균이라고 명시하지만 분산은 제시되지 않는다. 코딩·agentic 벤치마크는 반복 횟수조차 대부분 불명(PostTrainBench의 3회 평균이 예외). ProgramBench 77.8 vs 77.6, CorpFin v2 71.6 vs 71.8, OSWorld-Verified 84.8 vs 85.0 같은 0.2점 차 순위가 통계적으로 의미 있는지 판단할 수 없다.
  • 비교 공정성 문제가 양방향으로 존재한다. (a) 저자에게 불리한 방향: Fable 5는 fallback 포함, GPT-5.6 Sol은 cyberguard 포함이며 in-house 벤치마크에서 상당한 거부율(80개 중 10~14건)을 보인다. (b) 저자에게 유리한 방향: in-house 벤치마크 16개 중 일부(KAET, Swarm Bench, Online Experience, Deep Research Bench 등)는 K3만 Kimi 자체 harness(Kimi Code, Kimi Agent)에서 평가하고 경쟁 모델은 Claude Code·Codex에서 평가한다. 다만 24/7 ClawBench(OpenClaw), MIRA Bench, CLIF·Agentic Vision(Kimi Code), Agent Behavior·Chat All-in-One(Kimi Work)은 모든 모델이 동일 harness를 쓴다고 명시되어 있어, 비대칭은 전면적이라기보다 부분적이다. SWE-Marathon은 공식 릴리스 전 H20 보정 브랜치 기반이고, PostTrainBench는 공식 H100 대신 H20에서 돌렸다. 이런 조정들이 결과를 어느 방향으로 얼마나 움직이는지에 대한 민감도 분석이 없다.
  • 학습 비용이 공개되지 않는다. GPU-시간, 총 학습 토큰 수, 데이터셋 규모(도메인별 토큰 수), 클러스터 구성 중 어느 것도 보고되지 않는다. "scaling efficiency 2.5× 개선"이라는 핵심 주장이 어떤 절대 비용에서 나온 것인지 알 수 없어, 재현은 물론 다른 연구와의 비교도 어렵다. RL도 "수백 GPU 이내"라는 언급뿐 총량은 없다.
  • Figure 7(scaling law)의 축 값이 없다. FLOPs 축과 validation loss 축이 모두 레이블 없이 그려져 "2.5×"가 어느 구간에서 측정된 것인지, 외삽인지 보간인지 판별할 수 없다.
  • "2.5× scaling efficiency"의 정의가 모호하다. 동일 loss 도달에 필요한 FLOPs 비율인지, 동일 FLOPs에서의 loss 개선을 환산한 것인지, held-out OOD validation set의 구성은 무엇인지 명시되지 않는다.
  • 사이버 능력 공개의 위험 논의가 얇다. 16개 미공개 취약점 발견, 익스플로잇 36개 중 14개 해결 — 이는 상당한 능력이다. 저자들은 프론티어 모델들이 거부해서 비교가 불가능했다고 하고 독립 평가로 보완하지만, 가중치를 완전 공개하는 모델에서 이 능력이 갖는 함의(안전장치 제거 후 남용 가능성)에 대한 논의는 "능력의 하한으로 간주한다" 정도에 그친다. 릴리스 결정의 위험–편익 분석이 없다.
  • 케이스 스터디의 검증 가능성. "2시간 vs 1~2주", "8,700 tokens/s" 같은 수치는 인상적이지만 대부분 단일 실행이고 통제군이 없다. MiniTriton과 nano-kpu는 코드가 공개되어 검증 가능하지만, I–Love–Q 재현이나 AI ASIC 웹사이트 같은 사례는 결과물이 공개되지 않아 주장을 확인할 수 없다.
  • MOPD의 손실 측면이 보고되지 않는다. 9개 전문가를 하나로 합치면 어느 정도 성능 손실이 있을 텐데, 통합 모델 vs 개별 전문가의 비교가 없다. "compositional generalization"을 주장하려면 이 비교가 필수다.
  • 인프라 최적화의 정량적 효과가 대부분 정성적이다. FlashKDA가 "Triton 참조를 크게 앞선다", ViT 오버헤드가 "거의 사라진다", 하드웨어 활용도(utilization)가 "유지된다" — 구체적 숫자는 AgentENV(133 ms / 49 ms / 6.5× / 51.2M 샌드박스)를 제외하면 드물다.

Key Takeaways — 이 논문에서 가져갈 것

  1. "세 방향 정보 흐름" 프레임은 재사용 가능한 설계 렌즈다. 시퀀스(어텐션)·깊이(residual)·너비(MoE)를 따로 최적화되는 축이 아니라 동일한 정보 흐름 문제의 세 단면으로 보는 관점. 특히 AttnRes가 "Transformer가 시퀀스에서 한 일을 깊이에서 반복한다"는 유비로 도출된 것은, 다른 축(예: 전문가 간, 모달리티 간)에도 같은 유비를 적용해볼 여지를 남긴다.
  2. 수치 안정성 제약이 커널 최적화로 환금되는 패턴. lower-bounded decay($g_{\min}=-5$)는 표현력을 아주 조금 희생해 BF16 범위를 보장하고, 그 결과 대각 타일 전용 코드 경로 자체를 삭제했다. "제약을 걸면 느려진다"는 직관과 반대다. 저정밀도 학습을 설계할 때 범위 보장이 곧 코드 단순화가 되는 지점을 찾아볼 것.
  3. Quantile Balancing은 auxiliary-loss-free MoE를 쓰는 누구에게나 즉시 적용 가능하다. 하이퍼파라미터 $\gamma$가 사라지고, 히스토그램 all-reduce라는 저렴한 구현이 있으며, 전문가 수가 $10^3$급으로 커질수록 이득이 커진다. 부록 C의 LP 쌍대 유도까지 있어 이론적 근거도 명확하다.
  4. SigLIP 초기화는 필수가 아니다. from-scratch ViT를 next-token prediction으로 공동 학습하면 gradient norm이 더 안정적이고 성능은 동등하다. 멀티모달 모델을 새로 설계한다면 이 선택지를 기본으로 재검토할 가치가 있다 — 파이프라인이 단순해지고 대조 사전학습 단계가 통째로 사라진다.
  5. "9개 전문가 → 1개 모델" 패턴은 multi-effort 모델 설계의 실용적 레시피다. 도메인 × effort 격자로 RL을 나눠 각각 최적화하고 MOPD로 합치는 방식은, 단일 모델에서 모든 조합을 동시에 RL 하는 것보다 훨씬 다루기 쉽다. 다만 통합 시 손실은 논문에 보고되지 않았으니 직접 측정할 것.
  6. Agentic RL 인프라의 병목은 모델이 아니라 환경 상태 관리다. AgentENV의 pause/resume(샌드박스 생애의 98%가 모델 추론 대기), fork(부작용 없는 reward judging), external KV cache pool은 모두 "모델을 어떻게 학습시킬까"가 아니라 "긴 궤적의 상태를 어떻게 살려둘까"에 대한 답이다. long-horizon RL을 시도한다면 이쪽에 먼저 예산을 배정할 것.
  7. 비판적으로: ablation 없는 "2.5×"는 재현·차용의 지도가 되지 못한다. 이 논문의 개별 기법(QB, SiTU-GLU, lower-bounded decay, KCP)은 각각 독립적으로 매력적이지만, 어느 것이 얼마나 기여했는지 모른 채로는 자기 시스템에 무엇을 먼저 넣을지 판단할 수 없다. 채택 시에는 자체 ablation을 필수로 계획할 것.
