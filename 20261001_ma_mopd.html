목차

TL;DR

  • 문제: 최신 LLM (Large Language Model) post-training은 도메인마다 다른 reinforcement learning (RL) 파이프라인 — 수학은 검증 가능한 정답 RL, 소프트웨어 엔지니어링(SWE)은 sandbox agent RL, 지시 따르기(IF)는 rubric RL — 으로 능력을 끌어올린다. 그런데 이 능력들을 한 모델에 모으는 기존 방법들은 각자 결함이 있다. Mix-RL은 도메인 간 간섭(see-saw), Cascade RL은 앞 단계 능력의 감쇠, Off-Policy Finetune(teacher rollout으로 supervised fine-tuning (SFT))은 exposure bias, Param-Merge는 불안정성을 겪는다.
  • 해결: MOPD (Multi-teacher On-Policy Distillation). ① 공통 SFT 모델을 만들고, ② 거기서 도메인마다 독립적으로 RL을 해 전문 teacher를 얻은 뒤, ③ student(같은 SFT 모델)가 스스로 답을 생성하면 프롬프트 도메인에 맞는 teacher가 그 답을 prefill해 토큰별 확률을 주고, student는 per-token reverse Kullback–Leibler (KL) divergence로 teacher를 따라간다.
  • 왜 작동하는가: student가 자기 rollout 위에서 배우므로 학습–추론 분포가 같다(exposure bias 없음). teacher가 토큰마다 분포를 주므로 응답당 보상 하나인 RL보다 신호가 훨씬 촘촘하다. 통합이 가중치 평균이 아니라 프롬프트별 라우팅이라 안정적이고, teacher가 모두 같은 SFT에서 출발(same-origin)해 student와 분포가 가깝다(초기 KL 0.04).
  • 비유: 과목마다 전담 선생님을 따로 키운 뒤, 학생이 숙제를 직접 하면 과목에 맞는 선생님이 한 글자씩 빨간 펜으로 첨삭한다. 선생님들이 학생과 같은 학교 출신이라 말투가 비슷해서 첨삭이 잘 통한다.

핵심 기여 (Key Contributions)

  1. MOPD 패러다임: 여러 도메인 RL teacher의 능력을 student 자신의 rollout 위에서 토큰 단위로 증류하는 post-training 방식. 통합을 가중치 공간이나 정적 데이터 공간이 아니라 정책 공간에서 한다 (§3).
  2. 두 가지 구현과 인프라: 기존 PPO/GRPO 프레임워크에 advantage만 바꿔 끼우는 policy-gradient 형태, teacher top-k 토큰 위에서 편향을 보정한 top-k 형태, 그리고 teacher를 보상 서비스처럼 비동기로 돌려 시간 오버헤드를 거의 없애는 배치 (§3.2–§3.3).
  3. 통제 비교와 대규모 배포: Qwen3-30B-A3B에서 Mix-RL·Cascade RL·Off-Policy Finetune·Param-Merge를 모두 넘는 정규화 점수 0.937(차선 0.882)과 도메인별 91–95% 회복, 309B MiMo-V2-Flash의 실제 post-training 배포 (§4.2–§4.3).
  4. 분석: 두 손실 형태가 비슷하다는 것, same-origin teacher가 안정성의 조건이라는 것(외부 235B teacher로 바꾸면 붕괴), 여러 라운드 반복으로 더 올라간다는 것(0.937 → 0.986) (§4.4).

배경 (Background) — 능력 통합 문제와 네 가지 기존 해법 (§1, §2)

도메인별 RL과 '하나의 모델' 문제

RL은 LLM 능력을 끌어올리는 중요한 방법이 되었고, 도메인마다 다른 RL 파이프라인을 쓴다. 수학 추론은 검증 가능한 정답 RL(DeepSeek-R1, DeepSeekMath), 소프트웨어 엔지니어링은 실행 가능한 sandbox의 agent식 RL(R2E-Gym, SWE-RL), 지시 따르기와 창작은 rubric 기반 RL(InstructGPT), 검색 agent는 웹 환경 RL(Search-R1, WebGPT)이다. 각 파이프라인은 목표 도메인에서 확실히 능력을 올린다. 그러나 최종적으로 원하는 것은 이 모든 도메인에서 잘하는 하나의 모델이고, 이를 만드는 것은 여전히 열린 문제다.

reinforcement learning with verifiable rewards (RLVR)에서는 PPO (Proximal Policy Optimization)식과 GRPO (Group Relative Policy Optimization)식 결과 보상 최적화가 표준이다. 각 파이프라인이 강한 도메인 전문가를 만들어 내므로, 그것들을 한 모델로 모으는 multi-domain / multi-task 문제가 자연스럽게 생긴다.

기존 네 가지 해법 (Table 1)

  1. Mix-RL (Qwen3): 모든 도메인의 프롬프트를 한 데이터셋으로 모아 공동 RL을 한다(각 표본은 자기 도메인의 보상과 advantage를 그대로 쓴다). 도메인 간 학습 신호가 서로 간섭해 see-saw 효과가 나고, 공동 모델이 도메인별 teacher보다 낮게 남는다.
  2. Cascade RL (Nemotron-Cascade): 도메인을 하나씩 순서대로 학습한다. 뒤 단계가 진행되면서 앞 단계 능력이 감쇠할 수 있고, 전체 학습이 길어져 안정성 위험이 커진다.
  3. Off-Policy Finetune (DeepSeek-V3.2): 도메인별 RL teacher를 학습하고 그 rollout으로 student를 SFT한다. 이 off-policy 지도는 고전적인 exposure bias를 낳는다 — student는 teacher가 쓴 앞부분만 보고 배우지만 추론 때는 자기가 쓴 앞부분을 이어 가야 한다.
  4. Param-Merge (task arithmetic, model soups): teacher 가중치를 평균하거나 가중치 공간에서 task vector를 조합한다. 합친 모델은 보통 불안정하고 모든 teacher의 능력을 다 맞추지 못한다. TIES-Merging, DARE, AdaMerging 같은 후속 연구가 파라미터 충돌을 줄이려 한다.

요컨대 이 방법들은 학습 효율, 도달 가능한 최고 성능, 학습 안정성을 서로 맞바꾸며, 만족스러운 중간 지점이 없다.

비유로 말하면: 수학·영어·코딩 실력을 한 학생에게 모두 키워 주는 네 가지 방법이다. 한 반에서 다 같이 가르치면(Mix-RL) 진도끼리 부딪히고, 한 과목씩 순서대로 가르치면(Cascade) 앞에서 배운 것을 잊는다. 전담 선생님의 풀이를 베끼게 하면(Off-Policy) 자기가 실제로 틀리는 지점을 못 고치고, 선생님들의 '두뇌를 평균 내 이식'하면(Merge) 결과가 들쭉날쭉하다.

On-policy distillation

고전적 증류(Hinton et al., 2015; Kim & Rush, 2016)는 teacher 출력으로 이뤄진 고정 corpus에서 forward KL을 최소화하므로 off-policy이고, student의 추론 궤적이 학습 분포에서 벗어날 수 있다. On-policy distillation은 student 자신의 rollout에서 teacher를 채점 신호로 써서 이를 해결한다 — MiniLLM(reverse KL), teacher-as-reward 변형(GKD, SimPO). 그러나 이들은 teacher 하나, 도메인 하나로 제한되어 있었다. MOPD는 "student가 샘플하고 teacher가 채점한다"는 틀을 유지하면서 이를 프롬프트별로 라우팅되는 여러 도메인 teacher로 확장하고, 실제 production 규모 base 모델에서 검증한다.

직관적으로 말하면: on-policy distillation은 RL과 증류의 장점을 합친다. RL처럼 student가 자기 답으로 배우고(분포 일치), 증류처럼 teacher가 토큰마다 정답 분포를 준다(신호 밀도). MOPD는 여기서 "teacher를 과목마다 따로 두자"는 한 걸음을 더한다.

§3 방법

3.1 파이프라인 — 세 단계

  • Stage 1: 일반 SFT. 관심 있는 모든 기본 능력을 덮는 넓은 corpus로 base 모델을 fine-tuning해 SFT 체크포인트를 만든다. 이것이 Stage 2 도메인 RL의 공통 초기화이자 Stage 3 student의 초기화다.
  • Stage 2: 도메인 특화 RL. 도메인 $d$마다 Stage-1 체크포인트에서 전문가 $\pi_{\phi_d}$를 학습한다. 각 전문가는 자기 도메인에 가장 자연스러운 RL 레시피(수학은 정답 검증 RL, SWE는 실행 sandbox agent RL 등)를 쓴다. 도메인별 학습은 서로 독립이라 완전히 병렬로 실행할 수 있다.
  • Stage 3: MOPD. student를 Stage-1 SFT에서 초기화하고, Stage-2 전문가 $\{\pi_{\phi_d}\}$를 고정해 teacher 그룹으로 둔다. 다중 도메인 데이터셋으로 student를 학습하며, 매 최적화 스텝은 (1) 프롬프트 배치를 샘플링하고, (2) student가 프롬프트마다 궤적을 생성하며 토큰별 확률분포를 기록하고, (3) 각 궤적을 과제 도메인에 맞는 teacher로 보내 teacher가 그 궤적을 prefill해 토큰별 확률분포를 얻고, (4) 궤적을 따라 student와 해당 teacher 사이 per-token reverse KL을 최소화해 student를 갱신한다. 끝나면 모든 도메인 능력을 가진 단일 모델이 나온다.

구조적 이점 (원문 정리):

  • Exposure bias 없음: student가 자기 rollout으로 학습하므로 학습과 추론의 상태 분포가 구조적으로 같다.
  • 촘촘한 토큰별 지도: teacher가 궤적의 모든 토큰에서 확률분포를 준다. 표준 RL의 궤적 단위 보상보다 훨씬 촘촘해 분산이 낮고 표본 효율이 높다.
  • 정책 공간의 안정적 통합: teacher 파라미터를 평균하거나 task arithmetic을 하지 않고 프롬프트를 맞는 teacher로 라우팅해 능력을 합친다. 가중치 공간 융합 특유의 불안정을 피한다.
  • 모듈형·병렬 teacher: teacher RL은 완전히 병렬로 돌고 각자 하이퍼파라미터를 쓸 수 있다. 한 teacher 학습의 실패나 수정이 다른 teacher에 영향을 주지 않는다.
  • Same-origin teacher 안정성: 각 teacher가 student를 초기화한 바로 그 SFT 체크포인트에서 도메인 RL로 만들어지므로, teacher와 student의 정책 분포가 가깝다. 초기 KL이 낮고 증류 내내 최적화가 매끄럽다 (§4.4.2).

3.2 알고리즘 — per-token reverse KL

Stage 3에서 student는 배정된 teacher에 대한 per-token reverse KL로 최적화된다.

$$\mathcal{L}_{\text{rev-KL}} = \mathbb{E}_{x,\, y \sim \pi_\theta}\left[\frac{1}{|y|}\sum_t \sum_v \pi_\theta(v) \log \frac{\pi_\theta(v)}{\pi_{\phi_d}(v)}\right] \tag{1}$$

$\pi_{\phi_d}$는 프롬프트 $x$에 배정된 teacher이고, $\pi_\theta(v)$, $\pi_{\phi_d}(v)$는 각각 $\pi_\theta(v \mid x, y_{<t})$, $\pi_{\phi_d}(v \mid x, y_{<t})$의 줄임이다.

직관적으로 말하면: reverse KL $\mathrm{KL}(\pi_\theta \| \pi_\phi)$는 "student가 확률을 준 곳에서 teacher가 동의하지 않으면 벌을 준다". 그래서 student는 teacher가 낮게 보는 토큰을 피하게 되고(mode-seeking), teacher가 여러 답을 허용하더라도 그중 하나를 확실히 고르는 쪽으로 간다. forward KL처럼 "teacher의 모든 가능성을 다 덮으라"고 요구하지 않는다.

3.2.1 Policy-gradient 구현

MiniLLM을 따라 MOPD 증류를 RL 과정으로 본다. (1)의 기울기는

$$\nabla_\theta \mathcal{L} = -\mathbb{E}_{x,y}\left[\frac{1}{|y|}\sum_t \log \frac{\pi_{\phi_d}(y_t)}{\pi_\theta(y_t)}\, \nabla_\theta \log \pi_\theta(y_t)\right] \tag{2}$$

로, 정확히 policy-gradient 형태이며 teacher–student 로그 차이가 토큰별 advantage 역할을 한다.

$$\hat{A}_{\text{MOPD},t} = \mathrm{sg}\left[\log \pi_{\phi_d}(y_t) - \log \pi_\theta(y_t)\right] \tag{3}$$

학습 안정성을 위해 advantage를 양쪽으로 clip한다: $\hat{A}^{\text{clip}}_{\text{MOPD},t} = \mathrm{clip}(\hat{A}_{\text{MOPD},t}, -A_{\max}, +A_{\max})$ (기본 $A_{\max} = 5$). 최종 손실은

$$\mathcal{L}^{\text{PG}}_{\text{MOPD}}(\theta) = -\mathbb{E}_{x,y}\left[\frac{1}{|y|}\sum_t \hat{A}^{\text{clip}}_{\text{MOPD},t}\, \log \pi_\theta(y_t)\right] \tag{4}$$

이다. 이 형태는 기존 PPO/GRPO 학습 프레임워크에 바로 들어가며, 바뀌는 것은 advantage 계산뿐이다.

직관적으로 말하면: GRPO가 "응답 전체에 점수 하나"를 advantage로 쓰는 자리에, MOPD는 "토큰마다 teacher가 student보다 이 토큰을 얼마나 더(덜) 좋아하나"를 넣는다. 양수면 그 토큰 확률을 올리고, 음수면 내린다. clip은 teacher가 극단적으로 싫어하는 토큰 하나가 기울기를 폭발시키지 않게 막는 안전장치다.
비유로 말하면: 학생이 쓴 글의 단어마다 선생님이 "+2점(이 단어 좋다)", "−1점(나라면 안 쓴다)"을 붙여 준다. 학생은 높은 점수를 받은 단어를 더 자주 쓰도록 배운다. 다만 한 단어에 ±5점 넘게는 주지 않는다.

3.2.2 Top-k 증류 구현

왜 문제인가: policy-gradient 형태는 rollout 위치마다 샘플된 토큰 하나만 쓴다. 해법: 분산이 더 낮은 대안으로 teacher의 top-$k$ 토큰 위에서 증류한다(Peng et al., 2024). 구현이 간단하면서 teacher 분포를 더 많이 쓴다. 위치 $t$에서 teacher의 top-$k$ 토큰 집합을 $\mathcal{T}^d_t = \mathrm{TopK}_k(\pi_{\phi_d}(\cdot \mid x, y_{<t}))$라 하면

$$\mathcal{L}^{\text{TopK}}_{\text{MOPD}}(\theta) = \mathbb{E}_{x,y}\left[\frac{1}{|y|}\sum_t \sum_{v \in \mathcal{T}^d_t} \left(\pi_\theta(v) \log \frac{\pi_\theta(v)}{\pi_{\phi_d}(v)} - \pi_\theta(v) + \pi_{\phi_d}(v)\right)\right] \tag{5}$$

표준 reverse KL에 $\pi_{\phi_d}(v) - \pi_\theta(v)$ 항을 더했다. 이 항이 top-$k$ 절단이 만드는 편향을 바로잡아 손실이 top-$k$ 토큰에서 $\pi_\theta = \pi_{\phi_d}$일 때 최소가 되게 한다. 순진하게 잘라 낸 top-$k$ reverse KL은 이 성질이 없다. 정확성 외에 인프라 부담도 줄인다 — teacher prefill 결과를 가벼운 보상 신호처럼 보낼 수 있을 만큼 작게 유지한다. 전체 어휘 증류는 토큰마다 어휘 전체 분포를 보내야 한다.

직관적으로 말하면: 잘라 낸 집합 위에서는 확률 합이 1이라는 제약이 없다. 그래서 $q \log(q/p)$만 최소화하면 student가 모든 확률을 teacher의 $1/e$ 수준(약 37%)으로 깎아 내리는 이상한 해가 나온다. $-q + p$는 이를 상쇄하는 "확률 질량 보존" 항으로, 미분하면 정확히 $\log(q/p) = 0$, 즉 $q = p$가 된다 (아래 그림은 요약자 유도).

3.3 인프라 — teacher를 보상 서비스처럼

왜 문제인가: Stage 3의 추가 연산은 teacher prefill이다 — 모든 student rollout을 배정된 teacher에 통과시켜 토큰별 로그확률(또는 top-$k$ logit)을 얻어야 한다. 이를 RL 학습 루프 안에 넣으면 인프라가 복잡해지고 직렬 지연이 늘어난다.

해법: teacher prefill 계산이 RL의 보상 계산과 같은 성격이라는 점에 착안해, 각 도메인 teacher를 RL trainer 바깥의 독립 prefill 서비스로 배치한다. student sampler는 계속 rollout을 생성하고, 한 시퀀스의 rollout이 끝나는 즉시 trainer가 해당 teacher 서비스에 비동기 prefill 요청을 보낸다. teacher 서비스는 토큰별 로그확률을 계산해 돌려준다. teacher prefill과 다른 시퀀스의 샘플링이 시간상 겹치므로 MOPD의 wall-clock 비용은 샘플링이 지배하고 teacher 비용은 student 샘플링 뒤에 거의 숨는다. 저자들의 배포에서 ##teacher는 측정 가능한 wall-clock 오버헤드를 거의 더하지 않았다.##

비유로 말하면: 시험지를 다 걷은 뒤 한꺼번에 채점하면 채점이 끝날 때까지 다음 수업을 못 한다. 대신 먼저 낸 학생 답안부터 바로 채점실(teacher 서비스)로 보내면, 마지막 학생이 답안을 낼 즈음엔 채점도 거의 끝나 있다.

평가 지표 — 정규화 점수: 세 도메인의 절대 여유(headroom)가 크게 달라 원점수 평균은 여유가 큰 도메인을 과대 반영한다. 그래서 도메인 $d$마다 Stage-1 SFT student 정확도 $s^s_d$, Stage-2 전문가 정확도 $s^t_d$로

$$\tilde{s}_d = \frac{s_d - s^s_d}{s^t_d - s^s_d}, \qquad \bar{\tilde{s}} = \frac{1}{|\mathcal{D}|}\sum_{d \in \mathcal{D}} \tilde{s}_d$$

를 쓴다. student가 0, 도메인 전문가 teacher가 1이며, 1 초과는 전문가 이상, 0 미만은 Stage-1 student보다 퇴보를 뜻한다. Table 2 값으로 역산하면 도메인 점수 $s_d$는 그 도메인 벤치마크들의 평균이다(요약자 확인, 아래 히트맵).

비유로 말하면: 같은 학교 바로 윗기수 선배(same-origin RL teacher)의 첨삭은 학생이 알아듣는다. 다른 학교의 대가(235B)는 실력은 더 좋지만 풀이 방식 자체가 달라, 학생 답안의 거의 모든 단어에 "나라면 이렇게 안 쓴다"는 빨간 줄을 긋는다. 벌점만 계속 받은 학생은 점점 소심해져 한 가지 답만 고집하고(entropy 수축), 결국 수학을 망친다.
직관적으로 말하면: reverse KL의 advantage $\log \pi_\phi - \log \pi_\theta$는 student가 샘플한 토큰에서만 계산된다. student의 토큰이 teacher가 거의 안 쓰는 토큰이면 advantage가 크게 음수가 되고, 이런 토큰이 대부분이면 기울기가 "확률을 내려라"로만 채워진다. 무엇을 올려야 하는지에 대한 신호는 거의 없다 — 이것이 "주로 벌점 신호"의 뜻이다.

(ii) Iter-2 teacher의 지도로 Iter-2 student는 Math와 IF에서 더 좋아져 정규화 점수가 0.937 → 0.986(+0.049)으로 오른다. MOPD 파이프라인이 더 강한 teacher로부터 계속 능력을 흡수할 수 있다는 뜻이다. (SWE는 2라운드에서 teacher를 재학습하거나 증류하지 않았으므로, SWE 점수는 Math/IF 증류의 간접 효과만 반영한다: 50.40 → 50.20.)

척도 확인: 원문은 명시하지 않지만, Stage-1 student와 1라운드 RL teacher를 0과 1로 둔 같은 척도로 다시 계산하면 Iter-2 teacher 1.030(Math 1.073, IF 1.068, SWE 0.948), Iter-2 MOPD 0.986(Math 0.995, IF 1.028, SWE 0.935)이 그대로 나온다(요약자 확인). 즉 1.030은 "1라운드 teacher를 넘었다"는 뜻이다.

비유로 말하면: 1년 차에 선생님들께 배운 학생이 2년 차에는 직접 각 과목 심화반(RL)을 거쳐 더 강한 선생님이 되고, 그 선생님들이 다시 원래 학생을 가르친다. 대를 이어 실력이 쌓인다 — 다만 이번에는 SWE 심화반을 열지 않아 SWE는 그대로다.

§5 논의 — 워크플로 관점

MOPD는 실험상의 이득 외에, 다중 도메인 post-training에 내재한 직렬 의존성을 구조적으로 끊는다 — 능력 생산(Stage 2 도메인 RL)과 능력 통합(Stage 3 증류)을 분리한다. 워크플로상 세 가지 결과가 따른다.

  • 병렬 개발: Stage-2 teacher들은 서로 독립이다. 각 도메인 팀이 자기 보상·sandbox·데이터 파이프라인을 정해진 순서 없이 동시에 반복할 수 있고, 계산 자원이 충분하면 팀 전체의 개발 처리량이 그대로 오른다.
  • 레시피 수준 분리: 각 도메인은 다른 도메인과의 충돌이나 자기 최적화 선택이 남을 방해할 걱정 없이 RL 레시피(알고리즘, rollout 절차, 보상 함수, 하이퍼파라미터 등)를 자유롭게 고른다.
  • 위험 격리: RL 학습은 능력을 올리거나 안정성 문제를 해결하려고 알고리즘·하이퍼파라미터를 반복 조정해야 하고, 조정마다 학습을 재시작해야 한다. 공동 다중 도메인 RL에서는 재시작이 전체 run을 처음으로 되돌리지만, MOPD의 병렬 teacher 개발에서는 재시작이 영향받은 한 도메인에 국한되고 다른 teacher는 방해받지 않는다.
비유로 말하면: 공동 RL은 다섯 명이 한 줄로 묶여 달리는 2인3각 경기 같다 — 한 명이 넘어지면 모두 출발선으로 돌아간다. MOPD는 각자 따로 달리다가 결승선에서 바통만 모으는 방식이라, 한 명이 넘어져도 그 사람만 다시 뛰면 된다.

§6 결론

MOPD는 다중 도메인 능력 통합을 정책 공간에서 수행하는 post-training 패러다임이다: student가 자기 rollout에서 샘플링하고, 각 프롬프트가 해당 고정 도메인 teacher로 라우팅되며, teacher가 모든 위치에서 촘촘한 토큰 단위 로그확률 신호를 준다. Qwen3-30B-A3B에서 MOPD는 Mix-RL, Cascade RL, Off-Policy Finetune, Param-Merge 중 가장 좋은 총합 통합을 달성하고, 차선보다 정규화 점수 5.5점 앞서며, 모든 도메인에서 student–teacher 여유의 91–95%를 메운다. MiMo-V2-Flash에서는 같은 레시피가 대부분의 벤치마크에서 해당 teacher와 같거나 넘는다. 분석은 두 손실 형태가 비슷하고, same-origin teacher가 안정적 최적화에 결정적이며, 파이프라인이 여러 라운드의 student–teacher 진화를 지원함을 보인다. §5의 구조적 분리와 합쳐, MOPD는 병렬 개발과 빠른 통합을 지원하는 대규모 LLM post-training의 공학적 경로를 제시한다고 저자들은 결론짓는다. 별도의 한계(Limitations) 절은 없다.

이 저장소의 관련 요약과의 연결

MOPD는 이 저장소에 정리된 여러 on-policy 증류 논문과 같은 뼈대("student가 샘플하고 teacher가 채점")를 공유한다. 차이는 teacher가 누구이고, 무엇을 보며, student는 어디서 출발하는가에 있다.

비판적 분석 (Critical Analysis)

강점

  • 간단하고 바로 쓸 수 있는 레시피: GRPO 프레임워크에서 advantage 계산만 바꾸면 되고(Eq. 3–4), teacher를 보상 서비스처럼 비동기로 붙여 시간 비용이 거의 없다. 309B 모델의 실제 post-training에 배포했다는 점이 실용성을 뒷받침한다.
  • 통제된 비교: 다섯 가지 통합 방법이 같은 SFT 출발점과 같은 Stage-2 teacher를 공유한다. 정규화 점수의 정의도 명확하고, 그 값을 원 표에서 정확히 재현할 수 있다.
  • "균일성"이라는 유용한 관점: 총점뿐 아니라 도메인 간 범위(0.044 vs 0.36–0.41)를 보고해, 다른 방법들이 "평균은 비슷하지만 특정 도메인을 버리는" 실패 양상을 드러낸다.
  • Same-origin 실험의 설득력: "더 강한 teacher가 더 좋은 teacher인가?"에 대해 KL·entropy 궤적까지 보여 주는 대조 실험으로 '아니다'를 보인다. IM-MOPD 등 후속 연구가 이 관찰 위에 서 있다.
  • top-k 보정항: 절단 reverse KL의 편향을 짚고 한 줄 보정으로 고친 것은 깔끔한 기술적 기여다.

한계와 의문점

  • 통계적 불확실성: 모든 결과가 단일 run으로 보이고 표준편차가 없다. AIME는 avg@32지만 IFBench·IFEval·SWE-bench는 1회 평가이며, SWE-bench Verified(500과제)의 1–2점 차이는 노이즈일 수 있다. 0.055 차이(MOPD vs Mix-RL)의 유의성은 판단할 수 없다.
  • 계산량 비교 부재: MOPD는 배치 2048·N=1, Mix-RL은 256·N=8이고 MOPD는 teacher prefill이 추가된다. "표본 효율"은 도메인별 학습 표본 수 기준이며, GPU 시간이나 FLOPs 기준 비교가 없다. MOPD의 learning rate도 부록에 없다.
  • 기준선 구현 세부: Param-Merge(task arithmetic)의 계수, Off-Policy Finetune의 데이터 양·epoch이 보고되지 않는다. 특히 Param-Merge는 "레시피에 민감하다"고 결론짓지만 탐색한 계수 범위가 없다 — IM-MOPD가 보여 주듯 merge는 MOPD의 대체재가 아니라 보완재일 수도 있다.
  • teacher 상한 문제: MOPD는 정의상 teacher를 넘기 어렵고(정규화 0.937 < 1), 30B에서 MOPD가 teacher를 넘은 벤치마크는 AIME26 하나다. 2라운드 반복이 이를 우회하지만, 라운드마다 도메인 RL을 다시 해야 하는 비용이 든다.
  • same-origin의 경계: 외부 teacher 실험은 Math 한 도메인, 한 모델(235B)뿐이다. "teacher가 같은 SFT에서 나와야 한다"는 결론은 강하지만, 분포 차이가 어느 정도까지 허용되는지(예: 같은 계열의 더 큰 모델, SFT warm-up 후의 외부 teacher)는 보여 주지 않는다. 또 이 조건은 서로 다른 base·이력의 teacher를 합칠 수 없다는 제약이기도 하다.
  • MiMo 실험의 범위: 309B 결과에는 기준선 비교가 없고, teacher별 학습 설정·데이터도 공개되지 않는다. "산업 규모에서도 teacher 수준"까지만 지지한다.
  • 도메인 수와 충돌: 통제 실험은 세 도메인(Math, IF, SWE)뿐이다. 프롬프트가 여러 도메인에 걸치거나(예: 수학을 코드로 푸는 과제) 도메인 라벨이 애매할 때의 라우팅 규칙은 다루지 않는다.
  • 코드 공개: 코드나 학습 데이터 공개 언급이 없다.

Key Takeaways — 이 논문에서 가져갈 것

  1. 다중 도메인 통합은 '정책 공간'에서 하라: 도메인별 RL teacher를 따로 만든 뒤, student rollout 위에서 프롬프트별 teacher로 토큰 단위 reverse KL을 거는 것이 Mix-RL·Cascade·SFT·merge보다 높고 고르게 통합한다(0.937, 도메인 범위 0.044).
  2. 구현은 GRPO에서 advantage 한 줄 바꾸기: $\hat{A}_t = \mathrm{clip}(\log \pi_\phi(y_t) - \log \pi_\theta(y_t), \pm 5)$. teacher는 보상 서비스처럼 비동기로 붙이면 시간 비용이 거의 숨는다.
  3. teacher는 '가장 강한 모델'이 아니라 '같은 출발점의 모델': 외부 235B teacher는 초기 KL이 5배 높아 학습을 망쳤다(top-k는 AIME 0점대 붕괴). teacher를 student와 같은 SFT에서 만드는 것이 안정성의 조건이다.
  4. top-k 증류에는 질량 보정항이 필요하다: 잘라 낸 reverse KL만 쓰면 최적점이 $p/e$로 치우친다. $-\pi_\theta + \pi_\phi$를 더하면 정확히 $\pi_\theta = \pi_\phi$에서 최소가 된다.
  5. 조직 관점의 이득이 크다: 도메인 팀이 서로 기다리지 않고 각자 RL 레시피를 고치며, 한 팀의 재시작이 다른 팀을 되돌리지 않는다. 이 워크플로 분리가 frontier 모델 개발에서는 성능 차이만큼 중요할 수 있다.
  6. (비판적) 단일 run, 계산량 미정규화, merge 탐색 범위 미보고라는 조건을 감안해야 한다. 특히 merge는 MOPD의 경쟁자가 아니라 출발점으로 쓸 때 보완 효과가 있다는 후속 결과(IM-MOPD)와 함께 읽는 것이 좋다.
