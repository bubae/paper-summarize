목차

TL;DR

  • 문제: 대규모 언어 모델(large language model, LLM)의 도메인별 강화학습(reinforcement learning, RL)으로 만든 전문 teacher 여러 명을 한 student에 합치는 multi-teacher on-policy distillation (MOPD)은 지금까지 프롬프트 단위 도메인 라벨로 teacher 한 명을 골라 응답 전체를 맡기는 "domain-label hard routing"을 썼다. 그래서 ① 라벨이 없는 실제 혼합 데이터(supervised fine-tuning(SFT)·chat 데이터)에는 적용할 수 없고, ② 수학 문제 속 Python 검증·JSON 출력처럼 다른 teacher가 더 잘 아는 토큰의 보완 신호를 버린다.
  • 해결: MOPD-Router — 매 토큰마다 plug-in 지표(metric)로 전체 teacher 풀의 점수를 매겨 가중치 $w_{i,t}$를 정하고, teacher별 sampled-token advantage $A_t^{(i)}$를 가중합해 PPO식 clipped 목적함수에 넣는다. 라벨도, 별도로 학습하는 router 모델도 없다. 이 interface 위에서 Entropy(teacher 확신), Novelty(접근 가능한 teacher–student 차이), 그리고 제안 지표 ExpertAlign(teacher의 교정 방향이 그 teacher가 post-training으로 얻은 전문성 방향과 정렬되는가)을 비교한다.
  • 왜 작동하는가: teacher와 student가 다르다는 것만으로는 그 차이가 "전문성"인지 "잡음"인지 알 수 없다. ExpertAlign은 teacher와 공통 base 모델의 log-확률 차이 $\mathbf{e}_{i,t}$(teacher가 RL로 무엇을 배웠나)와 teacher와 student의 차이 $\mathbf{d}_{i,t}$(teacher가 지금 student를 어디로 밀려 하나)의 cosine이 양수인 teacher만 남기고 그 크기로 가중한다. 그래서 각 토큰에서 "자기 전공 쪽으로 교정하는" teacher만 발언권을 얻는다.
  • 비유: 학생이 쓴 풀이 한 장을 수학·코딩·글쓰기 선생님 셋이 동시에 첨삭한다. 기존 방식은 표지에 "수학"이라고 적혀 있으면 수학 선생님 혼자 전부 고친다. MOPD-Router는 줄마다 셋 모두에게 펜을 주되, "이 수정이 당신이 대학원에서 따로 배운 전공 지식에서 나온 것인가?"를 확인해 그런 선생님의 빨간 펜만 반영한다 — 수식 줄은 수학, 코드 줄은 코딩, 마지막 JSON 줄은 글쓰기 선생님이 주로 고친다.

핵심 기여 (Key Contributions)

  1. MOPD-Router 프레임워크: 프롬프트→teacher 고정 배정을 토큰 단위 가중합으로 바꾸는 plug-in interface (식 4). 도메인 라벨이나 별도 routing 모델 학습 없이 전체 teacher 풀에서 신호를 고르고 가중한다 (§3.2, Algorithm 1). 코드 공개.
  2. ExpertAlign 지표: base 대비 teacher 변위(expertise vector, 식 8)와 student 대비 teacher 변위(teaching vector, 식 9)의 양의 cosine으로 teacher를 선택·가중한다 (식 10–11). 라벨 없음/라벨 있음 × strong-to-weak/same-size의 4개 설정 모두에서 Overall 1위 (§4.2).
  3. 지표 비교 분석: teacher 확신(Entropy)은 math teacher를 70% 토큰에서 top-1로 고르는 고정 편향 때문에 Mean과 비슷하고 (§4.3.1), Novelty의 접근성 항은 student–teacher 지지(support)가 어긋나는 strong-to-weak에서만 이득이며 (§4.3.2), ExpertAlign의 선택(gate)과 가중(cosine)은 각각 독립적으로 기여한다 (§4.3.3).
  4. 교차 도메인 보완성의 증거: 라벨이 지정한 teacher만 남기거나 응답 단위 고정 가중으로 바꾸면 성능이 떨어지고, 세 도메인 모두 off-domain teacher가 routing 질량의 50% 이상을 받는다 (§4.3.4, Figure 2).

배경 (Background) — OPD, MOPD, 그리고 "누가 이 토큰을 가르쳐야 하나"

On-policy distillation (OPD)과 sampled-token advantage

OPD란: 지식 증류(knowledge distillation)에서 teacher가 만든 응답을 student가 따라 쓰게 하면(off-policy, SFT식) 학습 때 본 문맥과 추론 때 student가 실제로 만드는 문맥이 달라지는 exposure bias가 생긴다. OPD (Agarwal et al., 2024)는 student가 자기 현재 정책으로 응답 $y \sim \pi_\theta(\cdot\mid x)$를 생성하고, teacher가 그 응답을 prefill해 각 위치의 다음 토큰 분포를 제공하게 한다. 그러면 student는 "자기가 실제로 갈 길" 위에서 토큰마다 촘촘한(dense) 지도를 받는다. 응답 하나에 스칼라 보상 하나를 주는 RL보다 신호가 훨씬 조밀하다.

RL 형식으로 쓴 OPD: 최근 구현(Li et al., 2026 등)은 OPD를 PPO (Proximal Policy Optimization; Schulman et al., 2017) 틀에 그대로 넣는다. student가 샘플한 토큰 $y_t$에서 teacher log-확률과 student log-확률의 차를 그 토큰의 advantage로 쓰고(stop-gradient), 별도 critic 없이 clipped surrogate 목적함수를 최대화한다. 이 차이는 per-token reverse KL의 단일 샘플 추정치와 같은 꼴이다: teacher가 student보다 그 토큰을 더 좋아하면 양수(그 토큰 확률을 올려라), 덜 좋아하면 음수다. MOPD-Router는 바로 이 "sampled-token" 형식을 기반으로 한다 (식 1).

직관적으로 말하면: student가 쓴 글자 하나하나에 대해 teacher가 "나라면 이 글자를 더 자신 있게 썼을까?"를 log-비율로 답하고, 그 답이 RL의 보상 자리를 차지한다.

MOPD와 domain-label hard routing

MOPD (Ma et al., 2026; 이 저장소의 요약 20261001_ma_mopd.html)는 최신 LLM post-training의 사실상 표준이 된 3단계 레시피다: ① 공통 base(또는 SFT) 모델에서 출발해, ② 도메인마다 따로 RL을 돌려 math·code·instruction following (IF) 같은 전문 teacher를 얻고, ③ 프롬프트의 도메인 라벨 $d(x)$에 맞는 teacher 하나가 student rollout 전체를 OPD로 지도한다. 원문은 MiMo-V2-Flash, GLM-5, DeepSeek-V4, Kimi K3(이 저장소 요약 20260728_kimiteam_kimik3.html), Nemotron-Cascade 2가 이 방식을 채택했다고 정리한다.

MOPD의 후속 연구들은 대부분 라우팅은 그대로 두고 다른 축을 고친다. Open-MOPD (Gao et al., 2026; 이 저장소 요약 20261102_gao_open-mopd.html)는 정답 라벨로 완벽하게 라우팅해도 남는 통합 격차를 도메인 간 최적화 예산(토큰 몫·보상 크기·staleness)의 불균형으로 진단하고 예산을 재분배한다 — 이 논문에서는 baseline으로 쓰인다. D³-MOPD (Sun et al., 2026)는 도메인 스케줄링을 적응적으로 바꾼다. 이 저장소의 IM-MOPD(20260930_kim_im-mopd.html, 원문 미인용, 이 저장소의 관련 요약)는 student 초기화를 teacher task vector의 반복 merge로 바꾸고, Latent-MOPD(20261102_fang_latent-mopd.html, 원문 미인용, 이 저장소의 관련 요약)는 hidden state 수준의 지도를 더한다. 네 연구 모두 "프롬프트 하나 = teacher 하나"를 전제한다.

이 전제의 한계: Open-MOPD 요약의 §3.2가 보여 주듯 teacher들은 대부분의 토큰에서 서로 크게 다르지 않다(평균 불일치 0.126 nat). 그렇다면 남은 차이가 큰 소수 토큰 — 예컨대 수학 풀이 중 코드 블록 — 에서 "어느 teacher의 의견을 들을지"를 토큰 단위로 정하는 것이 자연스러운 다음 질문이다. MOPD-Router는 바로 이 질문을 연다.

토큰 단위 teacher 선택의 선행 아이디어

  • 확신 기반 중재(confidence arbitration): H-OPD (Yin et al., 2026)는 멀티모달 추론에서 vision-language teacher와 text-only teacher 중 예측 엔트로피가 낮은(더 확신하는) 쪽을 토큰마다 고른다. 이 논문의 Entropy 지표가 이 계열의 대표다.
  • 학습 가능성(teachability): Li et al. (2026), Wang et al. (2026b)은 유효한 OPD 업데이트가 teacher와 student가 함께 높은 확률을 두는 후보에 집중되며, student의 국소 지지 밖에 있는 교정은 흡수하기 어렵다고 보고한다. Novelty의 "접근성(accessibility)" 항이 여기서 온다.
  • post-training 변위 = 전문성: On-policy delta distillation (Heo et al., 2026)과 Feng et al. (2026)은 teacher와 그 base 모델의 log-정책 차이가 post-training이 만든 정책 변화를 담는다고 본다. 같은 base에서 갈라진 MOPD teacher들이라면 이 차이가 곧 "그 teacher가 RL로 얻은 전문성의 방향"이 된다. ExpertAlign의 출발점이다.

§1 서론 — 왜 라우팅을 다시 생각하는가

LLM post-training에서 도메인마다 RL 파이프라인이 다르다. 수학은 검증 가능한 보상, 소프트웨어 엔지니어링은 실행 가능한 환경, IF는 규칙·루브릭 피드백을 쓴다. 이렇게 독립적으로 만든 전문 모델들을 하나로 합치는 것이 capability integration 문제이고, MOPD는 이제 주요 LLM 개발사들의 합의된 해법이다. 그러나 표준 MOPD는 거친(coarse-grained) teacher 배정, 즉 프롬프트의 도메인 라벨로 teacher 한 명을 고르고 그 teacher가 rollout 전체를 감독하는 domain-label hard routing을 쓴다. 이 방식은 주 전문가를 잘 찾고 안정적인 신호를 주지만, 궤적 전체를 프롬프트 수준 라벨에 묶어 둔다.

두 가지 한계:

  1. 라벨 부재: 실제 SFT·chat 혼합 데이터에는 신뢰할 만한 도메인 라벨이 없는 경우가 많다. 한 프롬프트가 일반 대화, 지시 따르기, 수학 추론, 코드 실행을 동시에 담으면 표준 MOPD에는 teacher를 고를 규칙이 없다. 부록 C에서 보듯, LLM으로 라벨을 붙여도 "코드를 도구로 쓰는 수학 문제"는 경계가 모호하다.
  2. 보완 신호 손실: 도메인 라벨은 주 teacher만 가리킬 뿐 다른 teacher가 개별 토큰에서 가질 가치를 무시한다. 수학 프롬프트에서도 code teacher는 프로그램식 추론에, IF teacher는 형식·출력 제약에 도움이 될 수 있고, 그 유용성은 생성 단계와 토큰 위치에 따라 달라진다.

따라서 교차 도메인 보완성을 활용하려면 토큰·문맥 인지(token- and context-aware) 라우팅이 필요하고, 핵심 질문은 이렇다: 각 토큰에서 어떤 routing 지표가 관련 teacher를 식별·선택하고 그 신호에 적절한 가중치를 줄 수 있는가? MOPD-Router는 이 질문을 같은 MOPD 파이프라인 안에서 지표만 바꿔 가며 연구할 수 있는 interface이고, 그 안에서 서로 다른 정보원을 쓰는 세 지표(Entropy, Novelty, ExpertAlign)를 비교한다.

§2 관련 연구

2.1 On-policy distillation

OPD 연구는 세 갈래로 정리된다 (Yu et al., 2026의 분류): (a) strong-to-weak distillation — 더 강한 teacher의 능력을 약한 student로 옮기며, 표준 OPD 목적함수의 안정적·효과적 변형을 개발한다 (Agarwal et al., 2024; ExOPD = Yang et al., 2026a). (b) self-distillation — 같은 모델이 다른 문맥·피드백 조건에서 teacher와 student를 겸한다 (Hübotter et al., 2026; Zhao et al., 2026). (c) adaptive distillation — 균일하지 않은 OPD 지도 문제를 목적함수나 지도받는 토큰을 다른 신호로 조절해 해결한다 (Jin et al., 2026의 entropy-aware OPD; Wang et al., 2026b의 token teachability; TIP = Xu et al., 2026b; Li et al., 2026; Heo et al., 2026). 이들은 MOPD-Router의 지표 설계에 영감을 주었지만, 모두 단일 teacher OPD 안에서 지도를 수정할 뿐 여러 전문 teacher 사이에 지도를 배분하지는 않는다.

2.2 Multi-teacher capability integration

능력 통합의 기존 경로는 joint training(Mix-RL: 여러 도메인 프롬프트를 섞어 도메인별 보상을 함께 최적화), sequential training(Cascade RL: 도메인별 RL을 순차 적용; Nemotron-Cascade), weight-space composition(parameter merging, task arithmetic)이다. MOPD는 독립적으로 학습된 도메인 teacher를 student rollout 위의 dense 지도로 정책 공간에서 통합한다. Open-MOPD와 D³-MOPD는 최적화 예산 균형과 적응적 도메인 스케줄링으로 회복률을 올렸고, H-OPD는 vision-language와 text-only teacher 사이에 확신 기반 토큰 중재를 도입했다. 그러나 대부분의 MOPD 구현은 여전히 도메인 라벨 기반 hard routing에 의존하며, 라벨 없는 routing 지표 설계는 거의 탐구되지 않았다는 것이 저자들의 문제 제기다.

§3 MOPD-Router

MOPD-Router는 고정된 프롬프트→teacher 배정을 teacher 전체에 대한 토큰 단위 가중으로 바꾼다. 먼저 sampled-token MOPD를 "teacher별 OPD advantage 위의 라우팅"으로 정식화하고(§3.1), interface를 정의한 뒤(§3.2), teacher 분포·teacher–student 관계·공통 pre-RL base 대비 teacher 전문성이라는 세 정보원에 기반한 세 지표를 구체화한다(§3.3).

3.1 Multi-teacher on-policy distillation

설정: 프롬프트 $x \sim \mathcal{D}$, student 정책 $\pi_\theta$, 전문 teacher $\{\pi_{\phi_i}\}_{i=1}^{M}$. rollout 정책 $\pi_{\theta_{\text{old}}}$가 응답 $y=(y_1,\dots,y_T) \sim \pi_{\theta_{\text{old}}}(\cdot\mid x)$를 샘플하고, 위치 $t$에서 teacher는 student가 방문한 문맥 $h_t=(x, y_{<t})$를 평가한다. sampled-token OPD 구현(Li et al., 2026)을 따라 teacher별 advantage와 라우팅된 advantage를 정의한다:

$$A_t^{(i)} = \mathrm{sg}\big[\log \pi_{\phi_i}(y_t\mid h_t) - \log \pi_{\theta_{\text{old}}}(y_t\mid h_t)\big], \qquad A_t = \sum_{i=1}^{M} w_{i,t}\, A_t^{(i)} \tag{1}$$

$\mathrm{sg}[\cdot]$는 stop-gradient이고, $A_t$는 teacher별 신호를 음이 아닌 가중치 $\{w_{i,t}\}$로 합친 것이다. RL식 OPD 구현처럼 $A_t$는 학습된 critic 없이 advantage 자리에 직접 들어간다. importance ratio $\rho_t(\theta) = \pi_\theta(y_t\mid h_t)/\pi_{\theta_{\text{old}}}(y_t\mid h_t)$로 student는 다음을 최대화한다:

$$J_{\text{MOPD}}(\theta) = \mathbb{E}\left[\frac{1}{T}\sum_{t=1}^{T} \min\big(\rho_t(\theta)A_t,\ \mathrm{clip}(\rho_t(\theta), 1-\epsilon, 1+\epsilon)A_t\big)\right] \tag{2}$$

두 가지 고정 규칙: 표준 MOPD는 프롬프트에 도메인 라벨 $d(x)$를 주고 응답 전체에 해당 teacher를 쓴다:

$$w_{i,t}^{\text{domain}} = \mathbb{I}[i = d(x)] \tag{3}$$

같은 one-hot 가중치가 모든 위치에서 재사용된다. 라벨이 없을 때의 직접적 대안은 Mean aggregation $w_{i,t}^{\text{mean}} = 1/M$이다. ##domain-label hard routing은 신뢰할 만하지만 거칠고, Mean은 라벨이 필요 없지만 모든 teacher 신호를 똑같이 유익하다고 취급한다## — MOPD-Router는 이 둘 사이의 빈칸을 채운다.

직관적으로 말하면: 식 (1)의 $A_t^{(i)}$는 "teacher $i$가 이 토큰을 student보다 얼마나 더 좋아하나"이고, 라우팅이란 결국 세 teacher의 의견을 어떤 비율로 섞어 한 표로 만들지 정하는 일이다. hard routing은 한 사람에게 전권을, Mean은 모두에게 똑같은 1/3 표를 준다.

3.2 Token-level metric routing

MOPD-Router는 고정 규칙 대신, student rollout의 모든 토큰 위치에서 모든 teacher에 대해 plug-in 지표 $\mathcal{M}$을 평가한다:

$$s_{i,t} = \mathcal{M}\big(\pi_{\phi_i}, \pi_{\theta_{\text{old}}}, \pi_{\theta_{\text{base}}}; h_t\big) \tag{4}$$

$\pi_{\theta_{\text{base}}}$는 teacher들이 post-training 전에 공유하던 base 모델이다. 각 토큰에서 점수로 적합한 teacher를 식별하고 $A_t$에 대한 상대적 기여를 정해, 도메인 라벨이나 별도 routing 모델 학습 없이 전체 teacher 풀에 대한 문맥 의존적 선택·가중을 얻는다. 지표가 바뀌어도 rollout, teacher 평가, 목적함수는 그대로라는 점이 "plug-in"의 의미다 — 지표 간 비교가 공정해진다.

Algorithm 1 (학습 루프):

for 각 training step q: π_θold ← π_θ ; 샘플러 D와 π_θold로 rollout batch R_q 생성 student · 모든 teacher · shared base를 student가 방문한 문맥 h_t 위에서 평가 (𝓜에 필요한 양) 식 (1)로 teacher별 sampled-token advantage A_t^(i) 계산 𝓜으로 전체 teacher 풀에 대한 음이 아닌 토큰 가중치 {w_i,t} 계산 A_t = Σ_i w_i,t · A_t^(i) for k = 0 … K−1 (inner minibatch B_q,k): 현재 student log-prob과 ρ_t(θ) 재계산 식 (2)의 clipped MOPD 목적함수를 최대화하도록 θ 갱신

3.3 Routing metrics

표기: $p^S_t(v) = \pi_{\theta_{\text{old}}}(v\mid h_t)$는 rollout student의 다음 토큰 분포, $p^i_t(v) = \pi_{\phi_i}(v\mid h_t)$는 teacher $i$의 분포, $p^{\text{base}}_t(v) = \pi_{\theta_{\text{base}}}(v\mid h_t)$는 공유 base의 분포다. Entropy와 Novelty 점수는 지표마다 좁은 척도에 몰려 있으므로, softmax 가중치에 1보다 작은 routing 온도를 써서 가중치가 거의 균등해지는 것을 막고 teacher 간 구분을 날카롭게 한다.

Entropy — teacher 확신 기반 (기준 지표 1)

가설: "더 확신하는 teacher에게 더 큰 가중치를" 이라는 자연스럽지만 순진한 가설이다. 엔트로피는 teacher의 다음 토큰 분포가 얼마나 퍼져 있는지를 재며, 낮을수록 확률이 소수 후보에 몰려 더 날카롭고 확신에 찬 예측이다. 확신 중재 방법(H-OPD; Prabhudesai et al., 2025)을 대표해 음의 예측 엔트로피를 점수로 쓴다:

$$s^{\text{Ent}}_{i,t} = -\mathcal{H}(p^i_t) = \sum_{v\in\mathcal{V}} p^i_t(v)\log p^i_t(v), \qquad w^{\text{Ent}}_{i,t} = \frac{\exp(s^{\text{Ent}}_{i,t}/\tau^{\text{Ent}}_R)}{\sum_{j=1}^{M}\exp(s^{\text{Ent}}_{j,t}/\tau^{\text{Ent}}_R)} \tag{5}$$

$\tau^{\text{Ent}}_R = 0.1$. teacher만 보는 지표라 계산은 단순하지만, ##엔트로피가 낮은 teacher가 지금의 student를 유용하게 교정하는지는 판단할 수 없고, teacher 고유의 엔트로피 척도 차이가 특정 teacher를 체계적으로 편애할 수 있다##.

직관적으로 말하면: 목소리가 가장 확신에 찬 선생님에게 마이크를 주는 규칙이다. 원래 단호한 성격인 선생님(math teacher)은 학생이 무엇을 쓰고 있든 늘 마이크를 잡는다.

Novelty — 접근 가능한 teacher–student 차이 (기준 지표 2)

근거: 선행 연구(Li et al., 2026; Wang et al., 2026b)는 효과적인 OPD 업데이트가 teacher와 student가 공유하는 고확률 후보에 집중되며, student의 국소 지지 밖의 교정은 흡수하기 어렵다고 보고한다. Novelty는 그래서 teacher와 student가 공유 고확률 후보 집합 안에서 크게 다르고 둘 다 그 집합에 충분한 확률 질량을 둘 때 높은 점수를 준다.

$S^S_t = \mathrm{TopK}(p^S_t, k)$와 $S^i_t = \mathrm{TopK}(p^i_t, k)$를 각자의 상위 $k$개 후보, $\Omega_{i,t} = S^S_t \cap S^i_t$를 공유 후보 집합이라 하자. 분포 $p$에 대해 $p(\Omega) = \sum_{v\in\Omega} p(v)$, $p|_\Omega$는 $\Omega$로 제한해 합이 1이 되도록 재정규화한 분포다. 접근성(accessibility)과 새로움(novelty) 성분은:

$$a_{i,t} = \sqrt{p^S_t(\Omega_{i,t})\,p^i_t(\Omega_{i,t})}, \qquad N_{i,t} = 1 - \exp\!\Big(-\mathrm{JS}\big(p^S_t|_{\Omega_{i,t}},\ p^i_t|_{\Omega_{i,t}}\big)/\tau_N\Big) \tag{6}$$

$a_{i,t}$는 두 모델이 공유 후보에 둔 확률 질량을, $N_{i,t}$는 공유 집합 안에서의 분포 차이(Jensen–Shannon divergence, JS)를 잰다. $\tau_N = 0.1$은 차이가 얼마나 빨리 포화(saturate)되는지 정한다. 둘을 곱해:

$$s^{\text{Nov}}_{i,t} = a_{i,t}N_{i,t}, \qquad w^{\text{Nov}}_{i,t} = \frac{\exp(s^{\text{Nov}}_{i,t}/\tau^{\text{Nov}}_R)}{\sum_{j=1}^{M}\exp(s^{\text{Nov}}_{j,t}/\tau^{\text{Nov}}_R)} \tag{7}$$

$\tau^{\text{Nov}}_R = 0.1$이며, $\Omega_{i,t}$가 비면 $s^{\text{Nov}}_{i,t} = 0$. top-$k$는 16 (Table 6).

직관적으로 말하면: "학생이 이미 고려하고 있는 답 후보들 안에서, 학생과 생각이 가장 다른 선생님"에게 발언권을 준다. 학생 머릿속에 아예 없는 답을 주장하는 선생님은 아무리 옳아도 지금은 전달이 안 된다고 보고 깎는다.

ExpertAlign — 전문성 정렬 지표 (제안)

왜 문제인가: Entropy와 Novelty는 teacher의 현재 출력만 채점하고, 그것이 teacher의 전문성을 반영하는지는 말해 주지 않는다. 예컨대 student가 base 모델과 조금 다른 문체로 쓰고 있다면, 아무 teacher나 student와 "다르다" — 그러나 그 차이는 teacher가 RL로 배운 능력과 무관한 일반적 불일치(generic disagreement)일 수 있다.

해법: teacher와 그 base 모델의 log-정책 차이가 post-training이 만든 정책 변화를 포착한다는 관찰(Heo et al., 2026; Feng et al., 2026)에 기대어, ##teacher가 지금 student를 자기 post-training 전문성 방향으로 움직이려 하는지를 토큰 단위로 평가하는 ExpertAlign##을 제안한다. 먼저 student의 top-$k$ 지지 $S^S_t$ 위에서 teacher $i$의 expertise vector를 정의한다:

$$\mathbf{e}_{i,t} = \big[\log p^i_t(v) - \log p^{\text{base}}_t(v)\big]_{v\in S^S_t} \tag{8}$$

이것은 공유 pre-RL base 대비 teacher $i$가 획득한 방향으로, student와 무관한 teacher 고유의 성질이다. 이에 맞서, student에 의존하는 teaching vector를 정의한다:

$$\mathbf{d}_{i,t} = \big[\log p^i_t(v) - \log p^S_t(v)\big]_{v\in S^S_t} \tag{9}$$

teacher $i$가 student의 국소 top-$k$ 지지 위 log-확률을 어떻게 바꾸려 하는지를 담는다. ExpertAlign은 teaching 방향 $\mathbf{d}_{i,t}$가 전문성 $\mathbf{e}_{i,t}$와 정렬될 때만 teacher $i$를 관련 있다고 본다 — 그 교정이 일반적 불일치가 아니라 post-training으로 얻은 능력을 반영한다는 신호이기 때문이다. 정렬 정도는 양의 cosine으로 잰다:

$$c_{i,t} = \max\!\left(\frac{\langle \mathbf{e}_{i,t}, \mathbf{d}_{i,t}\rangle}{\|\mathbf{e}_{i,t}\|_2\,\|\mathbf{d}_{i,t}\|_2},\ 0\right), \qquad \mathcal{E}_t = \{i : \langle \mathbf{e}_{i,t}, \mathbf{d}_{i,t}\rangle > \delta\} \tag{10}$$

노름이 0인 벡터는 $c_{i,t} = 0$, 수치적 정렬 여유는 $\delta = 10^{-6}$. 유지 집합 위에서 두 가중 규칙을 고려한다:

$$w^{\text{uniform}}_{i,t} = \frac{\mathbb{I}[i\in\mathcal{E}_t]}{|\mathcal{E}_t|}, \qquad w^{\text{cosine}}_{i,t} = \frac{\mathbb{I}[i\in\mathcal{E}_t]\,c_{i,t}}{\sum_{j\in\mathcal{E}_t} c_{j,t}} \tag{11}$$

$\mathcal{E}_t$가 비면 모든 가중치가 0이고 위치 $t$의 OPD 지도는 생략된다. $k = 16$ (민감도는 부록 E.4). 본문 실험의 ExpertAlign은 cosine 가중이다.

직관적으로 말하면: 선생님이 학생 답안에 빨간 펜을 대려 할 때 "그 수정 방향이 당신이 졸업 후 전공 수련(RL)에서 바뀐 방향과 같은가?"를 묻는다. 같으면 전공 지식에서 나온 교정이니 반영하고(cos가 클수록 더 크게), 다르면 그냥 취향 차이니 무시한다. Entropy·Novelty가 "얼마나 확신/얼마나 다름"을 본다면 ExpertAlign은 "왜 다른가"를 본다.

비교 포인트: 식 (9)의 $\mathbf{d}_{i,t}$는 Novelty가 보는 차이와 같은 재료이고, 식 (1)의 $A^{(i)}_t$는 $\mathbf{d}_{i,t}$의 샘플된 좌표 하나($v = y_t$일 때)다. 즉 ExpertAlign은 teacher가 주려는 신호 자체는 그대로 두고, 그 신호를 신뢰할지를 base라는 제3의 기준점으로 판정한다. 같은 base에서 갈라진 teacher라는 MOPD 산업 표준 설정(부록 A)에 의존하는 설계다.

4.3 Ablation과 분석

이 절은 세 지표가 왜 이 순서로 줄을 서는지 하나씩 해부한다: Entropy가 실패하는 이유(4.3.1), Novelty의 접근성이 작동하는 조건(4.3.2), ExpertAlign의 두 구성 요소(4.3.3), 그리고 교차 도메인 teacher의 실제 기여(4.3.4).

4.3.1 teacher 확신은 신뢰할 만한 routing 신호가 아니다

실험 의도 (Q3): Entropy는 "엔트로피가 낮은 teacher가 더 날카로운 국소 선호를 가지니 우선 지도하게 하자"는 직관적 휴리스틱이다. 그것이 왜 Mean 수준에 머무는지 확인한다.

결과: 두 가지 이유가 드러난다. 첫째, 확신만으로는 유용한 지도를 가려내지 못한다 — 엔트로피가 높은 위치는 여러 그럴듯한 연속이 있는 결정 지점(decision point)일 수 있고, 그런 위치에 오히려 중요한 OPD·RL 학습 신호가 있다(Jin et al., 2026; Wang et al., 2025a의 "high-entropy minority tokens"). 둘째, 엔트로피에는 강한 teacher별 편향이 있다: 두 증류 설정 모두에서 math teacher가 다른 teacher보다 일관되게 엔트로피가 낮아, router가 student의 현재 문맥에 적응하지 않고 한 teacher를 편애한다(부록 E.1, Table 11). ##math teacher는 약 70%의 토큰에서 확신 top-1이고 code teacher는 약 9%뿐##이며, 이 패턴은 student 크기와 학습 단계에 거의 무관하다.

뒷받침하는 주장: 배치 단위 엔트로피 정규화로 teacher 척도 편향을 없애면 가중치는 거의 균등(33.85/34.50/31.65%)해지지만 Overall은 34.65 → 34.83으로 미미하게 오른다(Table 12). 편향을 고쳐도 "확신 = 유용성"이라는 전제 자체가 틀렸다는 뜻이고, 이것이 student 조건부 지표(Novelty, ExpertAlign)의 동기다.

§5 결론

MOPD-Router는 multi-teacher OPD의 프롬프트 수준 domain-label hard routing을 plug-in 지표를 통한 전체 teacher 풀 위의 토큰 단위 라우팅으로 대체하며, routing 모델을 학습하지 않는다. 별도의 teacher 배정 단계 없이 라벨 없는 프롬프트 혼합에서 다중 teacher 증류를 가능하게 한다. 라벨 없음/있음 × strong-to-weak/same-size에서 효과적인 라우팅 지표는 도메인 라벨 없이 MOPD를 가능하게 하고 Mean과 표준 MOPD를 모두 능가하며, ExpertAlign이 일관되게 최고 성능을 낸다. 저자들은 이것이 다중 teacher 증류에서 보완적 teacher 신호를 동적으로 선택·결합하는 가치를 보여 주며, 토큰 수준·문맥 의존적 지도에 대한 탐구를 촉진하기를 기대한다.

부록 A — 한계와 열린 방향 (저자 서술)

실험은 두 데이터 체제와 두 증류 시나리오, 그리고 수학·코드·IF에 특화된 같은 계열(Qwen3) teacher 3명을 쓴다. 이 통제된 설정은 아키텍처·사전학습 차이로부터 라우팅을 분리해 주지만, 더 큰 teacher 풀로의 일반화는 아직 검증되지 않았다. 지표들은 지도 가치에 대한 서로 보완적인 관점을 담지만 통일된 설계 원리가 아니라 경험적 직관에 기반한다. 도메인 teacher가 pre-RL base를 공유하는 것은 산업 MOPD 파이프라인의 표준 설정(MiMo-V2-Flash, GLM-5, DeepSeek-V4, Kimi K3)이고, ExpertAlign은 이를 따라 각 teacher의 expertise vector를 공유 base 기준으로 정의한다. 향후 과제로는 더 다양한 teacher 풀과 증류 시나리오, 지표 설계의 체계적 원리, 서로 다른 base에서 만든 teacher로의 확장(각 teacher 자신의 pre-RL 체크포인트 사용), 그리고 verifier 피드백·보상 같은 외부 신호를 쓰는 지표가 제시된다.

E.3 교차 도메인 routing 예시

집계 routing 질량: 프롬프트 도메인 $d$와 teacher $i$에 대해 Figure 2 왼쪽은 응답 토큰 routing 질량을 보고한다:

$$R_{d,i} = \frac{\sum_{x: d(x)=d}\sum_t w_{i,t}}{\sum_{x: d(x)=d}\sum_t\sum_j w_{j,t}} \tag{12}$$

합은 라벨 있는 데이터 라우팅 감사의 유효 응답 토큰에 대해 취하므로 각 행의 합은 1이고, 도메인 $d$의 off-domain 질량은 $1 - R_{d,d}$다. 분모가 $\sum_j w_{j,t}$이므로 $\mathcal{E}_t = \emptyset$이라 가중치가 모두 0인 토큰은 자연히 빠진다.

직관적으로 말하면: "math 문제를 풀 때 생성된 모든 토큰의 발언권을 합쳐 보니, math 선생님 몫은 37.4%뿐이고 나머지 62.6%는 다른 두 선생님이 가져갔다"는 집계다.

프롬프트와 의미 단계: 수학 추론, 코드 검증, 출력 형식 제약을 결합한 Qwen3-1.7B student rollout을 본다. 프롬프트 전문: "What is the sum of the integers from 1 to 100? Solve it, verify your result using Python, and return the final answer in a strict JSON schema." 설명을 위해 생성된 응답을 수학 추론 / Python 검증 / JSON 형식의 세 의미 단계로 수동 분할했으며, 이 주석은 생성 후에만 적용되고 라우팅 계산에 들어가지 않는다. 본문 Figure 2 궤적은 원래 계수 척도를 유지하고 가독성을 위해 이웃 단어 위치만 평활화했다.

teacher별 routing 중심: Figure 3은 같은 응답을 단어 구간(word-span) 수준에서 보여 준다. 색 농도는 teacher마다 독립적으로 정규화되어, 한 teacher 안에서 단어 간 상대적 집중도로 해석한다. math teacher는 수치 유도 부근에, code teacher는 Python 계산 부근에, IF teacher는 구조 표지와 최종 JSON 출력 부근에 가장 강하게 집중한다. 이 보기는 정규화하지 않은 궤적(Figure 2)을 보완해 각 teacher의 국소 routing 중심을 명시한다.

E.4 student top-k 지지 크기 민감도

실험 의도: ExpertAlign이 지지 크기에 얼마나 민감한지 보기 위해 라벨 있음·Qwen3-4B 설정에서 student top-$k$를 $k\in\{1,4,8,16,32\}$로 바꾼다. 이 설정에서 Overall 기준으로 $k$를 골랐고 $k = 16$이 최고이며, $k = 1$~$16$의 Overall이 오차 막대 안에 있어 선택은 plateau에 둔감하다. $k = 32$에서 뚜렷하게 떨어진다.

$k = 1$: 수학은 $k = 1$에서 최고인 유일한 도메인이다. 이때 $S^S_t$는 student의 최빈 토큰 $v^\star_t$ 하나뿐이고 두 벡터는 스칼라 $e_{i,t} = \log p^i_t(v^\star_t) - \log p^{\text{base}}_t(v^\star_t)$, $d_{i,t} = \log p^i_t(v^\star_t) - \log p^S_t(v^\star_t)$가 된다. 두 0 아닌 스칼라의 cosine은 ±1이라 크기 정보가 사라지므로, 구현은 이 경우 식 (11)의 $c_{i,t}$를 비정규화 곱 $\max(e_{i,t}d_{i,t}, 0)$으로 바꾼다(유지 집합 $\mathcal{E}_t$는 동일, $k>1$은 cosine). teacher는 $v^\star_t$에 대한 post-training 변화와 student 교정의 부호가 같을 때만 유지되고, 두 양이 이 토큰의 확률을 얼마나 강하게 움직이는지로 가중된다. 이런 단일 토큰 정렬은 수학에 맞는다 — math teacher는 엔트로피가 가장 낮고 분포가 가장 날카로워(Table 11) 지도가 주 후보에 집중되기 때문이다. 코드와 IF는 그럴듯한 연속이 여럿인 위치가 많아, 한 토큰의 정렬로는 teacher가 경쟁 후보 사이에 확률을 어떻게 재분배하는지 포착할 수 없다.

$k = 32$: 세 도메인 모두 나빠진다. 추가 후보는 확률 질량이 거의 없다 — 공유 top-16이 이미 student 질량의 약 99%를 덮는다(Table 14). 그러나 각 후보는 확률과 무관하게 $\mathbf{e}_{i,t}$, $\mathbf{d}_{i,t}$에 좌표 하나씩을 보태고, log-비율은 작은 확률 사이의 차이를 증폭한다. 예컨대 student에서 $10^{-3}$이던 꼬리 토큰이 날카로운 teacher에서 $10^{-6}$이 되면 $|d_{i,t}(v)| \approx 6.9$인 반면, head 토큰이 0.5 → 0.4로 움직이면 0.22뿐이다. 작은 확률은 미세한 절대 변동에도 log-비율이 크게 흔들린다. 꼬리 후보가 늘수록 $\langle \mathbf{e}_{i,t}, \mathbf{d}_{i,t}\rangle$가 student가 실제로 생성할 주 후보가 아니라 거의 0인 확률의 토큰에 지배되어 선택과 가중이 모두 잡음이 된다.

E.5 ExpertAlign의 선택 범위와 학습 동역학

선택적이지만 넓은 지도 범위: 유효 응답 토큰에서 유지된 teacher 수를 $K_t = |\mathcal{E}_t|$라 하자. 네 설정에서 토큰의 37.02~51.24%가 세 teacher를 모두 유지하고, 다시 말해 48.76~62.98%의 토큰에서 ExpertAlign은 진부분집합을 고른다. 선택적으로 라우팅된 토큰 대부분은 여전히 지도를 받아 전체 토큰의 47.61~60.50%가 teacher 1~2명을 유지하고 $K_t = 0$은 0.52~2.48%뿐이다. 따라서 유효 응답 토큰의 97.52~99.48%가 적어도 한 teacher의 신호를 받는다 — ##게이트의 지배적 역할은 토큰을 OPD 목적함수에서 빼는 것이 아니라 teacher 구성을 바꾸는 것##이다.

전원 탈락 토큰은 학습 중 완만히 증가: $K_t = 0$은 내내 드물지만 Figure 5(b)는 모든 설정에서 양의 최소제곱(ordinary least squares, OLS) 기울기를 보인다. 100 step당 증가량은 라벨 없음 1.7B·4B에서 0.161·0.071%p, 라벨 있음에서 0.148·0.084%p. 저자는 이를 기술적 학습 동역학으로만 다루고, ExpertAlign 게이트의 기하와 정합하는지 검토한다.

기하학적 해석: 같은 지지 위에서 student의 base 대비 변위를 $\mathbf{q}_t = \big[\log p^S_t(v) - \log p^{\text{base}}_t(v)\big]_{v\in S^S_t}$라 하자. $\mathbf{e}_{i,t}\neq\mathbf{0}$이면 그 방향으로의 student 정규화 진척도를 $r_{i,t} = \langle \mathbf{e}_{i,t}, \mathbf{q}_t\rangle/\|\mathbf{e}_{i,t}\|_2^2$로 정의한다. $\mathbf{d}_{i,t} = \mathbf{e}_{i,t} - \mathbf{q}_t$이므로 게이트가 검사하는 정렬은:

$$\langle \mathbf{e}_{i,t}, \mathbf{d}_{i,t}\rangle = \|\mathbf{e}_{i,t}\|_2^2 - \langle \mathbf{e}_{i,t}, \mathbf{q}_t\rangle = \|\mathbf{e}_{i,t}\|_2^2\,(1 - r_{i,t}) \tag{13}$$

학습이 진행되어 student가 teacher $i$에 다가가면 $\mathbf{d}_{i,t}$가 줄어 내적이 수치 여유 아래로 떨어지기 쉬워진다. 또 $r_{i,t} \ge 1$이면 student의 사영이 그 방향에서 teacher의 base 대비 변위에 도달하거나 넘어서, 정렬이 0 이하가 된다. 두 경우 모두 student가 teacher의 전문성을 충분히 흡수해 그 teacher가 현재 토큰에서 양으로 정렬된 추가 교정을 거의 주지 못한다는 뜻이다.

직관적으로 말하면: 게이트는 "아직 배울 것이 남은 선생님"만 남기는 졸업 심사다. 학생이 어떤 선생님의 전공 방향으로 그 선생님만큼 와 버리면, 그 선생님은 그 토큰에서 자동으로 물러난다.

비판적 분석 (Critical Analysis)

강점

  • 실무 문제를 정확히 겨냥: 라벨 없는 혼합 데이터에서 MOPD를 쓸 수 있게 한다는 동기가 분명하고, 부록 C의 라벨 분포(code 3.30%)와 사람 검증(code 일치 76%)이 "프롬프트 라벨은 얽힌 기술을 담지 못한다"는 주장을 데이터로 뒷받침한다.
  • 깔끔한 plug-in 설계와 공정한 비교: 지표만 바꾸고 rollout·목적함수·예산은 고정해, 지표 간 차이를 해석하기 쉽다. Entropy·Novelty를 단순한 허수아비가 아니라 선행 연구에 근거한 강한 기준선으로 만든 점도 좋다.
  • ExpertAlign의 아이디어가 간결하고 해석 가능: base라는 제3의 기준점으로 "차이"와 "전문성에서 나온 차이"를 구분하는 발상은 새롭고, 식 (13)의 기하 해석이 게이트의 동작(학습 후반 탈락 증가)까지 설명한다.
  • 통계적 엄밀성이 이 분야 평균보다 높다: Holm 보정 paired bootstrap(12 비교)과 3-seed 반복을 함께 보고하고, 유의하지 않은 비교(라벨 있음 1.7B vs Open-MOPD)를 숨기지 않는다.
  • ablation이 주장의 구조와 1:1 대응: 선택 vs 가중(Table 3), 풀 vs 토큰 단위(Table 4), 접근성(Table 13), 확신 편향 보정(Table 12), k 민감도(Figure 4).

한계와 의문점

  • teacher 풀이 작고 동질적: 같은 base(Qwen3-4B)에서 나온 3명, 그중 2명은 외부 공개 체크포인트(ExOPD). ExpertAlign은 공유 base를 전제하므로, base가 다른 teacher(또는 base가 공개되지 않은 teacher)에는 그대로 쓸 수 없다. 저자도 부록 A에서 인정한다.
  • 규모: student 최대 4B, teacher 4B, 학습 약 170 step. 산업 MOPD(MiMo, GLM-5, DeepSeek-V4 등)의 수십~수백 B 규모와 수천 step에서 같은 경향이 유지되는지는 미지수다.
  • same-size의 특수성: same-size에서는 student가 곧 base이므로 학습 시작 시 $\mathbf{q}=0$, $\mathbf{d}=\mathbf{e}$로 모든 teacher가 완벽히 정렬된다. 이 설정에서 이득이 가장 큰 것(+5.00/+3.95)이 ExpertAlign 고유의 장점인지, "student = base" 구조의 부산물인지 분리되지 않았다.
  • 교란 요인: ① ExpertAlign은 $K_t=0$ 토큰을 건너뛰고 Mean·hard routing은 모든 토큰을 지도하므로, 지도 토큰 수와 advantage 크기 분포가 방법마다 다르다. ② 방법마다 응답 길이가 크게 다르다(3,278~4,893 토큰). Entropy·Novelty의 짧은 응답이 성능 저하의 원인인지 결과인지 분석이 없다. ③ Table 4의 w/o Cross-Domain 변형은 단일 teacher에도 게이트를 적용해 지도 토큰이 줄었을 수 있다.
  • Figure 2(오른쪽)의 서술 강도: 실제 추출 곡선에서 Python 구간 대부분은 IF teacher가 code teacher보다 높다. "code teacher가 Python 검증에서 활성화"는 상대적 상승일 뿐이고, 단일 사례·수동 구간 주석이라 일반화 근거로는 약하다.
  • IF teacher의 넓은 점유: IF teacher가 math 프롬프트에서도 40.9%를 받는다. "형식·구조 보완"일 수도 있지만, IF teacher가 일반 문체 차원에서 student와 가장 다르다는(Table 14) 점과 겹쳐 "범용 교정자" 역할일 가능성도 있다. 토큰 유형별 분해가 있었다면 판별 가능했다.
  • 학습 seed 반복은 1개 설정뿐: 3-seed는 same-size·라벨 있음에만 있다. 이득이 가장 작은 라벨 없음·1.7B(Std 대비 +2.25, p = .045)는 seed 변동이 측정되지 않았다.
  • 하이퍼파라미터 선택: $k = 16$을 평가 Overall로 골랐고(부록 E.4), 그 설정이 주 결과 중 하나(라벨 있음 4B)와 같다. 오차 막대 안의 plateau라 영향은 작겠지만 별도 검증셋을 쓰지 않았다. 지표별 온도(τ = 0.1)의 민감도는 보고되지 않는다.
  • Open-MOPD 재현 조건: Open-MOPD는 원래 SmolLM3-3B·다른 데이터에서 설계된 레시피다. 이 논문 설정(mini-batch = batch, K = 1)에서는 Open-MOPD의 reward refresh 같은 구성 요소가 의미가 없을 수 있는데, 어떤 구성 요소를 어떻게 이식했는지 서술이 부족하다.

Key Takeaways — 이 논문에서 가져갈 것

  1. MOPD의 라우팅 단위는 프롬프트가 아니라 토큰이어도 된다: 같은 base에서 갈라진 teacher들이라면 토큰마다 teacher를 섞어도 학습이 안정적이고, 라벨 없는 데이터에서도 MOPD가 가능하다. 라벨링 파이프라인이 부담인 팀에 즉시 실용적이다.
  2. "얼마나 다른가"보다 "왜 다른가"를 물어라: teacher–student 차이(d)를 teacher–base 차이(e)에 투영하는 ExpertAlign의 발상은 단순하고 계산이 싸며(base forward 1회), OPD의 다른 토큰 가중 문제(예: 단일 teacher OPD의 토큰 선택)에도 이식할 만하다.
  3. teacher 확신은 routing 신호로 쓰지 마라: 엔트로피는 teacher 고유 성질(날카로운 math teacher)을 반영해 고정 편향을 만들고, 보정해도 성능이 거의 오르지 않는다. H-OPD식 확신 중재를 텍스트 MOPD에 그대로 쓰는 것은 경계할 일이다.
  4. log-비율 기반 지표는 지지 크기에 민감하다: 꼬리 토큰이 좌표를 지배하므로 top-k를 너무 키우면(k = 32) 신호가 잡음이 된다. 이런 지표를 설계할 때는 확률 가중이나 작은 k가 안전하다.
  5. 교차 도메인 보완성은 실재하지만 "섞기만" 해서는 안 된다: 응답 단위 고정 혼합은 오히려 hard routing보다 나쁠 수 있고(1.7B 36.57 < 37.52), 이득은 토큰 단위 선택에서 나온다.
  6. (비판적 관점) 결론의 범위는 아직 좁다: 같은 base의 4B teacher 3명, 최대 4B student, 약 170 step, 대부분 단일 run이다. 서로 다른 base·더 큰 teacher 풀·대규모 student에서 ExpertAlign이 유지되는지, 그리고 same-size의 큰 이득이 "student = base" 구조 덕분인지가 검증되기 전까지는 유망한 소규모 증거로 읽는 것이 적절하다.
