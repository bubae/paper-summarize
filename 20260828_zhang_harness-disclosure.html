목차

TL;DR

  • 문제: LLM 에이전트 평가의 표준 관행은 {모델, 벤치마크} 쌍마다 숫자 하나를 보고하고 그것을 모델에 귀속시킨다. 그런데 모든 벤치마크 점수는 모델과 harness가 공동 생산한 것이고, harness는 거의 공개되지 않으며 비교 시 고정되지도 않는다. ##결과적으로 현재의 평가 프로토콜은 harness 수준의 이득을 체계적으로 모델 개선으로 오귀속한다.##
  • 해결: Binding Constraint Thesis를 형식화하고 방어한다 — long-horizon 과제에서 능력이 비슷한 프론티어 모델들을 비교할 때, 성능 분산은 모델 선택보다 harness 구성에 더 크게 지배된다. 그리고 처방으로 harness 공개 표준(Harness Card)과 분산 분해 프로토콜을 제안한다.
  • 왜 작동하는가: 세 갈래 논증이다. ⑴ 제어이론적 형식화 — harness를 폐루프 동역학계의 제어기로, LLM을 그것이 지배하는 확률적 정책으로 본다. ##LLM은 open-loop다 — 상태 $s_t$에 직접 접근하지 못하고 harness가 노출하기로 한 투영 $c(s_t)$만 본다.## 따라서 안정성·컨텍스트 드리프트·제어 지연이 모두 제어기의 성질이지 정책의 성질이 아니다. ⑵ 경험적 증거 — 공개 리더보드에서 harness 유발 분산이 모델 유발 분산을 크게 넘고 모델 순위 역전까지 발생한다. ⑶ 통제된 factorial — 3모델 × 3harness 격자에서 ##HV/MV 비율 7.80배, 9개 모델쌍/harness쌍 비교 중 6개에서 순위 역전##.
  • 비유: 자동차 경주에서 랩타임을 엔진 성능으로만 보고하는 관행과 같다. 그런데 같은 엔진을 다른 섀시에 얹으면 랩타임이 9.5초 달라지고, 엔진 세대 교체는 2~4초를 만든다. 지금 리더보드는 섀시를 밝히지 않은 채 엔진 순위를 발표하고 있다. 이 논문의 요구는 "섀시를 통일하라"가 아니라 "섀시가 무엇인지 적어라"다.

핵심 기여 (Key Contributions)

  1. Binding Constraint Thesis의 형식화: $HV(M) = \mathrm{Var}_{H}[B(M,H)]$, $MV(H) = \mathrm{Var}_{M}[B(M,H)]$를 정의하고, long-horizon·비슷한 프론티어 능력 레짐에서 HV가 MV와 비슷하거나 더 크며 많은 경우 지배한다고 주장한다. 현재 프로토콜은 미공개 $H^*$ 하나에 대한 $B(M,H^*)$만 보고하므로 ##HV를 측정 불가능하게 만든다##.
  2. 제어이론적 근거: 에이전트 실행을 이산시간 폐루프 동역학계로 놓고, 장기 신뢰성을 결정하는 세 양을 제어기의 성질로 정의한다 — Stability(Lyapunov 유사 측도의 비증가), Context Drift($\delta_t = D_{KL}(p_t \| p_0)$), Control Lag($\tau = t_c - t_d$). ##더 유능한 모델은 이상(anomaly) 발생률을 낮출 수 있지만, 이상이 발생한 뒤의 대응은 모델을 업그레이드해도 개선되지 않는 제어기 성질이다.##
  3. 분산 분해 항등식: $\mathrm{Var}[B(M,H)] = MV + HV + \text{interaction}$. 모델 순위를 모델의 성질로 취급하려면 interaction 항이 MV에 비해 작아야 하는데, 이 논문은 그 조건을 부정한다.
  4. 통제된 3×3 factorial 실험: 코딩 리더보드에서 밀집한 세 모델(GPT-5.4, Kimi K2.6, GLM-5.1) × 세 harness 구성(Minimal / Improved / Full)을 SWE-bench Verified 난이도 층화 100문항에서 각 셀 2회 실행. ##평균 HV 18.48 pp² vs 평균 MV 2.37 pp² → 7.80배##. harness 변경이 GLM-5.1을 13.0%p 움직이는 반면, 고정 harness에서 모델 변경은 2.5~5.0%p만 움직인다.
  5. 공개 리더보드 증거의 체계적 수집: SWE-bench Pro에서 표준 SEAL scaffold 하 상위 6개 프론티어 모델의 폭이 4.9%p인데, Claude Opus 4.5를 고정하고 harness만 바꾸면 9.5%p로 벌어진다 — ##모델 내 harness 범위가 harness 내 모델 범위의 약 2배##. HAL은 SWE-bench Verified Mini에서 동일 모델의 scaffold 간 격차를 34%p(Claude Sonnet 4.5, GPT-5 Medium), o4-mini는 거의 48%p로 보고한다.
  6. 네 가지 표준 대응이 왜 부족한지: harness 표준화 / 모델 스케일링 / 벤치마크 추가 / harness 최적화 — 각각 문제의 일부를 다루지만 귀속(attribution) 질문을 해결하지 못한다. 특히 "벤치마크를 늘리면 잡음이 상쇄된다"는 기대는 harness 기여의 평균이 0이 아니므로 실패한다.
  7. harness-aware 평가 프레임워크: ⑴ Harness Card — ETCSOVG 7층(Execution, Tool, Context, Scheduling, Observability, Verification, Governance) 구조화 공개. ⑵ 분산 분해 프로토콜 — 최소 2×2 격자, HV/MV·비율·순위 역전 수·부분 에타제곱 $\eta_p^2$ 보고. ⑶ 궤적 수준 지표 — Recovery Rate $RR(k)$, Context Retention, Control Lag $\tau$.
  8. 반증 가능성을 명시: 이 주장은 경험적이며, H를 변화시키고 M을 고정한 factorial과 그 반대를 수행해 비슷한 모델 능력 하 long-horizon 과제 분포에서 MV > HV를 발견하면 반증된다고 밝힌다. ##position paper가 자기 반증 조건을 구체적으로 제시하는 것은 드물다.##

배경 (Background)

harness는 모든 벤치마크 점수에 어떻게 들어가는가 (§2.1)

표준 에이전트 평가는 다음 파이프라인으로 작동한다 — 과제 서술, 시스템 프롬프트, 도구 카탈로그, 이전 궤적 상태로 조립한 프롬프트로 모델에 질의하고, 토큰 수준 출력을 최종 답·도구 호출·잘못된 문자열로 파싱하고, 도구 호출을 라우팅하고, 오류를 처리하고, 궤적이 길어지면 컨텍스트를 압축하고, 일정 스텝 후 정지한다.

##이 파이프라인의 모든 단계가 harness 결정이다.## 컨텍스트 구성, 도구 호출, 파싱, 재시도, 요약, 정지 — 하나의 벤치마크 점수는 이 선택들과 그에 맞서 출력을 생성하는 모델의 결합된 결과인데, 발표된 숫자는 모델만 기록하고 나머지를 생략한다.

이 혼동은 가설이 아니다. 저자들이 드는 사례들:

  • SWE-bench Pro: 표준화된 SEAL scaffold 하에서 Claude Opus 4.5가 45.9%인데, Claude Code 하에서 같은 모델이 55.4%에 도달한다.
  • WarpGrep 검색 subagent 하나를 다른 조건이 동일한 인프라에 추가하면 MiniMax 2.5와 Claude Opus 4.6의 SWE-bench Pro 순서가 뒤집힌다 — Claude Opus가 대부분의 다른 벤치마크에서 더 높은데도.
  • HAL(Holistic Agent Leaderboard)은 SWE-bench Verified Mini에서 같은 모델의 scaffold 간 두 자릿수 격차를 보고하며, 프론티어 모델 단일 모델 스윙이 거의 48%p에 이른다.
  • 독립 제3자 벤치마크 모니터링은 SWE-bench Verified에서 GPT-5에 11%p, Kimi K2 Thinking에 15%p의 scaffold만의 변동을 보고한다.

저자들의 결정적 문장: ##이 중 어느 것도 모델 업그레이드가 아니다. 전부 harness 교체이며, 논문들이 유의미한 모델 진보로 보고하는 2~4%p 변화를 일상적으로 압도한다.##

귀속 격차가 왜 중요한가: 같은 합성수가 양립 불가능한 세 방식으로 읽히고 있다 — (i) 논문 간 모델 비교에서는 모델 성질로, (ii) 분야 진보 추적에서는 벤치마크 성질로, (iii) 배포 결정에서는 에이전트 성질로. 세 번째만이 well-defined하다. 앞의 둘은 현재 보고가 제공하지 않는 분리를 요구한다.

구조적 이유 — 에이전트는 폐루프 시스템이다 (§2.2)

이 혼동은 에이전트가 작동하는 방식에 대한 구조적 사실을 반영한다. 에이전트 실행은 이산시간 폐루프 동역학 과정이다.

스텝 $t$에서의 에이전트 상태를 $s_t$라 하자 — 전체 컨텍스트 창과 지속 메모리를 포함한다. 모델은 확률적 정책으로 작동한다.

$$a_t \sim \pi_\theta(\cdot \mid c(s_t))$$

여기서 $c$는 harness가 구현하는 컨텍스트 구성 함수다. harness는 제어기 $C$를 구현해 $(s_t, a_t, o_t)$로부터 $s_{t+1}$로 상태를 갱신하며, $o_t$는 환경 관측으로서 상태에 통합되기 전에 필터링·검증된다. 서로 다른 harness 구성 $H$는 같은 모델 $\pi_\theta$ 위에 서로 다른 제어기 $C_H$를 유도한다.

이 모형에서 LLM은 open-loop다. 저자들이 나열하는 세 가지 결여:

  1. $s_t$에 직접 접근하지 못한다 — harness가 노출하기로 선택한 상태의 투영 $c(s_t)$만 본다.
  2. 스텝 간 메모리를 유지하지 못한다 — $C_H$가 $c(s_{t+1})$에 주입하는 것 외에는.
  3. $C_H$가 $o_t$로부터 구성하는 피드백 경로 외에는 자기 교정 메커니즘이 없다.

##따라서 적응, 오류 복구, long-horizon 일관성은 $C_H$의 성질이지 $\pi_\theta$의 성질이 아니다.##

이 논문에서 가장 인용할 만한 문장: "교훈은 에이전트보다 넓다. Open-loop 시스템은 더 큰 액추에이터로 신뢰성을 얻지 않는다. 피드백 제어로 신뢰성을 얻는다." — 이것이 "모델을 키우면 harness 문제가 해소된다"는 반론에 대한 구조적 답이다.

네 가지 표준 대응이 왜 부족한가 (§2.3)

혼동이 구조적이라면 무엇을 할 것인가. 분야는 네 부류의 대응으로 수렴했는데, 각각 문제의 일부를 다루지만 어느 것도 귀속 질문을 해결하지 못한다.

대응구현 사례왜 부족한가
① 단일 harness로 표준화HAL(9개 벤치마크), SWE-bench Pro 통합 scaffold, Epoch AI의 mini-SWE-agent 권고저자들이 부분적으로 지지한다(두 유효 레짐 중 하나). 그러나 어떤 표준 harness든 모델 성질과 상호작용하는 설계 선택을 내장하고, 현재 증거가 크다고 보이는 harness 쪽 이득을 봉쇄한다. 요구는 통일이 아니라 공개다
② 모델 스케일링"충분히 유능한 모델이 자기 제어기를 관리할 것"##경험적 추세가 반대다## — Claude Code는 능력이 커지면서 harness 컴포넌트를 제거한 게 아니라 재설계했고, managed-agents 아키텍처는 harness 가정이 모델 개선보다 빨리 낡기 때문에 모델과 harness를 명시적으로 분리하며, AHE는 프론티어 base model 위에서 두 자릿수 이득을 낸다
③ 벤치마크 추가freelance 소프트웨어, ML 엔지니어링, 오염 내성 코딩, 코드 합성, 시각 프론트엔드, 전문 서비스##이 내기는 실패한다## — 각 벤치마크가 자기만의 미공개 harness를 쓰고, harness 기여의 평균이 0이 아니므로 벤치마크를 늘리는 것은 독립적인 {모델, harness} 추출을 더할 뿐 어느 하나 안의 귀속도 해결하지 못한다. APEX-Agents는 정반대를 발견한다 — 에이전트 실패가 지식 실패가 아니라 실행·조율 문제가 지배적이다

저자들의 결론: 구조적 문제는 구조적 해법을 요구한다 — 공개(disclosure). 점수를 만든 harness는 실험 조건의 일부여야 하고, 모델 간 비교는 harness를 고정하거나(locked-harness) 통제 인자로 변화시켜야 한다(factorial).

1. Binding Constraint Thesis (§3)

The Binding Constraint Thesis — long-horizon 과제에서 능력이 비슷한 프론티어 모델들로 평가할 때, $B(M,H)$를 모델 $M \in \mathcal{M}$이 harness $H \in \mathcal{H}$ 하에서 얻은 벤치마크 점수라 하고 다음을 정의한다.

$$HV(M) = \mathrm{Var}_{H \sim P(H)}\big[B(M,H)\big], \qquad MV(H) = \mathrm{Var}_{M \sim P(M)}\big[B(M,H)\big]$$

이 레짐에서 HV는 흔히 MV와 비슷하거나 더 크며, 현재의 많은 long-horizon 에이전트 평가에서 MV를 지배할 수 있다. 현재 벤치마크 프로토콜은 단일 미공개 $H^*$에 대한 $B(M, H^*)$만 보고하므로 ##HV를 측정 불가능하게 만들고 모델 비교를 불완전하고 잠재적으로 오도하게 만든다##.

1.1 분산 분해 — 방법론적 핵심

$\{M, H\}$ 추출 모집단에 대한 전체 성능 분산은 정확히 다음과 같이 분해된다.

$$\mathrm{Var}\big[B(M,H)\big] = \underbrace{\mathrm{Var}_M \mathbb{E}_H\big[B(M,H)\big]}_{MV} + \underbrace{\mathrm{Var}_H \mathbb{E}_M\big[B(M,H)\big]}_{HV} + \underbrace{\mathrm{Var}\big[\text{model} \times \text{harness}\big]}_{\text{interaction}} \tag{1}$$

주장은 두 번째와 세 번째 항이 합쳐서 첫 번째를 지배한다는 것이다.

interaction 항이 왜 무시할 수 없는가: 폐루프 설명에 따르면, 자기 검증을 강조하는 harness는 false-confidence 비율이 높은 모델에게 보수적 출력 분포를 가진 모델보다 더 많이 도움이 된다. 따라서 같은 harness 변화가 모델마다 다른 이득을 낸다.

##모델 순위를 모델의 성질로 취급하려면 interaction 항이 MV에 비해 작아야 하는데, 이 주장은 그 조건을 부정한다.##

1.2 harness 제어기의 세 가지 신뢰성 양 (§3.2)

안정성, 컨텍스트 드리프트, 제어 지연이 harness 구성이 분산을 만드는 세 구조적 통로다. 각각은 $C_H$의 성질이지 $\pi_\theta$의 성질이 아니고, 각각은 현재 평가가 단일 합성 점수로만 포착하는 경험적 실패 모드에 대응한다.

정의 1 (Stability). 에이전트 실행이 안정적이라 함은 Lyapunov 유사 측도 $V(s_t) = d(s_t, \Omega^*)$가 제어기 $C$ 하에서 기대값으로 비증가한다는 것이다. $\Omega^*$는 목표 일관 상태 집합, $d$는 과제 특정 거리 측도다.

$$\mathbb{E}\big[V(s_{t+1}) \mid s_t\big] \leq V(s_t) \quad \forall t$$

불안정성의 경험적 발현: hallucination spiral, 컨텍스트 오버플로, 실행 runaway — ##전부 정책 실패가 아니라 제어기 실패다##.

정의 2 (Context Drift). $p_t$를 스텝 $t$에서 컨텍스트 창 임베딩의 분포라 하자(고정 임베딩 모델로 전체 컨텍스트 창을 인코딩해 얻는다). 컨텍스트 드리프트는 현재 컨텍스트 분포가 초기 과제 관련 상태 $p_0$로부터 벌어진 정도다.

$$\delta_t = D_{KL}(p_t \| p_0), \qquad \dot\delta = \delta_t - \delta_{t-1}$$

높은 드리프트율 $\dot\delta$는 제어기가 컨텍스트 창에 과제 관련 정보를 유지하지 못하고 있음을 뜻하며, 경험적으로 과제 포기와 긴 지평에서의 의미적 비일관성과 상관한다. ##드리프트는 컨텍스트 구성 정책 $c$를 통해 harness 구성 $H$의 성질이다 — 제어기가 관리에 실패하면 모델의 어떤 성질도 드리프트를 막을 수 없다.##

정의 3 (Control Lag). harness 특정 신뢰성 측도로 제어 지연 $\tau$를 제안한다 — harness가 이상을 감지한 시점(도구 실패, 잘못된 출력, 빈 결과)과 교정 행동이 피드백 경로를 통해 정책에 도달하는 시점 사이의 스텝 수다. 이상이 스텝 $t_d$에서 감지되고 교정 관측 $o_{t_c}$가 스텝 $t_c$에서 정책에 도달하면

$$\tau = t_c - t_d$$

##높은 $\tau$는 실패 캐스케이드를 가능하게 한다 — 정책이 harness가 오류를 처리하는 동안 $\tau$ 스텝에 걸쳐 손상된 상태 위에서 계속 행동하며 교정이 도달하기 전에 피해를 복합시킨다.##

세 양이 왜 함께 제시되는가: 자기 검증(안정성에 영향), 컨텍스트 압축(드리프트에 영향), 이상 복구(제어 지연에 영향)에서 다른 두 구성 $H_1, H_2$는 고정된 $M$에 대해 각각 $B(M,H)$를 이동시키며 HV에 독립적으로 기여한다. 즉 이 세 양이 "HV는 무엇의 분산인가"에 답한다.

구조적 비대칭의 핵심: 더 유능한 모델은 이상이 발생하는 기저율(base rate)을 낮출 수 있고 그만큼 $C_H$에 대한 요구를 줄인다. ##그러나 이상이 일단 발생한 뒤의 대응은 $C_H$의 성질이며, 모델을 업그레이드해도 개선되지 않는다.## 이것이 이 주장이 그럴듯한 구조적 이유다.

1.3 범위, 반증 가능성, 함의 (§3.3)

범위: 이 주장은 long-horizon 과제와 비슷한 프론티어 모델로 제한된다.

  • Long-horizon이란 최종 결과에 도달하기 위해 다단계 도구 사용, 오류 복구, 컨텍스트 관리가 필요한 과제를 뜻한다. 폐루프 신뢰성 양들은 그런 지평에서만 작용할 기회를 갖는다.
  • 비슷한 프론티어 모델이란 모델 능력 격차가 harness 구성과 무관하게 MV가 기계적으로 지배할 만큼 크지 않은 레짐을 뜻한다.

저자들이 정확히 말할 수 있다고 하는 것은 무엇이 레짐 밖에 있는가다 — 단기 지평 과제, 그리고 한 모델이 관련 기술에서 다른 모델들보다 극적으로 유능한 구성. ##남는 레짐이 바로 벤치마크 리더보드가 연구와 제품 결정을 주도하는 레짐이다.##

반증 가능성: 이 주장은 경험적이다. $H$를 변화시키고 $M$을 고정하는 factorial 실험과 그 반대를 수행해, 비슷한 모델 능력 하의 long-horizon 과제 분포에서 $MV > HV$를 발견하면 반증된다. 저자들은 이 주장이 공허하지 않음을 강조한다 — 그런 결과는 원리적으로 상상 가능하고, 자기들의 통제된 격자가 분산 순서를 경험적 질문으로 만든다.

position paper로서 이례적인 점: 대부분의 입장 논문은 반증 조건을 제시하지 않는다. 이 논문은 구체적 실험 설계로 반증 조건을 명시하고, 나아가 동시기 심리측정 연구(에이전트 능력을 독립적인 LLM 성분과 scaffold 성분으로 분해하는)를 외부 프로브로 지목하며 — scaffold 능력 분산이 벤치마크 전반에서 체계적으로 LLM 능력 분산보다 작다면 이 주장은 그 연구와 긴장 관계에 놓인다고 밝힌다.

3. harness-aware 평가 프레임워크 (§5)

long-horizon 에이전트 평가는 세 구성요소를 갖춘 harness-aware 프레임워크를 채택해야 한다 — 구조화된 공개 카드, 분산 분해 프로토콜, 짧은 궤적 수준 지표 집합. 이 셋이 함께 harness 분산을 보고 가능하고, 해석 가능하고, 귀속 가능하게 만든다.

3.2 분산 분해 프로토콜

분산 분해는 다음 조건에서 프로토콜이 된다 — 평가가 같은 모델을 최소 두 개의 의미 있게 다른 harness로, 그리고 같은 harness를 최소 두 모델로 고정 과제 집합에서 실행할 때.

최소 유효 설계: 2×2 모델×harness 격자. 과제 순서, 실행 환경, 평가 스크립트, API 파라미터, 정지 규칙을 고정한 채로.

"의미 있는 harness 차이"의 기준: ##ETCSOVG 층 중 최소 하나를 안정성·드리프트·제어 지연에 영향을 줄 것으로 예상되는 방식으로 바꾸어야만 의미 있는 차이로 친다.## 예: retrieval 기반 컨텍스트 압축, 도구 스키마와 오류 형식 변경, 검증·복구 훅 추가.

보고할 네 통계 (헤드라인 점수와 함께):

  1. 모델별 HV와 harness별 MV
  2. 집계 비율 HV/MV
  3. harness 간 모델쌍 순위 역전 수
  4. 부분 에타제곱 계수 — $\eta_p^2 = \dfrac{SS_{interaction}}{SS_{interaction} + SS_{error}}$ (고정효과 이원 ANOVA의 제곱합)

$\eta_p^2$에 대한 세 가지 유보(저자들이 스스로 명시):

  • 선택된 격자에 대한 고정효과 양이다 — harness가 더 큰 모집단에서 표집된다면 적절한 양은 혼합효과 모형의 분산 성분 $\sigma_{MH}^2$다
  • 작은 격자에서 양의 편향을 가지므로 $\omega^2$나 부트스트랩 구간과 함께 보고해야 한다
  • 큰 $\eta_p^2$는 순위 뒤집힘의 필요조건도 충분조건도 아니므로 명시적 역전 수와 짝지어야 한다

비판적 분석 (Critical Analysis)

강점

  • position paper인데 통제된 실험을 한다. 대부분의 입장 논문은 주장과 인용으로 끝난다. 이 논문은 3모델 × 3harness × 100문항 × 2회 실행 격자를 돌려 HV/MV = 7.80배, 순위 역전 6/9를 직접 측정한다. 조건 통제도 촘촘하다 — 과제 순서, Docker 환경, 평가 파이프라인, 50스텝 예산, 120초 타임아웃을 전부 고정했다. ##"입장"을 "검증 가능한 주장"으로 바꾼 것이 이 논문의 가장 큰 미덕이다.##
  • 반증 조건을 구체적으로 명시한다. "$H$를 변화시키고 $M$을 고정하는 factorial과 그 반대를 수행해 비슷한 능력 하 long-horizon 과제에서 $MV > HV$를 발견하면 반증된다"고 쓴다. 나아가 동시기 심리측정 연구를 외부 프로브로 지목하며 자기 주장이 그 연구와 긴장 관계에 놓일 조건까지 밝힌다. position paper에서 드문 수준의 지적 정직성이다.
  • 제어이론 형식화가 장식이 아니라 예측을 낳는다. "LLM은 open-loop"라는 프레이밍에서 세 가지 검증 가능한 귀결이 따라 나온다 — 안정성·드리프트·제어 지연이 모델을 바꿔도 개선되지 않는다는 것. 그리고 이 셋이 §5의 세 궤적 지표(RR, Context Retention, $\tau$)로 직접 조작화된다. ##형식화 → 정의 → 지표 → 귀속의 사슬이 끊기지 않는다.##
  • "$\tau$는 모델을 바꿔도 변하지 않는다"는 논거가 특히 강하다. 더 좋은 모델은 이상의 기저율을 낮출 뿐, 이상이 발생한 뒤 교정 신호가 몇 스텝 만에 도착하는가는 harness의 관측성·도구 층이 정한다. 이것이 "모델을 키우면 해소된다"는 반론에 대한 구조적(경험적이 아니라) 답이다.
  • 네 반론을 정면으로, 그리고 공정하게 다룬다. 특히 반론 ④("harness는 에이전트의 일부")에 대해 "배포에 대한 서술로는 옳다"고 먼저 인정한 뒤 배포형 귀속과 모델비교형 귀속을 분리한다. 반론 ②(표준화)에 대해서도 부분적으로 지지한다고 명시하고 locked-harness를 두 유효 레짐 중 하나로 인정한다. ##"우리 입장만 옳다"가 아니라 "이 구분이 필요하다"는 논조가 설득력을 높인다.##
  • "harness를 통일하라"가 아니라 "공개하라"는 요구가 현실적이다. 표준화가 실무에서 균일해지지 않을 이유를 명확히 든다 — 벤더는 런타임 층에서 차별화할 강한 경쟁 유인을 갖는다. 이 관찰이 처방을 실행 가능하게 만든다.
  • 공개 증거의 관찰적 성격을 스스로 표시한다. "공개 harness들은 여러 차원에서 다르고 서로 다른 팀이 서로 다른 엔지니어링 예산으로 만들었으므로, 공개 데이터만으로는 어느 컴포넌트가 분산을 만드는지 분리할 수 없다"고 쓴 뒤 그래서 통제 실험을 했다고 이어간다. 증거의 층위를 정확히 구분한다.
  • $\eta_p^2$의 세 가지 통계적 유보를 스스로 단다. 고정효과 양이라는 점, 작은 격자에서 양의 편향이 있다는 점, 순위 뒤집힘의 필요·충분조건이 아니라는 점. 자기가 제안하는 지표의 한계를 제안과 동시에 밝히는 것은 흔하지 않다.

한계와 의문점

  • 격자가 작고 반복이 2회뿐이다 — 이것이 가장 큰 약점이다. 3×3 = 9개 셀, 셀당 2회 실행, 100문항. ##pass@1이 100문항 기준이므로 1문항이 1%p이고, 2회 실행의 표준오차가 보고되지 않는다.## 예컨대 $H_2$에서 GPT-5.4 58.5 vs Kimi K2.6 59.0의 0.5%p 차이는 1문항의 절반이며, 이것이 순위 역전 6건 중 하나를 만든다. 역전 수가 이 논문의 핵심 통계인데 그중 몇 개가 통계적으로 유의한지 알 수 없다.
  • 제안한 세 궤적 지표를 자기 실험에서 측정하지 않는다. 저자들이 명시하듯 RR($k$), Context Retention, $\tau$는 "향후 평가의 보고 요건으로 명세"된 것이다. 그런데 §3.2의 세 정의가 이 논문의 이론적 중심이므로, 자기 격자에서 이 셋을 재서 $H_1 \to H_2 \to H_3$의 변화를 보였다면 형식화와 실험이 연결되었을 것이다. 지금은 궤적 로그 분석이 "제어 잡음 감소"·"검증 복구 루프" 같은 정성적 서술로만 제시된다.
  • $H_1$이 "지나치게 약한 baseline"일 수 있다. $H_1$은 압축 없음, verbose 스키마, 재시도 없음, 검증 훅 없음, 이상 복구 없음이다 — ##현실에서 아무도 이렇게 배포하지 않는다.## $H_1 \to H_3$의 8.5~13.0%p 중 상당 부분이 "아무것도 없음 → 기본적인 것"의 이득일 수 있고, 실무적으로 중요한 질문인 "괜찮은 harness 두 개 사이의 차이"는 $H_2 \to H_3$(4.0~9.0%p)만이 답한다. 그리고 그 구간에서도 GLM-5.1은 9.0%p인데 Kimi K2.6은 1.5%p로 편차가 매우 크다.
  • "비슷한 프론티어 모델"의 선정이 순환적이다. 세 모델을 "LLM Stats 코딩 리더보드에서 밀집해 있었다"는 이유로 골랐는데, ##저자들 자신이 §7에서 "리더보드 근접성이 그 자체로 harness에 교란되어 있다"고 인정한다.## 즉 교란된 지표로 비교가능성을 판정한 뒤 그 교란을 보이는 구조다. 저자들이 이 문제를 열린 질문 ①로 명시하는 것은 정직하지만, 그것이 자기 실험 설계의 타당성에도 적용된다는 점은 짚지 않는다.
  • HV/MV 비율이 $P(H)$ 표집 분포에 전적으로 의존한다. 저자들도 열린 질문 ②로 인정하듯, harness 세 개를 의도적으로 세 신뢰성 양을 따라 벌려서 만들었으므로 HV가 크게 나오는 것은 설계의 결과이기도 하다. 만약 $H_1, H_2, H_3$를 모두 "합리적인 프로덕션 harness" 중에서 골랐다면 비율이 훨씬 작았을 것이다. ##7.80배는 harness 공간을 어떻게 표집하느냐의 함수이지 자연 상수가 아니다.##
  • 공개 증거 중 일부의 출처 추적이 어렵다. Grok 4의 "SWE-agent → xAI scaffold, 58.6% → 72~75%"는 범위로 제시되고, "코딩 벤치마크에서 ~10배"는 무엇의 10배인지 본문에서 명확하지 않다(Table 1의 Δ 열에만 등장). Vercel의 "80% → 100%"도 과제 수와 조건이 불명이다. 블로그·리포트 출처의 수치를 표에 넣으면서 측정 조건을 함께 싣지 않은 것은 이 논문이 요구하는 공개 표준과 긴장한다.
  • Harness Card가 부록에만 있고 실제 사례가 없다. ETCSOVG 층별 공개 요건이 부록 A Table 3에 있다고 하지만, 본문에 채워진 예시 카드가 하나도 없다. 자기 실험의 $H_1/H_2/H_3$를 Harness Card 형식으로 제시했다면 제안의 실행 가능성을 직접 보였을 것이다.
  • 비용 축이 완전히 빠져 있다. $H_3$는 스텝별 자기 점검, 5스텝마다 드리프트 점검, 이상 감지 미들웨어, 최근 10상태 checkpoint를 돌린다 — $H_1$보다 훨씬 비싸다. 그런데 토큰·시간·비용 비교가 없다. "harness가 13%p를 준다"는 주장은 그 13%p가 얼마짜리인지를 알 때만 실무 결정에 쓸 수 있다. 논문이 배포 결정을 명시적 청중으로 삼으면서 이 축을 빼놓은 것은 일관성 문제다.
  • 단일 벤치마크·단일 도메인이다. 통제 실험이 SWE-bench Verified(코딩) 하나에서만 이루어졌다. §3.3에서 범위를 "long-horizon 과제"로 잡았지만 웹·GUI·연구·업무 도메인에서 같은 비율이 나오는지는 알 수 없다. 특히 강한 자동 oracle이 있는 코딩은 검증·복구 루프($H_3$의 핵심)가 가장 잘 작동하는 도메인이므로 HV가 과대평가될 수 있는 조건이다.
  • "harness 공개"의 실행 가능성이 낙관적이다. 저자들이 지적하듯 벤더는 런타임 층에서 차별화할 경쟁 유인을 갖는다 — 그렇다면 왜 벤더가 Harness Card를 공개하겠는가? 논문은 열린 질문 ③에서 "공개만으로는 적대적 harness 선택을 다루지 못할 수 있다"고 인정하지만, 공개 유인 자체의 부재는 다루지 않는다. 학계 논문에는 적용 가능한 규범이지만 리더보드를 지배하는 벤더 제출에는 강제력이 없다.

Key Takeaways — 이 논문에서 가져갈 것

  1. 리더보드를 읽는 방식을 바꾸는 한 문장. ##"모든 벤치마크 점수는 {모델, harness} 쌍이 만든 합성수인데 절반만 보고된다."## 이제부터 남의 비교표를 볼 때 harness가 명시되어 있는가를 먼저 확인하게 된다. 명시되어 있지 않으면 그 표는 model–harness 시스템 비교이지 모델 비교가 아니다 — 그리고 대부분의 표가 그렇다.
  2. 제어이론 프레이밍이 실무 진단을 바꾼다. hallucination spiral, 컨텍스트 오버플로, 실행 runaway를 "모델이 이상하다"로 분류하면 처방이 모델 교체가 된다. 제어기 실패로 분류하면 처방이 안정성 강제·드리프트 관리·제어 지연 단축이 된다. 특히 $\tau$(이상 감지 → 교정 도달 스텝 수)는 자기 시스템에서 즉시 계측 가능하고, 모델을 바꿔도 변하지 않는 양이다.
  3. 2×2 최소 격자를 자기 평가에 도입하라 — 비용이 작다. 같은 모델 × 2개 harness, 같은 harness × 2개 모델이면 HV·MV·순위 역전을 계산할 수 있다. 실행 4회면 된다. ##그리고 harness 차이는 "의미 있어야" 한다 — ETCSOVG 층 중 최소 하나를 안정성·드리프트·제어 지연에 영향을 줄 방식으로 바꿔야 한다.## 아무 프롬프트 변경이나 세면 무의미하다.
  4. harness 효과의 크기는 모델 간 격차 대비로 읽어라. WarpGrep 사례가 이 논문에서 가장 통찰적이다 — 2.1%p는 절대값으로 작지만 SEAL 하 상위 6모델 전체 폭(4.9%p)의 43%이므로 순위를 뒤집는다. 프론티어 모델들이 수렴할수록 이 비율이 커지고, 따라서 harness 공개의 필요성은 시간이 갈수록 커진다(모델 격차가 좁아지므로).
  5. 배포 결정과 모델 선택을 다른 질문으로 다뤄라. 배포에는 리더보드 점수를 써도 되지만 자기가 쓸 harness와 같은 harness의 점수여야 한다 — "Claude Code로 배포할 거면 Claude Code 점수를 보라". 모델을 고를 때는 harness가 명시된 점수를 찾거나 자기 harness에서 직접 재야 한다. ##같은 숫자가 두 역할을 겸할 수 없다.##
  6. 실무 우선순위: 모델 교체보다 harness 개선의 기대 이득이 크다 — 단, 비용을 모른다. 통제 격자에서 harness 8.5~13.0%p vs 모델 2.5~5.0%p다. 그러나 이 논문은 $H_3$가 얼마나 비싼지 보고하지 않는다(스텝별 자기 점검 + 5스텝마다 드리프트 점검 + 이상 감지 + checkpoint 10개). 자기 시스템에 도입할 때 토큰·지연을 함께 재라 — survey 논문(2606.20683)이 보고하듯 큰 컨텍스트가 타임아웃을 줄이는 반직관적 경우도 있다.
  7. "모델을 키우면 해소된다"에 대한 구조적 반박을 기억하라. 더 좋은 모델은 이상의 기저율을 낮출 뿐, 이상이 발생한 뒤의 감지·전달·복구는 harness의 몫이다. 그리고 궤적이 길수록 "이상이 한 번도 안 생길 확률"이 낮아지므로 long-horizon일수록 제어기의 비중이 커진다. 저자들의 표현 — "Open-loop 시스템은 더 큰 액추에이터로 신뢰성을 얻지 않는다. 피드백 제어로 얻는다."
  8. 비판적으로: 수치보다 어휘를 가져가라. 7.80배는 harness 공간을 어떻게 표집했느냐의 함수이고($H_1$은 현실에서 아무도 배포하지 않는 구성이다), 순위 역전 6건 중 3건은 문항 0.5개 격차에 의존하며 표준오차가 없다. 그리고 통제 실험은 코딩 벤치마크 하나에서만 이루어졌다 — 강한 자동 oracle이 있어 검증·복구 루프가 가장 잘 작동하는, 즉 HV가 과대평가되기 쉬운 도메인이다. 안전하게 남는 것은 개념적 도구다: HV/MV 분해 · 순위 역전 수 · 세 신뢰성 양 · Harness Card 7층. 이 넷이 앞으로 이 논의에서 쓸 어휘다.
