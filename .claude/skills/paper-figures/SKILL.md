# 논문 요약용 SVG 그림 작성 가이드

기준 예시(golden reference): `20260728_kimiteam_kimik3.html`
— 47페이지 논문 → 4,841줄 / SVG 그림 55개 / 모든 그림에 3~5문장 분석형 캡션.

HTML 골격은 `assets/summary_template.html`을 복사해서 시작한다. head 안의
KaTeX 설정(`ignoredTags`에 `svg` 포함), 목차 자동 생성 스크립트, 그림 번호
자동 부여 스크립트, `figure`/`figcaption`/`#toc`/`.small-table` CSS가 이미 들어 있다.

---

## 1. 몇 개를 그릴 것인가

| 논문 분량 | SVG 그림 최소 개수 |
|---|---|
| ~10 페이지 | 12개 |
| 10~20 페이지 | 20개 |
| 20~35 페이지 | 30개 |
| 35 페이지+ | 45개 |

추가 규칙:
- **논문의 모든 주요 Figure는 재현한다.** 재현 대상을 고르지 말고, 의미 있는 것은 다 그린다.
- **주요 h3(하위 절)마다 최소 1개.** 그림 없는 절이 3개 연속 나오면 밀도가 부족하다는 신호다.
- **핵심 수식마다 수치 예제 그림 1개** (아래 유형 C). 이것이 이 포맷의 차별점이다.
- 첫 번째 그림은 항상 **논문 전체 지도**(유형 D)로 시작한다.

## 2. 그림의 4가지 유형

캡션 머리말로 유형을 구분한다. 그림 번호는 JS가 자동으로 앞에 붙이므로 직접 쓰지 않는다.

### A. 논문 Figure 재현 — `[Figure N 재구성]` / `[Figure N 설명]`
논문에 실제로 있는 그림을 SVG로 다시 그린다.
- `재구성`: 논문 그림의 구조를 옮기되 레이아웃·주석을 요약에 맞게 재배치한 것
- `설명`: 논문 그림의 내용을 거의 그대로 옮긴 것
- 논문 그림에 축 값이 없거나 정보가 빠져 있으면 **캡션에 그 사실을 명시**한다
  (예: "원문 그림에는 축 값이 표시되지 않으며, 2.5×가 보간인지 외삽인지 판별할 수 없다").
  없는 숫자를 그려 넣지 않는다. 개념적으로 재구성한 부분은 "중간 궤적 모양은 개념 재구성"처럼 밝힌다.

### B. 개념도 — `[Figure: <제목>]`
논문에 그림이 없는 메커니즘을 직접 도식화한다. 아키텍처 데이터 흐름, attention/masking
패턴, 학습 curriculum, 파이프라인, 시스템 계층 구조, 두 방법의 대비(before/after) 등.

### C. 수치 예제 — `[Figure: <수식/개념> 수치 예제]`  ★ 가장 중요
핵심 수식을 **작은 장난감 입력에 직접 대입해 계산 과정을 표로 그린다.**
- 2×2 행렬, 4~8 토큰, 4개 전문가처럼 손으로 따라갈 수 있는 크기를 쓴다
- 스텝별 중간값을 전부 적고, 어느 칸이 요점인지 색으로 표시한다
- 하이퍼파라미터가 왜 그 값인지 역산해 보인다 (예: `g_min = -5` → 16토큰 누적 `-80` → `e^80 ≈ 5.5e34` → BF16 범위 안)
- 통신량/메모리/비용 계산도 이 유형이다 (예: 토큰당 1.33 MB → 129 KB, 10.3배 절감)
- 논문에 없는 계산이므로 캡션에 "논문의 수치를 따라 재구성" 같은 단서를 남긴다

### D. 전체 지도 — `[Figure: 논문 전체 지도]`
문서 맨 앞. 출발 문제 → 축/컴포넌트 → 안정화·인프라 → 결과를 한 장에 담고,
각 박스에 절 번호(§1.1 등)를 달아 문서 내 위치를 알려준다.

## 3. 캡션 작성 규칙

캡션은 "그림 설명"이 아니라 **짧은 분석 문단**이다. 2~5문장, 100~400자.

포함할 것:
1. 무엇이 그려져 있는가 (색·기호의 의미 포함: "주황은 직렬 전파, 파랑은 병렬 구간")
2. 왜 그것이 중요한가 / 무엇이 요점인가
3. **다른 절과의 연결** — `§4.1.1`처럼 절 번호로 상호 참조한다. 이 상호 참조가 문서를 하나의 논증으로 묶는다
4. 해당되면 한계·불확실성 (원문에 없는 정보, 판별 불가한 주장)

형식:
```html
<figcaption><strong>[Figure 3 설명]</strong>: (a) … (b) …</figcaption>
```

나쁜 캡션: "Figure 3. 아키텍처 전체 구조."
좋은 캡션: "두 어텐션이 서로 다른 일을 맡는다. KDA가 위치·최신성을 담당하므로 MLA는 위치
인코딩을 버릴 수 있고(NoPE), 그 결과 컨텍스트를 1M으로 늘릴 때 위치 인코딩 파라미터를 손댈
필요가 없다. 캐시 관점에서는 층의 3/4이 길이에 무관한 고정 크기 상태를 쓰므로 …"

## 4. SVG 작성 규칙

```html
<figure>
<svg viewBox="0 0 800 500" xmlns="http://www.w3.org/2000/svg" font-family="sans-serif">
  <defs><marker id="arwA" markerWidth="9" markerHeight="9" refX="7" refY="3" orient="auto">
    <path d="M0,0 L0,6 L8,3 z" fill="#666"/></marker></defs>
  <text x="400" y="20" text-anchor="middle" font-size="15" font-weight="bold">그림 제목</text>
  <rect x="30" y="34" width="740" height="40" rx="7" fill="#dbeafe" stroke="#3b82f6"/>
  <text x="400" y="58" text-anchor="middle" font-size="11.5" font-weight="bold">박스 라벨</text>
  <path d="M400,76 L400,90" stroke="#666" marker-end="url(#arwA)"/>
</svg>
<figcaption><strong>[Figure: …]</strong>: …</figcaption>
</figure>
```

지켜야 할 것:
- **`viewBox`만 쓰고 `width`/`height` 속성은 쓰지 않는다** (CSS `max-width:100%`가 반응형 처리)
- 폭은 `0 0 780 …` ~ `0 0 800 …`이 본문 폭(860px)에 맞는다. 높이는 내용에 따라 200~560
- `<svg>`에 `font-family="sans-serif"`를 걸고, 텍스트마다 `font-size`를 명시한다
  (제목 14~15, 박스 제목 11~12, 본문 10~10.5, 주석 9~9.5)
- **`marker` id는 그림마다 다르게** 짓는다 (`mapA`, `ck1`, `kcp2`…). 한 문서에 55개 SVG가
  들어가므로 id 충돌이 실제로 발생한다
- 텍스트 줄바꿈은 없다. **여러 `<text>` 요소를 y좌표 15~18px 간격으로 쌓는다**
- 좌표는 손으로 계산한다. 박스와 텍스트가 겹치지 않게 `y`는 박스 상단 +18, +36, +52 식으로
- **SVG 안에서는 `$…$` KaTeX 문법이 렌더링되지 않는다** (head에서 `svg`를 ignoredTags로 제외).
  SVG 안에서는 유니코드로 쓴다: `Γ ⊙ Q[t] · S[t]`, `e⁸⁰`, `α ∈ (0,1)`, `−5`(U+2212)
- SVG 안에서 `<`, `>`, `&`는 `&lt;` `&gt;` `&amp;`로 이스케이프한다
- 표 형태의 수치 예제는 `<rect>` 격자 + `<text>`로 그린다 (foreignObject 쓰지 않음)

## 5. 색상 팔레트 (Tailwind 계열, 문서 전체에서 일관 유지)

| 의미 | fill | stroke |
|---|---|---|
| 중립/배경 | `#f1f5f9` | `#64748b` |
| 주 경로·핵심 (파랑) | `#dbeafe` | `#3b82f6` |
| 강조·병목 (주황/노랑) | `#fef3c7` | `#f59e0b` |
| 성과·개선 (초록) | `#dcfce7` | `#16a34a` |
| 문제·실패 (빨강) | `#fef2f2` | `#ef4444` |
| 대안·보조 (보라) | `#f3e8ff` | `#a855f7` |
| 경고 박스 | `#fffbea` | `#eab308` |

텍스트 강조색은 stroke보다 진하게: 파랑 `#1e40af`, 주황 `#92400e` / `#b45309`, 회색 `#666` / `#555`.
비교 그림에서 **"기존 방법 = 주황, 이 논문 = 파랑"** 규칙을 문서 전체에 일관되게 적용한다.

## 6. 도식 유형 카탈로그 — ★ 유형을 다양하게 쓴다

**가장 흔한 실패는 문서 전체가 "박스 + 화살표"로만 채워지는 것이다.**
읽는 사람은 20개의 비슷한 흐름도를 구분하지 못한다. 다음 규칙을 지킨다:

- 한 문서에서 **서로 다른 도식 유형을 최소 6종** 사용한다
- **박스+화살표(파이프라인/블록도)는 전체 그림의 1/3 이하**로 제한한다
- 데이터가 있으면 **먼저 데이터 시각화(차트)를 고려**하고, 흐름도는 데이터가 없을 때 쓴다
- 같은 유형을 연속 3개 쓰지 않는다. 앞 그림과 다른 유형을 고른다

### 6.1 데이터 시각화 — 수치가 있으면 이쪽을 먼저 쓴다

| 유형 | 언제 쓰나 | 그리는 법 |
|---|---|---|
| **가로 막대** | 항목 5~12개 비교, 라벨이 길 때 | 좌측에 라벨, `rect` 폭 = 값 비례, 막대 끝에 수치 |
| **그룹 막대** | 2~3 조건 × 여러 항목 | 항목마다 막대 2~3개를 4px 간격으로 |
| **누적 막대** | 구성비 분해 (전체=100%) | `rect`를 옆으로 이어붙이고 각 조각에 % |
| **덤벨 / 슬로프** ★ | **before→after 쌍 비교** (가장 자주 쓰게 된다) | 두 점을 `circle`로, 사이를 굵은 `line`으로 잇고 화살표. 개선=초록, 악화=빨강 |
| **워터폴** | 기여도 분해 (시작 → +a → −b → 최종) | 떠 있는 `rect`를 계단식으로, 증감은 색으로 |
| **도넛 / 파이** | 3~5개 범주 비율 (실패 유형 분포 등) | `<path d="M cx cy L x1 y1 A r r 0 flag 1 x2 y2 Z">`. 각도는 손으로 계산 |
| **히트맵 / 행렬** ★ | **N개 모델 × M개 벤치마크** 같은 2차원 표 | `rect` 격자, 채움색 농도로 값. 셀 안에 수치도 함께 |
| **산점도** | 두 변수의 상관, 이상치 강조 | 축 + `circle`. 추세선은 `line stroke-dasharray`, 사분면 구분선 유용 |
| **꺾은선** | 시간/스텝에 따른 변화 | `<polyline points="...">`가 `path`보다 좌표 계산이 쉽다 |
| **레이더** | 4~6개 축 다차원 프로파일 | 정다각형 격자 + `polygon`. 축 개수 5~6이 적정 |
| **깔때기(funnel)** | 단계마다 줄어드는 수량 | 사다리꼴 또는 폭이 줄어드는 `rect` 스택 |
| **박스플롯 / 오차막대** | 분산·seed 편차를 논할 때 | `line` + `rect`. 논문이 표준편차를 안 주면 그리지 말 것 |
| **불릿 / 게이지** | 단일 비율 (92% 달성 등) | 배경 바 + 채움 바 + 목표 눈금 |

축 값이 논문에 없으면 **값을 적지 말고 축 라벨만** 적고, 그 사실을 캡션에 밝힌다.

### 6.2 구조·관계 도식

| 유형 | 언제 쓰나 |
|---|---|
| **시퀀스 다이어그램** ★ | 두 주체의 왕복(에이전트↔환경, 클라이언트↔서버). 세로 lifeline 2~3개 + 가로 화살표. **개입이 어느 왕복 지점에 끼어드는지** 보이기에 최적 |
| **상태 기계** | 원형 노드 + 곡선 전이 화살표. 루프·복구 경로 표현 |
| **플로차트(분기)** | 마름모 `<path d="M x,y-20 L x+60,y L x,y+20 L x-60,y Z">` 로 조건 분기. Yes/No 라벨 필수 |
| **격자/마스크** | attention·causal mask, 토큰 배치. 작은 `rect` 격자 + 대각선 |
| **계층 스택** | 아래→위로 쌓은 `rect` (커널→런타임→라이브러리) |
| **트리 / 계통도** | 분류 체계, taxonomy, ablation 조합 |
| **벤 다이어그램** | 개념 3개의 포함·교집합. `circle` + `fill-opacity="0.35"` |
| **타임라인** | 긴 `rect`를 비율 분할, 또는 좌→우 마일스톤 축 |
| **파이프라인/블록도** | 위 어느 것도 안 맞을 때. **1/3 이하로 제한** |

### 6.3 이해를 돕는 "쉬운" 그림 — 적극적으로 섞는다

| 유형 | 설명 |
|---|---|
| **텍스트 diff 패널** ★★ | 실제 입력/출력 문자열을 그대로 두 칸에 놓고 왼쪽=잘못된 것(빨강 배경), 오른쪽=고쳐진 것(초록 배경). 등폭 느낌은 `font-family="monospace"`를 해당 `<text>`에만 건다. **추상적 설명 열 줄보다 이 그림 하나가 낫다** |
| **주석 달린 예시** | 실제 프롬프트·관측·로그 한 조각을 그리고, 옆에서 화살표로 "여기가 문제" 주석 |
| **비유 그림** | 개념을 일상 사물로: 관문·검문소, 체크리스트, 신호등, 저울, 깔때기, 수도관, 자물쇠. 단순 도형으로 충분하다 |
| **카드 갤러리** | 예시 3~6개를 같은 크기 카드로 나열 (실패 사례 모음, 벤치마크 소개). 화살표 없음 |
| **아이콘 픽토그램** | 사람=`circle`+`path`, 문서=모서리 접힌 `rect`, DB=원통(`ellipse`+`rect`), 톱니=단순 별. 정교할 필요 없다 |
| **숫자 카드(스코어보드)** | 큰 폰트(24~32px) 숫자 3~5개를 카드로. 핵심 결과 요약에 강력 |
| **before/after 2패널** | 좌=기존(주황), 우=제안(파랑). 같은 좌표계로 그려야 비교가 된다 |

### 6.4 유형 선택 빠른 결정표

```
수치가 있다?
  ├─ 쌍(before/after)이다 → 덤벨/슬로프
  ├─ 2차원 표다        → 히트맵
  ├─ 합이 100%다       → 도넛 또는 누적 막대
  ├─ 분해·기여도다     → 워터폴
  ├─ 두 변수 상관이다  → 산점도
  └─ 그 외 비교다      → 가로/그룹 막대
수치가 없다?
  ├─ 두 주체의 왕복이다      → 시퀀스 다이어그램
  ├─ 조건 분기가 핵심이다    → 플로차트(마름모)
  ├─ 실제 문자열을 보여야 한다 → 텍스트 diff 패널
  ├─ 예시 나열이다           → 카드 갤러리
  ├─ 층 구조다               → 계층 스택
  └─ 그 외 흐름이다          → 파이프라인 (단, 1/3 이하)
```

## 7. 본문과 그림의 관계

그림은 본문을 대체하지 않는다. 본문 서술 순서는:

1. `<p><strong>왜 문제인가</strong>: …` — 기존 방법의 구체적 실패 모드
2. `<p><strong>해법</strong>: …` + `$$수식 \tag{5}$$` (원문 수식 번호 유지)
3. `<blockquote><strong>직관적으로 말하면</strong>: …</blockquote>`
4. `<figure>` — 개념도
5. `<figure>` — 같은 수식의 수치 예제

`<h4>`는 절 안에서 "이 논문이 선행 연구에서 바꾼 지점"을 하나씩 다룰 때 쓴다
(예: `<h4>Lower-bounded decay — K3가 Kimi Linear에서 바꾼 첫 번째 지점</h4>`).

## 8. 마지막 점검

- [ ] **도식 유형이 6종 이상인가. 박스+화살표가 전체의 1/3을 넘지 않는가** (§6)
- [ ] **같은 유형이 연속 3개 나오지 않는가**
- [ ] 목차가 렌더링되고 `그림 N–M` 범위 표시가 각 절에 붙는가
- [ ] `figcaption`이 전부 3문장 이상이고, 절 상호 참조(§)가 들어 있는가
- [ ] `marker` id가 전부 유일한가
- [ ] SVG 안에 `$` 수식 문법이 남아 있지 않은가
- [ ] 박스/텍스트 겹침이 없는가 (브라우저로 열어 확인)
- [ ] 핵심 수식마다 수치 예제 그림이 있는가
- [ ] 논문의 주요 Figure가 빠짐없이 재현되었는가
