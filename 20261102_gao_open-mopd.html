목차

TL;DR

  • 문제: 도메인별 강화학습(reinforcement learning, RL) 전문가 셋(math·code·instruction following(IF))을 multi-teacher on-policy distillation(M-OPD)으로 한 student에 합치면, 라우팅을 정답 라벨로 완벽하게(oracle routing) 해 줘도 성능이 도메인별로 따로 증류한 student(RouteOPD)보다 3.50점 낮다. 특히 짧은 응답 도메인인 IF가 6.16점 떨어지고 가장 먼저 정체한다. 무엇이 통합을 막는가?
  • 해결: 진단부터 한다. teacher 간 토큰 불일치(conflict)는 원인이 아니었고(평균 0.126 nat, 개입하면 오히려 손해), 진짜 원인은 토큰 수준 최적화 예산의 잘못된 배분이었다. 세 원인 — ① 응답 길이 차이로 IF가 gradient 토큰의 0.99%만 차지, ② 도메인별 보상 크기·수렴 속도가 달라 예산이 표류, ③ 한 rollout을 K번 재사용할 때 student 항이 낡음(staleness) — 에 각각 처방을 붙인 Open-MOPD: token-share balancing(식 8), gap-following allocation(식 9), reward refresh(식 10).
  • 왜 작동하는가: 손실이 토큰 평균이므로 도메인의 실제 몫은 prompt 수가 아니라 "토큰 수 × 토큰당 보상 크기"로 정해진다. 토큰 몫을 목표치로 직접 고정하고, 남은 teacher–student 격차(보상 크기 $m_d$)가 큰 도메인에 예산을 더 주며(부호가 반대면 양성 되먹임으로 붕괴), 보상의 student 항을 매 inner update마다 현재 정책으로 다시 계산한다. 셋은 batch·학습 전체·inner update라는 서로 다른 시간 척도에서 작동해 독립적으로 쌓인다.
  • 비유: 세 과목(수학·코딩·글쓰기 규칙)을 한 학생이 과외받는데, 채점 시간이 "답안 글자 수"에 비례해 배정된다. 수학·코딩 답안은 1만 자, 글쓰기 규칙 답안은 400자라 글쓰기 선생님은 1%의 시간만 받는다. 처방은 (1) 과목별 채점 시간을 1/3씩 못 박고, (2) 아직 많이 틀리는 과목에 시간을 더 주며(이미 잘하는 과목에 더 주면 폭주), (3) 같은 답안지를 여러 번 고쳐 볼 때 학생의 "현재" 실력 기준으로 다시 채점하는 것이다.

핵심 기여 (Key Contributions)

  1. 통제된 open M-OPD testbed: SmolLM3-3B-Base에서 mixed-domain supervised fine-tuning(SFT) → 도메인별 RL teacher 3개 → oracle-routed M-OPD까지 전 과정을 공개 데이터와 8×A100-80GB 한 노드로 재현 가능하게 구성했다. 정답 도메인 라벨로 라우팅해 "라우팅 오류"와 "능력 통합"을 분리한다 (§2, 부록 A).
  2. 통합 격차의 실증 진단: Naive M-OPD는 mixed SFT → RouteRL 향상분의 35.6%만 회복한다. 격차는 비대칭이어서 IF가 −6.16점(math −1.89의 3.3배)이고 가장 먼저 정체한다 (§3.1).
  3. 메커니즘 분해: teacher 간 토큰 불일치는 주된 병목이 아니며(§3.2), 원인은 세 가지로 분리된다 — 도메인 간 응답 길이 차이, 수렴 속도 차이, 공유 rollout의 반복 minibatch에서 생기는 보상 staleness (§3.3).
  4. Open-MOPD 레시피: token-share balancing, gap-following(gap-aware) allocation, student reward refresh를 결합해 회복률을 35.6% → 83.4%로, RouteOPD와의 격차를 3.50 → 0.31점으로 줄였다. refresh는 측정 가능한 추가 시간 비용이 없다 (§4, §5).
  5. 공개: end-to-end post-training 레시피, 학습 궤적, 체크포인트, 평가 스위트를 공개한다 (부록 A).

배경 (Background) — OPD, MOPD, 그리고 "한 모델에 여러 전문가"의 세 갈래

On-policy distillation (OPD)

전통적 지식 증류(knowledge distillation, KD)는 teacher가 미리 생성한 응답 코퍼스로 student를 학습시킨다(Hinton et al., Sequence-level KD). 그러나 학습 때는 teacher가 만든 prefix를, 추론 때는 student 자신이 만든 prefix를 보므로 분포 차이(exposure bias)가 생긴다. On-policy distillation(MiniLLM, Generalized Knowledge Distillation(GKD))은 student가 직접 응답을 샘플하고, teacher가 그 응답을 한 번 prefill해서 각 위치의 확률분포를 준다. student는 자기가 실제로 방문하는 prefix 위에서 teacher를 따라가므로 exposure bias가 없다.

구현상으로는 RL과 같은 형태다. 응답 하나에 보상 하나를 주는 대신, 위치마다 "teacher가 이 토큰을 student보다 얼마나 더 좋아하는가" — $\log \pi_\phi - \log \pi_\theta$ — 를 토큰별 advantage로 넣는다. 이를 per-token reverse Kullback–Leibler (KL) divergence의 policy gradient로 볼 수 있다. 이 논문은 critic 없이 이 dense reward를 Proximal Policy Optimization(PPO)의 advantage 자리에 그대로 넣는다(§2.1).

직관적으로 말하면: 학생이 직접 쓴 답안지에 선생님이 단어마다 "+/−" 점수를 매겨 주는 첨삭이다. RL이 "답안 전체에 점수 하나"라면 OPD는 "단어마다 점수" — 훨씬 촘촘한 신호다.

Multi-teacher OPD (MOPD)와 이 저장소의 관련 요약

MOPD(원문 참고문헌 [4]; 이 저장소의 요약 20261001_ma_mopd.html)는 표준 3단계 레시피를 제안했다. ① 공통 SFT 모델을 만들고, ② 거기서 도메인마다 따로 RL을 돌려 전문 teacher를 얻고, ③ student(같은 SFT 모델)의 rollout을 프롬프트 도메인에 맞는 teacher로 라우팅해 토큰별 reverse KL로 증류한다. teacher와 student가 같은 SFT에서 출발(same-origin)하므로 분포가 가깝고, 가중치 평균이 아니라 프롬프트별 라우팅이라 안정적이다. Open-MOPD는 바로 이 레시피를 그대로 받아들이고, "라우팅이 완벽해도 왜 격차가 남는가"를 묻는다.

같은 문제의식을 다른 축에서 공략한 요약이 이 저장소에 두 편 더 있다(둘 다 원문 미인용, 이 저장소의 관련 요약):

  • IM-MOPD — student 초기화 축. SFT로 키운 teacher의 능력이 잘 안 옮겨지는 문제를, teacher task vector를 merge한 출발점과 뒤처진 도메인에만 반복 merge를 더하는 방식으로 푼다. "도메인별 회복도를 재서 뒤처진 쪽에 더 준다"는 점에서 Open-MOPD의 gap-following(§4.2)과 발상이 닮았지만, 조절 대상이 손실 가중치가 아니라 가중치 공간이다.
  • Latent-MOPD — 신호 종류 축. 토큰 확률에 더해 teacher hidden state까지 증류한다. 토큰 채널의 advantage를 도메인별 표준편차 $\sigma_d$로 나누는데, 이는 Open-MOPD가 §4.2에서 경고한 "보상 크기 역정규화"와 같은 방향의 처리다(이 문서의 해석이며, 두 논문의 설정·지표가 달라 직접 비교는 불가).

PPO의 multi-minibatch 재사용과 staleness

생성(rollout)은 비싸므로 실전 RL은 큰 rollout batch 하나를 K개의 minibatch로 나눠 K번 순차 갱신한다(PPO). 첫 갱신 이후 정책은 rollout 당시와 달라지므로 PPO는 importance ratio를 clip해 이를 견딘다. 비동기 RL에서는 이 "policy lag"가 더 크며(AReaL, StreamRL 등), 최근 AsyncOPD는 OPD에서 정책이 변하면 reverse-KL 신호의 student 의존 항을 현재 student로 다시 계산해야 한다고 보였다. Open-MOPD는 이 통찰을 동기 파이프라인의 inner update 내부 staleness에 적용한다(§4.3).

§1 서론 — 완벽한 라우팅으로도 부족하다

RL은 도메인 특화 능력을 키우는 핵심 도구가 되었지만, 실서비스에서 전문 모델 여러 개를 동시에 띄우는 것은 비싸다. 그래서 각 프롬프트를 해당 도메인 전문가에게 보내 student 궤적 위에서 dense per-token 보상을 받는 M-OPD가 산업 파이프라인(MOPD, Llama-Nemotron 등)에서 널리 쓰이지만, 원문에 따르면 "다도메인 능력 통합을 지배하는 메커니즘은 잘 이해되지 않았고 엄밀히 재현 가능한 공개 레시피도 없다".

저자들은 이를 위해 SmolLM3-3B-Base에서 출발하는 완전 통제 환경을 만든다: 3도메인 mixed SFT 초기화, math·code·IF 세 RL teacher, 정답 도메인 라벨에 의한 oracle routing. 정답 라벨로 라우팅하므로 라우팅 오류가 통합 문제에 섞이지 않는다.

핵심 관찰: 6개 벤치마크 표준 프로토콜에서 Naive M-OPD는 평균 28.05, 도메인마다 따로 증류한 RouteOPD는 31.55다. RouteOPD는 배포 시점의 통합 격차를 재는 기준이다. 특히 짧은 IF 과제는 RouteOPD보다 6.16점 낮고(math 격차의 3.3배), 학습 중 가장 먼저 정체한다. ##완벽한 라우팅은 성공적인 능력 통합의 충분조건과 거리가 멀다.##

원인의 위치: 도메인별 측정으로 격차의 원인을 "파국적 gradient 충돌"이 아니라 관리되지 않은 토큰 수준 최적화 예산 배분에서 찾는다. OPD 목적함수는 토큰에 걸쳐 손실을 집계하므로 각 도메인이 실제로 받는 최적화 몫은 prompt 빈도가 아니라 gradient 토큰 양으로 결정된다. IF는 prompt의 20.3%를 받지만 gradient 토큰은 0.99%뿐이다. 토큰 예산을 처음에 맞춰도 student가 teacher마다 다른 속도로 수렴하면서 보상 크기가 다르게 줄어 수십 step 안에 다시 벌어지고, multi-step rollout 재사용이 student 의존 보상 항을 낡게 만들어 불균형을 키운다.

처방: 세 직교 실패 모드에 전용 메커니즘을 하나씩 붙인다(§4). token-share balancing은 gradient 예산을 응답 길이에서 떼어 내 가중 토큰 몫 목표를 세우고(고정 배치 quota가 아님), gap-aware allocation은 남은 student–teacher 격차가 가장 큰 도메인으로 예산을 옮긴다 — 이미 수렴한 도메인에 예산을 몰아주는 naive 보상 정규화가 step 74에서 붕괴하는 것을 막는다. student reward refresh는 teacher 상태를 캐시하고 student log-prob만 매 gradient step 전에 다시 계산해, 무시할 만한 비용으로 staleness를 없앤다. 누적 ablation에서 회복률은 35.6% → 83.4%로 오른다.

§2 Open-MOPD 레시피 — 다중 teacher 능력 통합을 위한 공개 레시피

도메인 집합을 $\mathcal{D} = \{\text{math}, \text{code}, \text{IF}\}$, 도메인 $d$의 RL teacher를 $\pi_{\phi_d}$, student를 $\pi_\theta$라 하자. 학습 샘플은 도메인 라벨 $d(x)$를 가지므로 student는 세 과제 각각에서 해당 도메인 전문가의 신호를 받는다. 학습 프레임워크를 고정한 채 세 전문가의 능력을 한 student로 안정적으로 옮기는 레시피를 찾는 것이 목표다.

2.1 Multi-teacher on-policy distillation 목적함수

설정: 프롬프트 $x$에 대해 student가 현재 정책에서 $y \sim \pi_\theta(\cdot \mid x)$를 샘플하고, 라우팅된 teacher $\pi_{\phi_{d(x)}}$가 student rollout을 prefill 한 번으로 평가한다. 위치 $t$에서 student 분포의 top-$k$ 토큰 집합을 잡는다(기본 $k=16$).

$$\mathcal{S}_t = \mathrm{TopK}_k\big(\pi_\theta(\cdot \mid x, y_{<t})\big) \tag{1}$$

각 $v \in \mathcal{S}_t$에 대해 teacher–student log-probability 차이를 정의한다. $\mathrm{sg}[\cdot]$는 stop-gradient이고, 이것이 dense distillation의 토큰 수준 advantage 신호다.

$$\delta_t(v) = \mathrm{sg}\Big[\log \pi_{\phi_{d(x)}}(v \mid x, y_{<t}) - \log \pi_\theta(v \mid x, y_{<t})\Big] \tag{2}$$

이를 $\mathcal{S}_t$ 위의 softmax 가중치로 모아 dense reward를 만든다. $\mathcal{S}_t$ 밖의 토큰은 0을 기여한다.

$$r_t(v) = \delta_t(v) \cdot \tilde{\pi}_\theta(v \mid x, y_{<t}), \qquad \tilde{\pi}_\theta(v \mid x, y_{<t}) = \mathrm{softmax}_{u \in \mathcal{S}_t}\big(\log \pi_\theta(u \mid x, y_{<t})\big)(v) \tag{3}$$ $$r_t = \sum_{v \in \mathcal{S}_t} r_t(v) \tag{4}$$

critic이 없으므로 $r_t$는 PPO의 advantage 자리에 직접 들어간다. $\delta_t(v) > 0$은 teacher가 토큰 $v$에 student보다 높은 확률을 준다는 뜻이고, $\tilde{\pi}_\theta$는 top-$k$ 안의 각 토큰이 위치 수준 보상 $r_t$에 기여하는 몫만 정한다. student가 모든 응답을 생성하므로 지도 분포가 student의 현재 정책을 따른다 — 고정된 teacher 궤적에 대한 SFT와의 핵심 차이다. §3은 학습 메커니즘을 아무것도 더하지 않은 이 최소 버전에서 출발해, 이후 변화의 효과를 식별하기 쉽게 한다.

직관적으로 말하면: 식 (3)–(4)를 합치면 $r_t = -\sum_{v} \tilde{\pi}_\theta(v)\big[\log \pi_\theta(v) - \log \pi_\phi(v)\big]$, 즉 top-$k$로 제한한 reverse KL의 음수에 가깝다. 그래서 $r_t$는 보통 0 이하이고, 그 크기 $|r_t|$가 "이 위치에서 student가 teacher와 얼마나 다른가"를 잰다. 이 성질이 §3.3의 보상 크기 $\bar m_d$를 "남은 격차"로 읽는 근거가 된다.

2.2 기본 모델 선택

레시피의 기본 모델은 SmolLM3-3B-Base다. web·math·code 데이터로 사전학습되고 64K 문맥으로 학습된 완전 공개 3B decoder-only 모델이다. 원문은 두 기준의 균형으로 이 선택을 정당화한다.

  • 실험 가능성: M-OPD는 student 생성, teacher forward(하나 이상), 긴 응답 학습, 도메인별 검증을 동시에 요구하고, 전체 재현에는 mixed SFT·RL teacher 3개·최종 증류까지 들어간다. 7B 이상에서 시작하면 실험 하나의 GPU 시간이 커져 메커니즘 비교에 필요한 반복 실행이 감당되지 않는다. 그래서 "8×A100-80GB 한 노드에서 실행 가능"을 레시피 제약으로 둔다.
  • 모델 용량: 모델이 너무 작으면 응답 길이 한도가 긴 추론 지도를 잘라 버려, 실험 실패가 알고리즘 탓인지 모델 능력 탓인지 구분할 수 없다. Qwen3-1.7B-Base는 같은 OpenR1-Math-93k로 5 epoch SFT 해도 AIME24 최고 7.08%, 31K 생성 예산에서도 잘림 비율 69.17–80.42%였다. Qwen2.5-7B-Base는 31.25%, 잘림 12.92%였다(부록 A.1). SmolLM3-3B-Base는 32,768 토큰 한도의 math·code SFT 응답을 배울 만큼 크다.

부록 A.1은 1.7B의 문제가 "생성 길이 부족"이 아니라 추론 궤적을 닫지 못하는 것임을 강조한다: 다섯 체크포인트 모두에서 31K 예산 안에 </think>를 닫는 답이 20.00–31.25%뿐이고, epoch를 늘려도 단조 개선이 없다. 같은 데이터에서 7B는 정확도가 오르고 잘림이 줄어 "OpenR1 궤적이 원래 너무 길다"는 설명을 배제한다. 3B는 "1.7B 아래로 가면 잘림이 지배해 귀인이 불가능, 7B로 가면 전체 ablation이 자원 경계를 넘는" 두 실패 경계 사이의 작동점이다.

직관적으로 말하면: 시험지 답을 끝까지 쓰지 못하는 학생에게는 어떤 첨삭 방식도 효과를 판별할 수 없다. 실험이 실패했을 때 "방법이 나빴다"고 말하려면 학생이 최소한 답안을 끝까지 쓸 줄 알아야 한다.

2.3 End-to-end 학습 레시피

레시피는 세 단계이며, Stage II의 teacher와 Stage III의 student는 모두 같은 mixed SFT 모델에서 초기화된다.

  • Stage I: mixed-domain SFT — SmolLM3-3B-Base에서 출발해 도메인별 샘플 수를 응답 토큰 수 기준으로 균형 맞춘 뒤 4 epoch SFT → $\pi_{\text{mixsft}}$. 데이터: math OpenR1-Math-93k(93,733개), code는 OpenCodeReasoning 전체에서 샘플한 OCR-50k(50,000개), IF는 Instruction-Nemotron aligned(820,039개). 응답 토큰 기준 몫은 대략 math 37%·code 28%·IF 35%(부록: 37.3/28.1/34.6%), 시퀀스 한도 32,768.
  • Stage II: 도메인별 RL teacher — $\pi_{\text{mixsft}}$에서 따로 초기화해 자기 도메인의 검증 가능한 보상으로만 RL. math는 DAPO-Math-17k, code는 DeepScaler-24k(LiveCodeBench 오염 제거판), IF는 Nemotron-IF-RL-46k → $\pi_{\phi_{\text{math}}}, \pi_{\phi_{\text{code}}}, \pi_{\phi_{\text{IF}}}$.
  • Stage III: multi-teacher OPD — student도 $\pi_{\text{mixsft}}$에서 초기화. 학습 prompt는 세 도메인 합집합에서 도메인 혼합으로 샘플하고, 도메인 라벨이 §2.1 목적함수의 teacher를 고른다. 응답 한도는 math·code 16K, IF 2K, dense reward는 student top-16에서 계산.

3.2 teacher 충돌 가설 시험

왜 의심했나: math·code·IF teacher는 각자 자기 도메인에서만 선택되었지만 서식 단어, 접속사, 추론 템플릿을 대량으로 공유한다. teacher들이 이런 공통 토큰에서 엇갈린다면 multi-task OPD가 공유 파라미터의 gradient를 서로 다른 방향으로 밀어 간섭을 일으킬 수 있다.

측정: student가 샘플한 모든 토큰을 세 teacher 전부가 같은 문맥에서 채점하게 하고 teacher 불일치를 정의한다.

$$c_t = \max_{d \in \mathcal{D}} \log \pi_{\phi_d}(y_t \mid x, y_{<t}) - \min_{d \in \mathcal{D}} \log \pi_{\phi_d}(y_t \mid x, y_{<t}) \tag{5}$$

충돌이 다중 과제 OPD 실패의 주원인이라면 상당 비율의 토큰에서 $c_t$가 커야 한다. 기준은 1 nat — 가장 높게 본 teacher와 가장 낮게 본 teacher의 확률비가 $e \approx 2.7$인 지점이다.

직관적으로 말하면: 세 심사위원이 같은 단어에 점수를 매길 때 "최고점과 최저점의 차이"다. 1 nat 이상이면 한 심사위원이 다른 심사위원보다 그 단어를 2.7배 이상 더 그럴듯하게 본다는 뜻이다.

세 가지 시험:

  1. 불일치는 작고 안정적이다: 전체 학습 동안 $c_t$의 평균은 0.126 nat이고, 300 step 내내 0.27 nat 아래다(Figure 2a). 둘 다 1-nat 기준보다 훨씬 작다.
  2. 고충돌 토큰은 드물다: $c_t > 1$인 토큰은 평균 0.62%뿐이다. 불일치가 가장 큰 IF에서 3.9%, math에서 0.31%다(Figure 2b). 최댓값 30.58 nat이 보여 주듯 극단적 충돌은 존재하지만 소수 토큰에 국한된다.
  3. 고충돌 토큰을 직접 바꾸면 손해다: conflict mask는 $c_t$ 상위 1%, 5%, 20% 토큰(임계값 0.83, 0.49, 0.22 nat)을 증류 손실에서 제거하고 나머지 가중치를 재조정해 전체 손실 크기를 유지한다. consensus target은 $c_t \le 1$일 때 hard-routed teacher 대신 세 teacher log-prob의 평균을 목표로 쓰고, $c_t > 1$이면 라우팅된 teacher를 유지한다. 같은 설정에서 세 mask는 Total을 0.52, 0.73, 0.75점, consensus는 0.83점 떨어뜨린다.

해석: 고충돌 토큰은 무관한 잡음일 수도, 도메인 고유 정보를 실을 수도 있다. 토큰 수준 불일치만으로는 둘을 가를 수 없고, 이것이 제거·대체가 성능을 해치는 이유일 수 있다. ##이 지표 아래에서 토큰 수준 teacher 불일치는 지배적 병목이 아닐 가능성이 높다## — 그래서 시선은 "각 도메인이 공유 student에 얼마나 많은 학습 신호를 주는가"로 옮겨 간다.

3.3 도메인 간 학습 불균형 측정

이제 각 도메인이 받는 학습 신호의 양과 그 변화를 잰다. 먼저 도메인별 유효 응답 토큰 수와 토큰당 평균 보상을 재고, 그 다음 학습 궤적에 따른 변화, 마지막으로 같은 rollout batch의 후속 inner update에서 낡은 student 확률을 쓰는 효과를 본다. 세 측정은 각각 토큰 수, 보상 크기, 낡은 확률 기반 갱신이라는 세 불균형 원천에 대응한다.

원천 ① 도메인 간 토큰 불균형

왜 문제인가: 학습 손실은 token-mean 집계를 쓰므로 모든 유효 응답 토큰이 손실에 한 번씩 기여한다. 따라서 도메인 $d$의 원시 토큰 몫은

$$s^{\text{tok}}_d = \frac{n_d L_d}{\sum_{j \in \mathcal{D}} n_j L_j} \tag{6}$$

이다. $n_d$는 그 도메인의 prompt 수, $L_d$는 평균 응답 길이다.

결과: Figure 3에서 두 몫은 학습 전 구간에서 완전히 분리되어 있다. 샘플러가 정한 prompt 몫은 39.8%/39.8%/20.3%인데 토큰 몫은 49.7%/49.3%/0.99%다(Figure 3a). 300 step 전체에서 IF의 토큰 몫은 1.65%를 넘은 적도, 0.44% 아래로 내려간 적도 없다 — 특정 batch의 우연이 아니다. 원인은 길이(Figure 3b): math·code 평균 응답은 약 10,500 토큰, IF는 409 토큰으로 25배 넘게 차이 나므로 식 (6)은 거의 전적으로 길이가 정한다. 따라서 IF 샘플링 빈도만 올리는 것은 해법이 아니다. IF가 토큰 예산의 1/3을 얻으려면 prompt 수를 약 33.6배 늘려야 하고(Figure 3c), 그러면 batch 안 math·code prompt가 줄어 긴 추론 지도를 유지할 수 없다. ##IF는 prompt의 20.3%를 받지만 gradient 토큰은 0.99%만 받는다 — 도메인의 실제 학습 몫은 prompt 빈도가 아니라 토큰 양이 정한다.##

직관적으로 말하면: 회의 발언권을 "발언한 글자 수"로 배분하면, 한 줄 답만 하는 사람은 참석자 명단에 20% 올라 있어도 회의 시간의 1%만 쓴다. 참석 인원을 33배 늘려야 공평해지는데, 그러면 다른 사람들이 회의실에 들어올 자리가 없다.

원천 ② 보상 크기도 갱신 예산을 바꾼다

왜 문제인가: 토큰 수 말고도, 갱신의 세기는 보상 크기에 달려 있다. 갱신 예산의 단순 추정으로 도메인 기여를

$$B_d \propto s^{\text{tok}}_d \, \bar{m}_d, \qquad \bar{m}_d = \mathbb{E}_{t \in d}\big[|r_t|\big] \tag{7}$$

로 둔다. $\bar m_d$는 도메인 $d$의 토큰당 평균 보상 크기, 즉 그 도메인 토큰들에 대한 $|r_t|$의 기댓값으로, 토큰 하나가 파라미터 갱신에 주는 평균 효과를 잰다.

결과: 학습 초기 $\bar m_d$는 math 0.019, code 0.063, IF 0.091로 최대가 최소의 4.9배다(Figure 4a). $\bar m_d$는 student–teacher 정책의 평균 차이를 재므로 student가 teacher에 다가갈수록 줄어야 하는데, 줄어드는 속도가 도메인마다 다르다: 같은 궤적에서 IF는 2.4배, math 2.1배, code 1.9배 줄었다(Figure 4b).

토큰을 맞춰도 표류한다: 보상 크기의 효과는 토큰 몫을 균형 맞춘 뒤에 분명해진다. 모든 도메인의 $s^{\text{tok}}_d$를 1/3로 고정하면 식 (7)에서 기여는 $\bar m_d$에만 의존한다. 그러자 25 step 안에 IF의 예산 몫이 48.7%에서 약 9%로 떨어지고 최종 11.4%로 끝나며, code는 39.6%에서 63.8%로 오른다(Figure 4c). 즉 토큰 수를 맞춰도 보상 크기가 달라서 이후 단계의 학습 기여는 균형을 유지하지 못한다.

직관적으로 말하면: 발언 시간을 똑같이 나눠도, 어떤 사람은 크게 말하고 어떤 사람은 속삭이면 청중에게 전해지는 양은 다르다. 게다가 IF는 처음엔 가장 크게 말하다가(teacher와 차이가 큼) 가장 빨리 목소리가 작아진다(가장 빨리 수렴).

원천 ③ 반복 inner update가 보상을 낡게 만든다

왜 문제인가: 생성 비용을 줄이려고 실전 학습은 큰 rollout batch 하나로 K번 inner update를 한다. teacher는 고정이지만 student는 첫 inner update 이후 바뀐다. 후속 갱신이 rollout 때 계산한 student 확률 $\log \pi_\theta(v \mid x, y_{<t})$와 $\tilde\pi_\theta(v \mid x, y_{<t})$ ($v \in \mathcal{S}_t$)를 그대로 쓰면, 식 (3)의 student 의존 부분이 현재 정책과 맞지 않는다.

결과: Figure 5는 같은 batch 안에서 rollout 정책과 현재 정책 사이의 KL로 정책 이동을 잰다. 값은 K와 함께 단조 증가해 K=1에서 0(정의상 이동 없음), K=4에서 0.059, K=32에서 0.216이 된다(Figure 5a). PPO가 clip한 토큰 비율도 K와 함께 0에서 0.86까지 오른다(Figure 5b). 따라서 고처리량 설정에서는 대부분의 토큰이 student가 이미 rollout 정책에서 벗어난 뒤에 갱신되는데도, dense reward는 여전히 rollout 시점의 student·teacher 확률로 계산된다.

세 측정의 정리: 학습 신호에서 통제해야 할 부분은 셋이다 — 도메인 간 토큰 예산, 학습 중 teacher–student 격차(보상 크기), inner update 안의 보상 지연(신선도). 다음 절은 각각에 방법 하나씩을 제시한다.

§4 진단에서 방법으로: Open-MOPD

Open-MOPD는 §2.1의 teacher 라우팅과 on-policy distillation 목적함수를 그대로 두고, 최적화 예산을 어떻게 배분하는지와 보상 성분을 어떻게 계산하는지만 바꾼다. 세 메커니즘은 §3.3의 세 측정에 대응한다: token-share balancing은 batch 안의 도메인 토큰 예산을, gap-following allocation은 남은 증류 격차에 따라 학습 과정 전체의 예산을, reward refresh는 한 rollout의 여러 inner update에 걸친 student 의존 보상을 다룬다. 서로 다른 시간 척도에서 작동하므로 독립적으로 검증할 수도, 하나의 레시피로 결합할 수도 있다.

4.1 Token-share balancing

왜 문제인가: §3.3 원천 ①에서 IF는 prompt 20.3%에도 gradient 토큰 0.99%만 받았고, 샘플링 빈도로 고치려면 33.6배 oversampling이 필요해 긴 추론 지도가 무너진다.

해법: 각 도메인의 token-mean 손실에 고정 가중치를 준다. 목표 도메인 예산을 $g^\star_d$ ($\sum_d g^\star_d = 1$)라 하고, 매 batch에서 attention mask로 $s^{\text{tok}}_d$를 계산해 도메인 $d$의 손실에

$$w^{\text{share}}_d = \frac{g^\star_d}{s^{\text{tok}}_d} \tag{8}$$

를 곱한다. 그러면 도메인 $d$의 실효 몫은

$$\frac{w^{\text{share}}_d \, s^{\text{tok}}_d}{\sum_j w^{\text{share}}_j \, s^{\text{tok}}_j} = g^\star_d$$

가 되어, 응답 길이의 안정성이나 짧은 답의 oversampling에 기대지 않고 손실 안의 실제 토큰 비율을 직접 제어한다. 본 레시피는 코퍼스별 튜닝이 필요 없는 균등 목표 $g^\star = (1/3, 1/3, 1/3)$를 쓴다. Figure 3의 토큰 몫에서 이는 math 0.69, code 0.66, IF 32.7의 가중치를 낳는다 — IF 토큰 하나가 25배 길이 열세를 보상하려고 약 48배 증폭되고, 식 (8)이 세 도메인의 가중 몫을 정확히 33.33%로 보장한다. prompt 샘플링 비율만 바꾸는 것과 달리 math·code prompt의 다양성을 유지하면서 짧은 IF 응답에 의미 있는 기여를 준다.

바꾸지 않는 것: token-share balancing은 토큰 가중치를 통해 각 도메인의 손실 기여만 바꾸고, 샘플링 빈도나 개별 토큰의 보상 크기는 건드리지 않는다. 의도적이다 — 보상 크기는 teacher와 student의 격차를 보여 주므로 단순히 정규화하면 학습 진척에 대한 유용한 정보가 사라진다(이것이 §4.2의 출발점).

직관적으로 말하면: 학생 수를 늘리는 대신 "한 줄 답안 한 글자 = 긴 답안 48글자"로 환산해 채점 시간을 배분한다. 답안 개수(prompt 다양성)는 그대로 두고 저울의 눈금만 바꾸는 것이다.

4.2 Gap-following allocation

왜 문제인가 — 역정규화의 함정: 도메인 $d$의 이동 평균 토큰당 보상 크기를 $m_d$(예: $|r|$의 exponential moving average(EMA))라 하자. 이는 남은 teacher–student 격차의 관측 가능한 대리 지표다. 순진한 발상은 손실을 $m_d^{-\alpha}$로 정규화해 보상이 작은 도메인에 큰 가중치를 주는 것이다. 학습 초기엔 그럴듯하다 — 보상이 작다는 것은 그 도메인이 느리게 배우는 신호일 수 있으니까. 그러나 $m_d$는 남은 증류 격차도 추적한다: 도메인이 teacher에 다가갈수록 $m_d$가 작아진다. 따라서 역정규화는 이미 더 많이 진척한 도메인에 더 많은 예산을 준다.

이는 불안정한 되먹임 고리를 만든다. 도메인이 수렴 → $m_d$ 감소 → 가중치 $m_d^{-\alpha}$ 증가 → 예산 증가 → 더 빠른 수렴 → $m_d$ 더 감소. 균형 잡는 힘이 없으면 가중치는 계속 발산해 결국 학습을 무너뜨린다. 원문은 이를 실험에서 직접 관찰했다: 처음 75 step 동안 IF의 $m_d$가 35.3배 줄었고, $\alpha = 0.5$로 두자 IF 가중치는 26.7 → 90.7로 오르고 code 가중치는 0.44 → 0.27로 떨어졌다. 그래서 저자들은 $\alpha$가 양수이고 너무 작지 않을 때 역규칙이 불안정하다고 본다. (여기서의 $m_d^{-\alpha}$, $\alpha=0.5$는 식 (9) 표기로 $\alpha=-0.5$와 같은 설정이지만, 수치는 §5.2의 같은 실험 서술과 다르다 — 비판적 분석의 불일치 그림 참조.)

해법: gap-following allocation은 격차의 방향을 유지해 이를 "아직 증류되지 않은 능력"으로 해석하고, 격차가 더 큰 도메인에 예산을 준다.

$$\tilde w_d = w^{\text{share}}_d \cdot \mathrm{Clamp}\!\left(\left(\frac{m_d}{m_{\text{ref}}}\right)^{\alpha},\ 0.05,\ 20\right), \qquad w^{\text{gap}}_d = \frac{\tilde w_d}{\sum_j \tilde w_j \, s^{\text{tok}}_j} \tag{9}$$

$\tilde w_d$는 최종 정규화 전의 가중치로, 앞 절의 token-share 가중치와 clip된 격차 인자를 결합한다. 기준값 $m_{\text{ref}}$는 현재 batch에서 도메인들의 $m_d$ 평균이므로 $(m_d/m_{\text{ref}})^\alpha$는 다른 도메인 대비 상대적 보상 크기를 잰다. 한 도메인 보상이 급변해도 가중치가 너무 작거나 커지지 않도록 이 인자를 [0.05, 20]으로 clip한다. 분모 $\sum_j \tilde w_j s^{\text{tok}}_j$는 token-share 가중 평균 가중치이므로 정규화 후 $\sum_d w^{\text{gap}}_d s^{\text{tok}}_d = 1$이 되어 batch 전체 손실 크기가 변하지 않는다. 결과적으로 도메인이 teacher에 다가가면 $m_d$와 예산이 함께 줄고, 격차가 큰 도메인이 더 많은 갱신을 받는다. 본 레시피는 $\alpha = 1.0$이다(Table 8).

직관적으로 말하면: 과외 선생님이 "아직 많이 틀리는 과목"에 시간을 더 쓰는 것이다. 반대로 "이미 잘해서 틀린 점이 작은 과목"에 시간을 더 주면, 그 과목은 더 빨리 완벽해지고 틀린 점은 더 작아져 시간을 더 받는 — 폭주하는 고리가 된다. ##$\alpha$의 부호는 튜닝 대상이 아니라 격차의 방향이 정하는 구조적 선택이다.##

4.3 Reward refresh

왜 문제인가: 앞의 두 메커니즘은 도메인 간 예산을 다룬다. reward refresh는 한 rollout 안의 시간적 불일치를 다룬다. 설계는 AsyncOPD의 통찰 — student가 바뀌면 reverse-KL 신호의 student 의존 부분을 현재 student로 다시 계산해야 한다 — 에서 왔다. 저자들은 이를 다른 staleness 원천, 즉 동기 multi-teacher 파이프라인에서 K번의 inner update 각각에 적용한다. 한 rollout batch 안에서 student는 K번 갱신되지만 rollout 궤적은 갱신 전 student에서 나왔으므로 보상에 어긋남이 생긴다.

해법: 한 rollout을 K개의 갱신 minibatch에 쓴다고 하자. teacher는 $\log \pi_{\phi_{d(x)}}(v \mid x, y_{<t})$를 계산하는 데 prefill 한 번이면 되고, student 확률은 갱신마다 다시 계산한다. $k$번째 inner update의 actor forward에서 reward refresh는 같은 집합 $\mathcal{S}_t$ 위의 student 의존 항을 다시 계산한다.

$$\begin{aligned} \delta^{(k)}_t(v) &= \mathrm{sg}\Big[\log \pi_{\phi_{d(x)}}(v \mid x, y_{<t}) - \log \pi^{(k)}_\theta(v \mid x, y_{<t})\Big], \\ r^{(k)}_t(v) &= \delta^{(k)}_t(v) \cdot \tilde\pi^{(k)}_\theta(v \mid x, y_{<t}), \qquad v \in \mathcal{S}_t,\ k = 0, \ldots, K-1. \end{aligned} \tag{10}$$

$\tilde\pi^{(k)}_\theta$는 식 (3)을 따라 현재 student log-prob로 계산하고, 식 (4)로 $r^{(k)}_t$로 모아 PPO advantage 자리에 넣는다. 갱신은 현재 도메인의 $w_d r^{(k)}_t$로 구성되며, gap-following을 켜면 $w_d = w^{\text{gap}}_d$, 아니면 $w^{\text{share}}_d$다. reward refresh는 PPO가 이미 요구하는 student forward를 재사용하고 teacher forward를 더하지 않으므로, 매 갱신이 현재 student와 teacher의 차이를 쓴다.

범위: K=1이면 식 (3), (4), (10)은 §2.1의 목적함수로 돌아간다. K>1에서는 student에 명시적으로 의존하는 보상 부분만 고친다. 샘플된 student 상태(prefix)는 여전히 rollout 시점의 것이므로, ##reward refresh는 추가 prefill 없이 제거할 수 있는 staleness만 제거한다.##

직관적으로 말하면: 같은 답안지를 네 번에 나눠 고쳐 쓰는 동안, 선생님의 모범답안(teacher 항)은 그대로지만 "학생이 지금 얼마나 틀렸나"는 매번 학생의 현재 실력으로 다시 잰다. 이미 고친 부분을 또 세게 지적하지 않게 된다.

이 결과가 뒷받침하는 주장: Naive M-OPD에서는 토큰 손실 대부분이 student가 이미 teacher에 가까운 math·code에 쓰이고 있었다. 토큰 몫을 재배분하면 그동안 거의 학습되지 않던 IF가 개선되고, M-OPD 전체 점수도 오른다 — §3.3 원천 ①이 실제 성능 손실의 원인이었음을 강하게 시사한다(이 문서의 해석; 단일 실행이고 math는 −0.71).

5.2 Gap-following allocation

실험 의도: 정적 균형 위에 동적 재배분을 더하면 이득이 있는지, 그리고 인자의 부호가 정말 중요한지 확인한다.

결과 — 예산의 이동: 모든 도메인을 약 1/3에 두는 정적 균형과 달리 gap-following은 학습이 진행되면서 도메인 비율을 동적으로 바꾼다(Figure 7a). 이 설정에서 예산은 teacher–student 격차 $\bar m_d$가 가장 큰 도메인으로 간다. baseline 궤적의 중간 구간 평균에서 $\bar m_d$는 code 0.028, math 0.008, IF 0.003(평균의 2.16×, 0.61×, 0.23×)이다. 처음 25 step에서 200–300 step으로 가며 math 몫은 15.1% → 32.6%로 늘고 IF 몫은 34.5% → 17.1%로 줄며, code가 가장 많은 예산을 받는다(평균 55.4%, 최고 87.6%). reward refresh 없이 단독으로 시험하면 이 메커니즘은 +0.72점을 준다(K=1 사다리, Table 4). 흥미롭게도 IF 몫이 절반으로 줄었는데도 IF 점수는 47.53 → 49.50으로 오른다.

결과 — 부호 반전: 인자를 뒤집으면 격차가 작은 도메인, 즉 student가 이미 잘 다루는 도메인에 예산이 더 가서 양성 되먹임이 생긴다. 실험에서 IF 격차가 32.5배 줄고 가중치가 24.4 → 80.9로 오르며 학습이 step 74에서 멈췄다(Figure 7b). 따라서 ##$\alpha$의 부호는 격차의 방향으로 고정된다.##

이 결과가 뒷받침하는 주장: §3.3 원천 ②(보상 크기 표류)는 "보상 크기를 없애는" 방향이 아니라 "보상 크기를 따라가는" 방향으로만 안전하게 다룰 수 있다. 정적 균형(§5.1)이 IF의 '양'을 고친다면, gap-following은 수렴한 IF에서 아직 격차가 큰 code로 예산을 넘겨 '때'를 고친다.

5.3 Reward refresh

실험 의도: refresh가 성능을 올리는지, 그리고 그 대가로 실행 시간이 얼마나 드는지 측정한다.

설정: reward refresh는 dense reward의 student 의존 부분을 매 inner update로 옮긴다. teacher log-prob는 여전히 rollout batch 맨 앞에서 한 번 prefill되어 재사용되고, student log-prob는 PPO가 이미 수행하는 actor forward에서 읽는다. 따라서 student forward가 추가되지 않는다. refresh가 없으면 dense reward는 rollout 시점에 저장한 student 확률을, 있으면 현재 inner update의 student 확률을 쓴다. 두 경우 모두 teacher 항은 outer step당 한 번 계산되고, 보상을 평가하는 student 파라미터만 바뀐다.

결과: K=4에서 dense reward 계산은 refresh 있을 때 27.3 s, 없을 때 27.8 s로, outer step의 2.10%, 2.12%다(Figure 8). 전체 step은 refresh 있을 때 1298 s, 없을 때 1313 s다. 차이는 작고 step 간 변동 범위 안이므로 ##reward refresh는 측정 가능한 추가 실행 비용이 없다.## share+gap 위에서 refresh는 K=4에서 +0.81점을 더하며(Table 4), 이로써 Open-MOPD 레시피가 완성된다.

§6 관련 연구

6.1 On-policy distillation과 다중 teacher 확장

  • 고정 코퍼스 증류: KD는 student가 teacher의 출력 분포를 맞추게 한다. 시퀀스 모델에서는 teacher가 응답을 미리 생성하고 student가 그 고정 코퍼스로 배우므로, 학습(teacher prefix)과 추론(student prefix)의 분포 차이가 exposure bias를 만든다. teacher–student 용량 격차가 크면 증류가 어려워진다는 연구도 있다.
  • On-policy distillation: student가 자기 rollout으로 학습하고 실제로 방문한 prefix에서 teacher 피드백을 받는다(MiniLLM, GKD). 이후 연구는 divergence, 샘플링 규칙, 토큰 수준 학습 신호를 바꾸거나(DistiLLM, DistiLLM-2, Speculative KD 등) 긴·표류한 prefix에서의 신뢰할 수 없는 피드백 같은 실패 모드를 다룬다. 대부분은 여전히 teacher 하나를 쓴다 — 이 논문은 여러 teacher가 한 student의 갱신을 어떻게 나누는지를 연구한다.
  • Batch 재사용에서의 staleness: PPO는 한 rollout 주기 안에서 다중 minibatch 갱신을 지원한다. 비동기 RL에서는 rollout이 learner보다 몇 갱신 뒤처진 정책에서 오는 policy lag가 생기며(AReaL, StreamRL, Laminar, AReaL-Hex, RollPacker, HybridFlow), 얼마나 낡은 데이터를 견딜 수 있는지(Prosperity before Collapse, A-3PO)와 OPD의 staleness(AsyncOPD, Blockwise Policy-Drift Gating)가 연구되었다. 이 논문의 동기 파이프라인에서는 각 rollout batch를 K개 minibatch로 나눠 순차 갱신하므로 student 의존 보상이 낡을 수 있고, reward refresh가 PPO의 기존 actor forward로 이를 재계산한다.
  • 단일 → 다중 teacher OPD: MOPD는 공유 SFT에서 도메인 전문가를 학습하고, 각 student rollout을 도메인 teacher로 라우팅해 토큰 수준 피드백으로 학습하는 3단계 레시피로 OPD를 확장했다(MOPD, MiMo-V2-Flash). 이 레시피는 여러 공개 모델에 쓰였다: Nemotron-Cascade 2는 Cascade RL에서 잃은 능력을 강한 중간 teacher로 복구하고, Agents-A1은 도메인 teacher 6개를 결합하며 응답·도메인 단위로 손실을 정규화한다. 더 큰 규모에서 DeepSeek-V4는 10개 이상의 teacher를, Kimi K3는 도메인과 reasoning effort로 정의한 teacher 9개를 증류한다. Open-MOPD는 이 통합 과정에서 도메인들이 받는 학습을 어떻게 균형 맞출지를 연구한다.

6.2 도메인 전문가 통합

  • 도메인 전문가 학습: 단일 도메인 RL은 강한 전문가를 만든다(DeepSeekMath, DeepSeek-R1, DAPO). 도메인 특화 RL은 소프트웨어 공학(R2E-Gym, SWE-RL), 검색(Search-R1), 지시 따르기로 확장되었다. 파이프라인마다 전문가 하나가 나오지만 배포는 보통 모든 도메인을 다루는 한 모델을 요구한다.
  • 데이터 공간 통합: 혼합 데이터로 한 모델을 학습하거나(Qwen3의 general-domain RL), 도메인을 순서대로 학습한다(Nemotron-Cascade). 공동 학습에서는 데이터 혼합이 최종 모델을 크게 좌우하며(DoReMi, MoDoMoDo), 같은 비율로 과제를 샘플해도 과제마다 gradient 크기가 매우 다를 수 있다(Imbalanced Gradients in RL Post-Training). Open-MOPD는 응답 토큰 수 차이, teacher–student 격차 차이, 낡은 보상이 multi-teacher OPD에서 도메인 불균형을 만드는 방식을 연구한다.
  • 가중치·모듈 공간 통합: Task Arithmetic, TIES-Merging, DARE는 과제별 파라미터 변화를 한 체크포인트로 병합하고, BTM·BTX·BTS는 전문가 구조를 유지한 채 앙상블·Mixture of Experts(MoE)·stitch layer로 잇는다. 이들은 따로 학습한 뒤 합치지만, multi-teacher OPD는 전문가 출력으로 공유 student 하나를 학습한다.

§7 결론

저자들은 mixed SFT, 도메인 RL teacher 셋, multi-teacher OPD로 이어지는 완전 공개 파이프라인을 처음부터 구축하고, 한 가지 구체적 질문 — 라우팅이 이미 오류 없을 때, 세 전문가의 능력이 같은 파라미터 집합에 동시에 기록되는 것을 무엇이 막는가 — 에 답한다. 실험은 최적화 예산의 배분을 주된 병목으로 지목한다. 불균형의 분리 가능한 세 원인은 불균등한 토큰 수, 불균등한 보상 크기, 반복 inner update 동안의 낡은 보상이다. Open-MOPD의 세 메커니즘 — token-share balancing, gap-following allocation, reward refresh — 은 이 세 원천에 1:1로 대응하고 ablation에서 따로 검증된다. 함께 쓰면 ##통합 격차를 3.50점에서 0.31점으로 줄이고, RouteRL 대비 회복률을 35.6%에서 83.4%로 올린다.## 전체 레시피와 메커니즘 구현을 공개한다.

비판적 분석 (Critical Analysis)

강점

  • 진단이 처방을 정한다: "teacher 충돌"이라는 가장 그럴듯한 가설을 세 가지 방식(크기, 빈도, 개입)으로 시험해 기각한 뒤에야 예산 배분으로 넘어간다. 세 메커니즘이 세 측정에 1:1로 대응해 논증이 깔끔하다.
  • 측정 가능한 단순 지표: $s^{\text{tok}}_d$와 $\bar m_d$는 학습 로그에서 바로 계산되는 양이라 다른 M-OPD 파이프라인에도 진단 도구로 그대로 쓸 수 있다. 특히 "prompt 몫 ≠ 토큰 몫"(20.3% vs 0.99%)은 짧은 응답 도메인을 섞는 모든 token-mean 학습에 일반화되는 관찰이다.
  • 부호 실험: gap-following의 반대 부호가 실제로 붕괴함을 보여(step 74) 설계의 방향성을 실험으로 고정했다. "튜닝 가능한 하이퍼파라미터"처럼 보이는 것이 구조적 선택임을 드러낸 좋은 negative result다.
  • 비용 없는 refresh: teacher 항 캐시 + 기존 actor forward 재사용으로 추가 forward 없이 staleness를 줄였고, 시간 측정(1298 s vs 1313 s)으로 이를 확인했다.
  • 재현성: 공개 데이터, 단일 8×A100 노드, 실제 실행 설정 그대로의 하이퍼파라미터 표(Table 7, 8), 체크포인트·궤적 공개.

한계와 의문점

  • 헤드라인 비교의 혼입: 35.6% → 83.4%는 K=1 Naive(28.05)와 K=4 Open-MOPD(31.24)의 비교다. 같은 K=4 Naive는 29.28(회복률 54.0%)이므로, 세 메커니즘의 순효과는 +1.96점(54.0% → 83.4%)이고 나머지 +1.23점은 처리량 설정(rollout batch 4배) 전환에서 온다. 원문은 Table 4에서 이를 투명하게 보여 주지만 초록·서론·결론은 혼합된 수치를 앞세운다.
  • 단일 실행, 분산 미보고: Table 2·4의 모든 행이 단일 실행으로 보이며 seed 수가 없다. Figure 2c의 검증 표준오차가 개입당 약 ±0.17–0.27점이므로, gap-following +0.72점이나 refresh +0.81점 같은 증분이 seed 간 변동을 넘는지 확인할 수 없다.
  • 메커니즘 증분의 비가법성: refresh는 K=4에서만, share·gap은 K=1에서 각각 측정되었고, K=4에서는 share+gap을 묶어서만 보고한다. K=4에서 share만, refresh만 켠 행이 없어 각 메커니즘의 독립 기여를 분리하기 어렵다.
  • 원문 내부 불일치: 역방향 gap 실험의 수치(35.3배·26.7→90.7 vs 32.5배·24.4→80.9)가 §4.2와 §5.2에서 다르게 적혀 있고, code 최고 몫(87.6%)이 Figure 7a 곡선과 맞지 않으며, Figure 1c의 기준(RouteRL vs RouteOPD)이 캡션과 본문에서 다르다(아래 그림).
  • 규모·도메인 일반성: 3B student 하나, 도메인 셋, teacher도 같은 3B에서 나온 same-origin 설정뿐이다. teacher가 student보다 훨씬 크거나, 도메인이 10개 이상(DeepSeek-V4 규모)이거나, 응답 길이 분포가 덜 극단적일 때도 같은 처방이 최적인지는 검증되지 않았다. 균등 목표 $g^\star=(1/3,1/3,1/3)$가 "튜닝 불필요"라지만 다른 목표와의 비교는 없다.
  • math의 잔여 격차와 trade-off: share 단독에서 math가 0.71점 떨어지고, 최종 math 회복률(71%)이 RouteOPD(83%)에 가장 못 미친다. IF를 살리는 대가로 긴 추론 도메인의 토큰당 가중치를 0.69로 줄인 영향일 수 있으나 원문은 분석하지 않는다.
  • 강한 baseline과의 거리: ParamMerge-TA(30.46, 71.7%)가 Naive M-OPD보다 훨씬 강하고 code에서는 RouteRL을 넘는다. Open-MOPD(31.24)는 TA보다 0.78점 높을 뿐이며, TA 초기화 위에 Open-MOPD를 얹는 조합(IM-MOPD식)은 시험되지 않았다. baseline들의 설정(병합 계수, $\pi_{\text{mixrl}}$의 데이터·step)도 원문에 없다.
  • $\bar m_d$의 해석: $|r_t|$를 "남은 격차"로 읽는 것은 top-k 위 reverse KL의 크기라 자연스럽지만, 도메인마다 응답 엔트로피·top-k 질량이 달라 같은 격차라도 $|r_t|$의 척도가 다를 수 있다. 실제로 IF는 초기 $\bar m_d$가 가장 큰데 Fig.1에서 가장 덜 회복된다. 격차와 "학습 가능한 격차"를 구분하는 분석은 없다.

Key Takeaways — 이 논문에서 가져갈 것

  1. token-mean 손실에서 도메인의 실제 몫은 prompt 수가 아니라 토큰 수다: 짧은 응답 도메인(IF, 분류, 짧은 대화)을 긴 추론 도메인과 섞는다면 $s^{\text{tok}}_d$부터 로그로 찍어 보라. 20%의 prompt가 1%의 gradient가 되는 일이 흔하다.
  2. 샘플링 대신 손실 가중치로 몫을 맞춘다: $w_d = g^\star_d / s^{\text{tok}}_d$는 한 줄 구현이고, prompt 다양성을 해치지 않으며, 응답 길이 변동에도 batch마다 자동 보정된다.
  3. 보상 크기 정규화의 방향을 조심하라: OPD의 $|r_t|$는 "남은 격차"다. 이를 역으로 정규화하면 이미 수렴한 도메인에 예산이 몰리는 양성 되먹임이 생겨 학습이 무너질 수 있다. 다중 과제 advantage를 도메인별 표준편차로 나누는 흔한 관행도 같은 위험을 품는지 점검할 가치가 있다.
  4. PPO inner update에서 OPD 보상의 student 항은 공짜로 새로 고칠 수 있다: teacher log-prob만 캐시하고 student 항은 actor forward에서 다시 읽으면 된다. K=4에서 이미 토큰의 57.6%가 clip되는 상황이라 기본값으로 켤 만하다.
  5. "충돌"을 의심하기 전에 "배분"을 재라: 다중 teacher·다중 과제 실패를 gradient 충돌로 설명하고 싶을 때, 충돌 지표를 실제로 측정하고 개입해 보라. 이 논문에서는 충돌 개입이 모두 손해였다.
  6. (비판적 관점) 헤드라인 수치는 같은 설정의 대조군과 다시 계산하라: 35.6% → 83.4% 가운데 일부는 K=1 → K=4 처리량 설정 전환에서 온다. 같은 K=4 대조군 대비 순효과는 54.0% → 83.4%이며, 단일 seed라 +0.7~0.8점 단위 증분의 신뢰도는 아직 미확정이다.
