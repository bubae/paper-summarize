"각 modality의 코치는 자기 종목만 담당한다.
학생이 이미 잘하는 부분에서는 물러나고,

이 논문이 짚는 문제

Omni-modal LLM (Qwen3-Omni, Gemini 등)은 하나의 shared backbone에서 text, image, audio를 처리한다. 그런데 이 backbone을 post-training으로 개선할 때 modality 간 tradeoff가 반복 관찰된다. 예컨대 audio RL로 튜닝하면 text가 떨어지고, vision RL로 튜닝하면 audio가 떨어진다. 이 논문은 세 개의 modality-specialist teacher가 있을 때 그것들을 하나의 student로 통합하는 문제를 다룬다.

가장 직관적인 시도는 세 modality data를 pooled해서 GRPO로 훈련하는 것이다. 그러나 같은 base에서 시작했을 때, 각 modality specialist는 자기 modality에서 강력해지지만 pooled model은 그 강점들의 합집합을 못 만든다.

Figure 1: (a) 세 specialist가 서로 다른 방향으로 강해진다. (b) parameter 이동 방향이 modality 쌍마다 크게 갈린다. (c) OPOD만이 모든 벤치마크에서 broad하게 이긴다.

여기서 두 가지 challenge가 부상한다:

Conflict
세 teacher가 shared backbone을 다른 방향으로 밈
Ceiling
Symmetric OPD는 student가 이미 teacher를 넘어선 곳에서도 뒤로 잡아당김

OPD 자체는 어떻게 생겼나?

OPD (On-Policy Distillation)는 student가 만든 rollout $y_i$의 각 위치에서 teacher와 student의 next-token log-prob를 비교한다. Token-level margin이 곧 dense reward가 된다.

OPD의 dense reward = teacher와 student의 log-prob 차이. OPOD는 이 중 음수 부분을 잘라낸다.

표준 OPD는 이 margin의 부호에 무관하게 최소화한다. Student가 이미 teacher보다 잘 예측하는 토큰에서도 학생을 teacher 방향으로 끌어당기므로, teacher가 student의 상한선(ceiling)이 된다.

직관적 비유

세 명의 전문 코치(text 코치, image 코치, audio 코치)가 한 선수를 훈련시키는 상황. 기존 방식은 세 코치가 모든 순간마다 선수를 자기 쪽으로 잡아당기고, 심지어 선수가 이미 코치보다 잘하는 부분에서도 놓아주지 않는다. OPOD는 (1) 각 코치는 자기 종목 상황에서만 조언, (2) 선수가 이미 코치보다 잘하면 놓아줌, (3) 각 코치의 목소리 크기를 자동 조절해 서로 목소리를 눌러 죽이지 않도록 한다.

컴포넌트 ① One-Sided Teacher Guidance

Log-ratio의 음수부(student가 앞선 부분)를 ReLU로 잘라낸다. 매우 단순한 변경이지만 효과가 크다.

왼쪽: 표준 OPD는 음수 margin에서도 loss가 커지므로 student를 뒤로 잡아당긴다. 오른쪽: OPOD는 음수 방향으로는 constraint=0.
이 하나의 변경만으로 얼마나 이득인가?

Ablation에서 One-Sided를 제거하면 30B-A3B avg가 70.8 → 69.0 (−1.8) 하락. 즉 이 단순 clipping이 방법 전체 gain의 상당 부분을 담당한다.

컴포넌트 ② Adaptive Modality Control

Modality마다 별도의 dual weight $\beta_m$과 별도의 target budget $\epsilon_m$을 유지한다. Budget은 10-step warm-up에서 자동 결정 후 고정, weight는 매 step 관측된 gap에 따라 자동 조정된다.

Stage 1: warm-up으로 modality별 budget $\epsilon_m$ 자동 결정. Stage 2: 관측된 gap을 따라 $\beta_m$을 dual update.
"modality 난이도"가 아니라 "constraint 스케일" 차이다

Text의 $\epsilon$이 가장 작다고 해서 "text가 가장 쉽다"는 뜻이 아니다. Teacher-student discrepancy의 자연 스케일이 다르다는 뜻. Audio는 스케일이 커서 (0.254) 초반 constraint가 크고 controller가 빨리 pressure를 풀어야 한다.

컴포넌트 ③ Verification Reward

같은 modality teacher를 verifier로 재활용한다. Rollout 전체에 대해 두 개의 신호를 얻는다:

Answer confidence는 정답인 경우에만 세고, reasoning gain은 정답이 아니어도 reasoning의 유용성을 인정한다. 이 gating asymmetry가 어려운 sample의 학습 신호를 살린다.
왜 reasoning gain은 gating을 하지 않나?

학습 초반에는 어려운 문제에서 최종 답이 대부분 틀린다. 만약 reasoning gain에도 correctness gating을 걸면 이 어려운 sample들은 process reward가 0이 되어 사실상 outcome reward만 남게 된다. Gating을 풀되 clip으로 magnitude만 제한하면, "정답까지 못 갔지만 방향은 맞았던" 시도에서도 학습 signal이 살아난다.

실험 세팅

모델 및 데이터

  • Student: Qwen3-Omni-30B-A3B-Instruct (MoE), Qwen2.5-Omni-7B / 3B (dense)
  • Teachers: 같은 base에서 각 modality data로 GRPO 개별 훈련
  • Training data: text/image/audio reasoning + multimodal QA. 12개 벤치마크와의 exact + normalized string overlap 제거로 contamination 방지
  • Benchmarks (12): AIME25, AIME26, HotpotQA, MMLU-Pro, GPQA (text) / MMMU, MathVista, ChartQA, A-OKVQA (vision) / MMAU, AVQA (audio) / OmniBench (omni)

Hardware & Hyperparameters

  • Hardware: 32 × NVIDIA H20. Student 16 GPU + 남은 GPU에 teacher server
  • Rollout: prompt당 8 sample, batch 16, global batch 64. Max prompt/response 각 8192
  • Verification: w_A = w_B = 0.2, C = 2.0
  • Dual controller: 10-step warm-up, ε_min = 0.02
  • Baselines: 모두 같은 backbone/data/batch/seed 사용, guidance objective만 다름

한계 및 남은 질문

① 단일 seed 결과

"single run per configuration with the same random seed" (§4.1). Ablation에서 1점 대 Δ의 통계적 유의성이 불분명. 특히 reasoning gain 제거의 −1.6은 재현 실험이 필요.

② Verification reward weight의 sensitivity 부재

w_A = w_B = 0.2와 C=2.0 고정으로만 실험. 이 값들이 modality 조합에 얼마나 robust한지는 sweep 없음. Reasoning-heavy 도메인(수학)과 perception-heavy 도메인(오디오 이해)이 서로 다른 최적값을 요구할 가능성.

③ Teacher pretraining 비용 미제외

세 modality specialist를 GRPO로 미리 훈련하는 비용은 method cost에서 빠져있다. Compute-fair 비교는 (teacher training + distillation) vs (pooled GRPO)로 이뤄져야 함.

④ 3-modality 특화 세팅

Video, 3D 등이 붙어 4-5 modality가 되면 dual variable의 안정성과 calibration의 확장성은 실증 부족. 3-way conflict가 K-way로 확장되었을 때 β_m 사이의 상호작용이 어떻게 될지는 open.

⑤ Answer parsing 가정

Final answer position S_i가 명확히 식별된다고 가정. Long CoT에서 answer parsing이 실패하면 answer confidence 신호가 왜곡됨. Verifier의 robustness에 대한 논의 없음.

한 줄 결론

"여러 modality teacher를 하나의 shared student로 합치려면,
token 수준에서 뒤로 잡아당기지 않고 · modality 수준에서 각자의 예산으로 조절하고 · rollout 수준에서 verification까지 다층 감독을 설계해야 한다."
