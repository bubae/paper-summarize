DuplexGen: Adaptive Synthesis of Human–AI Turn-Taking Dialogues

개요 브리핑 버전 보기 →

  • 연도: 2026

TL;DR

  • 문제: Full-duplex spoken dialogue 모델은 언제 backchannel(맞장구)을, 언제 floor-taking(끼어들기)을 할지 매 순간 결정해야 한다. 그러나 실제로 적절한 turn-taking 동작은 시나리오에 따라 달라진다 (튜터는 조용히 듣고, 협상자는 자주 끼어든다). 기존 학습 데이터는 (a) 무연출 human-human corpus, (b) 프롬프트/휴리스틱 기반 synthetic로만 존재하고, 인간이 실제로 선호하는 시나리오별 turn-taking 분포를 담지 못한다.
  • 해결: ##DuplexGen## — 4-stage 파이프라인으로 시나리오-적응적 turn-taking dialogue를 합성한다. (1) 텍스트 대화를 spoken-style로 변환, (2) turn-taking slot 후보를 heuristic + LLM으로 식별, (3) 각 슬롯에서 인간이 선호하는 action 분포를 소규모 human annotation으로 LLM에 calibrate, (4) calibrated 모델로 target scenario 대화 합성. 6개 시나리오(협력 3 + 경쟁 3)에서 검증.
  • 왜 작동하는가: 인간 라벨을 soft distribution(다수결이 아닌)으로 만들고, LLM의 verbalized confidence 분포와 KL을 맞추는 context-aware calibration을 fine-tuning으로 학습한다. 이는 temperature 같은 context-agnostic scaling이 못 잡는 시나리오-의존 miscalibration을 교정한다.
  • 비유: 초짜 통역자에게 여러 상황(강의, 협상, 잡담) 각각에서 "언제 끼어드는 게 자연스러운가"를 시나리오별 소규모 정답지로 재훈련시켜, 상황마다 다른 인간의 감각을 학습시키는 것.

핵심 기여 (Key Contributions)

  1. Scenario-adaptive synthesis framework: LLM 기반 turn-taking을 시나리오별 인간 선호에 정렬시키는 최초의 프레임워크. Per-scenario annotation budget이 작아도 (총 1395 utterance) calibration이 가능.
  2. Six scenarios covering cooperative & competitive dynamics: 협력 (TEA / PLN / INT) + 경쟁 (NEG / PER / SOC). Cross-scenario 통계로 backchannel/floor-taking 비율이 시나리오마다 유의미하게 다름을 증명.
  3. Soft-label KL calibration: 5명의 annotator label을 majority-vote가 아닌 empirical distribution으로 유지. LLM의 verbalized action distribution과 KL divergence를 최소화하는 LoRA fine-tuning. 이는 hard label의 disagreement 정보 손실을 회피.
  4. Full-duplex 모델 훈련 실증: DuplexGen으로 합성한 1,623 시간 데이터로 PersonaPlex fine-tune (PP-DG) → Instruction Following (GPT judge)과 Turn-Taking Naturalness (human) 양쪽에서 baseline (Moshi, PP) 대비 유의한 개선.
  5. Distributional evaluation: 단일 correct label이 아닌 D_KL(Human ‖ Model)로 평가. Qwen3 1.7B/4B/14B 세 스케일에서 DuplexGen 방법이 최저 KL 달성.

배경 (Background)

Turn-taking과 full-duplex dialogue

Full-duplex language model (Moshi, PersonaPlex 등)은 half-duplex와 달리 동시에 listening + speaking을 지원한다. 이런 시스템에서 turn-taking은 conversational floor(누가 지금 말하는 권리를 가졌는가)의 순간별 조정을 의미한다. 매 순간 어시스턴트는 다음 중 하나를 결정해야 한다:

  • [LISTEN]: 침묵하며 계속 청취 (기본값)
  • [BACKCHANNEL]: "mm-hmm", "right", "yeah" 같은 짧은 acknowledgement — floor는 사용자에게 유지
  • [TAKE_FLOOR]: floor를 가져와 발화 시작 — 사용자 발화를 truncate

Turn-taking은 시나리오 의존적이다

Conversation analysis(Sacks et al. 1978; Skantze 2021)는 turn-taking이 사회적 맥락에 의존한다는 것을 오래전부터 확립했다. 예컨대:

  • 튜터/강사: 학생을 조용히 청취하며 짧은 격려 위주 (backchannel↑, floor-taking↓)
  • 협상가: 자주 끼어들어 자기 주장을 관철 (floor-taking↑)

그러나 현재 full-duplex 모델은 단일 turn-taking prior를 사전학습 corpus에서 학습하고, 배포 시에도 시나리오 무관하게 그 prior를 적용한다. 이 논문은 이를 "scenario-sensitivity의 부재"로 명명.

기존 학습 데이터의 두 가지 한계

  1. Human-human corpus (Switchboard, Fisher, Candor): 자연스러운 timing은 담지만 역할/시나리오 grounding이 없다. 낯선 두 사람에게 임의 topic을 주고 대화시킨 corpus라 assigned role이 없다.
  2. Synthetic dialogue with turn-taking (Duplex-UltraChat, Behavior-SD, InteractSpeech): heuristic rule이나 LLM prompt로 turn-taking action을 삽입. 그러나 인간 선호에 대한 validation이 없다. LLM은 자체 prior에 따라 action을 배분할 뿐, target scenario에서 실제 인간이 선호하는 분포와 다를 수 있다.

Calibration의 배경

Post-RL LLM은 verbalized confidence가 miscalibrated된다는 관찰(Tian et al. 2023). Post-hoc temperature scaling은 context-agnostic이라 global miscalibration은 잡지만 시나리오-context 변화를 못 잡는다. 이 논문은 대신 context-aware calibration을 LoRA fine-tuning으로 수행한다.

3.2 Turn-Taking Dialogue Generation (4 stages)

Dialogue turn $D$에서 utterance는 token 시퀀스:

$$U_D = [u_D^1, u_D^2, \dots, u_D^{n_D}]$$

3.2.1 Spoken-Style Dialogue Conversion

Text-based dialogue를 spoken-style로 변환 (GPT-4.1-2025-04-14 사용).

  • Text 특유 요소 제거: 괄호, 번호 매김
  • Spoken 요소 추가: filler ("um", "uh", "you know"), self-repair, contractions ("I'm", "don't")
  • Assistant는 disfluency 제거 (professional tone), user는 자연스러운 disfluency 허용

Switchboard corpus와의 lexical 비교(Table 3): DuplexGen user의 filler 사용률 3.50% (Switchboard 3.88%와 근접), repetition은 낮음(0.43% vs 1.39%) — 과도한 disfluency 방지가 의도적.

3.2.2 Turn-Taking Slot Identification

각 spoken-style utterance에서 turn-taking action이 가능한 슬롯을 식별. Rule + LLM 결합:

  1. Candidate detection: 각 토큰 뒤에서 다음 중 하나면 candidate — (a) clause/sentence punctuation (. , ? !), (b) hesitation marker (um, uh, umm, hm, huh), (c) GPT-4.1-mini가 clause/sentence boundary로 마킹
  2. Cluster thinning: 연속 candidate (스택된 disfluency)를 축약 — length≥2 run에서 2번째, 4번째, ...만 유지
  3. Long-gap fallback: 이전 slot으로부터 8 tokens 초과 gap이면 4 token 간격으로 추가 slot 삽입
  4. Tail handling: 마지막 slot에서 turn 끝까지 gap rule 적용, final token 제외

슬롯 최대 간격은 8 tokens (conversational phrase 단위). 슬롯은 user turn에만 삽입 (assistant turn은 슬롯 없음).

3.2.3 Scenario-Specific Annotation Calibration

Annotation collection:

  • Prolific로 US/UK 영어 화자 248명 recruit, 각자 20 annotation, €2 보상
  • 각 dialogue slot마다 5명이 독립 annotation → distribution over {LISTEN, BACKCHANNEL, TAKE_FLOOR}
  • 사용자 utterance를 chunk 단위로 순차 공개 (retroactive bias 방지, Umair et al. 2024)
  • Human annotations: $A_H = \{(l_j, a_j)\}$ — slot 위치와 action
  • LLM annotations: $A_L = \{(l_j, a'_j)\}$ — verbalized confidence score로 action distribution 예측

Distribution calibration: 목표는 calibration function $f_{\text{cal}}$을 학습해 LLM raw prediction을 human distribution에 정렬. Context $c$와 partial utterance $x_D^{l_j}$에 조건. 핵심 design choice: 훈련 target을 majority-vote hard label이 아닌 empirical distribution soft label로 삼음:

$$P_H(a \mid x_D^{l_j}, c) = \text{normalized 5-annotator count}$$

KL loss:

$$\mathcal{L} = \sum_{(c, U_D) \in \mathcal{D}_{\text{cal}}} \sum_{l_j \in L_D} D_{\text{KL}}(P_H(\cdot \mid x_D^{l_j}, c) \| P_{\text{cal}}(\cdot \mid x_D^{l_j}, c))$$

직관: turn-taking은 본질적으로 주관적 — 같은 슬롯에서도 여러 action이 모두 적절할 수 있다. Hard label은 이 disagreement 정보를 버리지만, KL은 다양성 preserved.

3.2.4 Turn-Taking Dialogue Synthesis

Calibrated $f_{\text{cal}}$을 target scenario 대화에 turn-by-turn 적용. Candidate slot을 스캔하며 [TAKE_FLOOR]나 [BACKCHANNEL] 삽입 여부 결정:

  • [TAKE_FLOOR]: current turn을 truncate하고 assistant 발화 시작 (interruption 시뮬레이션)
  • [BACKCHANNEL]: 짧은 acknowledgement 삽입, user는 계속 발화
  • [LISTEN]: default, 마킹 없음

Backchannel expression은 별도 prompt로 삽입 (§B.5): "mhm", "mm-hmm", "uh-huh", "yeah", "right", "okay", "oh", "wow", "really", "huh?".

Algorithm 1 (전체 파이프라인)

──── Phase 1: Calibration ──── Require: D_cal = {(c, U_D)} for each dialogue (c, U_D) in D_cal: L_D ← IdentifyCandidates(c, U_D) {A_H^{l_j}} ← HumanAnnotate(U_D, L_D, c) # 5 humans per slot {A_L^{l_j}} ← LLMAnnotate(U_D, L_D, c) f_cal ← Calibrate(A_H, A_L) # KL fine-tuning ──── Phase 2: Dialogue Synthesis ──── Require: Dialogue context c, learned f_cal Ensure: Utterance with turn-taking markers U_D ← TurnGenerate(c) L_D ← IdentifyCandidates(c, U_D) for each slot l_j in L_D: a_j ← f_cal(LLMAnnotate(x_D^{l_j}, c)) # Calibrated decision return Ũ_D with [TAKE_FLOOR] or [BACKCHANNEL] inserted

비판적 분석 (Critical Analysis)

강점

  • 문제 정의의 명확성: "시나리오별 turn-taking preference가 다르다"는 empirical fact를 Figure 3의 chi-square로 정량 증명한 후 문제를 build up. Motivation의 근거가 튼튼.
  • Soft label KL의 사용: Turn-taking처럼 본질적으로 주관적인 task에서 majority-vote hard label의 정보 손실을 피한 것은 합리적. 5명 annotator가 각각 다른 판단을 내리는 사례가 많다는 사실은 (a) 문제 자체가 어렵고 (b) hard label로 짜지 않아야 한다는 점을 지지.
  • Distribution 평가: Single-correct label이 아닌 D_KL(Human ‖ Model)로 평가한 것은 문제 성격에 맞는 선택. 다른 turn-taking 벤치마크(FullDuplexBench, FD-Bench, TalkingTurns)와 상보적.
  • End-to-end 실증: Prediction level (§4.2)뿐 아니라 full-duplex 모델 훈련 (§4.3)까지 이어져, calibration → synthesis → downstream까지 파이프라인 전체가 실효성 있음을 보임.
  • Data efficiency: 1,395 calibration slot으로 KL 0.4 대로 진입 (baseline 6.4 대비). Small annotation budget으로 큰 개선.

약점 및 의문점

  • Text-grounded supervision의 한계: Calibration이 incrementally revealed transcript에 기반. 실제 turn-taking은 prosody, pause duration, intonation, speech rate, overlap 같은 acoustic cue에 강하게 의존. 저자들도 §Limitations에서 인정. 특히 협상/설득 시나리오의 미묘한 turn-taking은 tone에 크게 의존.
  • 주요 시나리오 카테고리의 이분법: Cooperative/competitive 이분법이 편리하지만 실제 대화는 이 두 모드를 자유롭게 오간다 (예: 튜터가 학생 실수에 강하게 개입하는 경우). Mixed dynamics 시나리오는 별도 category로 다뤄지지 않음.
  • Backchannel expression 선택의 별도 처리: "무엇을 backchannel로 발화할지"는 별도 prompt(§B.5)로 처리 — calibration의 범위 밖. Backchannel expression 자체가 시나리오 의존적일 텐데(협상에서 "yeah"와 튜터의 "mm-hmm"은 다름) 이 축은 미탐색.
  • Slot identification의 sensitivity: Maximum gap 8 tokens, cluster thinning의 rule 파라미터가 결과에 미치는 영향에 대한 ablation 없음. Slot의 granularity가 KL에 영향을 줄 것으로 예상.
  • User simulator 편향: Full-duplex 평가에서 PersonaPlex를 user simulator로 사용. Simulator 자체가 realistic한 user behavior를 못 내면 평가 오염. gpt-realtime을 쓸 수 없었다는 이유(backchannel 처리)도 논문에서 명시.
  • PP-DG는 task별 6개 checkpoint: 이는 배포 시 시나리오 감지 → 적절한 checkpoint 로드하는 라우팅 필요. Single unified model이 아님.
  • KL의 modality: KL은 대칭이 아니므로 D_KL(Human ‖ Model)과 D_KL(Model ‖ Human)의 차이가 있다. 논문은 (Human ‖ Model)만 리포트 — model이 human의 mode를 커버하지 못하는 실패(mode-drop)를 잡지만 model이 human이 안 하는 action을 부여하는 실패는 덜 강조.
  • 4B에서 SWBD-Only 성능 하락: 1.7B에서 SWBD-Only가 1.26으로 나쁘지 않으나 4B에서 오히려 0.75로, 14B에선 1.47로 악화. 이 non-monotonic 스케일링에 대한 설명 부족.

Key Takeaways

  • Scenario-adaptive는 corpus scale로 해결되지 않는다: 2.4K dialog Switchboard(SWBD-Only)로도 시나리오 편차를 못 담는다. Small-but-targeted human calibration이 훨씬 강력. 이는 도메인-specific fine-tuning의 일반적 recipe에 대한 evidence.
  • Soft label + KL은 주관적 task에 표준 recipe가 되어야 한다: Turn-taking처럼 정답이 여러 개인 문제에서 hard label majority vote는 정보 손실. Empirical distribution을 target으로 KL 최소화는 이런 문제 전반에 적용 가능한 pattern (RLHF의 preference distribution과 유사).
  • Verbalized confidence + fine-tuning의 조합: LLM의 raw verbalized probability는 miscalibrated. Post-hoc temperature scaling은 context 무관한 fix밖에 못 한다. LoRA fine-tuning으로 context-aware calibration이 유효함.
  • Diversity metric의 필요성: KL divergence만 보면 mode collapse된 model이 유리해질 수 있다. 시나리오간 Δ와 SD를 함께 리포트해야 진짜 adaptive인지 판별 가능.
  • Data-centric approach의 유효성: 모델 구조나 loss 대신 훈련 데이터의 turn-taking distribution을 시나리오별로 정렬하는 접근. Full-duplex 모델 훈련의 practical recipe로 즉시 활용 가능.
