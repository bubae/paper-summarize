목차

TL;DR

  • 문제: 같은 reference 모델에서 출발해 supervised fine-tuning (SFT)이나 reinforcement learning with verifiable rewards (RLVR)로 따로 키운 5개 도메인 teacher(Medical, Law, Tool Use, Finance, Instruction Following)를 multi-teacher on-policy distillation (MOPD)으로 한 student에 합치면, RL로 키운 teacher(Finance·IF)의 능력은 잘 옮겨지지만 SFT로 키운 teacher(Tool Use·Medical)의 능력은 거의 회복되지 않는다. MOPD는 student가 쓴 prefix 위에서 teacher가 지도하므로, student의 출발점이 결과를 크게 좌우한다.
  • 해결: IM-MOPD — teacher들의 task vector(teacher − reference)를 균등하게 더한 merge 모델에서 시작하고, 25 step마다 검증셋으로 도메인별 회복도를 재서, 임계값 γ 이하인 도메인에만 그 teacher의 task vector를 δ=0.3만큼 더 더해 준 뒤 MOPD를 계속한다.
  • 왜 작동하는가: 좋은 출발점은 "초기 점수가 높은 모델"이 아니라 "teacher가 그 student의 prefix를 이어받아 잘 풀 수 있는 모델"이다(§5). merge는 초기 점수를 낮추기도 하지만 teacher와 호환되는 prefix를 만들고, 뒤처진 도메인만 반복해서 보정하므로 도메인 비율과 총 merge 크기가 학습 중에 저절로 맞춰진다.
  • 비유: 다섯 명의 전문 요리사가 견습생 한 명을 첨삭 지도한다. 레시피를 미리 베껴 연습시키면(SFT warm-up) 시험 점수는 오르지만 요리 흐름이 요리사와 어긋나 첨삭이 잘 안 먹힌다. 대신 요리사들의 손맛을 조금씩 이식해 두고(merge), 수업 중간중간 뒤처진 과목의 손맛만 한 스푼씩 더 넣어 준다(IM-MOPD).

핵심 기여 (Key Contributions)

  1. 초기 성능 ≠ 좋은 초기화: MOPD 전 점수가 더 높은 초기화(SFT warm-up)가 MOPD 후에는 merge 초기화보다 낮게 끝날 수 있음을 보이고, teacher 이어쓰기(continuation) 진단으로 벤치마크 점수가 "좋은 MOPD 출발점"을 다 설명하지 못한다는 prefix 수준 증거를 제시한다 (Figure 1, Figure 5).
  2. 추가 SFT 없는 merge 초기화: teacher task vector를 더한 merge로 student를 초기화하면 reference 초기화보다 MOPD 후 회복이 좋아지고, 평가한 SFT warm-up보다도 나을 수 있다. 추가 SFT 단계도, teacher 학습 데이터 접근도 필요 없다 (Figure 1, Table 1).
  3. IM-MOPD: 회복이 임계값 아래인 도메인에만 고정 크기 task vector 증분을 주기적으로 더하는 방법. 5-도메인에서 평균 정규화 회복 4B 86.9, 1.7B 76.0으로, SFT warm-up(59.0, 46.5)과 uniform merge(53.8, 46.3)를 모두 넘는다 (Table 1, Figure 4).

배경 (Background) — On-policy 증류와 model merging (§2)

이 논문은 두 기법의 교차점에 있다. 하나는 on-policy distillation (OPD), 다른 하나는 task arithmetic 기반 model merging이다. 둘 다 "여러 전문가를 한 모델로 모으는" 방법이지만, 전자는 학습으로, 후자는 파라미터 덧셈으로 모은다. 이 논문은 후자를 전자의 출발점과 중간 보정으로 쓴다.

설정 — 같은 뿌리에서 갈라진 teacher들

$K$개의 도메인 teacher 정책 $\{\pi_{\phi_i}\}_{i=1}^K$(파라미터 $\{\phi_i\}$)와 각자의 프롬프트 분포 $\{\mathcal{D}_i\}$가 있다. 모든 teacher와 student $\pi_\theta$는 같은 구조이고 공통 reference 체크포인트 $\theta_{\text{ref}}$에서 출발한 뒤, 도메인별 post-training으로 갈라진다. 이를 저자들은 same-origin multi-teacher setting이라 부른다. 목표는 이 독립적으로 특화된 teacher들의 능력을 student 하나에 통합하는 것이다.

비유로 말하면: 같은 요리학교(reference)를 졸업한 다섯 명이 각자 다른 식당에서 경력을 쌓았다. 어떤 이는 레시피를 외워서(SFT), 어떤 이는 손님 반응을 보며 시행착오로(RL) 실력을 키웠다. 뿌리가 같으니 "학교에서 배운 것 + 각자 더 배운 것"으로 실력을 분해할 수 있다 — 그 "더 배운 것"이 task vector다.

Multi-Teacher On-Policy Distillation (MOPD)

왜 on-policy인가: 전통적 knowledge distillation (KD)은 고정된 데이터 분포에서 teacher의 예측 분포를 맞추고, sequence-level KD는 teacher가 생성한 시퀀스로 학습한다. 이런 오프라인 지도에서는 student가 주로 teacher나 데이터가 만든 prefix만 보게 되어, 학습과 추론 사이 불일치(train–inference mismatch)가 생긴다. OPD는 student가 생성한 궤적 위에서 teacher에게 묻는 방식으로 이를 해결하며, 보통 student가 실제로 방문하는 상태에서 student 분포를 최적화하는 reverse KL과 짝을 이룬다.

해법 — MOPD: OPD를 여러 도메인 teacher로 확장해, 각 프롬프트를 해당 도메인 teacher로 라우팅한다 (Ma et al., 2026). 프롬프트 $x \sim \mathcal{D}_i$에 대해 student가 응답 $y = (y_1, \dots, y_T) \sim \pi_\theta(\cdot \mid x)$를 생성하고, 위치 $t$의 student 생성 prefix를 $s_t = (x, y_{<t})$라 할 때, student와 해당 teacher 사이 토큰 평균 reverse Kullback–Leibler (KL) divergence를 최소화한다.

$$\mathcal{L}_{\text{MOPD}}(\theta) = \frac{1}{K}\sum_{i=1}^{K} \mathbb{E}_{\substack{x \sim \mathcal{D}_i \\ y \sim \pi_\theta(\cdot\mid x)}}\left[\frac{1}{T}\sum_{t=1}^{T} D_{\mathrm{KL}}\big(\pi_\theta(\cdot \mid s_t)\,\|\,\pi_{\phi_i}(\cdot \mid s_t)\big)\right] \tag{2.1}$$

실제로는 계산 효율을 위해 on-policy distillation의 policy-gradient 형태로 최적화한다(부록 A.2: advantage 크기를 5로 clip, 잘린(truncated) completion은 mask, task reward나 reference-KL 항은 없음). ##지도가 student 생성 prefix에 조건화되므로, 초기화가 증류 중 만나는 prefix를 결정하고 따라서 이후 MOPD 궤적 전체를 좌우한다## — 이 한 문장이 논문 전체의 출발점이다.

직관적으로 말하면: student가 문장을 쓰고, 도메인 teacher가 "매 단어 위치에서 나라면 어떤 단어를 골랐을지"를 분포로 알려 주며, student는 그 분포에 가까워지도록 움직인다. 그런데 teacher가 조언하는 위치는 늘 student가 이미 쓴 앞부분 뒤다. student가 첫 문장부터 teacher가 절대 쓰지 않았을 방향으로 가면, teacher의 조언은 "이상한 글의 다음 단어"에 대한 것이라 쓸모가 줄어든다.

(policy-gradient 형태에서는 보통 토큰별 advantage로 $\log \pi_{\phi_i}(y_t \mid s_t) - \log \pi_\theta(y_t \mid s_t)$를 쓴다 — 이 식 자체는 원문 본문에 없고, OPD 계열의 일반적 구현을 요약자가 보충한 것이다.)

Model Merging과 task vector

Model merging은 호환되는 체크포인트를 추가 학습 없이 파라미터 공간에서 직접 합친다 (SWA, model soups). 이 설정에서는 모든 teacher가 $\theta_{\text{ref}}$를 공유하므로 각 teacher를 task vector $\tau_i = \phi_i - \theta_{\text{ref}}$로 나타낼 수 있다 (Ilharco et al., 2023, task arithmetic). merge 모델은

$$\theta_{\text{merge}}(\alpha) = \theta_{\text{ref}} + \sum_{i=1}^{K} \alpha_i \tau_i, \qquad \alpha_i \ge 0, \qquad \lambda = \sum_i \alpha_i$$

로 매개화된다. $\lambda$를 global merge scale이라 부른다. 보통의 가중 파라미터 평균은 $\lambda = 1$이고 균등 평균은 $\alpha_i = 1/K$다. 이 논문은 $\lambda$를 1로 제한하지 않아 teacher 기여를 더 크게 주는 설정도 허용한다. merge 모델을 MOPD의 초기 student로 쓸 수 있다: $\theta_0 = \theta_{\text{merge}}(\alpha)$.

직관적으로 말하면: task vector는 "reference에서 전문가로 가는 화살표"다. 화살표들의 가중 평균($\lambda=1$)은 전문가들 사이 어딘가에 떨어지지만, 합이 1을 넘으면($\lambda>1$) 전문가들보다 더 "앞으로" 나아간 지점이 된다. 저자들은 이런 지점이 MOPD 출발점으로 더 좋을 때가 있다는 것을 발견한다(§3.1).
비유로 말하면: 다섯 요리사 각각의 "학교 이후 배운 손맛"을 조금씩 떼어 견습생에게 이식하는 셈이다. 각 0.2씩 이식하면(λ=1) 다섯 명의 평균 수준, 합쳐서 2배 넘게 이식하면(λ>1) 한 사람 한 사람의 개성을 더 진하게 가진 채로 시작한다.

평가 척도 — 정규화 회복 점수

Ma et al. (2026)을 따라, 모델 $\theta$의 도메인 $i$ 평가 성능을 $s_i(\theta)$라 할 때 정규화 도메인 점수를 다음처럼 정의한다.

$$\tilde{s}_i(\theta) = \frac{s_i(\theta) - s_i(\theta_{\text{ref}})}{s_i(\phi_i) - s_i(\theta_{\text{ref}})}, \qquad \tilde{s}(\theta) = \frac{1}{K}\sum_{i=1}^{K}\tilde{s}_i(\theta)$$

공통 reference가 0, 해당 도메인 전문가가 1이 된다. 논문의 "Norm." 열과 "normalized recovery"가 이 평균값(×100)이다.

직관적으로 말하면: "reference와 teacher 사이 거리 중 몇 %를 따라잡았나"다. 단, 도메인마다 그 거리가 다르다 — 4B에서 Tool Use는 5.3→66.7로 61.4점 거리이고, Medical은 69.5→80.7로 11.2점뿐이다. 그래서 Medical에서는 1점이 회복률 9%에 해당하고 Tool Use에서는 1.6%에 해당한다.

§3 방법 — 관찰에서 IM-MOPD까지

개요: 이질적인 post-training 이력을 가진 teacher들을 MOPD로 통합할 때 student 초기화가 어떤 영향을 주는지 연구한다. 모든 teacher는 공통 $\theta_{\text{ref}}$에서 나왔지만 SFT 또는 RLVR로 독립적으로 특화되었다(구성은 §4.1, 부록 A). 세 가지 관찰이 방법을 이끈다.

3.1 관찰 (Observations)

관찰 ① merge 초기화는 효과적인 MOPD 출발점이다

왜 문제인가: Figure 1에서 reference에서 출발한 MOPD는 SFT로 학습된 Medical·Tool Use teacher의 능력을 회복하지 못하는 반면, RL로 학습된 Finance에서는 teacher 수준에 근접한다. 이 불균등한 회복은 student 초기화가 teacher 능력의 전이 효율에 영향을 준다는 신호다. SFT warm-up이 부분적으로 완화하지만, 추가 학습 비용이 들고 데이터 혼합·학습 일정을 따로 정해야 한다.

해법: teacher task vector를 merge해 student를 초기화하면 추가 학습 없이 MOPD 회복이 크게 좋아진다. model merging은 MOPD를 위해 student를 준비시키는 단순하고 값싼 방법이 될 수 있다.

관찰 ② 더 강한 student가 더 좋은 MOPD 초기화는 아니다

Figure 1에서 SFT warm-up은 Tool Use에서 스케일된 merge 초기화($\lambda = 2.1$)보다 초기 성능이 높지만(정규화 0.41 vs 0.13), MOPD 후에는 순서가 뒤집힌다(0.43 vs 0.74). IM-MOPD는 가장 강한 초기 성능에서 시작하지 않는데도(0 이하에서 출발) 회복을 더 끌어올린다(1.04). 학습 중 merge 개입에서도 같은 패턴이 나온다.

비유로 말하면: 모의고사 점수가 높은 학생이 반드시 과외 효과를 가장 크게 보는 것은 아니다. 문제 푸는 "방식"이 선생님과 비슷한 학생이 첨삭을 훨씬 잘 흡수한다. §5의 teacher 이어쓰기 실험이 이 "방식의 호환성"을 직접 잰다.

merge 개입 실험 (Figure 3a): 같은 5-도메인 MOPD 체크포인트에서 merge 개입을 넣은 가지와 넣지 않은 가지로 나눠 MOPD를 이어 간다. merge 직후에는 평균이 −0.38로 오히려 떨어지지만(특히 Finance −1.29, IF −0.58), 50 MOPD update 뒤에는 개입한 가지가 평균 +0.45로 앞선다(Finance +1.20, IF +0.85). ##즉시 벤치마크 성능만으로는 이후 MOPD를 위한 상태를 고를 수 없다.##

관찰 ③ 도메인이 늘수록 좋은 merge 계수를 고르기가 어려워진다

2-도메인 (Figure 3b, 부록 Table 11): Medical–IF 두 도메인에서도 계수 sweep이 MOPD 후 서로 다른 trade-off를 내고, MOPD 전 평균 정규화 점수가 가장 좋은 초기화 (0.4, 0.6)(86.7)가 MOPD 후 최고가 아니다 — MOPD 후 최고는 (0.8, 0.2)(105.4)로, MOPD 전에는 가장 나빴던(68.9) 초기화다. 후보를 평가하려면 그것이 가능하게 하는 학습까지 봐야 한다. IM-MOPD는 uniform에서 출발해 격자 탐색 없이 105.2에 도달한다.

비유로 말하면: 다섯 가지 향신료의 비율과 전체 양을 한 번에 맞추려는 것과 같다. 넣고 바로 맛보면(초기 점수) 짠맛이 튀어도, 한참 끓인 뒤(MOPD)에야 진짜 맛이 난다. 매번 끓여 봐야 하니 조합이 늘수록 시식 비용이 폭발한다 — 그래서 "끓이면서 부족한 향신료만 조금씩 더 넣자"가 된다.

3.2 Iterative Merging for MOPD (IM-MOPD)

해법: 한 번에 merge 계수를 탐색하는 대신, MOPD update 사이사이에 선택된 teacher task vector를 작은 고정 크기로 더하는 반복 절차로 바꾼다 (Figure 2).

student를 균등 merge로 초기화하고

$$\theta_0 = \theta_{\text{ref}} + \frac{1}{K}\sum_{i=1}^{K}\tau_i,$$

회복이 부족한 도메인에 대한 선택적 task vector 교정과 증류를 번갈아 수행한다. $H$ MOPD update마다 검증셋에서 도메인 회복을 잰다. $\tilde{r}_i(\theta)$를 도메인 $i$의 검증 데이터 정규화 점수(reference 0, teacher 1)라 하고, 임계값 $\gamma$ 이하인 도메인을 모아

$$\mathcal{M} = \{\, i \mid \tilde{r}_i(\theta) \le \gamma \,\}, \qquad \theta \leftarrow \theta + \delta \sum_{i \in \mathcal{M}} \tau_i$$

로 student를 갱신한다. $\delta > 0$은 도메인과 개입 시점 전체에 공유되는 고정 교정 크기다. MOPD는 교정된 student에서 재개되고, 다음 merge 결정은 그 뒤의 학습으로 달성된 회복을 반영한다. 회복이 계속 임계값 아래면 같은 도메인이 여러 번 교정을 받는다. ##이 증분들 덕분에 상대 merge 비율과 총 merge 스케일이 학습 중 함께 진화하며, 누적 계수의 합을 1로 제한하지 않는다.##

Algorithm 1: IM-MOPD Require: θ_ref, teachers {φ_i}, τ_i = φ_i − θ_ref, n MOPD iterations, H correction interval, δ fixed correction scale, γ threshold θ ← θ_ref + (1/K) Σ_i τ_i # uniform merge for t = 1..n: θ ← MOPD(θ; {φ_i}) # 1 update (Eq. 2.1) if t mod H == 0 and t < n: M ← { i | r̃_i(θ) ≤ γ } # 검증셋 정규화 회복 θ ← θ + δ Σ_{i∈M} τ_i # 뒤처진 도메인만 증분 return θ
직관적으로 말하면: 도메인별 연속 계수 5개를 찾는 문제를, 같은 크기 δ로 "이 도메인에 한 스푼 더?"를 반복 결정하는 문제로 바꿨다. 탐색 공간이 연속 5차원에서 매 교정 시점의 이진 선택으로 줄어든다. 잘하는 도메인은 건드리지 않고, 뒤처진 도메인은 여러 번 받는다.
비유로 말하면: 학원 선생님이 한 달마다 모의고사를 보고, 기준점(γ) 아래인 과목에만 보충 수업 한 회차(δ)를 배정한다. 몇 회차를 줄지 학기 초에 다 정하지 않는다. 끝까지 약한 과목은 보충을 여러 번 받고, 처음부터 잘하는 과목은 한 번도 받지 않는다.

(3) SFT Warm-up — 다섯 teacher가 생성한 혼합 샘플로 student를 먼저 SFT해 약 30% 정규화 회복에 도달시킨 뒤 MOPD (4B 167M, 1.7B 171M 토큰, 배치 32, 길이 32,768, LR 1e-5, packed sequence, 5% warm-up cosine decay).

IM-MOPD 설정: 두 크기 모두 uniform에서 시작, 같은 검증 기반 회복 규칙. γ = 0.6(4B) / 0.4(1.7B), δ = 0.3, H = 25. 검증 데이터는 Tool Use 128과제, 그 외 도메인은 학습 풀에서 떼어 낸 256 프롬프트.

평가: Medical = MedQA(1,273), Law = CaseHOLD(5,314), Finance = FinQA(1,147, 숫자 답 정확도), IF = IFBench(300, prompt-level loose), Tool Use = τ²-Telecom(114 base-split 과제, 과제 성공). temperature 1, top-p 1, top-k 비활성. 단일 턴 과제는 completion 26,624 토큰(IFBench 32,768) 상한. Tool Use는 pass@1, 나머지는 avg@3. τ² 평가는 공식 v1.0.1 harness, 문맥 32,768, 200 step 제한, 사용자 시뮬레이터 gpt-4.1-2025-04-14(temperature 0)이며, 빈 응답·실행/문맥 한도 오류는 실패로 센다. 이 split에는 상류 학습과 겹친다고 표시된 과제 ID 20개가 포함되어 있어, teacher 데이터 필터링이 상류 노출까지 배제하지는 못한다고 저자들이 밝힌다.

(2) 4B Tool Use 69.3은 teacher 66.7보다 높다(정규화 1.04). (3) 1.7B에서 MOPD는 Tool Use를 0.0점(reference 7.9보다 낮음)으로 떨어뜨리고, uniform merge도 4.4로 reference보다 낮다 — 작은 모델에서 SFT teacher 전이 실패가 더 심하다. (4) 1.7B Finance는 IM-MOPD(55.9)가 MOPD(59.1)·uniform(58.6)보다 낮아, "잘 옮겨진 도메인을 크게 해치지 않는다"는 주장이 1.7B Finance에서는 약하게 성립한다.

비유로 말하면: 다섯 과목 중 두 과목(Finance, IF)은 원래 과외만 받아도 금방 따라오는 과목이고, 나머지 세 과목(특히 Tool Use)은 어떤 준비를 해 와도 과외만으로는 안 오른다. IM-MOPD는 이 "안 오르는 과목"에만 보충 수업을 몰아주어 전체 평균을 끌어올린다.

학습 곡선 (Figure 4): 4B에서 IM-MOPD는 uniform merge에서 시작해 MOPD 중 뒤처진 도메인을 점진적으로 개선한다. 가장 큰 향상은 Medical, Tool Use, Law에서 보이고, 이미 잘 회복된 도메인은 대체로 안정적이다. (이하 그림 판독과 Table 7 대조에 근거한 요약자 관찰) merge 직후에는 교정 대상이 아닌 도메인도 흔들린다 — 예컨대 update 25에서 Finance는 교정 대상이 아닌데도 다른 도메인 task vector가 더해지면서 떨어졌다가, 이후 MOPD로 회복된다.

4.3 Ablation

반복 merge vs 초기화 시점에만 merge

실험 의도: Q2 — IM-MOPD의 이득이 단지 "최종적으로 더해진 task vector의 양" 때문인가? 같은 누적 계수를 초기화 때 한 번에 적용하고 같은 수의 MOPD update를 돌린 initialization-only 변형과 비교한다.

결과: 반복 merge 86.9% vs 초기화 한 번에 79.0%, 가장 큰 차이는 Tool Use(69.3 vs 57.0). 누적 계수를 고정했을 때 task vector 증분을 증류 전반에 나눠 주는 것이 처음에 모두 주는 것보다 효과적이다.

merge와 MOPD는 서로를 강화한다

실험 의도: 반대로, reference에서 추가 초기화 없이 MOPD를 끝낸 student에 IM-MOPD의 최종 누적 계수를 한꺼번에 적용하면 어떻게 되나?

결과: 이 late merging은 정규화 회복 ##23.3%##로 Base MOPD(42.8%)보다도 낮고 IM-MOPD에 크게 못 미친다(FinQA 74.3→59.6, IFBench 56.9→38.2로 붕괴). 뒷받침하는 주장: initialization-only 대조군과 함께, IM-MOPD의 이득은 merge가 만드는 최종 task vector 변위만으로 설명되지 않는다. 같은 merge 계수라도 MOPD와 번갈아 줄 때 훨씬 효과적이며, 각 교정 뒤 teacher 지도 update가 최종 회복에 중요하다.

비유로 말하면: 같은 양의 비료를 파종 전에 한꺼번에 주면(초기에 전부) 어느 정도 자라고, 수확 직전에 한꺼번에 주면(끝에 전부) 오히려 작물이 탄다. 자라는 도중 필요할 때 나눠 주고 물(MOPD)을 계속 주어야 가장 잘 자란다.

§5 분석 — student prefix 위의 teacher 이어쓰기

실험 의도: Q4 — 왜 merge student가 더 좋은 출발점인가? 선행 연구(Li et al., 2026)는 student가 생성한 prefix에서 teacher가 이어 쓰게 해 OPD에서 teacher 지도의 신뢰도를 평가했다. 이 진단으로 merge student와 SFT warm-up student의 teacher–student 호환성을 잰다.

방법 (부록 B.3): 각 student가 앞부분을 생성하고 해당 도메인 teacher가 나머지를 완성한다. student 생성 비율 α ∈ {0.1, 0.3, 0.5, 0.7}을 바꿔 과제 성능을 본다(0% = teacher 단독, 100% = student 단독). Medical은 기록된 MedQA 응답 길이 $L$마다 처음 $\lfloor \alpha L \rfloor$ 토큰 뒤를 teacher가 잇는다. Tool Use(τ²-Telecom)는 멀티턴이라 한 턴을 바꾸면 이후 상호작용이 달라지므로, student의 단독 평가 턴당 평균 토큰 $\bar{L}$로 턴당 예산 $N = \mathrm{round}(\alpha \bar{L})$을 정하고 student가 이 예산에 닿으면 teacher가 잇는다(평균을 쓰므로 짧은 턴은 student가 다 쓰기도 한다).

결과 (Figure 5): Medical과 Tool Use 모두에서, SFT warm-up student의 prefix는 짧아도 teacher 이어쓰기 성능이 떨어지는 반면, merge student의 prefix는 궤적 초반에 이를 더 잘 유지한다. Medical에서는 student 단독 성능이 비슷한데도(100% 지점) merge 초기화 prefix에서의 이어쓰기가 일관되게 강하고, Tool Use에서는 평가 체크포인트의 student 단독 성능이 더 낮은데도(IM-MOPD ≈25.5 vs SFT ≈28) 짧은 prefix에서 이어쓰기 성공률이 높다(30% 지점 ≈60 vs ≈44, 그림에서 읽은 근사치).

뒷받침하는 주장: teacher–student 호환성이 효과적인 OPD에 중요하다는 선행 결과와 일치하며, 이 이점은 merge student의 단독 성능이 SFT warm-up과 비슷하거나 낮을 때도 유지된다. ##merge는 student가 teacher가 더 잘 이어 갈 수 있는 prefix를 생성하게 해, MOPD 중 teacher 지도로부터 더 많이 배우게 한다.##

비유로 말하면: 견습생이 요리를 30%쯤 만들어 놓고 요리사에게 넘긴다. SFT로 레시피만 외운 견습생은 재료 손질부터 요리사가 쓰지 않는 방식이라, 요리사가 이어받아도 수습이 어렵다. 요리사들의 손맛을 이식받은 견습생은 요리 자체는 어설퍼도 "요리사가 하던 방식"으로 시작해 두어서, 요리사가 이어받으면 거의 원래 실력대로 완성한다. MOPD의 첨삭은 바로 이 "이어받기"의 연속이다.

§6 관련 연구

LLM의 on-policy distillation: KD(Hinton et al., 2015)는 고정 분포에서 예측 분포를 맞추고, Kim & Rush(2016)는 teacher 생성 시퀀스로 sequence-level KD를 제안했다. 이런 오프라인 지도는 학습–추론 불일치를 만들고, OPD는 student 궤적에서 teacher에게 물어 이를 해결하며(Agarwal et al., 2024) reverse KL과 짝을 이룬다(Gu et al., 2024, MiniLLM). 추론 길이가 긴 reasoning LLM에서 특히 중요해졌다(DeepSeek-V4, Nemotron 3, MOPD, Kimi K3). 그러나 on-policy 지도의 이득은 student가 방문하는 상태에서 teacher가 여전히 유익할 때만 성립한다 — 분포가 벌어지면 teacher 피드백이 덜 효과적이거나 신뢰할 수 없게 된다(Speculative KD, Li et al., 2026, Nemotron 3 Ultra). 그래서 최근 방법들은 teacher–student 정렬에 따라 증류를 제한하거나 조정한다(Trust Region OPD). 분포 호환성이 OPD의 핵심 난제다.

도메인 전문가 통합: post-training이 점점 RL로 이질적인 능력을 겨냥하면서 이를 한 모델에 모으는 것이 핵심 난제가 되었다. Mixed RL은 한 정책을 도메인 혼합으로 동시 최적화해 직접 통합하지만 데이터·보상·rollout 길이·최적화 동역학이 서로 얽힌다(Nemotron 3 Nano). Cascade RL은 도메인별 RL 단계를 순차 적용해 단계마다 전용 환경·설정을 쓸 수 있지만(Nemotron-Cascade), 단계가 특화될수록 능력 drift가 누적되어 중간 통합·안정화가 필요하다(Nemotron-Cascade 2). 또는 도메인 전문가를 독립적으로 키운 뒤 parameter merging(LongCat-Flash-Thinking)이나 MOPD(Ma et al., 2026)로 통합한다. 이 논문은 이 전문가-통합 패러다임 위에서, 반복 merge가 teacher–student 정렬을 유지하며 이질적 능력을 점진적으로 통합할 수 있는지를 본다.

비유로 말하면: 한 선수를 만능으로 키우는 네 가지 길이다. 모든 종목을 한꺼번에 훈련시키거나(Mixed RL), 종목을 차례로 훈련시키거나(Cascade RL), 종목별 선수를 따로 키운 뒤 "기술을 섞어 이식"하거나(merging), 종목별 코치가 번갈아 개인 지도하거나(MOPD). IM-MOPD는 마지막 두 가지를 섞는다 — 이식으로 출발점과 중간 보정을, 개인 지도로 실력을 만든다.

§7 결론

도메인 teacher들이 공통 reference를 공유하지만 서로 다른 post-training을 거친 경우의 MOPD를 연구했다. 초기 벤치마크 성능은 MOPD 초기화를 고르는 기준으로 신뢰할 수 없고, 효과적인 merge 초기화는 teacher 간 상대 가중치와 전체 merge 스케일 모두에 달려 있다. 이 관찰에 따라 uniform merge에서 시작해 증류 중 회복이 부족한 도메인에 task vector 교정을 점진적으로 더하는 IM-MOPD를 제안했다. 4B·1.7B 5개 도메인에서 IM-MOPD는 추가 SFT 단계 없이 uniform merge와 SFT warm-up보다 높은 총 회복을 달성했다. merge 시점 ablation은 같은 최종 누적 계수를 MOPD 전이나 후에 한꺼번에 적용하는 것이 증류와 번갈아 주는 것보다 덜 효과적임을 보였다. 이 결과들은 ##teacher 기여도를 학습 전에 고정하기보다 MOPD 중 점진적으로 정하는 편이 더 효과적##임을 시사한다.

저자들은 별도의 Limitations 절을 두지 않는다. 재현성 진술(Reproducibility Statement)에서 Algorithm 1, teacher 학습·데이터(부록 A.1), MOPD·SFT warm-up 설정(A.2–A.3), 검증 데이터·merge 일정(A.4), 평가 프로토콜(A.5), 추가 ablation과 진단(B.1–B.4)을 제시했다고 밝히며, 이 연구는 Kakao와 협력·지원으로 수행되었다.

비판적 분석 (Critical Analysis)

강점

  • 실용적 문제 설정: 도메인 팀들이 서로 다른 일정·레시피로 전문가를 만들고 나중에 합치는 모듈형 워크플로는 실제 조직에서 흔하다. teacher 학습 데이터 없이 task vector만으로 초기화를 개선한다는 점이 이 워크플로와 잘 맞는다.
  • "초기 점수"라는 흔한 휴리스틱을 반증: Figure 1(SFT warm-up vs λ=2.1), Figure 3a(merge 직후 하락 → 50 step 뒤 역전), Table 11(MOPD 전 최악 (0.8,0.2)이 MOPD 후 최고)의 세 갈래 증거가 같은 방향을 가리킨다.
  • 원인 분리형 ablation: 같은 최종 계수를 "처음에 전부 / 끝에 전부 / 나눠서"로 비교한 Table 2는 이득이 최종 변위가 아니라 "교정–증류 교대"에서 온다는 것을 깔끔하게 보인다. 특히 "끝에 전부" 23.3%는 강한 대조다.
  • 메커니즘 진단: teacher 이어쓰기(Figure 5)로 "왜 merge student가 나은가"에 대한 prefix 수준 설명을 제공한다.
  • 세부 공개: 실제 교정 일정(Table 7), 데이터 수·출처, 하이퍼파라미터, 평가 harness·시뮬레이터 버전, 과제 중복 문제까지 명시하고 코드를 공개했다.

한계와 의문점

  • 통계적 불확실성: 모든 결과가 단일 학습 run이다(평가는 avg@3 / Tool Use pass@1). τ²-Telecom은 114과제·pass@1이라 과제 몇 개의 성패로 수 점이 움직이고, Tool Use의 큰 분모(61.4점) 때문에 평균 정규화 점수 차이의 상당 부분이 이 한 도메인에서 나온다(Table 9에서 δ=0.2와 0.3의 차이 80.3 vs 86.9는 거의 전부 τ² 36.8 vs 69.3).
  • 검증셋 선택 편향 가능성: IM-MOPD는 검증셋 회복으로 교정 도메인을 고르는 적응형 방법이고, γ·δ도 Table 3 sweep에서 골랐다(1.7B는 γ=0.4·δ=0.3이 유독 높음). 기준선들은 이런 검증 기반 적응을 받지 않으므로, 비교에 선택 이점이 섞여 있다. 특히 1.7B의 "최적" 설정 선택이 테스트 점수(Table 10)와 같은 표에서 보고된다.
  • 기준선의 튜닝 폭: SFT warm-up은 "약 30% 회복까지"라는 하나의 설정만 평가했고, one-shot merge도 uniform(λ=1)만 주 기준선이다. Figure 1의 λ=2.1 수작업 merge(MOPD 후 Tool Use 50.9)나 TIES·DARE 같은 정교한 merge 규칙과의 비교는 주 표에 없다. 저자도 uniform이 "반복 적응의 효과를 분리"하기 위한 선택이라 밝힌다.
  • Figure 4 곡선과 Table 1의 불일치: Figure 4의 끝점(예: SFT warm-up Medical ≈0.54)은 Table 1 테스트 점수를 정규화한 값(0.39)과 맞지 않는다. 검증셋 기준으로 보이지만 원문이 명시하지 않는다.
  • 일반화 범위: Qwen3 계열 두 크기, 5개 도메인, same-origin 설정만 다룬다. teacher가 서로 다른 base에서 나온 경우(task vector를 정의할 수 없음)나 도메인 수가 훨씬 많을 때 교정 규칙이 어떻게 작동하는지는 미지수다. λ가 2.8까지 커지는데, 더 긴 학습에서 누적 계수가 계속 커질 때의 안정성도 보고되지 않는다.
  • τ² 오염 문제: 저자 스스로 밝히듯 τ²-Telecom 114과제 중 20개가 상류 학습과 겹친다고 표시되어 있고, teacher 데이터 필터링이 상류 노출을 배제하지 못한다. Tool Use 1.04(teacher 초과)의 해석에 주의가 필요하다.
  • 비용 보고 부족: 교정마다 5개 도메인 검증 평가(Tool Use 128과제 멀티턴 시뮬레이션 포함)가 필요하다. 이 비용이 SFT warm-up(167M 토큰) 대비 얼마인지 정량 비교가 없다.

Key Takeaways — 이 논문에서 가져갈 것

  1. OPD에서 초기화는 "시작 점수"가 아니라 "teacher가 이어받기 쉬운 prefix"로 평가하라: 점수가 높은 SFT warm-up이 MOPD 후 merge보다 낮게 끝난다. 후보 초기화를 고를 때 teacher 이어쓰기(continuation) 곡선이 더 좋은 신호일 수 있다.
  2. SFT로 만든 teacher는 on-policy 증류로 옮기기 어렵다: 4B에서 RL teacher(Finance·IF)는 reference 시작만으로도 0.93–0.96 회복되지만(1.7B는 0.84·0.66), SFT teacher(Tool Use·Medical)는 0.04·−0.04에 머문다. 여러 레시피의 전문가를 합칠 때 SFT 계열 도메인에 특별한 대책이 필요하다.
  3. task vector merge는 λ=1 평균에 묶일 필요가 없다: 합이 1을 넘는 확대 merge(λ=2.1, IM-MOPD 최종 2.8)가 더 좋은 출발점일 수 있다.
  4. "계수 탐색" 대신 "뒤처진 곳에만 고정 크기 증분": 연속 계수 공간 탐색을 반복 이진 결정으로 바꾸는 요령은 도메인 수가 늘어도 비용이 선형으로만 는다. 다른 multi-task 통합 문제에도 옮길 만한 설계 패턴이다.
  5. 같은 merge도 언제 주느냐가 결정적이다: 처음에 전부 79.0, 나눠서 86.9, 끝에 전부 23.3. merge는 뒤따르는 증류가 있을 때만 이롭다.
  6. (비판적) 평균 정규화 점수의 차이는 Tool Use 한 도메인이 좌우한다: 분모가 큰 τ²(114과제, pass@1, 상류 오염 20과제)가 평균을 흔든다. 단일 run·검증 기반 적응이라는 조건을 감안하면, 도메인별 점수와 반복 실험으로 재확인이 필요하다.

개인 메모

Q: 결국 이 논문은 MOPD 학습 셋업을 어떻게 하라는 것인가? (2026-10-01)

A: 논문의 권고를 순서대로 정리하면 다음과 같다.

  1. 출발점은 reference가 아니라 teacher merge로: $\theta_0 = \theta_{\text{ref}} + \frac{1}{K}\sum_i \tau_i$ (균등 merge). 추가 SFT warm-up 단계나 teacher 학습 데이터가 필요 없다 (§3.1, Table 1: 4B 42.8 → 53.8).
  2. merge 계수를 미리 탐색하지 말고 학습 중에 보정: $H=25$ update마다 도메인별 검증 정규화 회복을 재고, $\gamma$ 이하(4B 0.6, 1.7B 0.4)인 도메인에만 $\delta=0.3$의 task vector를 더한다. 계수 합 $\lambda$를 1로 묶지 않는다 (§3.2, 4B 86.9).
  3. merge는 반드시 MOPD 사이에 끼워 넣는다: 같은 계수를 처음에 몰아 주면 79.0, 끝에 몰아 주면 23.3, 나눠 주면 86.9 (§4.3 Table 2).
  4. 초기화를 초기 벤치마크 점수로 고르지 않는다: 점수가 높은 SFT warm-up이 MOPD 후에는 더 낮게 끝난다. 후보를 비교하려면 teacher 이어쓰기 성능이나 짧은 MOPD 후 점수를 본다 (§3.1, §5).

MOPD 자체 설정 (부록 A.2): 100 update · 배치 128 프롬프트 · 도메인 균등 샘플링 · 프롬프트당 completion 1개 · LR $10^{-6}$ · 최대 16,384 토큰 · temperature 1, top-p 1 · reverse KL의 policy-gradient 형태, advantage 크기 5로 clip · 잘린 completion은 mask · task reward와 reference-KL 항 없음. 검증셋은 Tool Use 128과제, 그 외 도메인 256 프롬프트.

비유로 말하면: "견습생을 백지에서 시작시키지 말고 요리사들의 손맛을 조금씩 이식한 채로 수업을 시작하라. 매달 시험을 봐서 뒤처진 과목에만 보충 수업을 한 회차씩 넣고, 보충 뒤에는 반드시 수업(MOPD)을 이어 가라."

적용 조건과 주의: (1) teacher들이 같은 reference에서 갈라져 나와야 task vector를 정의할 수 있다. (2) 이득은 주로 SFT로 만든 teacher 도메인(Tool Use·Medical·Law)에서 나오고, RL teacher는 기준 MOPD로도 4B에서 0.93–0.96까지 회복된다. (3) Qwen3 4B·1.7B, 5개 도메인, 단일 run 결과이며 γ·δ는 작은 모델(1.7B)에서 민감하다(57–76). 자기 설정에서는 γ·δ를 2–3개 후보로 짧게 sweep하는 것이 안전하다.
