목차

TL;DR

  • 문제: 인간–AI 상호작용은 여전히 "사용자가 말을 끝내면 → 모델이 답한다"는 턴 기반 사이클에 갇혀 있다. VAD(Voice Activity Detection)·ASR 같은 외부 모듈 조립으로는 끼어들기, 맞장구(backchannel), 다자 대화, 소음 같은 실제 상호작용 역학을 신뢰성 있게 다룰 수 없고, 실시간 반응성과 장기(long-horizon) 에이전트 추론을 단일 모델로 동시에 만족시키려면 양쪽 모두에서 타협이 생긴다.
  • 해결: 옴니 지각·실시간 상호작용·에이전트 능력을 하나의 프레임워크로 통합한 end-to-end 모델 Gander. ① 실시간 full-duplex 상호작용을 전담하는 전뇌(Cerebellum)와 장기 추론·과제 실행을 맡는 training-free 후뇌(Brain)를 tool call과 orchestration runtime으로 잇는 2층 구조, ② 모든 모달리티의 입출력을 1초 단위 청크로 평탄화(streaming chunk flattening)하고 청크마다 listen/speak/interrupt 제어 토큰을 예측하는 Thinker-Talker 전뇌.
  • 왜 작동하는가: "언제 말할 것인가"라는 상호작용 결정을 외부 모듈이 아니라 응답을 생성할 바로 그 표현(representation) 위에서 내리므로, 음향적 침묵이 아니라 의미적 완결을 기준으로 발화 시점을 정할 수 있다. 무거운 추론은 비동기 후뇌로 위임되므로 전뇌는 9B로 작게 유지되어 실시간성이 보존된다.
  • 비유: 유능한 비서와의 통화. 비서(전뇌)는 대화의 흐름·눈치·타이밍을 전담하면서, 시간이 걸리는 일은 뒤편의 전문가 팀(후뇌)에 넘기고 통화를 계속 이어간다. 일이 끝나면 상대가 말을 멈춘 틈에 결과를 요약해 전한다. 소뇌(cerebellum)가 운동 타이밍을, 대뇌(brain)가 사고를 맡는 신경과학 비유가 이름의 유래다.

핵심 기여 (Key Contributions)

  1. Omni Interaction Agent라는 문제 설정: 옴니 지각(음성·영상·텍스트) + 실시간 full-duplex 상호작용 + 장기 에이전트 실행을 단일 연속 프로세스로 통합하는 과제를 정식화하고, 이를 end-to-end로 구현한 첫 공개 시스템 중 하나인 Gander(9B)를 제시.
  2. Cerebellum–Brain 협업 프레임워크: 실시간 상호작용(전뇌)과 장기 추론(후뇌)을 분리하되, task_start / task_send / task_resolve라는 구조화된 tool call과 agent orchestration runtime으로 연결. ##후뇌는 training-free plug-and-play(Codex, Claude Code 등)라서 더 강한 추론 모델이 나오면 전뇌 재학습 없이 시스템 전체가 강해진다## — 상호작용성과 지능을 독립적으로 확장하는 경로.
  3. Streaming chunk flattening: 사용자 입력과 모델 출력을 1초 청크 수준에서 하나의 순서 있는 토큰 스트림으로 평탄화하고, 청크마다 제어 토큰(listen/speak/interrupt)을 먼저 예측하는 통합 표현. VAD 없이 모델 스스로 발화 타이밍을 제어한다.
  4. 상호작용 특화 데이터 파이프라인 2.7M: full-duplex 턴테이킹·interruption·backchannel을 명시적으로 합성하는 InteractionSpeech, 전뇌–후뇌–사용자 3자 궤적 시뮬레이션, 소음·다자·무명령 강건성 데이터까지 4개 계열의 대규모 코퍼스 구축 방법을 상세 공개.
  5. 실증과 공개: Full-Duplex-Bench v3에서 Take-turn 100% / Interrupt 8.0%로 6개 상용·오픈 시스템 대비 최고의 턴테이킹 달성, SpokenQA full-duplex 그룹 1위, 모달리티 융합 이득 +8.88pt. 모델 가중치·코드·데이터 공개.

배경 (Background)

먼저, 용어 정리 — 이 논문에서의 의미

이 논문은 음성 대화 시스템과 에이전트 시스템의 용어가 섞여 등장하므로, 논문 맥락에서의 의미를 먼저 고정한다:

  • Full-duplex (전이중): 통신 용어를 차용한 것으로, 듣기와 말하기가 동시에 일어날 수 있는 상호작용 체제. 단순히 "입출력이 동시에 가능하다"를 넘어, 이 논문은 복잡한 음향 조건에서 적절한 상호작용 상태를 유지하는 능력(누가 나에게 말하는가, 지금 멈춰야 하는가)까지를 full-duplex의 요건으로 본다.
  • Backchannel (맞장구): "응", "그렇지", "uh-huh"처럼 상대의 발화 도중 끼워 넣는 짧은 청자 반응. 핵심 성질은 발화권(conversational floor)을 요구하지 않는다는 것 — 시스템이 이를 interruption으로 오인하면 말을 멈추는 오류가, 실제 interruption을 backchannel로 오인하면 무시하는 오류가 난다. §4.1의 데이터 설계가 이 구분을 명시적으로 가르친다.
  • VAD (Voice Activity Detection): 오디오에서 음성 구간의 시작·끝을 탐지하는 외부 모듈(Silero VAD 등). 기존 파이프라인에서 "사용자가 말을 끝냈다"는 판정 — 즉 상호작용의 가장 근본적인 결정 — 을 모델 밖에서 내리는 주체다.
  • Thinker-Talker: Qwen Omni·MiniCPM-o 계열에서 확립된 옴니 모델 구조. Thinker(LLM 백본)가 멀티모달 이해·텍스트 생성을 맡고, Talker(경량 음성 디코더)가 Thinker의 hidden state를 받아 음성을 합성한다. Gander는 이 구조를 "재현성을 위해" 채택하고(§3.3), 그 위에 청크 평탄화를 얹는다.
  • Agent harness: 에이전트 모델을 실제로 구동하는 실행 기반 — 도구 제공, 상태 관리, 권한, 복구를 포함한 시스템 계층. Gander에서는 orchestration runtime(§3.2.2)이 이 역할이다.
  • Training-free: 후뇌에 대해 쓰일 때, 이 시스템을 위한 어떤 추가 학습도 하지 않은 기성 에이전트(Codex, Claude Code)를 그대로 쓴다는 뜻. 통합은 학습이 아니라 인터페이스(context_fetch·memory_search·share, §3.2.3)로 이뤄진다.

턴 기반 패러다임의 한계와 두 가지 근본 질문

왜 문제인가: 현재 LLM 기반 시스템의 상호작용 프로토콜은 대부분 "사용자가 완결된 발화를 제공 → 모델이 응답"이라는 이산적(discrete) 사이클이다. 전형적인 음성 시스템에서는 VAD(Voice Activity Detection, 음성 활동 감지)가 발화의 시작·끝을 판정하고, 잘라낸 음성 구간을 ASR(자동 음성 인식)로 텍스트화해 모델에 전달한다. 이 구조에서 모델 자신은 근본적인 상호작용 결정(언제 듣고, 언제 말하고, 언제 멈출지)에 대한 통제권이 없다. 정형화된 질의응답에는 충분하지만, 실제 인간 대화의 특징인 머뭇거림, 일시정지, 끼어들기(interruption), 겹치는 발화, "응", "그렇지" 같은 짧은 맞장구(backchannel), 배경 소음, 다자 대화 앞에서는 독립적으로 설계된 모듈들의 파이프라인이 신뢰성 있게 동작하지 않는다.

목표 패러다임: 인간–인간 소통처럼 참여자들이 모달리티를 넘나들며 연속적으로 정보를 교환하고, 동시에 듣고 말하고, 맥락 정보를 관찰·제시하며, 진행 중인 상호작용을 유연하게 개시·중단·전환하는 협업. 저자들은 이를 실현하는 데 세 가지 상보적 능력의 통합이 필요하다고 본다:

  1. 멀티모달(multimodal) — 음성·시각·텍스트를 아우르는 포괄적 지각과 이해
  2. 상호작용(interaction) — 자연스러운 실시간 소통을 지지하는 연속적·저지연·양방향 채널
  3. 에이전트(agentic) — 맥락 추론, 자율 계획, 도구 사용, 과제 실행

기존 연구는 셋 중 하나 또는 둘에 집중해 왔다(§배경의 세 갈래). 이 셋을 독립된 시스템 컴포넌트가 아니라 하나의 연속 프로세스로 통합할 수 있는가가 이 논문의 물음이다.

저자들은 여기서 두 가지 근본 질문을 던진다:

  1. 진정한 상호작용적 옴니 커뮤니케이션이 기존 지각·상호작용 모듈(VAD, ASR)의 조립으로 달성될 수 있는가, 아니면 상호작용성 자체가 모델의 내재적(intrinsic) 능력이어야 하는가?
  2. 단일 모델이 실시간 상호작용에 필요한 저지연 반응성과 복잡한 에이전트 과제에 필요한 장기 추론(long-horizon reasoning)을 동시에 제공할 수 있는가?

Gander의 답은: ①에 대해 ##"상호작용성은 모델에 내재해야 하며, 그래야 기저 지능이 커질 때 상호작용 능력도 함께 확장(scale)된다"## — 이것이 청크 평탄화(§3.3)의 동기다. ②에 대해서는 "단일 monolithic 모델은 반응성과 지능 사이에 내재적 trade-off를 만들므로", 두 요구를 분리한 뒤 구조적으로 다시 연결한다 — 이것이 Cerebellum–Brain 구조(§3.2)의 동기다.

3. Gander 아키텍처

3.1 개요 — 세 개의 컴포넌트

Gander는 전뇌(front cerebellum) · agent orchestration runtime · 후뇌(back brain)의 세 컴포넌트로 구성된다:

  • 전뇌: Thinker-Talker 구조의 실시간 full-duplex 옴니 모델(9B). 스트리밍 음성·카메라·화면 입력을 연속 지각하면서 듣기, 말하기, 짧은 피드백, 중단, 도구 호출까지의 상호작용 행동을 자기회귀적으로 결정한다. 사용자와 만나는 유일한 접점이다.
  • 후뇌: 정보 검색, 코드·파일 조작, 문서 처리 같은 장기 과제를 수행하는 범용 실행 에이전트. 과제 특화 학습이 전혀 없으며(training-free) Codex나 Claude Code 같은 기성 에이전트를 그대로 꽂는다.
  • agent orchestration runtime: 두 층 사이의 조정 계층. 실시간 멀티모달 추론(스트림 수집·스케줄링)과 비동기 백그라운드 과제 orchestration을 함께 관리하는 실행 기반이며, 전체 agent harness의 필수 구성 요소다.

3.2 Cerebellum–Brain 협업 프레임워크

전뇌의 활성화와 과제 라우팅 (§3.2.1)

왜 이렇게 나누는가: 일상 대화는 즉각적 응답과 지속적 맥락 적응을 요구하고, 복잡한 workflow는 장기 추론·반복 계획·도구 사용·지속 실행을 요구한다. 하나의 monolithic 모델로 둘 다 만족시키려 하면 반응성과 지능 사이의 내재적 trade-off가 생긴다. 그래서 Gander는 최근의 dual-brain 계열 연구(Mind-paced Speaking, VoiceMem 등)와 개념적으로 연결되는 Brain–Cerebellum 분리 구조를 채택한다.

전뇌는 그 자체로 GPT-Realtime, Seed-Realtime급의 실시간 옴니 상호작용 모델로서 일상적 대화, 정보 탐색, 간단한 검색 과제는 독립적으로 처리한다. 이중 뇌 구조에서 전뇌는 여기에 더해 과제 라우팅(task routing)의 역할을 맡는다: 현재 상호작용 맥락을 근거로 요청을 로컬에서 해결할지 후뇌로 위임할지를 동적으로 판단한다. 다단계 추론·외부 도구·장기 실행이 필요한 workflow만 후뇌로 넘어간다.

위임은 전용 특수 토큰으로 감싼 구조화된 tool call로 형식화된다:

<tool_call> {"name": "tool_state", "arguments": {"key": "value"}} </tool_call>

인터페이스는 세 가지 기본 연산으로 구성된다:

  • task_start — 새 백그라운드 과제를 초기화하고 현재 사용자 턴과 연결. 과제 설명/이름이 이후 수명주기 관리의 식별자가 된다.
  • task_send — 이후의 사용자 입력을 기존 과제로 라우팅. 두 가지 모드: main은 새 입력을 활성 실행 맥락에 병합해 주 과제를 조종하고, fork는 주 과제의 상태·실행 궤적을 건드리지 않는 읽기 전용 보조 질의를 생성한다 (예: "지금 어디까지 됐어?"라고 물어도 본 작업이 흔들리지 않는다).
  • task_resolve — 4가지 결정론적 해결 행동: cancel(주 과제 종료), allow_once(위험 연산 1회 승인), allow_session(세션 동안 승인 유지), deny(요청된 연산 거부·차단). 전뇌가 과제 수준 제어 결정을 구조화된 형태로 표현하면, runtime이 상태 전이와 실행 의미론을 결정론적으로 집행한다.
직관적으로 말하면: 전뇌는 "무엇을 할지"를 음성 대화의 흐름 속에서 말하듯 결정하고, 그 결정의 집행은 전부 시스템(runtime)이 맡는다. 모델의 유연성과 시스템의 결정론을 분리해서 얻는 설계다.

전뇌 → 후뇌로 무엇이 전달되는가: Gander는 가장 단순한 방식을 택했다 — 오디오 질의의 전사(transcribed) 텍스트와 입력 비디오의 관련 마지막 프레임들을 후뇌 입력으로 전달한다. 저자들은 이것이 열린 설계 고려사항임을 명시한다: 전뇌가 전사 질의에 추가 추론을 얹어 넘길 수도 있고, 학습 가능한 후뇌가 사용자의 완전한 멀티모달 입력 스트림을 실시간으로 직접 받을 수도 있다(둘 다 미래 과제).

결과 요약도 전뇌의 몫: 후뇌가 반환한 결과(중간 실행 상태 또는 최종 결과)를 요약해 최종 사용자 응답을 생성하는 것도 전뇌다. 요약 응답은 텍스트식 과제 완료 보고가 아니라 자연스러운 구어체 전달에 최적화된다 — 이는 학습 데이터와 목표 상호작용 시나리오로 결정되는 data scaling 설계 선택으로 취급된다.

Agent Orchestration Runtime (§3.2.2)

runtime은 전뇌와 후뇌 사이의 조정 계층이다. 실시간 멀티모달 데이터 전송과 백엔드 과제 orchestration에 통일된 인터페이스를 제공함으로써, 옴니 상호작용 모델을 상호작용적 과제 실행을 위한 통합 harness로 바꿔 놓는다. 실시간 쪽에서 관리하는 것들을 풀어 쓰면:

  • 오디오·비주얼 스트림 수집과 증분 추론 스케줄링 — 1초 청크 주기(§3.3.2)에 맞춰 스트림을 모델 호출로 변환
  • 모델 호출 직렬화 + static prefix caching — 매초 반복되는 호출에서 시스템 프롬프트·과거 청크의 KV 재계산을 피해 실시간 예산을 지킨다
  • source-aware rate limiting — 카메라·화면 공유 등 서로 다른 시각 소스별로 persistent state를 유지하며 유입 속도를 제어

또한 전뇌가 발행한 task_start/send/resolve 연산을 전송 계층에서 확인된 최종 사용자 턴에 바인딩해서, 과제 목표가 전뇌가 독자적으로 생성한 tool 파라미터가 아니라 인증된 사용자 입력에 일관되게 접지(ground)되도록 보장한다 — 모델의 환각이나 재구성이 과제 목표를 오염시키지 못하게 하는 신뢰 경계다.

Training-Free 후뇌 (§3.2.3)

후뇌는 Codex나 Claude Code 같은 시스템으로 인스턴스화되는 training-free 범용 과제 실행 에이전트다. 자체 파일·커맨드라인·검색 도구에 더해, 세 가지 runtime 전용 인터페이스를 호출할 수 있다:

  1. context_fetch — 현재 과제 계보의 실시간 과제 컨텍스트·이벤트·아티팩트를 참조·역할·이벤트 유형·시간 범위·문자 예산 기준으로 조회 (예: "사용자가 방금 화면에서 가리킨 것"을 후뇌가 가져올 수 있음)
  2. memory_search — 세션을 넘나드는 영속 멀티모달 메모리 검색
  3. share — 검증된 중요 발견, 중간 진행 상황, 정정 정보를 실시간 전뇌 쪽으로 반환 (그림 5의 "결과 반환" 화살표)
직관적으로 말하면: 후뇌는 "회사에 새로 온 유능한 컨설턴트"다. 회사 내부 사정(실시간 대화 맥락)은 모르지만, 필요할 때 조회하는 창구(context_fetch, memory_search)와 보고 채널(share)만 표준화해 두면 어떤 컨설턴트로든 교체할 수 있다. ##개선된 추론 모델을 끼우는 것만으로 시스템 전체의 지능이 올라가는 확장 경로##가 이 분리에서 나온다.

3.3 Streaming Thinker-Talker 전뇌

전뇌는 MiniCPM-o 4.5 계열의 Thinker-Talker 구조 위에 streaming chunk flattening 메커니즘을 얹은 것이다. 스트리밍 오디오·비디오를 받아 텍스트와 음성을 함께 생성하며, 청크마다 들을지 말할지를 동적으로 결정한다.

3.3.1 옴니 지각 — 두 개의 스트리밍 인코더

두 모달리티 인코더가 동시에 돌면서 출력을 LLM 백본의 토큰 공간으로 사영한다. 어느 인코더도 완결된 클립이나 발화를 기다리지 않는다 — 둘 다 고정 길이 창 위에서 증분적으로 동작해, 시각·청각 관찰이 턴 경계가 아니라 스트리밍 교환의 매 스텝마다 백본에 노출된다.

시각 지각: 임의 종횡비·해상도 프레임을 실시간 제약 안에서 처리하기 위해 any-resolution partitioning(LLaVA-UHD 계열)을 따른다 — 프레임을 슬라이스로 분해하고, 각 슬라이스를 SigLIP vision transformer로 독립 인코딩한 뒤, query 기반 resampler로 소수의 고정 개수 시각 토큰으로 응축한다. 결과적으로 raw patch grid 대비 약 16× 감소 — 많은 선행 옴니 모델의 4×보다 훨씬 공격적이다. full-duplex에서는 프레임이 조밀하게 도달하고 빠듯한 시간 창 안에 소비되어야 하므로, 해상도를 최대 448×448로 제한해 프레임당 토큰을 상시 지각이 가능한 수준으로 유지한다.

청각 지각: 주변 소리와 사용자 음성을 함께 담는 음향 스트림은 스트리밍 청크 단위 speech encoder(Whisper 계열)가 초당 약 50개의 frame-level feature로 방출한다. 이 rate를 백본에 그대로 넣으면 시퀀스가 부풀어 실시간성이 무너지므로, 경량 MLP projector가 5× 시간 다운샘플링을 적용해 초당 약 10 토큰으로 낮춘 뒤 백본에 넣는다. 이 압축은 구어 이해에 필요한 음소·운율 단서는 유지하면서, 어느 모달리티도 창 예산을 독점하지 않게 한다.

3.3.2 Streaming Chunk Flattening — 이 논문의 기술적 심장

왜 문제인가: 전통적 formulation에서 "사용자 요청"은 생성을 개시(gate)하는 특권적 역할이다. 그러나 always-on 환경에서는 그런 특권적 신호가 없다 — 들어오는 음성·영상은 연속적으로 관찰되는 세계 상태의 일부일 뿐이고, 모델은 무엇을 생성할지뿐 아니라 언제·생성할지 여부 자체를 매 청크마다 결정해야 한다.

해법: 최근 상호작용 모델(Thinking Machines Lab의 interaction models)의 정신을 따라, 모든 모달리티와 입출력 양쪽을 공유 시간축 위의 하나의 causal 토큰 스트림으로 직렬화한다. 구체적으로:

  • 연속 상호작용을 1초 고정 창으로 분할하고 창마다 청크 하나를 구성한다.
  • 각 청크는 시간 정렬된 3개 세그먼트의 평탄화된 연결이다: [그 1초 동안 관찰된 오디오·비디오 토큰] + [예측된 제어 토큰 1개] + [모델이 방출하기로 선택한 텍스트 토큰 N개] (N은 모델이 결정하며 0일 수 있다).
  • 연속 청크들을 이어붙인 단일 시퀀스를 표준 causal LM 백본이 소비한다. 청크 안에서 모델은 먼저 새로 도착한 지각 토큰에 attend한 뒤에야 출력을 생성하므로, 방출되는 모든 토큰이 가장 최신 관찰에 조건화된다.
  • 지각 세그먼트와 생성 세그먼트의 경계를 명시적으로 표시해, 모델이 관찰된 입력과 자기 출력을 구분하게 하고 스트리밍 디코딩을 안정화한다.
직관적으로 말하면: 모델의 "인생"이 1초짜리 프레임의 연속 필름이 된다. 매 프레임마다 세상을 한 번 보고(지각 토큰), 입을 열지 말지 정하고(제어 토큰), 열기로 했으면 말한다(텍스트 토큰). 창마다 결정이 갱신되므로 능동적(proactive) 행동이 별도 트리거 없이 같은 메커니즘에서 자연히 나오고, 외부 VAD가 필요 없다.

한 청크의 처리 사이클을 의사 흐름도로 옮기면:

매초 (청크 C_t): ① 지각 : 이번 1초의 비디오 토큰 V₁…V_k + 오디오 토큰 A₁…A₁₀ 을 스트림에 append ② 결정 : 제어 토큰 1개 예측 ── listen → 텍스트 0개, 다음 청크로 │ ├─ speak → ③으로 │ └─ interrupt → 진행 중 발화 즉시 중단 ③ 생성 : 텍스트 토큰 T₁…T_N 생성 (N은 모델이 결정) ④ 합성 : (T, hidden state) → Talker → speech tokens → flow-matching → 파형 청크 재생 ⑤ 슬라이딩: 청크 수 > 128 이면 가장 오래된 청크 축출

컨텍스트 관리: 고정 예산 128 청크 — 약 2분의 rolling receptive field. 예산이 차면 가장 오래된 청크가 축출되고 새 청크가 덧붙는 슬라이딩 방식이라, 세션이 아무리 길어져도 유효 컨텍스트 길이가 유한하게 유지되고 스텝당 추론 비용이 안정적이다.

제어 토큰의 3가지 값: 각 청크 출력 세그먼트의 머리에서 예측되는 제어 토큰이 상호작용을 지배한다. ① listen — 이번 창은 침묵을 유지하고 관찰을 계속한다(출력 세그먼트에 텍스트 없음, 청크는 지각만 전진). ② speak — 이번 창에서 발화를 커밋한다(이후 N개 텍스트 토큰이 생성되어 음성 합성으로 전달). ③ interrupt — 진행 중인 자기 발화를 중단한다(사용자가 말을 시작했거나 장면이 변해 진행 중 응답이 구식이 된 경우).

##콘텐츠 생성 전에 이 이산적 제어 결정을 먼저 예측하는 것 — "말할지"와 "무엇을 말할지"의 분리 — 이 둘을 한 예측 스텝에 엉키게 하는 것보다 더 안정적인 full-duplex 거동을 낳는다##고 저자들은 보고한다. §5.2의 해석처럼, 이 결정은 응답을 생성할 바로 그 표현 위에서 내려지므로 음향적 조용함이 아니라 의미적 완결까지 미룰 수 있다.

3.3.3 음성 생성 — 백본은 텍스트에 머문다

왜 문제인가: LLM 백본이 음향 유닛을 직접 자기회귀 생성하게 하면, 음성 토큰의 frame rate가 텍스트보다 훨씬 높아 초당 디코딩 스텝이 폭증하고, 백본의 핵심 언어 능력이 침식되는 경향이 있다(Mini-Omni2의 관찰).

해법: 의미 계획(semantic planning)과 음향 실현(acoustic realization)을 분리하고, 파형 생성을 두 개의 경량 하류 디코더에 위임한다:

  1. Speech token 생성: 백본 최종층 hidden state를 projection layer로 변형해 텍스트 토큰과 함께 소형 자기회귀 speech token decoder에 주입, 대응하는 이산 speech 토큰을 방출한다(CosyVoice 계열). 운율·스타일 결정은 백본 hidden에 이미 사전 인코딩되어 있으므로 speech decoder는 고수준 계획에서 해방되어 세밀한 음향 모델링에 용량을 집중한다. 이산 유닛은 supervised semantic token — 단일 codebook, 저비트레이트라 자기회귀 예측에 적합하다. 입력 텍스트 토큰과 출력 speech 토큰은 별도 pass가 아니라 §3.3.2의 시간 정렬 방식으로 공유 타임라인에 인터리브된다.
  2. 파형 합성: 이산 speech 토큰을 streaming flow matching decoder가 연속 파형으로 변환한다. 멀티모달 시스템 프롬프트에 실린 참조 오디오에 조건화되어 semantic token으로부터 목표 mel-spectrogram을 재구성하므로, zero-shot 음색 제어가 따라온다 — 합성 음성의 음색·정체성이 학습 시점이 아니라 참조에 의해 결정된다. 결정적으로 decoder는 청크 단위 causal로 동작해, 전체 발화의 디코딩을 기다리지 않고 speech 토큰이 도착하는 대로 파형 청크를 방출한다.

4.1 음성 상호작용 데이터 — InteractionSpeech의 4단계 합성

음성 상호작용 데이터는 실시간 구어 상호작용의 기본 능력을 구축한다. 의미 이해·응답 생성을 넘어, 연속적으로 도착하는 음성 위에서의 상호작용 행동 — 턴테이킹, interruption, 겹치는 발화, 응답 타이밍 — 을 감독해 언제 들을지·계속 말할지·발화권(conversational floor)을 양보할지를 가르친다. 핵심은 full-duplex 부분인 InteractionSpeech(260.8K)로, 턴 기반 코퍼스에서 물려받는 게 아니라(그런 코퍼스에는 구조상 interruption과 겹침이 없다) 상호작용 행동을 명시적으로 합성하는 전용 파이프라인의 산물이다.

파이프라인의 주목할 세부:

  • 소스 ①: 교육·의료·여행·금융·공공서비스·고객지원 등 45개 일상·업무 시나리오에 걸친 11.2K 장면·주제 시드를 DeepSeek-V4-Pro로 8~18턴의 다중 턴 구어 대화로 확장. 발화 시간 합계를 96초 이하로 강제해 모든 시퀀스가 전뇌의 스트리밍 컨텍스트(128청크≈2분) 안에 들어가고, 부자연스럽게 긴 독백에 과도 학습되는 것을 막는다.
  • 소스 ②: 실제 어시스턴트 상호작용 로그와 공개 대화 코퍼스를 duplex 형태로 변환. "읽기용으로 쓰인" 자료이므로 markdown·코드·URL·수식이 지배하는 턴, 음성으로는 있을 수 없는 길이·정보 밀도의 턴을 구어 적합성 필터로 걸러낸다(후보 대부분이 기각됨). 살아남은 대화는 진짜 사용자 의도·표현을 보존한 채 상호작용 이벤트를 주입받는다.
  • 5개 상호작용 프로파일: 각 대화는 제약 명확화 / 과정 제어 / 사용자 정정 / 서비스 진입 실패 / 안전·긴급 중지 중 하나에 조건화된다 — interruption이 단일 반복 패턴이 아니라 다양한 소통 동기에서 발생하도록. 영어 데이터는 직접 생성 + 검증된 중국어 대화의 번역으로 얻되, 번역 후 영어 토큰화 기준으로 중단점을 다시 선정해 중국어 어순이 전이되지 않게 한다.

두 가지 상호작용 이벤트가 주석된다. 경쟁적 interruption에서는 사용자가 어시스턴트 발화 도중 끼어들고, 어시스턴트의 남은 말은 사용자에게 들리지 않은 "숨겨진 연속(hidden continuation)"이 된다 — 텍스트로는 유지하되 음성 합성에서 제외하고, 이후 사용자 턴이 '들을 수 없었던 정보'를 재사용하지 않는지 검증한다. 모델이 실제 청자가 갖는 음향적 증거만 관찰하게 하는 장치다. 지지적 backchannel에서는 사용자가 짧은 맞장구를 내지만 어시스턴트는 발화권을 유지하고 멈추지 않는다. 두 이벤트의 구분은 가정이 아니라 강제된다: 상대 발화 내부에 포함되고, 중국어 8자·영어 6단어 이하이고, 어휘집과 일치하거나 명시 표기된 턴만 backchannel로 인정한다. 의문·요청·부정적 입장 단서가 있으면 일반 턴으로 강등 — 진짜 발화권 요구를 맞장구로 오인 라벨링하는 것을 막는다. backchannel 표현은 11개 의도 범주로 조직된 이중언어 어휘집(중국어 266개·영어 170개)에서 맥락 조건부로 샘플링해, 작은 고정 단어 목록 특유의 반복적 맞장구를 피한다.

렌더링과 타이밍: 사용자 채널만 화자 풀 위의 voice-cloning TTS로 오디오화하고, 어시스턴트 턴은 텍스트로 남겨 타임라인에서 duration placeholder로 존재한다. 모든 턴에 전역 onset·지속시간·겹침 구간이 부여되어, interruption·backchannel의 타이밍 자체가 우연한 연결 부산물이 아니라 명시적 감독 신호가 된다. 불안정한 합성을 피하려고 paralinguistic 토큰은 방출하지 않고 두 마커만 유지한다: 겹침 영역을 구획하는 interruption 마커, 합성 전에 제거되는 backchannel 마커.

품질 관리(2단): 규칙 기반 게이트가 언어적으로 불가능한 중단점, 퇴화한 겹침 구간, 못 들었을 내용을 누설하는 끼어들기 턴, 미해결로 끝나는 상호작용을 먼저 폐기한다. 생존 샘플은 LLM judge가 자연스러움·어시스턴트 일관성·interruption 타당성·backchannel 타당성의 4차원으로 평가해 모든 해당 차원에서 임계값을 넘는 것만 유지한다. 최종 260.8K 대화는 interruption 시작점이 피중단 턴 전체에 넓게 분산되어 있고(끝부분 집중 없음), barge-in 대부분이 담화 표지가 아닌 내용어로 시작한다 — ##모델이 interruption을 소수의 정형화된 어휘 단서와 연합하는 것을 구조적으로 차단##한 것이다.

4.2 시청각 상호작용 데이터 (1.1M, 40.66%)

음성 전용 대화를 연속 진화하는 멀티모달 환경으로 확장한다. 비디오 상호작용 데이터는 JoyAI-VL, LiveCC, Streamo에서 수집해 3개 과제 범주로 조직한다:

  • 스트리밍 비디오 질의응답 — 진행 중인 비디오에 대한 질문에, 그 시점까지 관찰된 내용만으로 답한다
  • 스트리밍 비디오 내레이션 — 전개되는 장면을 실시간으로 서술 (이벤트 접지 능력의 감독)
  • 능동적 시각 응답 (proactive visual response) — 명시적 질문 없이, 관찰된 시각 이벤트가 응답을 정당화하는 순간 먼저 발화 (그림 2의 시나리오 ⑤ "결과 슬라이드 뜨면 알려줘"가 이 능력이다)

전 샘플이 품질 평가·필터링을 거친 뒤 Qwen3.5-297B-A17B로 시간 정렬 refinement를 받아 시간 정렬된 타깃을 구성하고 원 데이터의 부정확한 정렬을 교정한다 — 약 1.1M 고품질 시청각 상호작용 쌍이 나온다. 타깃 응답은 DeepSeek-V4-Pro로 재작성해 평균 초당 8토큰으로 길이를 정규화한다(응답 정보량과 음성 지연의 균형). 사용자 발화는 Qwen3-TTS로 음성화한다. 이 데이터는 들어오는 시각 증거를 진행 중 상호작용에 연속 통합하고, 진화하는 이벤트·상태 변화를 추적하고, 현재 시점까지 가용한 정보에만 응답을 접지하도록 가르친다 — 관련 시각 이벤트가 나타나는 순간의 적시 응답이 목표다.

4.3 에이전트 상호작용 데이터 (359.6K, ~13%)

앞의 데이터가 사용자–전뇌 직접 상호작용에 집중한다면, 에이전트 상호작용 데이터는 사용자·전뇌·후뇌의 3자 조율로 설정을 확장한다. 기존 tool-use 데이터가 고립된 도구 호출·과제 완료를 포착하는 것과 달리, 이 상호작용 궤적들은 다중 턴 사용자 상호작용을 진화하는 백엔드 상태·실행 진행·중간 결과와 인터리브한다 — 과제 개시, 후속 요청, 제약 갱신, 명확화, 진행 문의, 취소, 최종 결과 전달까지 전체 과제 수명주기를 포괄한다.

  • 오디오 에이전트 데이터(320.2K): 시드 주도 궤적 합성. 과제 클래스(execution / information search / search-then-execute)·도메인·카테고리·과제 패밀리의 다층 구조화 시드에 다양한 질의·상호작용 패턴을 결합해 샘플링하고, DeepSeek-V4-Pro가 사용자·전뇌·후뇌 3자의 timestamped 궤적을 시뮬레이션한다. 후뇌는 독립 실행기로 두고, 감독의 초점은 전뇌가 진화하는 과제 상태 주위에서 어떻게 소통·조율하는가다. 결과 궤적은 과제 일관성·상호작용 유효성·전체 품질로 평가·필터링된다.
  • 옴니(GUI) 에이전트 데이터(36K): 시각적으로 접지된 과제로 확장 — 전뇌가 진화하는 시각 상태(화면)를 연속 추적하면서 사용자·후뇌 양쪽과 상호작용해야 한다. GUI·비디오 궤적은 크롤링한 상호작용 궤적, 기존 GUI 데이터셋(OpenCUA), Codex로 생성한 GUI 궤적의 3개 소스에서 조립(약 36K). 시간 순서 관찰·행동을 Qwen3.5-297B-A17B가 환경 상태·과제 진행·상호작용 맥락의 구조화된 기술로 변환하고, DeepSeek-V4-Pro가 관찰된 시각 상태에 접지된 3자 상호작용을 합성한다. 시간 일관성·과제 타당성·상호작용 품질로 필터링.

4.4 강건성·부정 데이터 (229.7K, ~9%)

신뢰할 수 있는 실시간 상호작용은 유효한 요청에 대한 적절한 응답뿐 아니라, 무관·소음·다자 조건에서의 강건한 응답 억제를 요구한다. 4개 설정: ① 무관 비디오(116.2K) — 웹 크롤링 비디오와 무관한 사용자 지시를 짝지어 구성, 무관한 시각 이벤트를 무시하게 한다. ② 무명령 환경(40K) — 지시가 없는 환경 입력에서 침묵을 유지하게 한다. ③ 간섭 억제(64.7K) — 소음·겹치는 방해 발화에 대한 강건성. ④ 다자 상호작용(8.8K) — 화자·수신자 추적으로 발화가 어시스턴트를 향한 것인지 판정. ③④는 고품질 Hy-Realtime 프로덕션 데이터에서 소싱했다. 이 데이터들이 §5.2에서 보게 될 낮은 조기 개입률(Interrupt 8.0%)의 기반이다.

5.2 Full-Duplex 상호작용 — Full-Duplex-Bench v3

실험 의도: full-duplex 아키텍처가 존재하는 이유인 "발화 타이밍"과, 도구가 얽힌 서비스 시나리오의 과제 정확도를 동시에 검증한다. Full-Duplex-Bench v3는 자연스러운 비유창성(disfluency)이 섞인 도구 증강 서비스 시나리오 100개에 구어 어시스턴트를 놓는다. 지표: 도구 선택 F1(ToolSel), 인자 정확도(ArgAcc), 구어 응답의 의도 충족(RespQual), 도구 multiset이 모든 인자까지 정확해야 하는 엄격 이진 Pass@1, 그리고 상호작용 지표 3종 — 적절한 순간에 턴을 잡은 비율(Take-turn), 사용자가 말을 끝내기 전에 시작한 비율(Interrupt), 대화형 placeholder("음, 확인해볼게요")로 서두를 뗀 비율(Filler). 채점 스크립트를 무수정으로 사용하고(GPT-4o judge 포함), 배포 스택을 end-to-end로 평가한다 — 오디오가 Thinker에 들어가고 Talker·speech decoder가 응답을 합성하며, 채점은 그 오디오의 ASR transcript를 읽는다. 즉 모든 수치에 실제 음성 합성·인식 오차가 포함되어 있다. Filler는 벤치마크의 LLM 기반 지연 분석이 판정을 반환하는, interruption 없이 턴을 잡은 91/100개 시나리오 위에서 정의된다.

공정성을 위한 비대칭 교정 하나: 벤치마크 시스템 프롬프트는 "명확화 질문 대신 도구를 즉시 실행하라"고 지시하는데, 후뇌는 외부 에이전트라 이 프롬프트를 받지 못한다. 그래서 같은 요구사항을 담은 contract 파일을 후뇌의 작업 디렉토리에 두어 양쪽이 동등한 지시 아래 동작하게 했다 — 전뇌의 프롬프트는 건드리지 않은 채로.

6. 결론과 향후 과제

Gander는 Brain–Cerebellum 프레임워크와 스트리밍 청크 패러다임 위에 옴니 이해·실시간 상호작용·장기 에이전트 실행을 네이티브로 통합한 end-to-end 확장 가능 아키텍처다. 이 패러다임의 초기 탐색으로서 저자들이 명시한 열린 과제 5가지:

  • 데이터·모델 스케일링: 에이전트 호출과 대화 행동은 특히 복잡한 옴니 시나리오에서 학습 데이터 분포에 민감하게 남아 있다. 데이터와 모델 용량 스케일링이 강건성·일반화의 관건이며, 산업 스케일 기반 모델 Hy-Realtime에서 체계적으로 연구 예정.
  • 안정적 post-training: 현재 모델은 on-policy distillation(OPD)이나 RL로 본격 최적화되지 않았다. 장기 Omni Interaction Agent 시나리오의 보상 설계·credit assignment·최적화 안정성은 열린 문제이고, Brain–Cerebellum 구조는 국소 상호작용 품질과 전역 과제 목표의 조율이라는 새 고려사항을 더한다.
  • Brain–Cerebellum 통신 구조: 현 설계는 두 컴포넌트 간 통신을 주로 ASR 유래 신호(전사 텍스트)에 의존한다. 더 풍부하고 구조화된 양방향 통신 — Brain→Cerebellum 정보 전달 개선, Cerebellum→Brain 피드백 강화 — 이 필요하다.
  • 메모리·장기 컨텍스트: 옴니 에이전트 상호작용은 긴 멀티모달 이력·도구 호출·진화하는 과제 상태를 수반한다. 과제 관련 정보의 효율적 유지·검색 메커니즘이 중요한 방향.
  • 평가: 기존 벤치마크는 옴니 이해·duplex 상호작용·에이전트 실행을 따로따로 평가하며, Brain–Cerebellum 협업(컴포넌트 간 통신·조율)을 포착하지 못한다. 통합 옴니 상호작용 에이전트를 위한 평가 프레임워크가 사실상 부재하다.

비판적 분석 (Critical Analysis)

강점

  • 정직한 진단적 평가 설계: 후뇌 단독 조건으로 병목을 실행 계층에서 분리하고, base 모델 대비 회귀를 벤치마크 비대칭(Daily-Omni vs WorldSense)까지 파고들어 "훈련이 보상한 것만 유지된다"는 결론을 끌어낸다. 자기 시스템의 낮은 Pass@1을 감추지 않고 원인을 특정하는 서술은 기술 보고서로서 드물게 성실하다.
  • 데이터 구축의 세부 공개: InteractionSpeech의 backchannel 인정 기준(길이 임계·어휘집 266/170·의도 11범주), interruption 시작점 분산 통제, 숨겨진 연속의 합성 제외와 누설 검증 등 재현에 필요한 설계 장치가 이례적으로 구체적이다.
  • 시스템 수준의 실전 고려: task 목표를 인증된 사용자 턴에 바인딩(전뇌 생성 파라미터의 단독 사용 배제), coordinator의 선언적 계획과 gateway 검증 분리, fork 격리 등 배포 관점의 안전·신뢰성 설계가 아키텍처에 내장되어 있다.
  • 모델·코드·데이터 공개 + 상용 시스템(GPT-Realtime, Gemini Live)과의 직접 비교.

한계와 의문점

  • 학습 세부의 공백: 기술 보고서임에도 optimizer, learning rate, batch size, 학습 단계 구성(SFT 단계 수), hardware, 학습 토큰 수가 전혀 없다. 9B라는 크기와 MiniCPM-o 4.5 초기화만 명시된다. 수식이 하나도 없는 시스템 논문이라 손실 함수 구성(제어 토큰 예측 가중치 등)도 알 수 없다.
  • 단일 run·무통계: 모든 결과가 단일 체크포인트 단일 실행이다. Full-Duplex-Bench v3는 100 시나리오뿐이라 Take-turn 100% vs 96%의 차이는 4개 시나리오 차이다 — 신뢰구간 없이 "표에서 최고"를 단정하기엔 표본이 작다.
  • 합성 데이터 순환 의존: 상호작용 데이터의 생성(DeepSeek-V4-Pro)·정렬(Qwen3.5)·품질 심사(LLM judge)가 모두 LLM이다. LLM이 상상한 interruption 분포가 실제 인간의 것과 얼마나 일치하는지는 Hy-Realtime 프로덕션 데이터가 일부 쓰였다는 것 외에 검증이 없다.
  • "내부 인간 평가"의 비공개: 초록은 SOTA 오픈소스 모델 수준의 자연스러운 구어 능력을 내부 인간 평가로 확인했다고 주장하지만 본문에 해당 수치·프로토콜이 없다(프로젝트 페이지 데모로 대체).
  • 전뇌→후뇌 정보 손실: 통신이 전사 텍스트 + 마지막 프레임뿐이므로 운율("빨리!"의 긴박함), 화자 정체성, 연속 시각 맥락이 후뇌에 닿지 않는다 — 저자들도 인정하는 열린 설계이며, §6의 통신 구조 과제와 직결된다.
  • 후뇌 의존성의 비용 미논의: 후뇌가 GPT-5.6 구동 Codex인데, 위임 빈도(Filler 51.6%가 시사)·지연·API 비용 같은 실배포 비용 분석이 없다.

Key Takeaways — 이 논문에서 가져갈 것

  1. 상호작용 결정은 응답을 만들 표현 위에서 내려야 한다: VAD 같은 외부 endpointer는 음향적 침묵에 커밋하므로 구조적으로 조기 개입(cascaded의 Interrupt 33%)하거나 턴을 놓친다. "언제 말할지"를 내용 생성과 같은 표현에서, 그러나 분리된 선행 예측으로 내리는 것이 Take-turn 100/Interrupt 8.0의 원천이다.
  2. 반응성과 지능의 분리-재결합 패턴: 실시간 계층(소형, 학습됨)과 추론 계층(대형, training-free)을 구조화된 tool call + 결정론적 runtime으로 잇는 설계는, 음성 에이전트 제품을 만들 때 그대로 참고할 만한 청사진이다 — 특히 task 목표의 사용자 턴 바인딩과 fork 격리.
  3. 상호작용 데이터는 "이벤트를 명시적으로 합성"해야 한다: 턴 기반 코퍼스에는 interruption·backchannel이 구조상 존재하지 않는다. 숨겨진 연속(들리지 않은 발화의 텍스트 유지 + 합성 제외 + 누설 검증) 같은 장치가 이 논문의 데이터 방법론에서 가장 재사용 가치 높은 부분이다.
  4. 스트리밍 formulation은 공짜에 가깝다: 프레임 동기 소비 + 발화 종료 판정이라는 추가 부담에도 SpokenQA에서 턴 기반과 대등(전체 2위) — full-duplex화가 지식 손실을 의미하지 않는다.
  5. 훈련은 보상하는 능력만 보존한다: Daily-Omni −1.67 vs WorldSense −6.08의 비대칭은, 파인튜닝 코퍼스가 연습시키지 않는 능력이 어디서 침식되는지 예측하는 일반 원리로 읽을 수 있다.
  6. (비판적 관점) 이 보고서는 "무엇을 만들었는가"에 비해 "어떻게 학습했는가"가 비어 있다. 하이퍼파라미터·손실 구성·아키텍처 ablation 없이 단일 run 결과이므로, 개별 수치보다는 설계 패턴과 데이터 방법론을 가져가는 것이 안전하다.
