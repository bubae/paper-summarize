기존 agent harness의 문제 (Figure 1 오른쪽 재현)

Figure 1 오른쪽 재현: (좌) 기존 agent는 하나의 growing session이 진행/자기평가를 동시에 담당 → context rot + drift. (우) LongHorizon-Harness는 3역할 분리, executor context는 라운드마다 폐기, audit report만 축적.

1. Compounding Errors

초기 실수가 이후 결정에 그대로 전파. Growing session에서는 잘못된 관찰도 다시 바닥에서부터 재검토되지 않음.

2. Context Rot

상호작용 이력이 커질수록 relevant 정보 검색이 어려워짐. Context utilization이 threshold를 넘으면 성능이 급락.

3. Task-State Loss

Requirement, 완료 action, artifact, fact를 정확히 추적하지 못함. 완료 판단의 baseline이 흔들림.

왜 fresh context인가

매 라운드 executor는 전 회차 raw trajectory 없이 시작. 이전 회차의 잘못된 관찰이 이번 라운드 결정을 오염시키지 못함. Context rot 자체가 발생 여지가 없음.

왜 executor trajectory를 auditor에게 안 주는가

Auditor가 executor의 자기평가를 보면 그 논리를 그대로 받아들일 유혹이 생김. Auditor는 결과 환경만 검증해 executor의 주장이 실제로 참인지 독립 확인.

Task State의 구조

Task state는 3종 record — requirement, artifact, fact — 각각 4가지 상태(completed, pending, blocked, untrusted) 중 하나. 상태는 오직 clean audit evidence로만 완료 표시됨.

대칭성이 시사하는 것

강한 모델은 subtask contract를 적은 audit-replan 라운드로 만족시킨다. 약한 모델은 반복 실행·복구에 더 많은 inference를 쓴다. ##Agent capability = model × harness의 시스템 속성##임을 실증.

Case Study: 실제 실행 궤적 비교 (Section 3.4)

Case 1: Stalled Interaction (WEB_task_16, WebRTC audit)

Baseline (0.59): Wireshark "Decode As" 다이얼로그가 unresponsive임을 인식하나, growing history에 이 관찰이 묻힌 채 같은 상호작용을 400+ steps 반복. 예산 소진.

LH (0.92): 실패한 상호작용을 task state에 pending으로 기록. 다음 executor들이 놓친 evidence에 집중.

Case 2: Apparent Completion (DOC_task_2, heading style)

Baseline (0.00): 문서 XML을 직접 편집해 시각적으로 그럴듯한 결과를 만들고 종료. 실제 style은 미적용.

LH (0.89): LibreOffice GUI workflow 사용. Auditor가 XML을 파싱해 15개 heading 모두 올바른 style임을 검증.

Case 3: Pre-repair Evidence (DOC_task_4, VLOOKUP)

Baseline (0.45): 초기 오류 캡처 후 spreadsheet 수정. 그러나 pre-repair evidence 완료 전에 수정해 파일 재열림 시 forensic context 소실.

LH (0.87): 누락된 pre-repair evidence를 pending으로 기록. 다음 executor가 evidence를 먼저 완성 후 수리. 9-screenshot 시퀀스 검증.

Case 4: Verified Progress (WEB_task_10, Lighthouse)

Baseline (0.53): Core optimization 후 DevTools evidence 수집에서 stuck. Growing session이 DevTools 반복 조작에 예산 소진.

LH (0.85): 완료된 optimization을 task state에 유지. Fresh executor들이 남은 evidence만 분산 처리. Optimization을 재구성하지 않음.

한계점

Token cost 증가 (약한 모델)

Qwen에서 3.2~3.6× 토큰 증가. Cost/quality trade-off 분석 부족. Terminal-Bench 예외 제외하면 대부분 비용 상승.

Auditor collusion 위험

Executor와 auditor가 같은 backbone이라 유사한 blind spot 공유. Adversarial auditor(다른 model family) 미검증.

Role별 model mix 부재

모든 역할이 같은 모델. Manager는 planning, Executor는 tool-use, Auditor는 verification에 특화된 다른 모델 혼합 실험 없음.

OSWorld 절대값 여전히 낮음

3× 개선했지만 8.3%. Harness만으로는 넘지 못하는 model capability 벽 존재.

Category-dependent 이득의 원인 불명확

Design +60 vs data-science −12.5의 격차 원인 예측 불가. 새 태스크 도입 시 이득 예측 rule of thumb 부재.

한 줄 결론

"Long-horizon agent의 능력은 model만의 특성이 아니다. Task state를 외부화하고 executor의 self-assessment를 아키텍처적으로 제거하면, 같은 모델도 완전히 다른 신뢰도로 작동한다."
