RLVR → SSL → RLSVR: 세 학습 패러다임의 비교 (Figure 1 재현)

Figure 1 재현: (a) RLVR은 known correct answer로만 채점 → 수학·코딩에 국한. (b) SSL은 데이터 자체가 label(masked token 예측). (c) RLSVR은 SSL 원리를 RL에 이식 — 환경이 latent variable(spy identity 등)을 pre-assign해 verifiable reward를 induce.

SpyRL Framework 개요 (Figure 2 재현)

Figure 2 재현: (좌) unverifiable open-ended task → (중) 비대칭 정보 배분 후 target task 수행 → (우) 투표로 spy 식별. Detection reward는 pre-assigned identity로 검증 가능, Performing reward는 vote 수 역비례.

RLSVR의 프레임워크: SSL의 pretext task 원리를 RL로 이식. 원 unverifiable objective Q를 verifiable proxy R로 변환.

한계점

Task-specific g(·) 설계 요구

Mask ratio: 요약 20%, 수학 40%로 태스크마다 다름. 새 도메인 도입 시 튜닝 필요. RAE가 완화하지만 완전 자동은 아님.

Detector-Performer collusion 위험

Policy π^P와 π^D가 같은 backbone. 서로 다른 모델을 쓸 때의 이점 미검증. 같은 backbone은 shared blind spot 가능.

Zero-sum reward의 exploitability

Civilian이 systematic strategic voting을 학습하면 spy detection이 아닌 arbitrary target에 몰릴 위험. Degenerate 균형 방어 미분석.

Compute cost

n=5 rollout + detection round = 5× standard RLVR. External verifier cost 절감이 상쇄 여지 있지만 순수 GPU 비용은 증가.

Long context 미검증

Max generation 2048 tokens. 실제 요약/창작은 훨씬 긴 output가 필요할 수 있음. Longer context에서 detector 능력 검증 없음.

한 줄 결론

"Verifiability는 태스크의 intrinsic property가 아니라 engineered property다. Information-asymmetric self-play는 open-ended task를 verifiable proxy로 변환하는 강력한 도구."
